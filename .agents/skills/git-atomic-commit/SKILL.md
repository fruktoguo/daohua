# Git 原子化全量提交

把当前工作区的全部改动快速拆成若干原子提交：按逻辑单元分组、整文件入组、提交说明统一中文。

## 硬性规则

1. **单文件不可拆分**：一个文件的全部改动只能进入一个提交。禁止 `git add -p` / `git add --patch`，禁止对同一文件分两次暂存不同 hunk。原子性以「文件」为最小粒度。
2. **原子化 = 按逻辑单元分组**：同一功能/模块/层的文件合为一个提交；不同关注点分开提交。宁可单个提交稍大，也不把同一逻辑单元的文件拆到两个提交。
3. **提交说明一律中文**，格式 `type(scope): 中文描述`，与仓库历史风格一致。
4. 只提交不推送：除非用户明确要求，禁止 `git push`；禁止修改 git config，禁止 `-i` 交互模式。
5. 暂存前快速检查是否含密钥、口令、token 等敏感信息；发现即停止并询问用户。
6. 已暂存内容视为用户改动的一部分，纳入分组提交，不得丢弃或重置。

## 执行流程

1. **并行收集**（一次发齐）：
   - `git status --short`（含未跟踪文件）
   - `git diff` 与 `git diff --cached`（理解改动内容）
   - `git log --oneline -10`（对齐提交风格与 scope 用法）
2. **冲突检查**：存在未合并文件（`UU`/`AA` 等）时停止并报告用户，不得自动提交。
3. **无改动**：工作区干净时直接说明，不产生空提交。
4. **分组**：按目录/模块/功能把文件分组，参考：
   - 同一功能的源码 + 配置 + 对应测试 + 直接相关文档 → 一个提交
   - `vendor/YuoCore` submodule 指针变更 → 单独提交
   - 纯文档/任务面板/技能文件 → 独立 `docs` 提交
   - 无法判断归属的杂项 → 收尾一个 `chore` 提交，不硬塞进功能提交
5. **逐组提交**：

   ```bash
   git add -- <该组文件列表>
   git commit -m "$(cat <<'EOF'
   type(scope): 中文描述

   可选正文：说明为什么，一两句即可
   EOF
   )"
   ```

6. **每组后校验**：`git status --short` 确认剩余文件与计划一致；pre-commit 钩子改写文件导致提交失败时，重新暂存被改写的文件再重试一次。
7. **收尾总结**：输出本次提交的 `git log --oneline` 列表，确认工作区已干净。

## 提交类型与 scope

- 类型：`feat` / `fix` / `refactor` / `docs` / `test` / `chore` / `style` / `perf`
- scope 按实际改动层选取：`domain` / `server` / `ecs` / `frontend` / `config` / `tools` / `deploy` / `design` / `tasks` 等；跨层大功能可省略 scope
- 描述写「做了什么、为什么」，一行以内；正文可选，解释动机与取舍
- 改动属于某个已登记任务时，可在正文注明任务编号（如 `TASK-20261004-04`）

## 边界情况

- **工作区混有多个任务的改动**：仍全量提交，分组时按任务边界拆开，各组提交说明注明对应任务编号。
- **用户只要提交部分文件**：不属于「全部提交」，按用户指定文件执行，同样遵守单文件不可拆分。
- **提交被钩子拒绝且重试无效**：阅读钩子输出修复后重试；无法修复时停止并报告，不使用 `--no-verify` 绕过（除非用户明确要求）。
