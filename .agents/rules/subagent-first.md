# 并行开发与 Subagent 协同优先准则 (Parallel Subagent First)

本规则规定智能体在处理开发与交互任务时，必须以多智能体并发协同为第一优先级。

---

## 1. 核心准则：杜绝单线程串行硬扛
智能体在处理包含多个异构模块、具有相对独立性或跨层的任务时，**严禁将所有探索、编码与验证过程塞入单个上下文单线程串行处理**。
只要任务满足并行拆分条件，**必须主动、优先调用 `invoke_subagent` 并发派发子智能体**。

---

## 2. 强制并发触发场景

1. **多模块与前后端分工**：
   - 前端界面（React / Tailwind）与后端（API / WebSocket / 领域协议）分离开发；
   - 业务领域逻辑编写与配套回归测试用例并行编写；
   - 数值配表数据设计与系统静态执行器逻辑实现分工。
2. **重构与全景影响面修复**：
   - 一个智能体专注于核心底层重构与迁移；
   - 另一个智能体并发扫描下游所有调用点并完成兼容性修复。
3. **复杂调研与全景排查**：
   - 遇到大仓库背景调查、日志分析、第三方协议勘测时，启动专门的 Research 子智能体，主智能体保持会话精简。
4. **多维度联合质量把关**：
   - 关键交付阶段，并发派出代码审计 Agent、数值审查 Agent 与自动化测试 Agent 联合审查。

---

## 3. 架构与调度契约

- **主智能体定位**：主智能体为总指挥与架构调度中心（Orchestrator），负责需求拆解、定义清晰的子任务契约、并发派发任务、汇总关键产出并执行最终集成门禁。
- **子智能体定位**：具备独立清晰的 Prompt 目标，在隔离的上下文中快速完成交付，主动回报改动文件、关键产出与自测证据。
