# Agent 协同与调度分级准则 (Agent Coordination and Dispatch Discipline)

本规则规定智能体在处理开发与交互任务时的 Agent 调度分级与协同契约。

---

## 1. 核心准则：按需分级，拒绝盲目并发

智能体严禁对所有任务不加区分地一刀切并发派发，必须严格依据任务规模与耦合度执行分级调度：

1. **小型需求严禁多 Agent**：
   - 凡局部 Bug 修复、单一文件/模块改动、文案与配置微调、小组件扩展等小型需求，**严禁启动多个 Agent**；
   - 必须由主 Agent 在单一上下文中独立高效完成，杜绝上下文同步开销、文件写冲突与碎片化调度。

2. **大型需求多 Agent 先行明示分工**：
   - 仅当需求具有跨前后端、跨独立领域与基础设施、或多份独立资产并发处理等明确正交分界的大型需求时，才可考虑使用多 Agent；
   - **在启动多 Agent 之前，必须先向用户明确表明每个 Agent 的负责情况**，包括：
     - **Agent 标识/角色**（如 `Ecs-Backend-Agent` / `Frontend-UI-Agent`）
     - **负责的模块与文件边界**（明确写范围，杜绝写冲突）
     - **任务目标与交付契约**（输入什么、产出什么、何种验证标准）
   - 用户知悉分工后方可派发，各 Agent 独立完成后由主 Agent 在主上下文统一集成并跑通全局门禁。

---

## 2. 调度场景判定矩阵

| 任务规模与特征 | 适用模式 | 执行要求 |
| :--- | :--- | :--- |
| **单点修复 / 局部微调**<br>（如修复一个计算公式、调整某处 UI 边距或文案） | **单主 Agent 独立执行** | 严禁调用 Subagent；主上下文内完成阅读、修改与针对性测试 |
| **单模块需求**<br>（如新增一个独立纯函数、修改单张数据表） | **单主 Agent 独立执行** | 严禁调用 Subagent；快速迭代，保持上下文集中 |
| **大型跨层需求**<br>（前后端同时新增协议与功能、跨 ECS 领域与持久化适配） | **多 Agent 并发协同** | **派发前必须列出 Agent 职责矩阵**；按写域严格切片；主 Agent 负责总控与门禁 |
| **独立资产大批量生成**<br>（如多批立绘生成、多类图标资产转换） | **多 Agent 并发协同** | 资产目录严格按命名隔离，先列出分工批次与负责范围再启动 |

---

## 3. 架构与调度契约

- **主智能体定位**：架构调度总控（Orchestrator）。负责需求理解与复述、规模评估、向用户明确公开分工矩阵、汇总各 Agent 产出并在主上下文执行统一门禁验证。
- **子智能体定位**：严格限定在其被声明的写域与契约内执行，严禁越界修改其他 Agent 或主 Agent 负责的文件，完成后主动汇报改动文件与自测证据。
