# 第一篇 核心哲学与顶层定位

## 1.1 产品定义
《道化太初》是一款以**服务端权威、高确定性离散事件推进（DES）、长线挂机放置**为核心的修仙 RPG 游戏。玩家绝大多数成长行为通过行动队列驱动，离线挂机与在线游玩具有完全等价的确定性数学模拟结果。

## 1.2 核心设计铁律
1. **怪我完全同构 (Monster-Player Isomorphism)**：怪物在领域模型中与玩家完全同构，共享同一套 14 基础属性池、技能装配逻辑、暴击破招对抗与抗性减伤公式，杜绝给怪物编写特殊隐藏补正。
2. **数值全域使用 `double` 精度**：所有属性、收益率、倍率、战斗伤害、时间与计数，计算与存储一律采用 IEEE 754 `double` 精度（百分比存储为 `double` 点数，1 点 = 1%），杜绝整数截断与精度损失。
3. **离散事件飞跃推进 (Discrete Event Simulation)**：游戏推进不依赖固定帧逐秒轮询，而是跳跃至下一个行动或战斗阶段的到期时间戳进行原子状态跃迁。
4. **长线数值闭环量化**：杜绝拍脑袋配表，全量技能、装备、丹药与怪物属性均由顶层数学模型（期望属性池、部位权重、质量预算）确定性推导。
5. **本地开发兼容清零**：在内测开发期直接废弃历史兼容包袱，不保留双读双写与兼容适配器，以代码精简、架构清晰为第一原则。

# 第二篇 修仙境界与四乘区数值底座

## 2.1 境界、阶位与品质三维架构
游戏建立**横向阶位（Tier 1~12 四阶段）**与**纵向品质（Quality 1~8）**交织的修仙体系：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        全 12 阶位四阶段全景架构                        │
├────────────────────────────────────────────────────────────────────────┤
│ 前期 (凡俗阶段) : 第 1 阶 (凡胎 Lv 1~12) ──> 第 2 阶 (叩仙门 Lv 13~24) │
│ 中期 (气基丹期) : 第 3 阶 (练气) ──> 第 4 阶 (筑基) ──> 第 5 阶 (金丹) │
│ 后期 (婴神虚体) : 第 6 阶 (元婴) ──> 第 7 阶 (化神) ──> 第 8 阶 (炼虚) ──> 第 9 阶 (合体) │
│ 大后期 (仙道真源): 第 10 阶 (大乘) ──> 第 11 阶 (渡劫) ──> 第 12 阶 (飞升真仙) │
└────────────────────────────────────────────────────────────────────────┘
```

- **八大品质等级**：Q1 凡品 (白 1.00x) $\to$ Q2 灵品 (绿 1.15x) $\to$ Q3 玄品 (蓝 1.35x) $\to$ Q4 地品 (紫 1.60x) $\to$ Q5 天品 (金 1.90x) $\to$ Q6 仙品 (橙 2.30x) $\to$ Q7 神品 (红 2.80x) $\to$ Q8 混沌 (彩 3.50x)。
- **一体化徽章表现**：`[大境界牌匾框] ◇位阶棱形框◇ (小境界胶囊框)`（如 `[练气] ◇极◇ (练气巅峰)`，悬浮展示精准等级 Lv）。
- **系统与世界观解耦说明**：12 阶阶位是底层数值、内视面板与装备穿戴的统一系统模型；剧情对白与世界观文案使用“未入门/引炁/炼炁/凝炁”沉浸式口径，两者各司其职。

# 第五篇 持续消耗品机制与生活制造体系

## 5.1 动作耗时分摊持续消耗品机制 (Sustained Consumable)
1. **动作绑定与耗时扣减**：持续消耗品仅在角色实际执行对应动作时，按本次动作**实际耗时**扣除槽位剩余时间：
   $$\text{NewRemaining} = \text{RemainingDurationSeconds} - \text{ActualDuration}$$
2. **状态常驻与槽位持久化**：不主动切槽时，剩余持续时间永久保存在 `AutoUseSlot` 中，绝不随自然时间流逝。
3. **透支免单友好规则**：当剩余持续时间不足以支付下一次动作时，直接消耗完当前物品并结算完整收益，不足部分免除。
4. **切槽惩罚 (Switching Penalty)**：若物品已开封使用了一部分时间，玩家主动切换/卸下该槽位时，已开封的当前这 1 件物品直接扣除作废，不退回时间。

# 第六篇 战斗引擎、减伤公式与状态常驻规约

## 6.1 两层动态抗性非线性减伤公式

战斗伤害采用**大类抗性平方穿甲** + **五行属性抗性百分比减免**两层减伤模型：

1. **第一层：大类抗性非线性平方减伤（护甲 / 法抗）**：
   $$\text{DamageAfterCategory} = \frac{\mathbf{RawDamage^2}}{\mathbf{RawDamage} + \mathbf{RES} \times K + 1.0}$$
   - **有效抗性 $\mathbf{RES}$**：物理伤害根据守方物理护甲（`Armor`）计算；术法伤害根据守方法术抗性（`MagicResistance`）计算。
   - **动态抗性系数 $K$**：随境界阶位线性递增（T1 $K=1.0$, T2 $K=2.0$, ..., T12 $K=12.0$）。
   - **天然穿甲特性**：单发原始伤害（$\text{RawDamage}$）越高，穿透减伤比例越强；法修凭借 2.0x 超大 AP 拥有极强的天然破防优势。

2. **第二层：五行属性抗性减免（金木水火土）**：
   当技能携带具体五行属性时（非 `Element.None`），依据守方对应五行抗性计算二次减免：
   $$\text{Mitigation} = \frac{\text{ElementRes}}{\text{ElementRes} + 100.0 \times K}$$
   $$\text{DamageAfterElement} = \text{DamageAfterCategory} \times \max(0.0, 1.0 - \text{Mitigation})$$

3. **最终伤害与暴击放大**：
   $$\mathbf{实际伤害} = \text{DamageAfterElement} \times (\text{是否暴击} ? \text{CritMultiplier} : 1.0)$$
## 6.2 三大对抗除法概率公式 (常数 $K = 100.0$)
1. **闪避 vs 命中对抗 (先判定是否被闪避)**：
   攻击发起时优先判定守方是否成功闪避：
   $$\text{闪避概率} = \frac{\text{守方闪避}}{\text{守方闪避} + \text{攻方命中} + 100.0}$$
   - **闪避成功**：本次攻击完全落空，造成 0 伤害；
   - **闪避失败 (即命中)**：进入后续伤害与暴击减免结算。$0$ 闪避对 $0$ 命中时闪避率为 $0\%$ (默认必中)。
2. **暴击 vs 免爆对抗**：
   命中后判定是否触发暴击：
   $$\text{暴击概率} = \frac{\text{攻方暴击}}{\text{攻方暴击} + \text{守方免爆} + 100.0} \quad (\text{基础暴伤 } 150\% + \text{暴伤加成})$$
3. **破招 vs 拆招 (化解)**：
   - **破招成功**（概率 $\frac{\text{攻方破招}}{\text{攻方破招} + \text{守方拆招} + 100}$）：**命中值与暴击值实际计算效果翻倍**；
   - **拆招成功**（概率 $\frac{\text{守方拆招}}{\text{守方拆招} + \text{攻方破招} + 100}$）：**双抗（护甲/法抗）与闪避实际计算效果翻倍**。

## 6.3 仇恨威胁与目标选择机制
- **威胁累积**：$\text{有效威胁值} = \text{基础累积伤害威胁} \times (1 + \text{嘲讽/仇恨加成})$。
- **单体技能与非全 AoE 抽取**：将全体存活目标的威胁值作为权重池 $S = \max(1.0, \sum \text{Threat}_i)$ 动态抽取目标；多目标技能采用**动态缩减概率池算法（Sequential Elimination）**逐一抽取，确保单次攻击不重复命中同一目标。

## 6.4 角色状态世界常驻、自然回复与复活规约
1. **世界状态常驻**：移除战斗边界与脱战无故回满。角色生命与灵力在各种行动（挂机、采集、炼丹、赶路、战斗）中连续流转。
2. **自然自动回复（基础属性表驱动）**：
   - 随境界的基础生命回复与灵力回复由基础属性配置提供；修改回复基础值应改表，代码只读取回复属性并结算明确的回复加成。
   - **2% 是生命回复的配表参考**：参考对应境界的基础生命上限，将点数写入表；不是运行时按基础或最终生命上限乘 2%，也不要求代码维持固定比例。
   - 仅增加生命上限不会自动增加回复；灵力回复独立配表，本次不指定其比例。不隐式添加保底 1 点或取整规则。
   - **结算周期基线**：当前实现基线为 **5 秒整额回复周期**（`HpRegen`/`MpRegen` 每 5 秒一跳结算整额回复量）；表中回复量的时间单位即按每跳整额理解。详见 [战斗规约 §9.2](./combat-design.md#92-自然回复属性由基础属性表配置)。
   - 死亡状态下：生命值保持 0，**经脉灵力持续正常回复并完整保留**。
3. **两类复活结算**：
   - **读条完成正式复活**（历练死亡阶段 180s 倒计时完成）：**满生命值、满灵力值**重塑肉身重新投入战斗。
   - **退出战斗脱战复苏**（死亡状态下取消队列或手动脱战）：**恢复至 1 点生命（1 HP）**防止脱战暴毙，**保持死亡期间已自然回复的灵力**，绝不一键回满。

# 第七篇 大世界地图拓扑与质量预算遇怪系统

## 7.1 通用世界地点模型 (`WorldNode`)
不存在割裂的“纯战斗副本”。所有地点均为通用地理节点，包含三大支柱：
1. **开放行动集合 (`availableActionIds`)**：采集、挖矿、炼丹、打坐、历练等。
2. **驻留生物生态 (`npcs`, `buildings`)**：常驻 NPC（任务/传功）与场景陈设建筑。
3. **节点可建列表 (`buildableTemplate` / `buildableList`)**：本节点可建造的公共建筑集合（详见 7.3 与 [`node-building-system.md`](node-building-system.md)）。

> **危险度预算归遭遇而非节点**：`[minBudget, maxBudget]` 战力预算区间、精英/Boss 周期（`battlesPerElite` 默认 5、`battlesPerBoss` 默认 20）与怪群权重池（`randomSpawns`/`eliteEnemyIds`/`bossEnemyIds`/`maxTotalStrength`）均定义在 `config/game-data/encounters/*.json`，节点仅通过 `encounterIds` 弱引用遭遇。节点不承载预算字段。

## 7.2 质量预算遇怪抽取算法
```mermaid
flowchart TD
    Start([寻怪倒计时结束]) --> CheckBoss{waveNumber % battlesPerBoss == 0 ?}
    CheckBoss -- 是 --> SpawnBoss[从 bossEnemyIds 抽取 1 只 Boss, 预算重置为 maxBudget - bossCost]
    CheckBoss -- 否 --> CheckElite{waveNumber % battlesPerElite == 0 ?}
    CheckElite -- 是 --> SpawnElite[从 eliteEnemyIds 抽取 1 只精英怪, 扣除 budgetCost]
    CheckElite -- 否 --> RollBudget[在 [minBudget, maxBudget] 确定性抽取总预算 remainBudget]

    SpawnElite --> DeductElite[剩余预算用于抽取小怪护从]
    DeductElite --> LoopExtract[质量预算扣减循环: 按权重轮盘抽取, 扣除 budgetCost, 直至预算耗尽或满编 3 只]
    RollBudget --> LoopExtract
    LoopExtract --> Finalize[生成怪群阵容 -> 进入 Combat 战斗]
```

> 单波满编 3 只（1 特殊怪 + 2 护从 / 3 普通怪），并受 `maxTotalStrength` 强度上限约束；候选池为空时按预算最低普通小怪保底，杜绝空波次。

## 7.3 节点公共建筑系统 (`NodeBuilding`)
节点级**公共设施**：无建造者概念，同节点同种仅一座，全民可发起建造、填充材料与升级；效果对同地所有玩家生效。核心规则：

- **双进度条**：总进度 = `min(材料%, 时间%)`；时间需求 `600×(1+0.2×(N-1))` 秒，材料需求 `基础×1.1^(N-1)`；惰性推算、无后台 tick。
- **效果模型**：`modifiers` 七项（采集/炼丹的加速与收益、修炼收益、战斗回血与减伤），Lv N 生效 = 每级基准 × N；收益类与消耗品/灵脉倍率同乘区叠加。
- **共享持久化**：节点级注册表落 `game.node_buildings`，玩家聚合内仅为最近已知投影。

完整规则、配表字段与数值见 [`node-building-system.md`](node-building-system.md)。

# 第九篇 世界观设定、主线剧情与叙事红线

## 9.1 时代底色：太初之世
- 天地初开不久，人烟稀少，聚落零星。大地上的“炁”浓郁可见，但**无人知晓炁的规矩**，没有宗门、传承与成型功法。
- 云来集是山脚下唯一的落脚聚落，北边有一口老井（**北井**），集口有刻了阵纹的木柱（**阵基**），山顶有看天的**观星客**。

## 9.2 七章主线剧情与 10 大碎片链
1. **序章·云来**：外乡人落脚云来集，学会引炁入体，夜里路过北井听见怪异声音（水声/风声/数数声）。
2. **第一章·泉变**：澄心灵泉水变味，林伯与兰婆各执一词，玩家学会炼制引炁丹，“听泉底”指向北井。
3. **第二章·矿光**：玄铁矿洞矿壁微光，失踪矿工反复念叨“下面有数数的”，带回发光石头。
4. **第三章·立碑**：古台立起新碑，守井人刻下八字八谜——“**炁有归处，人留门路**”，台基下发现古老暗纹。
5. **第四章·谷鸣**：暮影谷妖兽反常成群，暮影关立起哨塔，谷主身上发现同款暗纹，守岭人赐下行令。
6. **第五章·天铁**：观星客预警坠星，玩家取回天铁，矿光石与天铁放在一起微光暗去，互相感应。
7. **终章·井底**：泉变谷鸣汇聚，玩家与守井人下入北井，见井底窄门石隙与冷白光华，守井人留下谶语：“门不是锁，是留的。回去把碑上的话记住就行。”

## 9.3 文案口径红线清单
- **禁止出现的未来词汇**：道劫、天穹残宫、封天井、星铁雨（用“天铁/坠星”）；在主线剧情对白中不直白出现后世宗门术语。
- **禁止剧透与总结**：不解释井、碑、纹、光的终极来历；任何章节结束不做“所以这一切是……”的总结陈词。

# 第十一篇 服务端领域数据架构与聚合运行时规约

## 11.1 四层数据架构体系
```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 策划静态配置 (GameData 解析) │ 只读不可变、编译期内嵌启动加载、ReadOnlyDictionary │
├────────────────────────────────────────────────────────────────────────┤
│ 2. 运行时玩家聚合 (PlayerAggregate) │ PlayerSectionKind 八分段、PlayerActor 单写者 │
├────────────────────────────────────────────────────────────────────────┤
│ 3. 纯业务逻辑系统 (SimulationEngine) │ 纯函数离散事件模拟推进、100% 确定性      │
├────────────────────────────────────────────────────────────────────────┤
│ 4. 持久化与快照 (Snapshots/DTO)   │ 异步落盘、冷计算传输、不可变流式投影     │
└────────────────────────────────────────────────────────────────────────┘
```

## 11.2 纯函数离散模拟引擎与单写者架构
- **单一真源推进**：所有挂机时间、产物结算与战斗模拟严格以 `SimulationEngine.AdvanceTo(state, now)` 为唯一真源，杜绝任何第二套执行器或过渡调度系统。
- **领域聚合零损耗**：玩家状态收敛为单体聚合 `PlayerAggregate`，按 `PlayerSectionKind` 划分为 8 大分段（`progression` / `world` / `combat` / `buffs` / `loadout` / `settings` / `action_queue` / `duel`），高频 Tick 直接访问聚合内存字段，零反射、零哈希查找。
- **Actor 单写者并发**：同一玩家的命令与模拟推进在其专属 `PlayerActor`（由 `PlayerRuntime` 持有）内串行执行，`SemaphoreSlim` 保证单写者语义；跨边界访问不得直接持有聚合引用，杜绝多重分布式大锁。`YuoCore`（Ecs/Persistence/Runtime）基座引用在项目文件中保留待用，当前不构成运行时对象模型；若未来启用 ECS/Fiber，所有权约束另行定义。

# 第十三篇 行动统计系统（三账本）

原「战斗收益战报」泛化为**行动统计**，对任意行动持续记录收益与计数，共三类账本：

1. **行动实例账本**：绑定队列中的行动实例，从开始推进到出队归档期间持续记录；一个任务重复多次仍算一个行动。
2. **离线挂机账本**：`Presence` 转入 `Offline` 时重置，记录本次离线会话全部收益。
3. **每日统计账本**：按 UTC+8 自然日自动 rollover。

每本账本记录三类信息：**获取经验**（修为/底蕴/六维/功法参悟经验/等级提升）、**物品得失**（获得与失去分列）、**行动信息**（轮次/时长/遭遇场次/分级击杀/死亡/斗法胜负）。交易（坊市）不计入统计。

完整字段、记账点与协议口径见 [`action-statistics-system.md`](action-statistics-system.md)。
