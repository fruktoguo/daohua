## 28.1 定位与架构边界

1. **零 ECS / 八分段 / 冷挂机侵入**：每日签到状态不进入玩家八分段快照（`SectionCodec.CurrentSchemaVersion` 保持不变），不占用 `EcsWorldShard` 组件槽位，亦不进入冷挂机计算节点（`ComputeNode`）。
2. **单表旁路存储**：每名玩家至多在 `game.player_daily_checkins` 持有 1 行状态记录（未签过到的人 0 行）；每日按 **UTC+8 自然日**（`ShopDailyWindow.DayIndexOf`）刷新可签状态，无需定时批处理重置任务。
3. **资产与账本规范**：
   - 奖励固定发放**绑定功德（`item.gongde-bound`）**（`isTradable = false`，不可流转坊市，可在系统商店兑换觉醒石等物资，防小号批量刷取流通货币）。
   - 领取时在 `Serializable` 事务内同库更新签到行并调用 `PostgresEconomyRepository.CommitCoreAsync` 入账，使用 `economy.transient_idempotency`（`PersistLedger = false`，严格遵守 5 类账本白名单规范）防止重试/并发重放，提交后调用 `IPlayerRuntime.ReloadWalletAndNotifyAsync` 热刷新在线玩家内存钱包并下推增量快照。
4. **机器人隔离**：`identity.accounts.is_bot = true` 的账号在签到状态读取、WS 摘要推送及领奖入口全部屏蔽（不可签到、不落行）。

## 28.2 奖励数值与连续签到分布模型

### 28.2.1 数值口径

| 参数 | 数值 | 说明 |
| --- | --- | --- |
| 最低奖励 `MinMerit` | `10` | 单次签到保底获得整数功德·绑定 |
| 最高奖励 `MaxMerit` | `999` | 单次签到长尾上限（极小概率天降横财） |
| 基础日均奖励 `BaseMeanMerit` | `30` | 无连续签到加成时的参考基准期望均值 |
| 均值渐近上限 `MeanCeilingMerit` | `60` | 连续签到无穷天时目标均值逼近上限 |
| 连签日推进率 `StreakBonusPerDay` | `0.01`（`+1%/天`） | 每个有效连续签到天数额外提供的均值推进量 |

### 28.2.2 连续签到判定与目标均值公式

1. **UTC+8 自然日口径**：
   $$\text{DayIndex}(t) = \left\lfloor \frac{\text{unixSeconds}(t) + 28800}{86400} \right\rfloor$$
   设玩家上次签到日序号为 $D_{\text{last}}$、上次连签天数为 $S_{\text{last}}$，今日序号为 $D_{\text{today}}$：
   - 今日已签（$D_{\text{last}} = D_{\text{today}}$）：`CanClaimToday = false`，有效连签天数 $d_{\text{eff}} = \max(1, S_{\text{last}})$。
   - 昨日已签（$D_{\text{last}} = D_{\text{today}} - 1$）：`CanClaimToday = true`，本次签到后有效连签天数 $d_{\text{eff}} = \max(1, S_{\text{last}} + 1)$。
   - 首次签到或已断签（$D_{\text{last}}$ 为空或 $< D_{\text{today}} - 1$）：`CanClaimToday = true`，本次签到后有效连签天数重置为 $d_{\text{eff}} = 1$。
   - `TotalDays` 为历史累计签到总次数，不受断签影响。

2. **目标均值（饱和推进函数）**：
   $$\text{streakBonus} = d_{\text{eff}} \times 0.01, \qquad \text{TargetMean}(d_{\text{eff}}) = 30 + (60 - 30) \times \frac{\text{streakBonus}}{1 + \text{streakBonus}}$$
   - 首日签到（$d_{\text{eff}} = 1$）：目标均值 $\approx 30.297$
   - 连签 `30` 天（$d_{\text{eff}} = 30$）：目标均值 $\approx 36.923$
   - 连签 `100` 天（$d_{\text{eff}} = 100$）：目标均值 $= 45.000$
   - 连签趋于无穷：目标均值渐近逼近 `60.0`，只提高高值概率，不直接乘算奖励，亦不改变 `[10, 999]` 上下限。

3. **截断几何分布抽样**：
   - 在整数闭区间 $[\text{MinMerit}, \text{MaxMerit}] = [10, 999]$（跨度 $\text{span} = 989$）上求解离散截断几何分布参数 $q \in (0, 1)$（80 次二分迭代精度 $< 10^{-9}$；当目标偏移均值超过 $\text{span}/2$ 时对称镜像求解），使各偏移 $k \in [0, \text{span}]$ 的概率正比于 $q^k$ 且分布期望精确等于 $\text{TargetMean}(d_{\text{eff}})$。
   - 每次领取时以密码学安全随机数 `RandomNumberGenerator` 生成 $u \in [0, 1)$ 并按权重累加扫描命中，长期期望严格钉死在 $\text{TargetMean}(d_{\text{eff}})$，高额功德以自然长尾形式出现。
   - **已剔除道劫的签运/幸运值与月卡固定池**：本系统无幸运属性，仅返回纯功德奖励数值及当次连签进度。

### 28.2.3 签运文本与周月统计

1. **签运文本（沿用《道劫余生》10 档签文，纯叙事展示、无幸运值属性）**：
   - 按单次或本周日均功德相对于基础区间 $[10, 60]$ 的比例 $\text{ratio} = \max(0, (x - 10) / 50)$ 判定：
     - $x \ge 999$：`perfect`（`满签 · 天命唯一`）
     - $\text{ratio} > 8$：`transcendent_4`（`超签四阶 · 诸天共佑`）
     - $\text{ratio} > 4$：`transcendent_3`（`超签三阶 · 天眷独宠`）
     - $\text{ratio} > 2$：`transcendent_2`（`超签二阶 · 气运如虹`）
     - $\text{ratio} > 1$：`transcendent_1`（`超签一阶 · 鸿福齐天`）
     - $\text{ratio} \ge 0.8$：`great`（`上上签 · 福星高照`）
     - $\text{ratio} \ge 0.6$：`good`（`上签 · 福缘渐起`）
     - $\text{ratio} \ge 0.4$：`neutral`（`中签 · 气数平平`）
     - $\text{ratio} \ge 0.2$：`bad`（`下签 · 时运不济`）
     - $\text{ratio} < 0.2$：`very_bad`（`下下签 · 劫气缠身`）
   - **今日气运**：今日已签后按今日获得功德判定；未签时展示待占态。
   - **本周气运**：按当前 UTC+8 自然周（周一至周日）内已签到天数的平均单日功德判定。
2. **周月统计与单行压缩存储**：
   - 在 `game.player_daily_checkins` 同行内联维护 `week_start_day_index / week_days / week_merit / week_days_mask`（7 位周一~周日签到位图）与 `month_key / month_days / month_merit`，跨周/跨月读路径自动归零重计。

## 28.3 协议与接口契约

1. **WebSocket 握手摘要**：
   - `WireMessageType.CheckinSummary = 30`（仅服务端下行）：在 `Hello` 握手时并行加载轻量 `CheckinSummaryDto(CanClaimToday, TodayDate, DayIndex, StreakDays, TotalDays, LastRewardMerit, IsBot)` 并推送，用于客户端刚进游时立即点亮红点及触发当日首次自动弹窗判定。
2. **HTTP REST API**（均需 Cookie 鉴权会话，严格从 `ClaimsPrincipal` 解析 `player_id`）：
   - `GET /api/v1/checkin`：查询完整签到状态 `CheckinStatusDto`（含今日日期、`DayIndex`、是否可签、连续/累计天数、今日获得与今日气运、本周天数/总功德/7 日位图/本周气运、本月天数/总功德、上次获得与下次零点重置时间戳）。
   - `POST /api/v1/checkin/claim`（启用 `"command"` 限流）：执行原子领取并返回 `CheckinClaimResponseDto(Claimed, RewardMerit, RewardItemId, Status)`；若当日已签返回 `Claimed = false` 与最新状态（幂等安全，不报错弹窗崩坏）。

## 28.4 前端入口、弹窗样式与自动弹出策略

1. **导航归属**：
   - 桌面端侧边栏「其他」分组（`SIDEBAR_OTHER_TABS`）与竖屏底部「更多」分组（`MOBILE_NAV_GROUP_DEFS.more`）新增 `'checkin'`，与 `'help'` 同构：点击拉起独立居中 `CheckinModal`，不替换底层当前主界面页签。
   - 当 `canClaimToday === true` 时，在桌面端「其他」/「签到」与竖屏「更多」/「签到」展示红点徽记提示。
2. **高信息密度独立弹窗（`CheckinModal`）**：
   - 复用公共 `Modal`、`ItemTile` / `ItemTooltipTarget`、`Icon`，完整支持暗墨玄石与浅色宣纸双主题及桌面/矮横屏/竖屏响应式布局。
   - 界面保持克制清晰、不向玩家暴露概率区间与均值公式数值，聚焦展示：今日签到获得功德与当前持有功德、今日气运与本周气运（道劫签文）、连续与累计签到天数、本周签到（天数 + 总功德 + 周一~周日 7 日进度条）、本月签到（天数 + 总功德）以及跨日刷新倒计时。
3. **自动弹出规则**：
   - **每日首次在线**：完成建连与首帧快照同步、且新手引导已完成（`tutorialStep >= TUTORIAL_DONE` 且未处于觉醒结果/帮助提示/更新公告弹窗遮挡态）时，若 `canClaimToday === true` 且当日尚未在本地关闭过自动弹出，则自动打开 `CheckinModal`。
   - **在线跨越零点**：基于服务端时间基准（`serverTimeUnixSeconds`）计算距离下一 UTC+8 `00:00:00` 的精确延时定时器（并结合页签 `visibilitychange` 校时），跨过零点后自动刷新 `GET /api/v1/checkin`；若当日可签且处于可打扰状态，自动打开 `CheckinModal`。
