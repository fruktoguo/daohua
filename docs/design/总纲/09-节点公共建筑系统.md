# 第九篇 节点公共建筑系统

> 状态：已随 TASK-20260918-05 / TASK-20260918-06 落地。本文是节点公共建筑玩法的唯一权威设计真源。
> 配表真源：`config/game-data/buildings/buildings.json`；地图节点 `buildableTemplate` / `buildableList`。
> 领域实现：`src/Domain/World/NodeBuildings.cs`；服务端注册表：`src/Server/Clean/NodeBuildingRegistry.cs`。

## 9.1 定位与归属

- 建筑是**节点级公共设施**：无建造者/所有者概念，同节点同种建筑仅一座；任何人可发起建造、填充材料、发起升级。
- 效果对**同地所有玩家**生效（公共增幅），不区分贡献者。
- 建筑状态脱离玩家分段，作为**节点级共享注册表**（`nodeId → 建筑实例列表`）独立持久化到 `game.node_buildings`；玩家聚合内的 `World.NodeBuildings` 只是最近已知投影，供离线/冷挂机补算沿用，真源始终在服务端注册表。
- 跨节点不泄漏：投影记录 `NodeBuildingNodeId`，消费方经 `EffectiveNodeBuildingEffects` 读取，投影节点与当前节点不一致时返回空集。

## 9.2 配表结构

单座建筑定义字段：

| 字段 | 含义 |
| :--- | :--- |
| `id` / `name` / `description` / `effect` | 标识与展示文本（`effect` 为效果文案） |
| `group` | 分组：`production`（生产）/ `combat`（战斗）/ `other`（其他），供节点模板与候选弹窗分组 |
| `requiredRealmLevel` | 建造解锁所需境界等级 |
| `availableNodeIds` | 可选：限定可建节点；缺省表示不限定（仍受节点可建列表约束） |
| `baseModifiers` / `growthModifiers` | **1 级基准效果与每级增幅效果**（见 §9.4），Lv N 生效 = $(Base + Growth \times (N - 1)) \times Efficiency$；兼容旧字段 `modifiers`（等价于 Base=Growth） |
| `materials` | 一级基础材料清单（`itemId` + `quantity`），第 N 级需求 = 基础 × `1.1^(N-1)` |

节点可建列表（地图 JSON 节点字段，二选一，均不写 = 该节点不可建）：

- `buildableTemplate`：`all` 或分组名（`production`/`combat`/`other`），按分组映射全部建筑；
- `buildableList`：自定义建筑 ID 数组（优先于模板）。

节点自带建筑（地图 JSON 节点字段，可缺省）：

- `prebuiltBuildings`：`[{ "buildingId", "level" }]`，声明节点初始即存在的竣工建筑（如村口古阵）。
  注册表首次装载时对每条种子执行幂等播种（`Level=N`、`TargetLevel=0`、空材料——竣工态不参与
  惰性完工推算）；同 (节点, 建筑) 已存在行时保留数据库活行现状——播种只负责「缺则补座」，
  不覆盖玩家在既有行上的升级结果，跨实例并发由表唯一约束收敛。自带建筑与玩家建造建筑同权：
  照常参与效果聚合/拥挤衰减，也可经通用规则继续升级。

## 9.3 建造与升级流程（双进度条）

- 每条建造/升级任务有两条进度：**材料%** 与 **工期%（时间%）**；总进度 = `min(材料%, 工期%)`。
- **工期封顶与防积蓄机制（停工时间不补算）**：
  - 工期进度受限于当前已交付材料百分比：工期最大推进不得超过材料百分比（若材料交付 50%，工期最多推进至 50% 并停滞）。
  - 有效已耗工时计算：$T_{\text{effective}} = \min(T_{\text{raw}},\; \text{材料\%} \times T_{\text{req}})$，其中 $T_{\text{raw}} = \max(0, \text{now} - \text{StartedAtUnixSeconds})$。
  - **防积蓄重锚定**：当材料不足导致工期停工停滞时，不论现实时间流逝多久，停工等待期间的无效墙钟时间均不得积蓄；当玩家再次提交材料放宽上限时，在事务行锁内将基准起始时刻重锚定为 $\text{StartedAtUnixSeconds} = \text{now} - T_{\text{effective}}$。后续工期从停滞进度点重新起步匀速增长，严禁瞬间补全或跳跃完工。
- 时间需求：`600 × (1 + 0.2×(N-1))` 秒（基础 10 分钟，每级 +20% 线性；51 级 = 110 分钟）。
- 材料需求：基础清单 × `1.1^(N-1)`（指数 +10%/级）。
- 建成永久生效；升级 = 发起新一轮双进度条（目标 N+1）；升级期间维持旧级效果，完成瞬间跳变；无等级上限。
- 首建期间 `Level=0` 不生效；升级期间 `Level` 维持旧等级。
- 惰性完工：任何读取路径按当前时刻判定 `min(材料%,工期%)≥1` 即落成目标等级并清空材料投入，落库由注册表串行化完成。
## 9.4 效果模型与数值

建筑加成支持「1 级基准 + 每级增幅」的分级配置模型：配表中配置 `baseModifiers`（1 级初始基准）与 `growthModifiers`（每升 1 级的线性增量）。
当建筑有效等级为 $L$（$L \ge 1$）时，实际生效修饰项为：
$$Effect(L) = \big( Base + Growth \times (L - 1) \big) \times Efficiency$$
（缺省配置时，若仅提供 `modifiers`，则等价于 $Base = Growth = modifiers$）。

修饰项字段与作用通道：

| 字段 | 语义 | 接线点 |
| :--- | :--- | :--- |
| `gatheringSpeedRatio` | 采集行动加速比率（涵盖采药与砍伐） | `TimedActionDuration` 行动耗时 |
| `miningSpeedRatio` | 采矿挖掘行动加速比率 | `TimedActionDuration` 行动耗时 |
| `alchemySpeedRatio` | 炼丹行动加速比率 | `TimedActionDuration` 行动耗时 |
| `forgingSpeedRatio` | 炼器行动加速比率 | `TimedActionDuration` 行动耗时 |
| `talismanSpeedRatio` | 符箓绘制行动加速比率 | `TimedActionDuration` 行动耗时 |
| `formationSpeedRatio` | 阵盘研制行动加速比率 | `TimedActionDuration` 行动耗时 |
| `enhancementSpeedRatio` | 装备强化行动加速比率 | `TimedActionDuration` 行动耗时 |
| `cultivationOutputRatio` | 吐纳修炼收益增幅 | 行动收益乘区 |
| `combatHitpointRegen` | 战斗内每 5 秒气血回复固定值 | `PlayerAttributeResolver` 回血乘区 |
| `combatManapointRegen` | 战斗内每 5 秒灵力回复固定值 | `PlayerAttributeResolver` 回蓝乘区 |
| `combatDamageReductionRatio` | 战斗减伤比率 | `PlayerAttributeResolver` 减伤乘区 |
| `monsterWeakenRatio` | 怪物削弱比率：此地怪物面板按双曲阻尼衰减 | `NodeBuildingRules.WeakenMonsterStats`：怪物面板生成收口 |

- 收益增幅与消耗品/灵脉倍率**同乘区叠加**（`× (1 + ratio)`）；速度类为耗时 `÷ (1 + ratio)`。
- **封魔阵双曲阻尼削弱模型（无上限）**：
  为避免百分比削弱将怪物属性降为 0 或负数，`monsterWeakenRatio` 采用渐进阻尼折减公式：
  $$\text{折减系数} = \frac{1}{1 + \text{monsterWeakenRatio}}$$
  $$\text{实际属性} = \frac{\text{原始属性}}{1 + \text{monsterWeakenRatio}}$$
  （例：削弱 50% 折减为 $100 / 1.5 \approx 66.7$；削弱 100% 折减为 $100 / 2 = 50$；削弱 900% 折减为 $100 / 10 = 10$）。
  该模型在任意比率下均保持单调平滑且恒大于 0，**天然不设硬上限**。波次入场、快照恢复、钉死入战、生态刷怪与组队会话的怪物模板生成点统一走此收口。

### 9.4.2 拥挤衰减模型（承载人数与超载线性衰减）

建筑服务有承载人数上限：超过上限后效果对所有人等比衰减，鼓励分流建造与多节点布局。

- **承载上限**：`capacity(L) = 100 + 10 × (L - 1)`（一级 100 人，每级 +10% 基数线性；L2=110、L11=200、L51=600）。
- **使用人数**：在**当前节点**拥有 `Running` 状态、且行动类别属于该建筑**服务类别**的玩家数（在线/离线挂机一视同仁）。服务类别由建筑生效修饰项映射至对应 `ActionKind` 及具体技艺 `Technique`；多类别建筑人数为各类别之和（队列串行，同一玩家不会重复计）。Blocked/排队中/赶路中不计。
- **衰减公式**：`efficiency(L, n) = 1`（n ≤ capacity）；超载时 `1 − min(0.5, (n − capacity) × 0.001)`——每超 1 人 -0.1%（即每 100 人 -10%），减幅**封顶 50%**（n ≥ capacity + 500 时效果恒为 50%，永不归零）；L1 满 1000 人恰为 -50%。
- **衰减施加粒度**：整座建筑的全部修饰项统一乘 `efficiency`，非逐项独立衰减。
- **计数来源（读模型，无新增写路径）**：`game.player_action_queue`（flush 队列与 ComputeNode 回写两条写路径均事务性全量重建）JOIN `game.player_projection.current_node_id`，按 `(node_id, action_id) → ActionKind/Technique` 聚合；`presence='suspended'` 不计。计数为**秒级最终一致**的软指标（脏段去抖 + 读模型刷新，滞后 ≤~30s），不参与资产结算、不需要事务级精确。
- **投影一致性**：衰减后效果与使用数随既有节点建筑投影一并发入玩家 `World` 分段并持久化；离线/冷挂机补算沿用最近已知投影（含当时衰减口径），模拟确定性不受跨玩家耦合影响。

## 9.5 交互与协议

- 附近面板「建筑」Tab 展示当前节点建筑卡（名称 + 等级 + 效果 + 使用中人数/承载 + 建造中双进度与工期时长），点击弹详情 Modal（等级、效果、使用人数与超载衰减、双进度条、已耗工期与总时长对比、逐项材料清单与提交入口、升级按钮）。
- 工期真实时间展示：详情弹窗工期行右侧与卡片进度行均展示工期真实时间（`已耗时 / 总时长`，如 `5分0秒 / 10分0秒`），消灭纯百分比无时间概念的盲盒感知。
- 提交材料独立界面：每种材料一个数量输入，范围 `[0, min(背包剩余, 本级所需剩余)]`，提交前二次确认；提交不可退还。
- 候选弹窗按 `group` 分组列出全部可建建筑；未解锁灰显并标注所需境界。
- 命令：`building.build` / `building.upgrade` / `building.contribute`；目录端点 `/api/v1/catalog/buildings`。
- 快照 `world` 段透传 `buildableBuildingIds`（可建列表，null=不可建）与 `nodeBuildings`（等级/双进度/材料明细 + `activeUsers`/`capacity`/`efficiency` 拥挤三元组）。
- 大地图地点详情「地标与设施」同时展示配表陈设与玩家公共建筑：全图建筑索引经只读端点 `GET /api/v1/world/node-buildings` 下发（`nodeId → {buildingId, level, targetLevel}[]`，沿用注册表读路径惰性完工口径），前端面板挂载与本节点建筑变化时拉取，名称/描述/效果文案由建筑目录解析；等级、在建（建造中/升级中目标等级）随胶囊展示。

## 9.6 不变量

- 同节点同种建筑仅一座；同一时刻同一节点至多一个进行中的工程。
- 材料提交在数据库建筑行锁内按活行剩余需求封顶；`game.node_buildings`、钱包余额与流水、命令回执必须由同一 Serializable 事务提交，禁止通过独立扣账回调先行提交资产。
- 请求幂等键绑定原始提交参数，首次实际接纳量随结果持久化；重放不能按新的剩余需求重算扣款。事务完成前不发布缓存，成功后才刷新 World 派生投影。
- 所有进度推算只依赖持久化字段与当前时刻，在线/离线/冷挂机补算结果一致。
- 拥挤计数是最终一致读模型（`player_action_queue`×`player_projection` SQL 聚合）：滞后为可接受语义，任何读侧故障不阻塞建筑本体写路径与玩家模拟。
