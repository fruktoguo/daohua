# 第二十一篇 同道与组队系统

> **定位**：本篇是「同道」社交入口与完整组队系统的唯一设计真源。第十四篇 §14.5.2 的邀请制队伍仅描述最早的入队通道，本篇在其上扩展队伍档案、招募匹配、组队大厅与聊天队伍链接；传音频道机制本身仍以第十四篇为准。

---

## 21.1 定位与边界

1. **队伍是招募组织层**：目标类型/目标地图/身价门槛均为招募标签，不改变行动与战斗结算；本期不含「同图并肩作战」的战斗协同结算，队伍频道与成员在线态是已有的协作基础。
2. **同道 Tab**：左侧顶级导航「同道」是社交入口容器，本期只有「队伍」一个子页；好友管理仍留在聊天面板内，后续子页以同一子 Tab 结构扩展。
3. **服务端权威**：队伍档案、成员关系、匹配登记、大厅结果与身价数值全部由服务端产出；前端不本地推演成员/门槛/匹配结果，只保存最近一次服务端视图。

## 21.2 队伍档案（Party Profile）

每支队伍除 `party_id`/`leader_id` 外持有一组档案字段，全部落 `social.parties`：

| 字段 | 协议字段 | 口径 |
| :--- | :--- | :--- |
| 队伍名称 | `name` | 1~32 字符；为空时服务端生成「{队长道号}的小队」 |
| 目标类型 | `activityKind` | `any`（不限）/`combat`（讨伐战斗）/`exploration`（历练采集）/`cultivation`（吐纳修炼） |
| 目标地图 | `mapId` | 空串 = 不限；否则必须是配表已知 `mapId` |
| 身价门槛 | `minValuation` | ≥0；0 表示不设门槛；加入者与自动匹配均按它裁决 |
| 公开性 | `isPublic` | true 进组队大厅；false 只能被邀请或经聊天队伍链接进入 |

- 队伍上限恒为 5 人（含队长，`SocialRuntime.MaxPartyMembers`）。
- 一名玩家最多属于一个队伍（`social.party_members.player_id` 主键）。
- 每名玩家最多一条待处理队伍邀请；加入任何队伍时邀请与匹配登记同步清除。

## 21.3 身价（valuation）口径

> 「身价」是招募用的量化参照，**不是战斗属性**；名称刻意不锁死——协议与代码统一用 `valuation`，界面文案集中在 i18n 词条（`social.valuation`），后续改名只动词条。

```
身价 = 装备价值 + 功法价值
装备价值 = Σ 每件已穿戴装备的单价（强化 +N 按变体 "+N" 独立计价）
功法价值 = Σ 每门已参悟功法：参悟等级 × 对应秘籍单价
单价(itemId, variant) = 坊市当前最低挂售（卖一档）价
                      ?? 配表回收价（ItemDefinition.SellPrice）
                      ?? 0（物品不在配表时）
```

- **功法↔物品映射**：`ability.X` → `item.tome.X`；配表无该秘籍时回落 `item.fragment.X`（残卷）；两者皆无按 0 计。
- **参悟等级**由功法经验经 `AbilityExpCurve.LevelFor` 导出（与面板同式）。
- **六维/技艺不计入**：它们没有可交易的市场锚定价，身价保持「可支配资源口径」而非全角色强度。
- **数据源**：在线玩家取运行时聚合快照（`PlayerAggregateState.Loadout`）；离线玩家读 `loadout` 持久化分段（含刷盘队列叠加）。入队裁决与匹配自动并入使用实时值；列表展示允许 ≤30s 的估值缓存。
- **不可用兜底**：坊市分片未就绪/品种不在本进程分片 → 回落回收价；新玩家无 loadout 分段 → 身价 0。

## 21.4 无队伍四入口

| 入口 | 语义 |
| :--- | :--- |
| 自主选择 | 三模式页签：「组队大厅」「队伍匹配」「创建队伍」任选其一，一次只显示所选模式面板 |
| 队伍匹配 | 填目标类型/目标地图/队友最低身价 → `party.match.set`：服务端**先尝试自动并入**满足条件的公开队伍，未命中则登记入「匹配中」散人池 |
| 组队大厅 | 同类筛选 + 列表展示：公开队伍（含成员预览、门槛、加入按钮）与匹配中散人 |
| 创建队伍 | 填队名（可空→默认名）/目标类型/目标地图/身价门槛/是否公开 → 创建者任队长 |

## 21.5 匹配语义

1. `party.match.set {activityKind?, mapId?, minValuation?}`：仅无队伍玩家可用；先写/更新 `social.party_seekers` 行，再扫描公开队伍尝试自动并入。
2. 自动并入条件（全部满足）：队伍 `is_public` 且未满员；活动类型与地图与我方筛选一致——`any`/空串为「不限」，筛选侧与被筛侧任一为不限即放行（不限目标的队伍对所有筛选可见，不限筛选的散人匹配全部队伍）；我方身价 ≥ 队伍 `min_valuation`；**每名在队成员身价 ≥ 我方申报的队友最低身价**。命中多队时取人数最多、其次创建最早者。
3. 未命中：保持「匹配中」状态（`SocialStateDto.seeking` 下发），可随时 `party.match.clear` 撤下；加入队伍时登记自动清除。
4. 散人池不自建队伍、不反向强拉：大厅里队长可对散人发 `party.invite`（走既有邀请-接受流程）。

## 21.6 组队大厅

- 拉取式：`PartyLobbyRequest(25) {requestId, activityKind?, mapId?, minValuation?}` → `PartyLobby(26) {requestId, myValuation, parties[], seekers[]}`。
- `activityKind`/`mapId` 筛选沿用「不限双向通配」口径（同 §21.5）；`minValuation` 筛选语义：公开队伍按「成员最低身价 ≥ 阈值」、散人按「本人身价 ≥ 阈值」。
- 公开队伍条目含成员预览（道号/在线/身价），前端据此展示加入可行性（我的身价 < 门槛时置灰但可见）。
- 散人条目含道号/在线/身价/目标/队友门槛；本人是队长时提供「邀请」按钮。
- 上限：各类列表最多返回最近 50 条，按创建时间倒序。

## 21.7 队伍管理与权限

| 操作 | 权限 | 说明 |
| :--- | :--- | :--- |
| `party.update` | 队长 | 档案补丁：name/activityKind/mapId/minValuation/isPublic 任一非空字段即生效 |
| `party.invite` | 队长 | 按道号/ID 邀请；未满员、对方未组队 |
| `party.kick` | 队长 | 移除成员（不能踢自己，队长离队走 leave/移交） |
| `party.disband` | 队长 | 解散整队：成员行随 `ON DELETE CASCADE` 清除，聊天链接置空失效 |
| `party.leave` | 全体成员 | 队长离开时按加入序移交最早成员；最后一人离队删队 |
| `party.share` | 全体成员 | 把队伍卡片发布到世界/附近/好友频道 |
| `party.join` | 无队伍者 | 按 `partyId` 加入：公开队伍大厅加入与不公开队伍链接点击共用；校验未满员 + 身价 ≥ 门槛 |

队伍 ID 是不可猜的 UUID，链接本身即加入凭据：不公开队伍不进入任何列表，但持有链接者点击即可加入（仍受满员与身价门槛约束）。

## 21.8 聊天队伍链接

- `party.share {channel, targetPlayerId?}` 是社交动作，由服务端借 `ChatRuntime` 生成一条 `party_ref` 指向本队的传音消息；正文为服务端规范文本（不消耗 200 字输入），走与发言相同的频道作用域解析与限频。
- `ChatMessageDto.partyLink` 携带队伍卡片快照字段（队名/目标/门槛/成员数），由历史回放与实时广播统一供给。
- 队伍解散 → `party_ref` 外键 `ON DELETE SET NULL`，消息正文保留为普通文本，卡片消失。
- 前端在 `ChatRow` 渲染卡片：队名 + 目标徽标 + 门槛 + 「加入」按钮（已在队伍中/不满足条件时服务端拒绝并以错误帧提示）。

## 21.9 协议与数据

### 新增/变更动作（`SocialActions`）

```
party.create | party.update | party.disband | party.kick | party.join
party.match.set | party.match.clear | party.share
```

`SocialActionDto` 扩展：`partyId?`、`channel?`、`party?`（`PartyProfileDto{name?,activityKind?,mapId?,minValuation?,isPublic?}` 补丁语义）。

### 新增帧

| 值 | 类型 | 方向 | 载荷 |
| --- | :--- | :--- | :--- |
| 25 | `PartyLobbyRequest` | C→S | `PartyLobbyRequestDto` |
| 26 | `PartyLobby` | S→C | `PartyLobbyDto` |

### 字段扩展

- `PartyDto {partyId, leaderId, name, activityKind, mapId, minValuation, isPublic, members[]}`；`PartyMemberDto` 增 `valuation`。
- `SocialStateDto` 增 `seeking`（本人匹配中登记，无则 null）。
- `PartyInvitationDto` 增 `partyName`。
- `ChatMessageDto` 增 `partyLink?`：`PartyLinkDto{partyId,name,activityKind,mapId,minValuation,memberCount}`。

### PostgreSQL（schema v7）

```sql
ALTER TABLE social.parties ADD name varchar(32) NOT NULL DEFAULT '',
    ADD activity_kind varchar(16) NOT NULL DEFAULT 'any',
    ADD map_id varchar(128) NOT NULL DEFAULT '',
    ADD min_valuation double precision NOT NULL DEFAULT 0,
    ADD is_public boolean NOT NULL DEFAULT false,
    ADD updated_at timestamptz NOT NULL DEFAULT now();

CREATE TABLE social.party_seekers (
    player_id uuid PRIMARY KEY REFERENCES identity.players(player_id),
    activity_kind varchar(16) NOT NULL DEFAULT 'any',
    map_id varchar(128) NOT NULL DEFAULT '',
    min_valuation double precision NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL,
    updated_at timestamptz NOT NULL);

ALTER TABLE social.chat_messages ADD party_ref uuid REFERENCES social.parties(party_id) ON DELETE SET NULL;
```

迁移文件 `migrations/0006_v6_to_v7.sql` 就地升级；空库由 `PostgresSchema.Sql` 直建 v7。

### 新增失败码（`SocialFailure`）

`PartyNotFound`（队伍不存在）、`ValuationTooLow`（身价不达门槛）、`InvalidPartyProfile`（档案字段非法：活动类型未知/地图未知/门槛负数/名称超长）、`SeekingNotFound`（本人无匹配登记）。

## 21.10 服务端组件

- `SocialRuntime`：新动作分发、档案校验、匹配自动并入、大厅构建（`BuildLobbyAsync`）、成员身价投影进 `BuildStateAsync`。
- `PartyValuationService`：身价计算唯一口径——在线读运行时快照、离线读 `loadout` 分段（刷盘队列叠加），单价经 `MarketRuntime.TryGetBestAskPrice`（本进程分片才查，否则回落回收价）。
- `ChatRuntime.SendPartyShareAsync`：队伍卡片发言（限频/作用域解析与文本发言同口径）。
- `OrderBook.BestAskPrice`：卖一档价只读出口（`_askIndex` 队首即最低挂售）。
- `SectionCodec.DecodeLoadout` / `PostgresSectionRepository.LoadSectionAsync`：单分段读取，避免大厅批量估值拉全量快照。
- 社交/队伍依旧不进玩家级单写者门禁；加队并发用 `social.parties` 行级 `FOR UPDATE` 串行化，满员判队友好地落在事务内。

## 21.11 前端结构

- `uiStore.TabId` 新增 `social`；侧边导航「同道」+ 底部快捷栏同位。
- `SocialPage`（同道）→ 子 Tab「队伍」→ `PartyPanel`：
  - 无队伍：模式页签（大厅/匹配/创建，单面板切换）→ 匹配表单 / 大厅 / 创建表单；
  - 有队伍：档案头（名称徽标/目标/门槛/公开）+「队伍信息/组队大厅」页签；信息页含成员表（队长徽标、在线点、身价）、管理区（队长：改名/目标编辑/门槛/公开开关/踢人/解散/邀请）、全体成员可用的「分享队伍」（世界/附近/好友三向）与离队/解散；大厅页是散人邀请入口（邀请按钮仅队长可见）。
- `socialStore` 增 `seeking`、`lobby`（最近一次大厅结果 + `myValuation`）。
- `ChatRow` 卡片渲染与加入按钮；文案全部入 `social` i18n 域。
