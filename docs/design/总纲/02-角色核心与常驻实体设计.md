## 2.1 角色核心设计哲学（Core Philosophy）

### 2.1.1 统一常驻实体原理（The Unified Living Entity Principle）

在《道化太初》中，**修仙者角色是一个连续存在、拥有完整生命体征与修行底盘的“统一常驻实体”**。
- **拒绝孤立子系统**：彻底打破传统 RPG 将移动跑图、生产采集、打坐修炼、副本战斗、切磋竞技割裂为相互独立、状态互不连通的临时模块的做法。
- **同一性与守恒性**：无论是长途跋涉跨越大洲、在灵田采撷灵草、于丹房开炉炼药、在秘境斩妖伏魔，还是后续参与仙门切磋与玩家对决，**底层和设计上永远是这同一个角色实体在经历世间万象**。
- **状态不重置**：角色的气血、灵力、神识、增益（Buff）、负面状态（Debuff）、境界修为、随身储物与疲惫损伤，在时间轴上保持 100% 的连续演进，不因动作切换或界面跳转而凭空回满或重置。

```text
               ┌────────────────────────────────────────────────────────┐
               │           统一常驻修仙者实体 (Living Character Entity)   │
               ├────────────────────────────────────────────────────────┤
               │  • 生命体征：当前气血 (HP)、灵力 (MP)、技能/消耗品冷却   │
               │  • 修行底盘：境界等级、修为/底蕴/战斗经验、寿元、灵根、突破瓶颈 │
               │  • 常驻增益：各类丹药药效、祈福、伤病、负面 Debuff      │
               │  • 战备装配：主修心法、神通术法、六部位穿戴、技艺工具   │
               │  • 随身资产：储物袋物品、灵石、世界大地图驻留坐标       │
               └────────────────────────────────────────────────────────┘
                                      ▲
                                      │ 原地读写 / 连续演进 (In-Place Mutation)
               ┌──────────────────────┴────────────────────────┐
               │              世界与行为作用力 (World Forces)   │
               ├───────────────────────────────────────────────┤
               │  • 大地图旅行 (Travel)       -> 产生位移，消耗体魄/灵力 │
               │  • 洞府修炼 (Cultivation)   -> 吸纳灵气，增进修为     │
               │  • 灵野采集 (Gathering)     -> 消耗精力，产出天材地宝 │
               │  • 炉鼎炼丹 (Alchemy)       -> 消耗药材/灵力，产出灵丹│
               │  • 斩妖历练 (Combat)        -> 真实攻防损耗，结算战果 │
               │  • 秘境探索 / 切磋 (PvP)    -> 继承即时状态入场交锋   │
               └───────────────────────────────────────────────┘
```

### 2.1.2 行为与系统的“环境作用力”模型（Action as Environmental Force）

在系统交互模型上：
- **角色是状态的唯一容器**：所有的属性、资源与标记仅存储在角色实体上；
- **各类系统与行动是“外部作用力”**：移动、采集、炼丹、打坐、战斗并非持有独立生命周期的子程序，而是作为施加在角色身上的“环境作用力”。它们读取角色的当前状态作为前置判定，并在执行过程中将消耗、收益、创伤与增益**直接写回角色本身**。

### 2.1.3 确定性时空连续性（Deterministic Spatiotemporal Continuity）

- **离散事件推进（DES）的一致性**：无论玩家保持 WebSocket 实时在线、高频切换网络，还是完全断线离线长达数十小时，角色状态的推进逻辑完全一致。
- **离线快进等价于在线驻留**：服务端的确定性模拟引擎（`SimulationEngine`）基于时间轴推进。离线 8 小时的快进补算结果，与在线保持连接 8 小时逐秒计算得出的血量、灵力、修为与 Buff 衰减状态**完全等价、无缝自洽**。

## 2.2 角色多维体征与数据模型（Character Anatomy & Data Model）

角色实体在领域层聚合为一套完整自洽的数据网络，所有数值计算与持久化严格遵循 `double` 高精度规约。

### 2.2.1 精气神基础生命体征（Vital Signs）

| 体征属性 | 符号/字段 | 类型 | 设计定位与业务语义 |
| :--- | :--- | :--- | :--- |
| **当前气血** | `Hitpoints` | `double` | 玩家的生命底线。受战斗伤害、极恶环境侵蚀或特殊功法反噬损耗。脱战不自动回满；依靠自然回复属性、疗伤丹药或调息恢复；降至 0 即为力竭/阵亡。 |
| **当前灵力/法力** | `Manapoints` | `double` | 玩家体内周天运转的灵气储备。施展神通、催动法宝、御剑飞天、开炉控火等一切超凡行为的能量消耗。脱战不自动回满，需通过打坐纳气或回灵丹药补充。 |
| **回复周期余量** | `PlayerCombatState.RegenCarrySeconds` | `double` | 自然回复周期内不足一次结算的累计秒数。用于在低频/高频状态推演中保证回复计算无截断误差；现行实现战斗体征字段全部为 `double`，不再使用 long+Remainder 整数进位。 |
| **神通冷却** | `PlayerCombatSkillState.Cooldowns` | `IReadOnlyList<CombatSkillCooldown>` | 各已装配神通的剩余冷却秒数与吟唱状态，跨行动与脱战后持续倒计时，不受动作切换中断。 |
| **消耗品槽位冷却**| `AutoUseSlotState.CooldownUntilUnixSeconds` | `double` | 各自动使用槽位的绝对冷却就绪时间戳（Unix 秒）。 |

### 2.2.2 修仙境界与成长四池（Cultivation & Realm）

- **十一大境界**：凡俗、练气、筑基、金丹、元婴、化神、炼虚、合体、大乘、渡劫、飞升（涵盖修行四期；数值底座见 `总纲` 第十一篇）。其中凡俗（Lv 1~18）下含 18 个有名小境界：凡胎、炼皮、锻骨、易筋、洗髓、养气、通脉、瑶光、开阳、玉衡、天权、天玑、天璇、天枢、宗师、大宗师、临渊、叩仙门；凡胎、叩仙门为小境界名，不再是大境界。
- **成长四池（`PlayerProgression` / `PlayerLoadout` 字段清单）**：
  - **修为（`Progression.Experience`）**：当前层突破计量条，即顶部进度条；以配表 `expToNext[realmLevel]` 封顶，突破时清零；
  - **底蕴（`Progression.Foundation`）**：修为满层后继续获得的修为 100% 沉淀为底蕴；修为未满层时每 1 点底蕴兑换 1 点额外修为（单笔最高 3 倍，底蕴耗尽即止），突破不清空；
  - **战斗经验（`Progression.CombatExperience`）**：每次修为类收益按增幅前基础量等额入账、不受任何加成；参与命中/闪避对抗修正（口径见 [第七篇 §7.7.6](./07-战斗数值与内视规约.md)），突破不清空；
  - **六维经验（`Loadout.CoreAttributes`）**：体魄/经脉/力道/根骨/身法/神识各自经验（`StaminaExp` 等六字段），等级由 `RootAttributeCurve` 导出。
- **总修为（`Progression.LifetimeExperience`）**：历史修为类收益总量（增幅后口径，含满层转底蕴部分），单调递增永不清零；为前端「总修为」悬浮条数据源。
- **突破瓶颈状态（IsPendingBreakthrough）**：当修为达到当前境界上限（`expToNext`）时触发，修为停止增长、溢出沉淀为底蕴，必须完成突破心魔、渡劫或服用破境丹药方可晋升下一小境界。
- **寿元与道龄（Lifespan & Age）**：依据境界决定寿元上限，随时间与特定禁术消耗自然流逝。

### 2.2.3 核心先天与后天属性（Attributes Matrix）

> **量化落地口径**：战斗侧的属性量化以 [战斗设计 §7.5 六维根基](./07-战斗数值与内视规约.md)（体魄/经脉/根骨/力道/神识/身法）为准；本节为先天/后天能力的概念分层，生活与探索维度在对应系统设计时归入同一份角色底盘，不另建平行属性模型。

角色的战斗与日常行为能力统一基于以下四维与五行底盘展开：
1. **气血与体魄（Constitution）**：决定基础生命上限、物理防御、负重能力以及对恶劣环境的耐受力；
2. **灵力与神识（Divine Sense）**：决定法力上限、法术暴击、命中率、大世界侦测范围与高阶采集/炼丹感知精度；
3. **悟性与心境（Perception & Mind）**：影响神通领悟研读速度、打坐修炼吸纳效率与破境成功率；
4. **身法与遁速（Agility）**：影响战斗行动速度、先手闪避、大地图御剑飞行与长途跋涉耗时；
5. **五行灵根（Five-Element Roots）**：金、木、水、火、土五行亲和度，直接决定对应属性神通的增减伤（五行增伤/五行减伤亲和，点数见 [第七篇](./07-战斗数值与内视规约.md) §7.7.5）。

### 2.2.4 武道装配与战备底盘（Loadout & Equipment）

- **功法体系（Dynamic Kungfu Slots）**：
  - **首位核心主修心法（Internal Core）**：决定角色的灵气周天运转模式、属性转化倍率与基础回气速率；
  - **动态扩展神通槽位（Active Spells）**：随境界提升逐步解锁的战斗与辅助主动法术序列。
- **六大装备部位（Six Equipment Slots）**：
  - `weapon`（武器/神兵）、`head`（头部/道冠）、`armor`（衣服/宝甲）、`legs`（下装/胫甲）、`boots`（鞋履/行云履）、`trinket`（饰品/法宝灵佩）。
  - 各部位遵循严格的数值预算守恒模型，提供基础属性、增减伤修饰与附加词缀。
- **生活技艺工具槽位（Artisan Tool Slots）**：
  - 预留药锄、灵火鼎、探矿罗盘等生活生产专属工具，直接赋能采集与生产行为。

### 2.2.5 随身空间与大世界坐标（Spatial Presence & Storage）

- **随身储物与灵石（AssetWallet + economy 关系表）**：材料、丹药、法宝、战利品与灵石等随身资产**不放入玩家聚合分段**，统一由运行时 `AssetWallet` 钱包视图 + `economy.player_asset_balances` / `economy.player_asset_instances` 关系表承载，支持全自动消耗、堆叠与事务内原子扣减。灵石为修仙界通用硬通货，用于坊市交易、传送法阵消耗或阵法驱动。
- **大世界驻留节点（`PlayerWorldState`）**：记录角色当前所处的地理节点/边与坐标（如“云来集”、“青云门山门”等），位移动作会真实改变该坐标。

## 2.3 状态连续性与跨玩法流转（Cross-System State Continuity）

### 2.3.1 跨行为状态无缝穿透（Seamless State Penetration）

角色状态在各种行为切换之间**完全透明继承**，不存在任何形式的状态重置边界：

```text
 场景 A (历练受伤 -> 日常调理):
 ┌────────────────┐ 战斗结算扣减至 20% HP ┌────────────────┐ 动作队列自动轮转 ┌────────────────┐
 │ 幽林斩妖 (战斗) │ ───────────────────> │ 角色实体保留残血 │ ───────────────> │ 打坐调息 / 嗑药 │
 └────────────────┘                      └────────────────┘                 └────────────────┘
                                                                                    │ 真实消耗丹药/时间
                                                                                    ▼
                                                                            ┌────────────────┐
                                                                            │ 状态逐步恢复饱满 │
                                                                            └────────────────┘

 场景 B (日常准备 -> 突发切磋/秘境):
 ┌────────────────┐ 炼丹消耗 50% 灵力     ┌────────────────┐ 直入秘境/切磋   ┌────────────────┐
 │ 洞府炼丹 (制造) │ ───────────────────> │ 角色实体灵力半空 │ ───────────────> │ 以半蓝状态迎敌  │
 └────────────────┘                      └────────────────┘                 └────────────────┘
```

1. **战后创伤保留**：历练脱战后，血量与法力保持结算时的即时值。若玩家带伤切入采集或跑图，角色依然处于虚弱状态，若遭遇野外突发危险将承担更高风险。
2. **日常消耗穿透至战斗**：长途赶路御剑消耗的灵气、炼丹损耗的心神，若未及时打坐或服丹补充，直接作为战斗入场时的初始状态。
3. **装备与属性实时生效**：任何时刻更换装备、升级功法，其带来的属性变更（如最大生命上限提升、抗性变化）即刻作用于实体，并按比例或绝对值平滑过渡。

### 2.3.2 增益/减益（Buff/Debuff）的实体级统一定时衰减与多维共鸣

- **实体级挂载**：所有 Buff（无论是服用灵丹、阵法加持、环境影响还是受到的诅咒中毒）统一挂载在角色的 `Buffs` 列表中，记录其绝对过期时间戳（`ExpiresAt`）。
- **统一时间轴演进**：Buff 的生命周期由 `SimulationEngine.AdvanceTo` 模拟时间推进驱动，在跨越移动、打坐、炼丹与战斗时**连续倒计时，绝不因动作切换而刷新或提前清除**。
- **多维跨界效能**：单一 Buff 具备穿透多系统的能力。例如：
  - 一枚兼具身法与攻速增益的灵丹，在跑图时缩短位移耗时，在进入战斗时则直接提升攻击频次；
  - 一种降低全属性的剧毒 Debuff，既在战斗中削弱输出，又在炼丹时降低成丹概率，在打坐时增加走火入魔风险。

### 2.3.3 战斗脱战真实继承与 1 HP 濒死复苏机制（Post-Combat Retention & Respawn）

- **常规脱战继承**：战斗胜利或主动脱战时，角色的剩余气血、剩余灵力、技能冷却时间 1:1 原地写回 `CombatResources`，不予补满。
- **阵亡与 1 HP 濒死复苏**：
  - 当角色在战斗或极端环境中气血降至 0（`Hitpoints <= 0`）判定为阵亡/力竭；
  - 角色不会被销毁或硬性永久死亡，而是触发**脱战濒死复苏机制**：脱战后生命值自动恢复为 **1 点（1 HP）**；**灵力持续自然回复并保留**（死亡期间 MP 回复不中断，与 `总纲` §7.9 口径一致）；
  - 濒死状态下，高危险行动（如高阶秘境、斩妖历练）将因前置体征不足而受阻（Blocked），促使玩家安排休整或自动消耗补血药物。

### 2.3.4 秘境探索与切磋 PvP 的真实入场机制（Real-State Entrance for Dungeons & PvP）

> **实现状态**：本节为**规划意图，尚未落地**。当前战斗为 `CombatExpeditionState` 远征状态机，`BattleSnapshot`、秘境与 PvP 在代码中均无实现；落地时必须遵守下列设计红线。

- **无单独虚拟镜像**：后续拓展的秘境探索、宗门战或切磋对决（PvP），**严禁创建脱离主实体的“临时满状态克隆体”**；
- **即时快照切片**：入场交锋时，系统基于角色的即时物理状态（当前 HP/MP、当前装备、当前生效 Buff）生成当前局的战斗快照（`BattleSnapshot`）；
- **交锋结果闭环写回**：战斗中消耗的法宝耐久、药品、受到的伤病以及最终剩余气血，结算后直接原地反哺写回玩家常驻实体，维持全宇宙状态唯一性。

## 2.4 行动队列与物理状态互锁（Action Queue & Physical Interlocking）

### 2.4.1 前置体征准入条件（Pre-condition Gating）

每个行动的启动均需对角色的即时物理状态进行前置校验（`CanStartAction`）：
1. **生命条件**：气血必须处于健康存活状态（`Hitpoints > 0`），濒死（1 HP）且无回复手段时禁止开启高烈度历练；
2. **灵力条件**：高阶炼丹、御剑远行需满足最低启动灵力门槛，灵力枯竭时无法催动；
3. **空间条件**：角色的世界驻留节点必须在行动的允许可用节点集合内（`AvailableNodeIds`）；
4. **材料与道具条件**：随身储物袋必须包含该动作所需的全部输入原料（`Inputs`）。

### 2.4.2 动作阻断与自动跳过机制（Action Blocked & Queue Rotation）

- **条件不满足时的阻断**：当队列头部动作因角色当前状态（如灵力不足、原料耗尽、重伤濒死）无法启动时，状态标记为 `ActionStatus.Blocked`。
- **循环模式下的安全空转**：
  - 若开启队列循环（`LoopEnabled`），阻断的动作被安全移至队尾，尝试执行下一个可用动作；
  - 若全部排队动作均受阻，队列进入**安全空转期**。在此期间，角色进入自然休整状态，持续享受生命与灵力自然回复，直至体征恢复或玩家介入调整。
- **自动移动准入修正（`AutoTravelEnabled`，默认关闭）**：
  - 行动入队时把当前所在节点记入意图锚点（`ActionIntent.AnchorNodeId`）；
  - 队首行动开轮时若地点校验不通过（当前不在该行动允许节点集合内，含旅途中），且自动移动已开启、锚点仍在允许集合内且世界图可达，则不再落入 Blocked，而是把一条 `world.travel` 插队至队首自动赶往锚点，到达后原行动按挂起语义恢复执行；
  - 锚点缺失、锚点已被配表移出允许集、或路径不可规划时，回落原 Blocked 语义；材料不足等非地点原因恒不触发自动移动；
  - 与 `LoopEnabled` 叠加可构成跨节点挂机回路：A 地行动完成轮转 → B 地行动地点不符 → 自动赶往 B → 依此循环；
  - 自动移动只发生在开轮准入一刻，已 Blocked 的停泊行动不追溯解套。

### 2.4.3 四大动作类型自动消耗品槽位与动作时间池

为保障全常驻实体在无人值守时也能平滑维持生命体征与修炼增益，系统提供完善的消耗品自动使用体系：
- **四大分类独立槽位（4 类 × 3 槽）**：修炼（`Cultivation`）、探索（`Exploration`）、炼丹（`Alchemy`）、战斗（`Combat`）各自拥有独立的 3 个自动消耗品槽位（`AutoUseSlotState`）；
- **持续消耗品 300s 动作时间池机制**：
  - 开启 1 瓶持续型丹药时，消耗 1 件物品并获得 **300 秒有效动作时长**（`RemainingDurationSeconds = 300.0`）；
  - 该时长仅在角色**实际执行对应类型动作时按秒精准扣除**；
  - 动作中途切换或暂停时，剩余秒数精确保存在槽位中，绝不凭空蒸发；
  - 透支免单与切槽惩罚：剩余时间不足以覆盖单次动作时，允许该次动作享受完整增益且不提前吃药；若玩家在尚有剩余时长时主动更换绑定的丹药，旧丹药剩余时长清零（切槽惩罚）。

## 2.5 技术架构与系统落地映射（Technical Architecture & Implementation）

在底层实现上，“统一常驻实体”由**纯领域聚合根 + 确定性离散事件引擎 + ECS 分片 Fiber 单写者所有权**三层基座稳固支撑。

```text
 ┌─────────────────────────────────────────────────────────────────────────┐
 │              服务端运行时宿主 (EcsGameRuntime / EcsWorldShard)           │
 │   • 单写者调度：玩家按稳定哈希路由到 ECS 分片，推进在分片 YuoFiber        │
 │     内串行执行；EcsPlayerRuntimeAdapter 玩家级 gate 保证跨边界串行；      │
 │     所有权经 game.player_runtime_leases 租约维持                          │
 │   • 在线实体映射：playerId -> YuoEntity(ECS 组件集)；命令边界经           │
 │     MutatePlayer 通道将组件重建为 PlayerAggregate、执行领域操作、回写组件 │
 │   • 持久化：脏分段经 latest-only 刷盘队列异步写入 PostgreSQL              │
 └────────────────────────────────────┬────────────────────────────────────┘
                                      │ 持有并驱动
                                      ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │                      领域聚合根 (PlayerAggregate)                        │
 │   • POCO 纯数据模型，无任何外部框架/IO/数据库依赖                          │
 │   • 按 PlayerSectionKind 八分段聚合                                      │
 │     (Progression/World/Combat/Buffs/Loadout/Settings/ActionQueue/Duel)   │
 │   • 资产走 AssetWallet+economy；细粒度脏段追踪 MarkDirty(PlayerSectionKind)│
 └────────────────────────────────────┬────────────────────────────────────┘
                                      │ 作为唯一输入输出
                                      ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │               确定性模拟引擎 (SimulationEngine.AdvanceTo)               │
 │   • 时间片推进 (cursor -> target)，按行动完成边界/微步事件向前演进         │
 │   • 统一执行 Buff 到期结算、行动推进结算、自然回复结算                     │
 │   • 产生增量事件日志与脏分段标记 (DirtySections)                           │
 └─────────────────────────────────────────────────────────────────────────┘
```

### 2.5.1 领域层：`PlayerAggregate` 聚合根

- `PlayerAggregate`（定义于 `src/Domain/Player/PlayerAggregate.cs`）是角色全部状态的**唯一权威数据载体**；
- 内部按 `PlayerSectionKind` 八分段收敛 `PlayerProgression`、`PlayerWorldState`、`PlayerCombatState`（含 `PlayerCombatSkillState`）、`PlayerBuffState`、`PlayerLoadoutState`、`PlayerSettingsState`、`PlayerDuelState` 与行动队列；资产（灵石、物品、装备实例）不进聚合，统一由 `AssetWallet` + `economy.*` 关系表承载；
- 纯 POCO 设计使得任何状态操作都可以被轻松单元测试、离线重放和确定性断言。

### 2.5.2 模拟层：`SimulationEngine` 确定性推进

- `SimulationEngine.AdvanceTo` 是世界状态演进的唯一入口；
- 引擎按离散事件边界切分时间片，在推进循环中统一执行：
  1. Buff 到期结算：推进并失效到期 Buff；
  2. 行动推进与状态转移（根据行动类型由 SimulationEngine 执行挂机产出结算、战斗状态机推进或位移处理；技能施放由 `CombatSkillEngine` 结算）；
  3. 自然回复结算：读取基础属性表及明确加成计算后的回复属性，结算自然气血与灵力回复；不得由生命/灵力上限按固定比例生成回复值，周期口径见 [战斗规约 §7.9.2](./07-战斗数值与内视规约.md#792-自然回复属性由基础属性表配置)；
  4. 产出结算与脏分段标记汇总。

### 2.5.3 运行时层：`EcsGameRuntime` + `EcsWorldShard` + `EcsPlayerRuntimeAdapter`

- **单写者并发模型（Single-Writer）**：每个玩家在内存中是某个 `EcsWorldShard` 内的 `YuoEntity`（按 `PlayerId` 稳定哈希路由），其推进与命令在分片 `YuoFiber` 内串行执行，`EcsPlayerRuntimeAdapter` 的玩家级 `SemaphoreSlim` gate 兜底跨边界串行，从根本上杜绝了多线程并发读写导致的“状态撕裂”；
- **命令通道**：业务命令经 `EcsWorldShard.MutatePlayer` 将 ECS 组件重建为 `PlayerAggregate` 执行领域操作并整体回写，脏段差集驱动回执与推送；
- **冷热无缝切换**：玩家离线后实体休眠，脏分段经 latest-only 刷盘队列异步写入 PostgreSQL section 表。玩家重连时，从 `PlayerStateHead` + 各 `PlayerSectionSnapshot` 恢复组件并由确定性推进补算至当前时刻，状态与一直在线完全无差。

### 2.5.4 网络层：`ProtocolSnapshotMapper` 增量同步

- 服务端通过 `ProtocolSnapshotMapper` 将演进产生的脏分段（`DirtySections`/`PlayerSectionKind`）打包为轻量级快照/增量 DTO（透传当前激活 `GameDataCatalog`）；
- 前端仅针对发生变动的局部数据（如气血微调、Buff 列表变动、背包变动）进行响应式更新，绝不整体重建面板，确保高频状态流转下的流畅交互体验。

## 2.6 设计红线与扩展准则（Design Redlines & Guidelines）

为确保“统一常驻实体”核心哲学的长久纯粹性与系统健壮性，后续所有系统开发与玩法扩展必须严格遵守以下红线：

1. **【严禁设立影子角色】**：任何新玩法（秘境、竞技场、帮派战、大世界事件等）不得为玩家创建独立的“临时战斗载荷”或“脱离主实体的副角色”，必须直接引用和修改主 `PlayerAggregate`。（注：秘境/竞技场/PvP 均为规划意图，尚未落地。）
2. **【严禁跨玩法免费重置】**：严禁在进入或退出某个玩法时，私自执行“气血回满”、“灵力回满”、“重置所有技能冷却”等破坏状态连续性的破坏性操作。一切恢复必须有法可循（依赖丹药、打坐、技能或自然回复属性）。
3. **【严禁使用浮点截断】**：所有与时间、资源、属性、收益率相关的计算与存储必须统一使用 `double` 精度，微量回复必须走 `RegenCarrySeconds` 回复周期余量累加机制，严禁因整数截断导致长期挂机收益丢失。
4. **【闭环演进原则】**：任何新增的作用力（新动作类型、新环境效果、新交互机制），必须遵循“从 `PlayerAggregate` 读取条件 -> 计算影响 -> 原地写回 `PlayerAggregate` -> `MarkDirty(PlayerSectionKind.Xxx)`”的标准闭环管线。
5. **【确定性守恒】**：任何状态转移逻辑必须是纯函数的、无副作用的确定性计算，严禁在状态演进代码中调用系统随机数（必须使用确定性种子生成器）、系统时钟（必须使用传入的时间戳参数）或进行异步/外部 I/O 操作。
