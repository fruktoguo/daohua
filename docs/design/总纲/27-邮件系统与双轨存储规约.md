## 1. 设计目标与边界原则

道化太初「传书邮件系统」服务于全服补偿/公告群发与系统定向发奖/通知两类场景，遵循以下容量与架构边界：

1. **零 ECS / 八分段侵入**：邮件不进入玩家八分段快照（`SectionCodec.CurrentSchemaVersion` 保持不变），不占用 `EcsWorldShard` 实体/组件槽位，亦不进入冷挂机计算节点（`ComputeNode`），保证 `2000+` 离线与冷挂机玩家零额外加载和补算开销。
2. **双轨物理隔离存储**：
   - **全服群发轨（`social.broadcast_mails`）**：每次全服发件只在数据库生成 **1 行不可变公告记录**，由服务端 singleton `MailRuntime` 缓存未过期的全局只读不可变数组 `ImmutableArray<BroadcastMailRecord>`，所有在线玩家共享同一内存引用，零按角色复制。
   - **个人邮件轨（`social.player_mails`）**：仅存放面向单个角色的定向邮件（含系统发奖、交易/补偿补单等）；已读/已领标志内联在行内，删除执行物理 `DELETE`；单角色保留上限 `100` 封，超限写前优先淘汰最旧的「已读且无未领附件」邮件。
   - **群发个人状态位图轨（`social.player_mail_states`）**：按 `player_id` 稀疏建行，仅当玩家实际已读、领取或删除了某封群发邮件后才按需 `UPSERT` 唯一一行，内部以有序 `bigint[]` 保存 `read_ids`、`claimed_ids`、`deleted_ids`；不活跃角色零持久化行、零内存占用；每次写入均与当前活跃未过期 `broadcast_id` 集合求交集自动压实。
3. **机器人账号彻底隔离**：`identity.accounts.is_bot = true` 的系统/市场机器人账号在群发列表读取、WS 握手摘要、群发广播推送与领奖入口全面屏蔽，避免无谓写状态行与资产膨胀。

## 2. 红点、已读、附件与删除语义

1. **红点亮起规则**：只要角色存在任意「未读邮件」**或**「未领取附件的邮件」，即 `unreadCount > 0 || claimableCount > 0 || forceRedDot`，顶栏传书按钮显示红点提示：
   - 纯文本通知：阅读后标为已读并消除红点；
   - 带附件邮件：仅打开阅读不消除红点，需领取全部附件后消除（领取同时自动标为已读）。
2. **新创建角色保护（`only_existing_players`）**：全服群发默认 `only_existing_players = true`，仅 `identity.accounts.created_at <= broadcast.created_at` 的历史角色可见可领，防止停服补偿/周年奖励期间批量新建小号刷奖；需要针对新号发放的新手福利可将开关设为 `false`。
3. **附件领取原子性与事务锁序**：
   - 仅支持单封领取（`POST /api/v1/mails/{mailKey}/claim`）与一键领取全部可领附件（`POST /api/v1/mails/claim-all`）。
   - 单/全领路径严格复用 `IParticipationAssetBoundary` → `PlayerCommitGates.AcquireAllAsync` 的全局锁序（防与市场/宗门/ECS 经济写发生死锁），并在 `Serializable` 事务内对个人邮件行/玩家群发状态行加 `FOR UPDATE` 行锁后调用 `PostgresEconomyRepository.CommitCoreAsync(..., TransactionType: "mail.claim")`，写 `economy.player_asset_balances` 与流水账，事务提交后调用 `IPlayerRuntime.ReloadWalletAndNotifyAsync(playerId)` 为在线角色刷新 ECS 内存钱包并下推增量快照。
4. **防误删约束**：含附件且未领取的邮件（无论个人还是群发），前后端均严格禁止删除（单删返回 `409 Conflict`，「删除已读」批量跳过未领附件邮件）；用户删除群发邮件时仅向 `deleted_ids` 记录该 `broadcast_id`（并在清理前自动附带压实），不破坏其他角色可见性。
5. **列表与正文分离**：列表接口仅返回元信息与附件预览（不含长正文 `body`），点击展开详情时通过 `GET /api/v1/mails/{mailKey}` 按需拉取正文并在前端 `mailStore` 缓存；打开同时若为未读会自动触发标为已读并刷新红点摘要。

## 3. 实时推送与零群发风暴策略

- **WS 握手推摘要**：WebSocket `Hello` 阶段并行加载 `MailRuntime.GetSummaryAsync(playerId, isBot)`，仅下发轻量 `WireMessageType.MailSummary`（`{ unreadCount, claimableCount, forceRedDot }`）。
- **个人发件定向推送**：仅当接收者当前存在在线非机器人会话时，直接下推精准重算后的 `MailSummaryDto`。
- **全服群发零扇出推送**：全服发送成功后刷新全局不可变公告缓存，并**只序列化 1 帧** `{ unreadCount: 0, claimableCount: 0, forceRedDot: true }` 协议信封，经 `TrySendDroppableEnvelope` 向全服在线非机器人连接旁路通知点亮红点（`existing-players-only` 情况下按会话 `CreatedAtUtc <= broadcast.CreatedAtUtc` 过滤，或新客可见）；**不在后台瞬间为数千连接回查数据库重算各自已读集合**，真正实现推送零 DB 风暴；当玩家点击右上角邮件图标进入邮件页时，客户端才拉取完整列表与准确红点数字。

## 4. 保留期与清理策略

- 默认过期时间为发件起 `30 天`（可在 `Ops` 发件时按天定制，或勾选「永不过期」将 `expires_at` 置为 `NULL`）。
- `PostgresRetentionWorker` 定期分批清理：`expires_at IS NOT NULL AND expires_at < now()` 的个人邮件行与过期全服公告行（永不过期公告不参与过期清理）；同时清理已引用过期公告完毕的玩家状态阵位。
- `economy.transactions` 中的 `transaction_type = 'mail.claim'` 视为长期金融对账流水保留 `14 天`，与 `market`、`shop.buy`、`player.unlock_avatar` 口径一致。

## 5. 前后端交互与顶栏布局约定

- **顶栏位置**：无论桌面宽屏还是竖屏窄屏（`<= 960px` / `<= 520px`），传书角标始终置于右上角 `.topbar-actions` 内、`TaijiToggle`（明暗切换）正左侧；竖屏下自动压缩 `.player-block` / `.realm-progress` 进度条，确保信息区与操作区不重叠。
- **独立高密度弹窗（`<MailModal />`）**：点击顶栏传书按钮拉起基于公共 `Modal` 的独立响应式弹窗（`uiStore.mailOpen` 控制，挂载于顶层弹窗层），不隐藏或卸载底层 `.main-content` 主视图与侧边栏/底栏导航高亮，亦不挤占移动端底部 7 个主导航分组配额；按 `Esc`、点击遮罩/右上角关闭按钮，或点击弹窗内富文本词条跳转大地图时自动收起弹窗；横屏（含手机矮横屏）固定外框采用紧凑顶栏 + 左右双栏独立滚动，竖屏窄屏展开至近全视口并采用单栏列表/详情全高钻取。
- **运营后台（`/ops`）**：提供按玩家 UUID/道号发送个人邮件、发送/撤销全服群发邮件以及配置多附件与有效期的入口，全部写操作记入 `platform.ops_audit_logs`。
