# 第十三篇 前端 UI 设计系统与修仙交互规范

## 13.1 暗墨玄石美学与色调规范
- **材质底色**：`rgba(14, 12, 7, 0.96)` 高透明度深黑底色 + `backdrop-filter: blur(14px)` 毛玻璃效果。
- **古典修仙色调 (`FloatingTone` / `PillTone`)**：
  - `gold` (暗金/极品/破招)、`jade` (苍翠/生命/木行)、`qi` (灵虚淡蓝/灵力/神识)、`danger` (朱砂煞红/负伤/削弱)、`purple` (紫极天道/灵品)、`muted` (玄灰幽暗/背景注记)。

### 13.1.1 深色与浅色显示主题

- 设置 → 显示提供「浅色 / 深色」分段选择，默认浅色；选择在当前浏览器保存，刷新后在首屏恢复。
- 浅色采用平色浅黄纸底（背景不叠渐变）、深墨文字；印章红为主操作、选中态、焦点与危险语义的签名强调色，暖赭金退回边框、角纹与语义金等纹饰用途；保留现有字体、布局、间距、图标、品质层级、修仙色相、法阵及交互动效；深色延续暗墨玄石风格。
- 主题由根节点 `data-theme` 与统一配色、字重变量驱动，悬浮 Portal、弹窗、登录/连接屏幕、地图与战斗信息使用同一主题；物品图像与技能特效不做整体反色。
- 两套主题分别提供正文、次要文字、语义色、面板、输入框与交互状态配色。浅色普通文本对实际底色的对比度至少 4.5:1，焦点与必要控件边界至少 3:1；不能直接把深色高亮文字复用于浅色底。
- 浅色正文、辅助文字、输入控件与原 400/500 字重的标签和标题统一提升至至少 600 字重（由 `--font-weight-regular`/`--font-weight-medium` 主题字重变量驱动），原有 600 及以上字重保留不变；深色沿用原有字重。
- 切换只更新主题外观（配色与字重）与浏览器主题元数据，不重新挂载游戏界面，不触发网络命令，不改变输入值、滚动位置与游戏状态。
- 顶栏右侧提供太极快捷开关：对称正置的阴阳双鱼太极图（鱼眼取对色、盘底为偏差暖米色），常态静止；浅色主题阳鱼居上，深色主题整体翻转 180° 令阴鱼居上，点击切换主题时再旋转 180°；主题切换经 View Transitions 做以触发点为圆心的全屏圆形扩散过渡，扩散区内呈现目标主题；不支持该 API 或减少动效偏好时直接切换。

## 13.1.2 竖屏底部导航两级结构

- 竖屏（≤960px）底部导航固定为 **7 个一级分组**：内视 / 坊市 / 历练 / 详情 / 技艺 / 背包 / 更多；组内页签多于一个时在其上方浮现子行完成二次选择，单页签分组不渲染子行、保持一击直达。
- 分组与组内页签的真源是 `frontend/src/mobileNav.ts`（`MOBILE_NAV_GROUP_DEFS` 键即分组标识，`MOBILE_NAV_GROUP_ORDER` 决定展示顺序，`GROUP_OF_TAB` 以 `satisfies Record<TabId, …>` 保证每个页签都有归属且无多余键）。
- 组内构成：坊市＝坊市/商店；历练＝历练/地图；更多＝同道/图鉴/排行榜/更新日志/帮助/日志/记录/设置（其中点击「帮助」直接唤起独立大尺寸弹窗 `HelpModal` 而不替换底层主界面，顶部横向切换章节、下方正文独立滚动）；技艺组的子行是技艺模式切换条（炼丹/炼器/符箓/阵法/强化，含技艺等级），由 `CraftingModeTabs` 渲染，页面主体内不再重复出现；同道通用二级（队伍/对弈/宗门/攻略/邀请）由 `SocialSubTabs` 渲染在「更多」子行之上的底部子行中，`SocialPage` 内不再单独渲染页头切换条。
- 交互：点击非当前分组 → 切到该组记忆落点并展开子行（1 击到达内容）；点击当前分组 → 不改变当前页签；点击子项 → 切换页签且子行保持展开。落点按分组记忆于 `uiStore.mobileNavMemory`，任何 `setActiveTab`（含代码直跳与新手引导）都会更新所属分组的落点。
- 角标必须上提到分组层：日志未读与同道待处理邀请在「更多」分组图标上合计露出，子行各自只显示自己那份（日志报未读条数、同道报邀请数；进入同道页后，若停留在宗门/邀请页，邀请角标继续在「队伍」子项上提示），否则私聊与组队邀请会在二级沉底后完全静默。
- 导航高度由 `BottomNav` 实测反写 `--mobile-nav-offset`，页面底部占位与提示气泡避让统一引用该变量，不得再出现硬编码的 `72px`。
- 页签可达性：`docs/tasks` 以外的竖屏入口必须落在某个分组内（仅 `alchemy` 为例外——它是直达技艺-炼丹的别名，由 `setActiveTab` 归一为 `crafting`）；新手引导锚点 `[data-tour="nav-map"]` 同时挂在桌面侧边栏与「历练」组的地图子项上，取首个可见元素。
- 竖屏「详情」全屏专注模式：`@media (orientation: portrait)` 下「详情」页标题行最右侧展示放大/恢复切换按钮（`aria-expanded`，≤640px 效率条折行时仍固定居于标题第一行最右端，横屏不展示）；点击放大后详情面板按 `position: fixed; inset: 0; height: 100dvh; z-index: 55` 覆盖顶栏（`20`）与底部导航（`40`）并适配 `env(safe-area-inset-*)`，内容区维持独立纵向滚动且浅/深双主题铺实 `--panel` 底色；各类模态弹窗、悬浮窗、新手引导与提示气泡仍高于该层级；再次点击恢复按钮、无顶层弹窗时按 `Esc`、离开详情页或切出竖屏自动恢复常规布局。
- 桌面端（横屏）侧边栏（`Sidebar`）保持高可达平铺与适度收拢并行：
  - 主区保留「内视 / 历练 / 地图 / 详情」一级直达，并将「坊市（坊市 / 商店）」「技艺（炼丹 / 炼器 / 符箓 / 阵法 / 秘法）」「同道（队伍 / 对弈 / 宗门 / 攻略 / 邀请）」「其他（图鉴 / 排行榜 / 更新日志 / 帮助）」组织为可折叠二级分组（`.nav-group` + `.nav-sub-menu`），其中「坊市 / 商店」分组口径与竖屏一致；点击「帮助」直接唤起独立大尺寸弹窗 `HelpModal`（不替换底层主视图，横屏左目录固定、右正文独立滚动；竖屏章节目录置顶横向滑动、下方正文独立滚动）；
  - 侧栏底部（`.sidebar-footer`）保持「记录 / 设置」吸底直达不变。

### 13.1.3 纯字符双语终端挂机模式

- **入口、语言切换与生命周期**：设置 → 显示提供「挂机模式」开启入口（`uiStore.idleModeOpen`）；开启后以 `position: fixed; inset: 0` 铺满网页视口（不调用浏览器原生 Fullscreen API，不弹系统全屏提示条）。终端顶栏右上角常驻纯字符**中英文切换按钮**（`[ 中文* / EN ]` ↔ `[ 中文 / EN* ]`，状态由 `uiStore.idleTerminalLang` 管理并持久化至 `localStorage`，不影响游戏主界面全局语言）与退出按钮（`[ × 退出挂机 ]` / `[ × EXIT ]`）；仅点击右上角退出按钮返回常规游戏界面（退出登录或多开受阻时自动关闭）。
- **纯字符零图像与中英双语直观可读约束**：挂机遮罩（`TerminalIdleOverlay`）作为纯字符零图像例外视图，采用类似黑客模拟器 / CMD 监控控制台的全等宽字符分屏布局，**严禁渲染任何图像元素（`<img>`、`<svg>`、`<canvas>`、Emoji 或背景图）**；所有框线、进度条（`█▓░`）、Braille 双列点阵实时波形（`⠁⠃⠇⠏⠟⠿⣿`）、纯字符战斗血条、节点链路拓扑与内存帧检视均由字符构成。中文态通过 `app.idleTerminal.*` i18n 词条展示直观中文指标，英文态直接展示对应的直译英文游戏指标（`Realm`、`Experience`、`HP`、`MP`、`Action`、`Spirit Stones`、`Merit`、`Foundation` 等，实体名称由语义 ID 规范化为英文 Title）。
- **纯显示接管与全维度真实数据展示**：该模式仅改变前端视图呈现，不发送额外业务命令，底层 WebSocket 通信与行动结算照常推进；五窗格直观展示：① 角色境界、本层修为进度、气血/灵力实时条、灵石/功德/底蕴与动态波形；② 当前行动名称、单轮进度、剩余时间估算（复用 `calculateQueueActionEstimate`）与预计日收益/修为速率/频次（复用 `calculateBriefStats`）；③ 战斗中的敌我实时纯字符气血条（非战斗时展示当前地图节点链路与算力条）；④ 实时滚动的纯文本修行/采集/战斗掉落日志（直连 `gameLogService` 并支持频道筛选与键盘诊断指令交互）；⑤ 行动队列列表、自动消耗品背包余量告警、产出明细、生活技艺进度与十六进制内存检视切换。开启期间压制底层 `Notice` 气泡及每日签到、更新日志等自动弹窗，并在浏览器标签页标题同步按当前所选终端语言提示挂机运行状态。

### 13.1.4 主界面语言切换与运行态实体名称

- 主界面切换语言、外语包异步就绪时，境界牌匾及其悬浮详情必须立即刷新；包含译文的派生缓存以当前翻译函数为依赖，不能等待修为或等级变化才更新。
- 账号密码登录的无效凭据提示按稳定错误码翻译。不存在的账号、停用账号和错误密码仍显示同一提示。
- 协议快照保留服务端原始文本；队列、战斗详情和地点等展示入口，持有实体 ID 时优先复用已有语言词条与本地化目录。单位属性详情中的 Buff 条目及其悬浮标题同样按 Buff ID 取名。驻留地点参与讨伐名称替换时使用当前语言的节点名，不将服务端中文地点混入英文标题。动态宗门名、玩家原文与旅途中状态文案保留原语义，不由客户端猜译。
- **英文分组标题适配**：战斗装配区的英文分组标题横排置于槽位上方，并在正常文档流中占用独立空间；简中保留原竖排标签与内边距，避免将英文逐字符竖排的问题混同为公共布局缺陷。
- **公共槽位可达性**：桌面端不分语言，均按容器实际宽度让分组换行，单组仍放不下时让槽位换行；窄主面板高度受限时允许装配区内原生纵向滚动，保证所有槽位可达，不缩小槽位或裁切内容。移动端保留上方消耗品、下方功法的分行布局。保持桌面 64px、移动端 48px 的槽位尺寸约定，在中英 1440×1000、390×844 及 961px 附近窄主面板验收标题完整可读、与槽位不重叠且无横向溢出。
- 「武 / 玄 / 天 / 初 / 中 / 后 / 极」为境界牌匾共享字形，双语共用，不视为缺译。

## 13.2 核心公共组件速查 (强制收拢规范)
1. **`FloatingPopover` / `FloatingInfoCard` / `FloatingTooltip`**：基于 React Portal 挂载至 `#daohua-floating-root`，自动计算视口翻转（Auto Flip）与边界夹持（Viewport Clamp），标准宽度 `medium` (300px)，支持 `quantity={amount}` 独立中文四位分段副气泡；桌面 Hover 防抖、移动端 Touch 0 阻碍穿透底层。
2. **`RealmBadge`**：大境界牌匾框 + 境界阶段棱形框 + 小境界胶囊框，Hover 展示精准等级与属性。
3. **`PillStatLabel` / `PillBonusLabel`**：复合修仙胶囊，内置图标、专属下划线数值、内联进度条与 Tooltip。
4. **`ItemTile` / `ItemGridPicker`**：标准物品方块，品质光晕色调与边框、旋转填充倒计时遮罩。
5. **`QuantitySelector`**：数量输入、常用预设按钮与 `∞` 无限循环按键。
6. **`UnitNumber`**：万进紧凑展示（最多6位数字、2位小数、向下取整），Hover 弹出中文四位分段对照（如 `1234亿 7777万 5211`）。
7. **`CharacterAvatar`**：角色/妖兽立绘统一 128px WebP q80 运行时资源（矢量母模归档 `art/avatars/`，缺图回退默认立绘），敌方自动镜像翻转（`scaleX(-1)`）。
8. **通用富文本实体引用与更新日志提示 (`RichTemplateText` / `ChangelogNoticeModal`)**：战报、传音与更新日志正文共用 `{{kind:id|label}}` 富文本分词与图鉴同款悬浮详情卡（覆盖物品/装备/秘籍 `item`、功法 `ability`、特质 `trait`、建筑 `building`、状态 `buff`、妖兽 `enemy`/`encounter`、行动 `action`、地点 `location`、机制 `mechanic`）。更新公告首次弹窗严格绑定更新日志自带的独立 `noticeId`（与程序版本号解耦），仅当出现本地未关闭的新 `noticeId` 且主目录就绪、非新手引导中时自动弹出，关闭后持久化去重直至出现更新的更新提示记录。

## 13.3 普攻与受击反馈层级

- 普攻采用「掠斩、直刺、回锋、震击」四种短促演出，同一出手单位交替使用；变化只影响画面，不改变攻击时刻、目标、伤害或次数。
- 受伤采用「裂光、震纹、碎星」三种局部反馈，同一受击单位交替使用；正式前端由权威气血下降触发，画廊由沙盘扣血触发，一次伤害只启动一次受击动画。
- 普攻主色限于骨白与淡金，受击用克制的暖白与朱砂；禁止普通命中引发全屏闪白、震屏、大范围烟雾或长尾粒子。每次普攻最多 8 枚小粒子，主体轨迹在约 0.4 秒内收束，所有残留在 0.8 秒内清理。
- 光痕与震纹集中在立绘身位，尺寸跟随立绘台缩放，不触碰名字、资源条与行动条布局；连续攻击时保留目标轮廓与数值可读性。
- 画廊与正式前端共享普攻脚本和受击样式；画廊提供命名变体按钮供逐项查看，环境普攻自动交替。技能、暴击、阵亡仍保持独立演出层级。
