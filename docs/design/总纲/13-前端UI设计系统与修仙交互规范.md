# 第十三篇 前端 UI 设计系统与修仙交互规范

## 13.1 暗墨玄石美学与色调规范
- **材质底色**：`rgba(14, 12, 7, 0.96)` 高透明度深黑底色 + `backdrop-filter: blur(14px)` 毛玻璃效果。
- **古典修仙色调 (`FloatingTone` / `PillTone`)**：
  - `gold` (暗金/极品/破招)、`jade` (苍翠/生命/木行)、`qi` (灵虚淡蓝/灵力/神识)、`danger` (朱砂煞红/负伤/削弱)、`purple` (紫极天道/灵品)、`muted` (玄灰幽暗/背景注记)。

### 13.1.1 深色与浅色显示主题

- 设置 → 显示提供「浅色 / 深色」分段选择，默认浅色；选择在当前浏览器保存，刷新后在首屏恢复。
- 浅色采用平色浅黄纸底（背景不叠渐变）、深墨文字；印章红为主操作、选中态、焦点与危险语义的签名强调色，暖赭金退回边框、角纹与语义金等纹饰用途；保留现有字体、布局、间距、图标、品质层级、修仙色相、法阵及交互动效；深色延续暗墨玄石风格。
- 主题由根节点 `data-theme` 与统一配色、字重变量驱动，悬浮 Portal、弹窗、登录/连接屏幕、地图与战斗信息使用同一主题；物品图像与技能特效不做整体反色。
- 两套主题分别提供正文、次要文字、语义色、面板、输入框与交互状态配色。浅色普通文本对实际底色的对比度至少 4.5:1，焦点与必要控件边界至少 3:1；不能直接把深色高亮文字复用于浅色底。
- 浅色正文、辅助文字、输入控件与原 400/500 字重的标签和标题统一提升至至少 600 字重（由 `--font-weight-regular`/`--font-weight-medium` 主题字重变量驱动），原有 600 及以上字重保留不变；深色沿用原有字重。
- 切换只更新主题外观（配色与字重）与浏览器主题元数据，不重新挂载游戏界面，不触发网络命令，不改变输入值、滚动位置与游戏状态。
- 顶栏右侧提供太极快捷开关：对称正置的阴阳双鱼太极图（鱼眼取对色、盘底为偏差暖米色），常态静止；浅色主题阳鱼居上，深色主题整体翻转 180° 令阴鱼居上，点击切换主题时再旋转 180°；主题切换经 View Transitions 做以触发点为圆心的全屏圆形扩散过渡，扩散区内呈现目标主题；不支持该 API 或减少动效偏好时直接切换。

## 13.1.2 竖屏底部导航两级结构

- 竖屏（≤960px）底部导航固定为 **7 个一级分组**：内视 / 坊市 / 历练 / 详情 / 技艺 / 背包 / 更多；组内页签多于一个时在其上方浮现子行完成二次选择，单页签分组不渲染子行、保持一击直达。
- 分组与组内页签的真源是 `frontend/src/mobileNav.ts`（`MOBILE_NAV_GROUP_DEFS` 键即分组标识，`MOBILE_NAV_GROUP_ORDER` 决定展示顺序，`GROUP_OF_TAB` 以 `satisfies Record<TabId, …>` 保证每个页签都有归属且无多余键）。
- 组内构成：坊市＝坊市/商店；历练＝历练/地图；更多＝同道/图鉴/日志/记录/设置；技艺组的子行是技艺模式切换条（炼丹/炼器/符箓/阵法/强化，含技艺等级），由 `CraftingModeTabs` 渲染，页面主体内不再重复出现。
- 交互：点击非当前分组 → 切到该组记忆落点并展开子行（1 击到达内容）；点击当前分组 → 不改变当前页签；点击子项 → 切换页签且子行保持展开。落点按分组记忆于 `uiStore.mobileNavMemory`，任何 `setActiveTab`（含代码直跳与新手引导）都会更新所属分组的落点。
- 角标必须上提到分组层：日志未读与同道待处理邀请在「更多」分组图标上合计露出，子行各自只显示自己那份（日志报未读条数、同道报邀请数），否则私聊与组队邀请会在二级沉底后完全静默。
- 导航高度由 `BottomNav` 实测反写 `--mobile-nav-offset`，页面底部占位与提示气泡避让统一引用该变量，不得再出现硬编码的 `72px`。
- 页签可达性：`docs/tasks` 以外的竖屏入口必须落在某个分组内（仅 `alchemy` 为例外——它是直达技艺-炼丹的别名，由 `setActiveTab` 归一为 `crafting`）；新手引导锚点 `[data-tour="nav-map"]` 同时挂在桌面侧边栏与「历练」组的地图子项上，取首个可见元素。
- 桌面端侧边栏保持扁平结构不变：桌面空间充裕，二次选择只会增加点击成本。

## 13.2 核心公共组件速查 (强制收拢规范)
1. **`FloatingPopover` / `FloatingInfoCard` / `FloatingTooltip`**：基于 React Portal 挂载至 `#daohua-floating-root`，自动计算视口翻转（Auto Flip）与边界夹持（Viewport Clamp），标准宽度 `medium` (300px)，支持 `quantity={amount}` 独立中文四位分段副气泡；桌面 Hover 防抖、移动端 Touch 0 阻碍穿透底层。
2. **`RealmBadge`**：大境界牌匾框 + 境界阶段棱形框 + 小境界胶囊框，Hover 展示精准等级与属性。
3. **`PillStatLabel` / `PillBonusLabel`**：复合修仙胶囊，内置图标、专属下划线数值、内联进度条与 Tooltip。
4. **`ItemTile` / `ItemGridPicker`**：标准物品方块，品质光晕色调与边框、旋转填充倒计时遮罩。
5. **`QuantitySelector`**：数量输入、常用预设按钮与 `∞` 无限循环按键。
6. **`UnitNumber`**：万进紧凑展示（最多6位数字、2位小数、向下取整），Hover 弹出中文四位分段对照（如 `1234亿 7777万 5211`）。
7. **`CharacterAvatar`**：角色/妖兽立绘统一 128px WebP q80 运行时资源（矢量母模归档 `art/avatars/`，缺图回退默认立绘），敌方自动镜像翻转（`scaleX(-1)`）。

## 13.3 普攻与受击反馈层级

- 普攻采用「掠斩、直刺、回锋、震击」四种短促演出，同一出手单位交替使用；变化只影响画面，不改变攻击时刻、目标、伤害或次数。
- 受伤采用「裂光、震纹、碎星」三种局部反馈，同一受击单位交替使用；正式前端由权威气血下降触发，画廊由沙盘扣血触发，一次伤害只启动一次受击动画。
- 普攻主色限于骨白与淡金，受击用克制的暖白与朱砂；禁止普通命中引发全屏闪白、震屏、大范围烟雾或长尾粒子。每次普攻最多 8 枚小粒子，主体轨迹在约 0.4 秒内收束，所有残留在 0.8 秒内清理。
- 光痕与震纹集中在立绘身位，尺寸跟随立绘台缩放，不触碰名字、资源条与行动条布局；连续攻击时保留目标轮廓与数值可读性。
- 画廊与正式前端共享普攻脚本和受击样式；画廊提供命名变体按钮供逐项查看，环境普攻自动交替。技能、暴击、阵亡仍保持独立演出层级。

## 13.4 全技能程序化粒子演出

- **覆盖口径**：`docs/design/战斗演武画廊/index.html` 是技能视觉验收入口，覆盖配表中的全部 13 门主动技能和 10 门常驻内功。内功不得伪造施法、目标伤害或战斗 Buff；画廊只播放以自身为中心的运功预览。
- **共享实现**：画廊与正式前端共享 `vfx/abilities/` 技能脚本和 Canvas 粒子时间轴。每门主动技能拥有独立构图、配色与命中节奏，不以同一场粒子爆炸只换颜色冒充专属演出。正式前端仍由权威战斗事件驱动结算、受击和跳字，粒子脚本不得改变战斗状态。
- **清晰优先**：粒子采用细亮硬芯、有限宽度辉光和明确运动方向；禁止用大面积模糊烟雾、过曝全屏白闪、无层次粒子堆叠或持续遮罩角色表达威力。技能效果不得遮挡单位名称、资源条和行动条。
- **节奏约束**：真实吟唱时长属于战斗规则，保持不变；出手后采用约 80~260ms 起手、明确命中帧、快速消散的收束结构。主动技主体通常在 0.6 秒内完成，含多目标/多段的完整演出不超过约 1.15 秒；不得以长弹道、长拖尾或长后摇拖延战斗。
- **打击层次**：命中帧组合方向性碎光、短促冲击环与局部角色受击；重击可有低幅短震屏，但不得造成界面位移或阅读困难。治疗、支援和内功使用收束、展开、上升的粒子语言，不套用伤害性炸裂。
- **运行约束**：同一战斗舞台只运行一个 `requestAnimationFrame` 循环，复用固定粒子池，按设备像素比适配清晰度；页面隐藏时停止推进，重置/卸载时同步清理画布、粒子和排程。预览随机过程可播种，以便复现问题与逐帧验收。
- **目录真源**：权威配表仍是 `config/game-data/abilities/*.json`；画廊 `vfx/catalog.js` 仅作演示镜像。新增主动技能须同步配表镜像、粒子脚本、画廊加载清单与目录，内功须明确标注非施放。
