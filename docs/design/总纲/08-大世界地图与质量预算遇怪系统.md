## 8.1 核心设计哲学

### 8.1.1 摒弃纯战斗地图，确立“通用世界地点”模型
在《道化太初》中，**不存在与大世界割裂的“纯战斗副本”或“纯刷怪地图”**。
所有地点（`WorldNode`）都是世界中的真实通用地理节点（例如：青岚药谷、青云山门、落霞西岭、玄铁矿洞、流云集等）。

每一个世界地点都拥有自己独立的生态聚合体：
1. **行动体系（Actions）**：
   - **生活 / 采集 / 生产行动**（如：采药 `explore.gather-herbs`、挖矿 `explore.mine-ore`、炼丹 `craft.alchemy` 等）；
   - **历练探索行动**（如：后山寻猎 `combat.hunt-qi-beast`、清剿裂谷 `combat.sweep-twilight-valley`）。
2. **生物生态（Creatures）**：分为 **NPC** 与 **怪物（Monsters）** 两个支柱。
3. **地理建筑 / 阵法设施（Buildings）**：如山门防护阵、聚灵泉眼、老井、哨塔等。

```
┌─────────────────────────────────────────────────────────────┐
│                    通用大世界地点 (WorldNode)                  │
│                     例：青岚药谷 (node.herb-vale)            │
├──────────────────────────────┬──────────────────────────────┤
│ 1. 驻留生物 (Creatures)       │ 2. 开放行动 (Actions)         │
│  ├─ NPC 列表 (任务/传功/剧情)  │  ├─ 采集类行动 (采药/挖矿)    │
│  └─ 怪物生态池 (历练遇怪/掉落) │  └─ 历练类行动 (战斗/清剿)    │
├──────────────────────────────┴──────────────────────────────┤
│ 3. 危险度与预算参数 (Hazard / Budget Parameters)              │
│  ├─ 危险度总预算区间 [minBudget, maxBudget] (直接代表危险度)  │
│  ├─ 精英刷新周期 (battlesPerElite，如每 5 次遭遇)            │
│  └─ 领主刷新周期 (battlesPerBoss，如每 20 次遭遇)            │
└─────────────────────────────────────────────────────────────┘
```

## 8.2 生物生态数据模型（NPC 与 怪物）

### 8.2.1 NPC 数据模型（人物 / 住民）
NPC 代表该地点的常驻居民、散修、执事或向导。
- **当前阶段定位**：数据结构完整规范，界面展示头像与描述，**行为交互暂时留空（预留扩展接口）**。
- **后续扩展职能**：发布委托与支线任务、传授技能功法、提供特定交互对话与好感度。

#### 数据结构定义（`NpcDefinition`）：
```typescript
interface NpcDefinition {
  id: string;              // 唯一标识，如 "npc.herbalist-lin"
  name: string;            // 姓名，如 "采药人林伯"
  title?: string;          // 头衔/称号，如 "药谷向导"
  description: string;     // 角色生平与描述
  avatar?: string;         // NPC 头像资源路径/图标
  effectDescription?: string; // 当前环境职能描述（如"后续可提供采集委托"）
  // 后续扩展字段预留
  questIds?: string[];     // 关联任务列表 (预留)
  teachableAbilityIds?: string[]; // 可传授技能列表 (预留)
}
```

### 8.2.2 怪物数据模型（Monsters / 妖兽）
怪物代表栖息在该地点的野生妖兽、异化生物或敌对修士。
每个怪物除了具备既定的阶位（`Tier`）、层次（`Rank`）与属性权重外，**必须配置单体消耗预算 `budgetCost`（质量预算点数）**。

#### 怪物配表结构示例（`config/game-data/monsters/*.json`）：
```json
{
  "id": "enemy.demonized-rabbit",
  "name": "魔化野兔",
  "visual": { "renderer": "text", "source": "兔" },
  "budgetCost": 10,
  "weights": { "hp": 1.15, "ad": 0.3, "armor": 0.65, "hit": 1.0, "eva": 1.0 },
  "dropTable": [
    { "itemId": "item.beast-hide", "dropChance": 1.0, "minQuantity": 1, "maxQuantity": 1 }
  ],
  "qiReward": 10,
  "experienceReward": 10,
  "rootExpReward": 10
}
```
> 属性面板由 `budgetCost` 与 `weights` 统一推导；`rank`（`minion`/`elite`/`boss`）决定怪我同构倍率（见第八篇）。`skills` 为敌方技能槽（可选）。

#### 典型预算消耗梯度基准：

下表为算法教学示例，名称和预算范围不构成现行配表。实际怪物预算、属性权重、名称及遭遇频率以 `config/game-data/monsters/` 和 `config/game-data/encounters/` 为准；不因示例差异新增同名怪物或重写预算。属性由预算和权重统一推导，目录展示必须复用战斗的解析结果。
| 怪物层次 (`Rank`) | 消耗预算 (`budgetCost`) | 典型代表 | 战力定位 |
| :--- | :--- | :--- | :--- |
| **普通杂鱼小怪 (Minion - Low)** | 10 ~ 15 点 | 魔化野兔、溪边幼龟 | 最基础练手怪，单体弱，常成群出现 |
| **强力小怪 (Minion - High)** | 20 ~ 30 点 | 木灵、火灵、通臂魔猿 | 具备初级法术或特定抗性 |
| **精英怪 (Elite)** | 40 ~ 60 点 | 刀煞尸煞、黑煞猿首 | 拥有 5 倍生命与强力技能，5 波遭遇一次 |
| **关底领主 (Boss)** | 100 ~ 200 点 | 伥鬼妖虎、坠星异兽 | 拥有 20 倍生命，关底大怪，20 波遭遇一次 |

## 8.3 地图 (Maps) 与遭遇 (Encounters) 解耦架构

### 8.3.1 架构解耦设计理念
系统将**世界地理拓扑（Maps）**与**战斗遭遇生态（Encounters）**完全解耦，分别存储于 `config/game-data/maps/` 与 `config/game-data/encounters/`：
1. **地图配置 (`maps/`) 聚焦地理拓扑与设施**：定义大世界节点坐标（`x`, `y`）、背景设定、开放的生活/采集行动（`availableActionIds`）、场景常驻建筑（`buildings`）与 NPC，并通过 `encounterIds` 弱引用战斗遭遇；
2. **遭遇配置 (`encounters/`) 聚焦战力预算与怪群生成**：定义遭遇的质量预算区间 `[minBudget, maxBudget]`、怪群随机抽取权重表（`randomSpawns`）、精英怪池（`eliteEnemyIds`）与领主怪池（`bossEnemyIds`）；
3. **解耦优势**：同一套战斗遭遇与怪物生态可被多个地理节点复用，地图节点亦可独立挂载多种遭遇副本，数值调整与地图绘制互不干扰。

### 8.3.2 地图生灵生态原则（特色化分布）

本节地名和后文 JSON 为生态设计示例，未全部进入当前目录。当前地图索引见 [`../world/maps.md`](../../world/maps.md)，包含青云仙山与星陨异境。预算属于遭遇，不是地图节点属性；示例中的节点预算不得作为 maps 配表新增字段的要求。
- **按地理风貌分布 1~3 种怪物**：同阶（如 T1）怪物不需要全部挤在同一张地图内。每个地图节点根据其地理环境、五行属性与剧情风貌分配 1~3 种契合的怪物即可（灵活可配，不强制多怪）。
  - **青岚药谷 (`node.herb-vale`)**：草木繁茂之地，主要栖息【木灵】（或木灵 + 偶尔出没的野兔）；
  - **落霞西岭 (`node.sunset-ridge`)**：开阔山岭，主要出没【魔化野兔】与【重甲蛮熊】；
  - **暮影关 (`node.twilight-pass`)**：阴煞险关，主要出没【火灵】、【通臂魔猿】与关底【伥鬼妖虎】；
  - **澄心灵泉 (`node.spirit-spring`)**：静修灵泉，可仅出没水系生灵或作为清修少怪之地。

### 关键配置字段解析：
> 注：节点自身只声明 `encounterIds` 引用；以下预算与怪池字段均位于 `config/game-data/encounters/*.json` 遭遇配表中。

- **`minBudget` ~ `maxBudget`（危险度 / 总预算区间）**：**地图没有单独的危险度评级，危险度本身即为 `[minBudget, maxBudget]` 预算区间**。单次遇怪时系统在 `[minBudget, maxBudget]` 之间随机生成本场怪群的战力总预算，预算区间的高低直接体现了该地图遭遇战的危险程度与怪物强度规模。
- **`battlesPerElite`（精英周期）**：每进行 N 次战斗必定触发一次精英遇怪（缺省回退 5）。
- **`battlesPerBoss`（Boss 周期）**：每进行 N 次战斗必定触发一次关底领主 Boss 遇怪（缺省回退 20）。
- **`randomSpawns`（本地普通怪池）**：当前地图栖息的普通怪物及权重/强度（`enemyId`/`weight`/`strength`）。
- **`eliteEnemyIds`（本地精英怪池）**：触发精英波次时抽取的精英阵容。
- **`bossEnemyIds`（本地 Boss 怪池）**：触发领主波次时抽取的 Boss 阵容。
- **`maxTotalStrength`（总强度上限）**：本波怪物强度总和上限（缺省不封顶）。

## 8.4 遇怪与怪群生成算法规范

服务端在玩家完成每次寻怪倒计时（`Search` 阶段）后，调用确定性怪群生成算法：

当前 `EncounterWaveSelector` 按种子从预算区间选取预算，普通怪只从剩余预算可容纳的候选中按权重抽取，每波最多 3 只（`MaxWaveSize`）；第 5 的倍数波优先精英，Boss 使用 `BattlesPerBoss`（缺省 20）且优先于精英。特殊怪先入波，再以最大预算扣除其成本填充护从；指定 Boss 自身成本可以高于普通波预算。成本读取怪物 `BudgetCost`，不以展示字段重算属性。候选为空（普通怪全部超预算且未抽到特殊怪）时保底塞入 1 只消耗预算最低的普通小怪。下面流程图为现行口径示意，原三次失败重抽设计已由可容纳候选筛选取代。

该怪群列表以多敌同场进入战斗：单体技能与非全体群攻按威胁（仇恨）权重抽取目标（详见 [第七篇 §7.8.2](./07-战斗数值与内视规约.md)），全体技能（`allEnemies`）命中全波存活目标；整波怪物全部击杀后才推进波次计数。

```mermaid
flowchart TD
    Start([寻怪倒计时结束]) --> CheckCount[读取当前地点累计历练完成波次 N]
    
    CheckCount --> IsBoss{(N + 1) % battlesPerBoss == 0 ?}
    IsBoss -- 是 (如第20/40场) --> SpawnBoss[从 bossEnemyIds 抽取 1 只 Boss<br/>总预算分配 maxBudget]
    
    IsBoss -- 否 --> IsElite{(N + 1) % battlesPerElite == 0 ?}
    IsElite -- 是 (如第5/10/15场) --> SpawnElite[从 eliteEnemyIds 抽取 1 只精英怪<br/>扣除该精英 budgetCost]
    IsElite -- 否 --> NormalRoll[在 [minBudget, maxBudget] 随机生成总预算 remainBudget]
    
    SpawnElite --> DeductElite[剩余预算 remainBudget 继续用于抽取小怪护从]
    DeductElite --> LoopExtract
    NormalRoll --> LoopExtract
    
    subgraph LoopExtract [质量预算扣减循环]
        Filter[筛选 budgetCost <= remainBudget<br/>的可容纳候选池] --> HasCandidate{可容纳候选非空<br/>且 remainBudget > 0<br/>且数量 < 上限(3只)?}
        HasCandidate -- 是 --> RollMonster[从可容纳候选按 weight 轮盘抽取]
        RollMonster --> AddMonster[将怪物加入 spawnedList<br/>remainBudget -= candidate.budgetCost]
        AddMonster --> Filter
    end
    
    HasCandidate -- 否 (无可容纳候选或达上限) --> CheckEmpty{spawnedList 是否为空?}
    CheckEmpty -- 是 (保底) --> SafetyFallback[保底塞入 1 只消耗预算最低的普通小怪]
    CheckEmpty -- 否 --> Finalize[生成怪群列表]
    SafetyFallback --> Finalize
    SpawnBoss --> Finalize
    
    Finalize --> BattleSnapshot[构建入场战斗状态，进入 Combat 战斗]
```

### 算法执行示例：

#### 示例 A：单怪特色地图（如青岚药谷，仅栖息木灵）
- **配置**：`minBudget: 20`, `maxBudget: 60`, `randomSpawns: [{ enemyId: "enemy.wood-spirit", weight: 1, strength: 25 }]`（木灵 `budgetCost: 25`）
- **常规波次**：
  - 随机本场总预算 `remainBudget = 55`；
  - 第 1 次抽取：抽中【木灵】（`cost 25 <= 55`），加入阵容，`remainBudget = 30`；
  - 第 2 次抽取：抽中【木灵】（`cost 25 <= 30`），加入阵容，`remainBudget = 5`；
  - 再次筛选：【木灵】`cost 25 > 5`，可容纳候选为空，循环终止；
  - **本场阵容**：`[木灵, 木灵]`（根据预算生成 2 只木灵同场）。

#### 示例 B：多怪复合地图（如落霞西岭，栖息野兔与蛮熊）
- **配置**：`minBudget: 30`, `maxBudget: 80`, `randomSpawns: [{ enemyId: "enemy.demonized-rabbit", weight: 5, strength: 10 }, { enemyId: "enemy.armored-bear", weight: 2, strength: 45 }]`
  - 魔化野兔（`cost: 15`）、重甲蛮熊（`cost: 35`）
- **常规波次**：
  - 随机本场总预算 `remainBudget = 65`；
  - 第 1 次抽取：抽中【重甲蛮熊】（`cost 35 <= 65`），加入阵容，`remainBudget = 30`；
  - 第 2 次抽取：抽中【魔化野兔】（`cost 15 <= 30`），加入阵容，`remainBudget = 15`；
  - 第 3 次抽取：抽中【魔化野兔】（`cost 15 <= 15`），加入阵容，`remainBudget = 0`；
  - 预算耗尽，循环终止；
  - **本场阵容**：`[重甲蛮熊, 魔化野兔, 魔化野兔]`（共 3 只怪）。

## 8.5 前端界面与交互设计

前端主要涉及「地图/附近（`map`）」面板与「历练（`exploration`）」面板的展示与交互联动。

### 8.5.1 地图 / 附近面板（World Map & Nearby Display）
「历练」页（`combat` Tab）下含四个子页签：**地图 / 怪物 / 人物 / 建筑**（`App.tsx` 的 `MAP_TABS`）。当玩家停留在某个地图节点时，各页签直观展示该地点的全景信息：

```
地图页签：世界节点拓扑、玩家位置、赶路进度与目标地点赶路入口
怪物页签：栖息生灵（危险度预算区间 [minBudget, maxBudget]、精英/Boss 周期提示、怪物卡与数值详情）
人物页签：常驻 NPC 与当前分片可见玩家
建筑页签：当前节点公共建筑卡（等级/效果/双进度）、加号占位与可建候选弹窗
```

- **怪物卡**：展示预算消耗、气血/攻防/抗性与掉落，点击弹出统一 Modal 查看数值详情（复用公共 Modal，不再单列 `MonsterInfoModal` 组件）。
- **建筑卡**：展示名称、等级与效果；建造中显示材料%/时间% 双进度缩略；点击弹详情 Modal（逐项材料清单、提交材料、升级）。节点未配置 `buildableTemplate`/`buildableList` 时不显示加号占位。
- 节点的「本地可选行动」在历练页行动区呈现，与怪物/人物/建筑生态信息分栏。

### 8.5.2 历练交互流程闭环
1. **点击历练行动**：点击讨伐/历练行动卡，弹出行动配置弹窗（`ActionModal`）；
2. **行动名按驻留地点本地化**：战斗行动显示名与描述中内嵌的地图名替换为当前节点名（人在「漱玉溪」时显示「讨伐 漱玉溪」而非「讨伐 青云仙山」），行动卡、弹窗、队列与战斗区显示同口径；行进在道路上时保留地图级原名；
3. **节点生态妖兽预览**：弹窗内展示当前节点 `encounterIds` 解析出的栖息妖兽**图标网格**（与服务端实战遭遇同根同源），悬停图标出简要信息卡、单击弹详细信息卡，不再平铺全部怪物数值；节点未配置生态时回退行动钉死遭遇的怪群；
4. **选择挂机轮次**：可设置挑战 1 次、10 次、100 次或点击 `∞` 无限历练；
5. **确认进入战斗**：点击【开始历练】，系统立即向队列首位插入该历练任务，并**平滑自动跳转至「详情」战斗界面（`CombatArena`）**，实时推进寻怪与波次战斗。

## 8.6 当前实现落点（非待办规划）

本节记录该系统的实际实现落点，供代码对照；字段归属以本节与配表为准。

1. **配置层**：地图节点定义由 `config/game-data/maps/*.json` 的 `WorldNode` 承载（节点坐标、`availableActionIds`、`npcs`、`buildings`、`buildableTemplate`/`buildableList`、`encounterIds`）；遭遇预算与怪群池定义在 `config/game-data/encounters/*.json`（`minBudget`/`maxBudget`/`randomSpawns`/`eliteEnemyIds`/`bossEnemyIds`/`maxTotalStrength`/`battlesPerElite`/`battlesPerBoss`）；怪物定义在 `config/game-data/monsters/*.json`（含 `budgetCost`/`rank`/`strength`）。解析产物为 `GameDataCatalog` 持有的只读定义集合。
2. **领域层**：确定性波次抽取由 `src/Domain/Combat/EncounterWaveSelector.cs` 的 `Select(encounter, monsters, seed, waveNumber)` 实现质量预算扣减；世界图连通性由 `GameDataCatalog.BuildWorldGraph` 与 `WorldGraph` 维护。
3. **协议层与服务端映射**：地点节点 DTO 由 `src/Server/Clean/ProtocolSnapshotMapper.cs` 的 `ToWorldSection` 投影，输出 `minBudget`/`maxBudget`/`encounterIds`/`npcs`/`buildings`/`buildableBuildingIds`/`nodeBuildings` 等字段。
4. **前端**：`frontend/src/components/WorldMapPanel.tsx`（地图）与 `frontend/src/components/NearbyPanel.tsx`（怪物/人物/建筑页签）渲染，快照解码在 `frontend/src/network/snapshot.ts`；讨伐行动弹窗的节点生态图标面板为 `frontend/src/components/CombatEcologyPanel.tsx`（悬停简卡 + 单击详卡双层浮层），行动名地点本地化为 `frontend/src/game/ids.ts` 的 `localizeActionDisplayText`。
5. **门禁与测试**：确定性波次抽取由 `tests/Domain.Tests` 覆盖；建筑配表引用由 `DataTool validate --strict` 校验；整体门禁 `scripts/verify.sh`。
