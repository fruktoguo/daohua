## 32.1 定位、设计哲学与命名边界

### 32.1.1 核心定位
1. **贴合进度的动态委托与刷新博弈**：吸收《银河奶牛放置》任务板的进度锚定与重随思想，围绕玩家当前境界与技艺进度**上下浮动**抽取**采集、制造、击杀**三类委托——既有顺路可做的同阶单，也会刷出需切换采集地、调配产线或小幅越级的委托，不能每次无脑顺带白嫖，驱动玩家在「专程执行」与「刷新重随」之间做轻度决策。
2. **接取即无限循环（契合长线离线挂机）**：摒弃「做完一次即销毁」的碎片化高频点按模式。玩家从任务列表中接取 1 条任务后，该任务进入**无限循环结算态**：每跑满 1 轮自动发放奖励并结转余数直接进入下一轮，只要不主动放弃或切换接取其他任务便永久生效，完美兼容 48 小时离线挂机与 `RemainingRepeats == -1` 无限行动队列。
3. **功德主产出渠道与无限养成闭环**：任务核心产出为 **20% 流通功德（`item.gongde`）+ 80% 绑定功德（`item.gongde-bound`）**。通过任务获取的功德数量直接驱动**「功德等级」**无限升级（`Lv.1 → ∞`）；功德等级越高，每周可获取的功德上限越高，触达周上限时展示**「功德圆满」**，形成简洁透明、永不封顶的长线正反馈养成线。
4. **去地名概称剧情叙事**：每条任务附带贴合太初世俗与散修生态的简短委托背景（如妖兽骚扰周边城镇请协助清除、村落疫寒急需药草等），**严禁绑定任何具体地图地名或具名 NPC**，统一采用「城镇」「村落」「聚落」「商队」等概称，实现全等级段与未来新地图的零穿帮通用匹配。

### 32.1.2 命名红线与机器人隔离
1. **禁用历史废弃前缀**：遵循工程规约，严禁在服务端或协议中复用历史废弃的 `Task*` 命名前缀；代码与协议标识符统一使用 `Quest`（任务）与 `Merit`（功德等级体系），界面玩家侧展示名统一使用**「任务」「功德等级」「功德圆满」**。
2. **市场机器人隔离**：`identity.accounts.is_bot = true` 的市场机器人在任务命令入口（接取/刷新）一律拦截，且模拟推进不触发任务轮次结算，防止自动化机器人批量产出 20% 流通功德流入坊市。

## 32.2 任务面板结构、三大类型与浮动抽取规则

### 32.2.1 候选列表与单槽激活模型
1. **槽位编制**：每名角色持有 **4 个候选任务槽（`Candidates[0..3]`）** 与 **1 个当前执行槽（`Active`）**。
2. **首次初始化**：新角色首次进入或存量角色升级后首次加载时，若候选列表为空，按角色当前进度与确定性种子自动生成满编 4 条候选任务。
3. **接取与替换语义**：
   - 点击任一未接取候选槽的「接取」，该候选转入 `Active` 执行槽（当前进度 `Progress = 0`、已完成轮数 `CompletedRounds = 0`）；
   - 若执行槽原本已有进行中的任务，原任务直接被新任务覆盖替换（原任务未满 1 轮的零头进度作废，历史已入账奖励保留）；
   - **防零成本洗槽约束**：候选槽被接取后，原槽位标记为 `Accepted = true`（界面显示「已接取 · 刷新后补充」），**不会在接取瞬间自动免费刷出新任务**，直至玩家执行免费或付费刷新时统一重随补满全部 4 槽。
4. **放弃语义**：玩家可随时点击执行槽「放弃」清空 `Active`，回归无任务自由挂机态。

### 32.2.2 三大任务类型与候选池自动准入过滤
服务端在 `GameDataCatalog` 构建期自动从现有配表中筛选合法可循环标的池（零手工硬编码 ID 表，新增常规物品/怪物自动纳入）：

| 任务类别 | `QuestKind` | 候选池准入条件（加载期静态过滤） | 标的等级 $L_{\text{item}}$ | 进度计次口径（仅限接取后亲自执行） |
| :--- | :--- | :--- | :--- | :--- |
| **采集** | `gather` | `type == "exploration"` 且 `technique` 为 `gathering`（采集）或 `mining`（挖掘），且 `yields` 主产物为 `item.*` 普通灵材/矿石（**排除**直接产货币的 `explore.mine-spirit-stone`） | 行动显式 `level`（缺省取产物 `level`，再缺省 `1`） | 采集/挖掘行动每完成一轮实际产出的目标 `itemId` 数量（坊市购入、邮件、分解或背包旧存量不计） |
| **制造** | `craft` | `technique` 为 `alchemy`/`forging`/`talisman`/`formation`，含非空 `inputs` 与单一主产物 `yields`；**排除**：① `inputs` 含任何 `equipment.*` 上级装备的升阶配方；② `inputs` 含 `tier >= 2` 低爆率稀有异材或追忆副本独占特殊材料的配方；③ 宗门专属行动 `zongmen.*` | `ResolveRequiredRealmLevel`（行动显式 `level` → 产物装备/物品 `level` → `1`） | 制造行动每完成一轮实际炼制产出的目标成品件数（购买、掉落或库存旧物不计） |
| **击杀** | `kill` | 大世界讨伐行动（`combat.json`）关联遭遇池 `randomSpawns` 中的常驻普通/精英妖兽（**排除**仅靠长波次保底刷新的关底领主 Boss 及副本独占怪，避免挂机看脸卡波次） | 怪物配表 `level` | 野外讨伐或非助战追忆副本波次中击败目标 `enemyId` 的只数（组队讨伐为本人在场有效参战波次内的全队击杀数；副本 `assistMode` 助战态不计） |

### 32.2.3 贴合当前进度与上下浮动算法
1. **基准锚点等级 $L_{\text{anchor}}$**：
   - **击杀类**：直接锚定角色当前境界等级 $L_{\text{anchor}} = \text{RealmLevel}$；
   - **采集 / 制造类**：兼顾角色主境界进度与对应生活技艺专精，取：
     $$L_{\text{anchor}}(t) = \max\big(\text{TechniqueLevel}(t),\; \text{RealmLevel} - 4\big)$$
     （既让专精生活玩家刷到匹配高技艺的委托，又防止从不练某项技艺的高境界角色永远只刷出 `Lv.1` 新手单，落实「不用每次都能顺便做，不顺手可刷新」的设计意图。）
2. **上下浮动抽取窗口**：
   - 目标等级抽取区间为闭区间 $\big[\max(1, L_{\text{anchor}} - 6),\; L_{\text{anchor}} + 4\big]$；
   - **离散阶梯非空回退**：若某类别在上述窗口内无匹配配表标的，回退选取该类别中满足 $L_{\text{item}} \le L_{\text{anchor}} + 4$ 的最高等级标的群；仍为空时取该类别最低等级标的群，确保 `Lv.1 ~ Lv.127` 任意进度下生成恒定成功。
3. **4 槽分布与去重**：
   - 每次整板刷新生成 4 个候选槽时，前 3 槽固定各抽 **采集、制造、击杀** 各 1 条（顺序随机打乱），第 4 槽在三大类中等权随机抽取 1 条；
   - 同一次刷新的 4 个槽位优先保证 `targetId` 互不重复（仅当同档可用唯一标的不足时允许回退重复）。

## 32.3 单轮工作量折算与双轨刷新机制

### 32.3.1 单轮需求数量均衡公式
以**无加速基础行动耗时 $T_{\text{round}} = 600\text{s}$（10 分钟）**为单轮标准工作量基准，并抽取档位浮动乘子 $\eta \in \{0.85,\; 1.00,\; 1.15\}$ 使面板数量富有自然层次：

1. **采集 / 制造单轮目标件数**：
   设该行动配表基础单轮时长为 $d_{\text{action}}$ 秒、单轮固定产出件数为 $y \ge 1$，则：
   $$N_{\text{target}} = \max\left(5,\; \mathrm{round}\left(\frac{600 \times \eta}{d_{\text{action}}} \times y\right)\right)$$
   - 示例：`8s` 采摘凝气草单轮为 `64 / 75 / 86` 株；`12s` 炼制引气丹单轮为 `43 / 50 / 58` 颗；`20s` 绘制雷击符单轮为 `26 / 30 / 35` 张。玩家自身的技艺等级、技艺工具、建筑与消耗品加速将真实缩短实际完成耗时。
2. **击杀单轮目标只数**：
   设目标妖兽在其主出没遭遇池 `randomSpawns` 中的出现权重占比为 $p \in (0, 1]$（单一怪池 $p = 1$，三怪等权混编池 $p = 1/3$），按平均每 `15s` 基础战斗节奏折算并施加夹逼保护：
   $$N_{\text{target}} = \mathrm{clamp}\Big(\mathrm{round}\big(40 \times \eta \times \max(0.40,\; p)\big),\; 12,\; 50\Big)$$
   - 示例：单一怪遭遇池约 `34 ~ 46` 只/轮；多怪混编池自动折减至 `14 ~ 23` 只/轮，保证单轮期望挂机时长同样稳定在约 10~15 分钟。
3. **越级挑战功德系数 $k_{\text{diff}}$**：
   当抽出的标的等级高于玩家当前境界等级（$L_{\text{item}} > \text{RealmLevel}$）时，每越 1 级给予 `+5%` 单轮功德奖励加成（最高 `+20%`）：
   $$k_{\text{diff}} = 1 + 0.05 \times \mathrm{clamp}(L_{\text{item}} - \text{RealmLevel},\; 0,\; 4)$$
   （在候选生成瞬间按玩家当时境界定格存入候选卡，平级或低级委托恒为 $k_{\text{diff}} = 1.0$。）

### 32.3.2 双轨刷新规则（免费蓄能 + 灵石递增重随）
刷新操作一次性重随全部 **4 个候选槽**（不影响当前 `Active` 正在执行的任务）：

1. **免费冷却刷新（确定性懒恢复）**：
   - **最大蓄能上限**：`MaxFreeRefreshes = 3` 次（创角初始满额 `3` 次）；
   - **恢复周期**：恒定每 `4 小时`（`14,400 秒`）恢复 `1` 次；
   - **整点推进守恒**：存档仅维护锚点剩余次数 $R_0 \in [0, 3]$ 与锚点时间戳 $t_0$。在时刻 $t \ge t_0$：
     $$\Delta r = \left\lfloor \frac{t - t_0}{14400\text{s}} \right\rfloor, \qquad R(t) = \min(3,\; R_0 + \Delta r)$$
     消耗 1 次免费刷新时：若消耗前 $R(t) = 3$（原已满额），新锚点置为 $R'_0 = 2,\; t'_0 = t$；若消耗前 $1 \le R(t) < 3$，则保留余数秒推进 $R'_0 = R(t) - 1,\; t'_0 = t_0 + \Delta r \times 14400\text{s}$。
2. **灵石付费重随（跨日重置翻倍封顶）**：
   - 当 $R(t) = 0$ 时，玩家可消耗灵石（`currency.spirit-stone`）立即刷新；
   - 按 **UTC+8 自然日**（$\text{DayIndex} = \lfloor(\text{unixSeconds} + 28800)/86400\rfloor$）统计当日已付费刷新次数 $c_{\text{paid}} \ge 0$，跨零点自动归零；
   - 当日第 $c_{\text{paid}} + 1$ 次付费刷新的灵石消耗为：
     $$\text{RefreshCost}(c_{\text{paid}}) = \min\big(500 \times 2^{c_{\text{paid}}},\; 16{,}000\big)$$
     （依次为 `500 → 1,000 → 2,000 → 4,000 → 8,000 → 16,000` 灵石封顶。）
   - 命令防误扣守卫：`quest.refresh` 携带布尔字段 `allowPaid`；当服务端裁定 $R(t) = 0$ 且 `allowPaid == false` 时直接拒绝并返回 `FREE_REFRESH_EXHAUSTED`，绝不静默扣减灵石。

## 32.4 简易功德无限养成体系与「功德圆满」

### 32.4.1 功德等级（`MeritLevel`）无限升级模型
1. **单一养成真源**：
   - 角色维护累计任务功德总值 `LifetimeQuestMerit`（非负整数，初始 `0`），**每通过任务轮次结算实际入账 `1` 点功德（流通 + 绑定合计），`LifetimeQuestMerit` 同步累加 `1`**；
   - 签到、新手引导、邀请、储物袋、邮件或坊市交易获取的功德不计入 `LifetimeQuestMerit`；消费功德亦不扣减 `LifetimeQuestMerit`。
2. **无限升级曲线（`Lv.1 → ∞` 永不封顶）**：
   从功德等级 $L$（$L \ge 1$）升入 $L + 1$ 级所需的任务功德增量为：
   $$\text{MeritToNext}(L) = 300 + 100 \times (L - 1) + 15 \times (L - 1)^2$$
   前 $L - 1$ 级累计需求闭式和为：
   $$\text{CumulativeMeritFor}(L) = \sum_{k=1}^{L-1} \text{MeritToNext}(k) = 300(L-1) + 50(L-1)(L-2) + \frac{5(L-1)(L-2)(2L-3)}{2}$$
   任意时刻的当前功德等级 `MeritLevel`、本级已积进度 `CurrentLevelMerit` 与升级需求 `MeritToNext` 均由 `LifetimeQuestMerit` 确定性唯一导出。

### 32.4.2 每周功德上限、单轮收益与渐近耗时收敛
1. **UTC+8 自然周重置口径**：
   对齐每日签到周统计与周清节奏，以北京时间 **周一 `00:00:00+08:00`** 为自然周分界：
   $$\text{WeekIndex}(t) = \left\lfloor \frac{\text{DayIndex}(t) + 3}{7} \right\rfloor$$
   当推进时钟进入新 `WeekIndex` 时，`WeeklyMeritEarned` 自动归零重计。
2. **每周功德获取上限公式**：
   $$\text{WeeklyMeritCap}(L) = 500 + 100 \times (L - 1)$$
   - `Lv.1` 初始周上限为 **`500` 功德/周**，每提升 `1` 级功德等级，每周功德上限永久 **`+100`**，无上限封顶；
   - **升级实时扩上限**：某轮任务结算获得的功德令 `MeritLevel` 提升至 $L'$ 时，本周生效上限立即扩张至 $\text{WeeklyMeritCap}(L')$，当周即可继续获取新增的 `100` 点额度直至达到新等级上限。
3. **单轮基础功德产出公式**：
   $$M_{\text{raw}}(L, k_{\text{diff}}) = \mathrm{round}\Big(\big(15 + 2 \times (L - 1)\big) \times k_{\text{diff}}\Big)$$
   - **防肝度膨胀数学保障**：在 $k_{\text{diff}} = 1.0$ 基准下，每周打满上限所需的轮次数为 $\dfrac{500 + 100(L-1)}{15 + 2(L-1)}$，在 `Lv.1` 时约为 `33.3` 轮（约 5.5 小时基础时长），随等级趋于无穷严格单调渐近收敛至 **`50` 轮/周**（约 8.3 小时基础时长，计入技艺/工具加速后约 **4~6 小时/周**），确保无限养成永远维持轻松舒适的周常节奏。

### 32.4.3 20% 流通 + 80% 绑定拆分与「功德圆满」结算算法
每当 `Active` 任务累计进度跨过 1 轮（`Progress >= TargetCount`，`Progress -= TargetCount`，`CompletedRounds += 1`），按以下顺序精确裁决本轮奖励：

1. **未圆满态（`WeeklyMeritEarned < WeeklyMeritCap(MeritLevel)`）**：
   - 计算当前等级单轮应发总额 $M_{\text{raw}} = M_{\text{raw}}(\text{MeritLevel}, k_{\text{diff}})$；
   - **跨级平滑截断**：由于本轮获得的功德可能在入账途中触发 `MeritLevel` 升级并同步抬高 `WeeklyMeritCap`，结算函数按逐点/逐段推进校验：最终实发功德整数 $M \in [1, M_{\text{raw}}]$ 满足入账后 `WeeklyMeritEarned' <= WeeklyMeritCap(MeritLevel')`（仅当入账至新等级上限仍不足 $M_{\text{raw}}$ 时截断为触顶差额）；
   - **20% 流通 / 80% 绑定整数守恒入账**：
     $$M_{\text{bound}} = \mathrm{round}(M \times 0.80), \qquad M_{\text{tradable}} = M - M_{\text{bound}}$$
     向玩家钱包写入 `item.gongde-bound` $+M_{\text{bound}}$ 与 `item.gongde` $+M_{\text{tradable}}$（值为 `0` 的分项不生成空资产增量），同步累加 `WeeklyMeritEarned += M` 与 `LifetimeQuestMerit += M`。
2. **「功德圆满」态（入账前已满足 `WeeklyMeritEarned >= WeeklyMeritCap(MeritLevel)`）**：
   - 界面状态徽记展示为**「功德圆满」**；
   - 已接取任务**继续无限循环计次**，每完成 1 轮**不再发放任何流通/绑定功德，亦不再增加 `LifetimeQuestMerit`**；
   - 改为发放与该任务目标等级 $L_{\text{item}}$ 匹配的微薄基础回馈（控制在 10 分钟常规挂机产出的 `~8%` 添头水位，保持循环跳字反馈且零套利空间）：
     - **基础修为**：$\Delta \text{Exp} = \mathrm{round}\big(\text{BaseExperienceForLevel}(L_{\text{item}}) \times 5\big)$，经标准 `CreditExperience(amp, cap, combatExp: 0)` 入账（修为满层时按既有规则沉淀为底蕴）；
     - **基础灵石**：$\Delta \text{Stone} = \max\big(10,\; \mathrm{round}(\text{ExpectedAttributes.At}(L_{\text{item}}).\text{Hp} \times 0.20)\big)$，直接入账 `currency.spirit-stone`。

## 32.5 概称剧情委托文案规约（严禁出现具体地名）

1. **零具体地名与零具名 NPC**：任何任务标题、委托引子与完成日志中，**严禁出现具体地图区域名、节点地名或具名人物**（如禁止出现「云溪村」「青云山」「离山驿」「星陨异境」「雾梦泽」「林伯」等），确保同一模板在任意境界、任意驻留区域下均完全自洽。

## 32.6 领域架构、ECS 确定性与持久化规约

### 32.6.1 玩家分段状态结构
任务状态属于角色长线模拟与成长事实，内聚于 **`PlayerProgressionState`（`progression` 分段）** 下的 `Quest` 属性（`PlayerQuestState`）：

- `LifetimeQuestMerit`（`double`）：历史任务累计获得总功德（驱动等级导出的唯一真源）；
- `WeekIndex`（`long`）+ `WeeklyMeritEarned`（`double`）：当前自然周序号与本周已获任务功德；
- `FreeRefreshes`（`int`）+ `RefreshUpdatedAtUnixSeconds`（`double`）：免费刷新锚点次数与锚点时间戳；
- `PaidRefreshDayIndex`（`long`）+ `PaidRefreshCountToday`（`int`）：当日付费刷新日序号与计数；
- `GenerationNonce`（`long`）：单调递增生成游标，结合 `PlayerId` 与 `ExplorationSeed` 构造纯确定性无状态哈希抽样（不污染战斗与强化随机流）；
- `Active`（`ActiveQuest?`）：`QuestId`、`Kind`、`TargetId`、`TargetLevel`、`TargetCount`、`Progress`、`CompletedRounds`、`DifficultyMultiplier`、`FlavorKey`；
- `Candidates`（`IReadOnlyList<QuestCandidate>`，定长 `4`）：`SlotIndex`、`Kind`、`TargetId`、`TargetLevel`、`TargetCount`、`DifficultyMultiplier`、`FlavorKey`、`Accepted`。

### 32.6.2 离散推进、批量快进与跨周自然边界
1. **跨周零点自然窗口切分**：
   - 在 `ActionExecutionRules.PrepareResourceBoundaryCore` 中，当 `player.Progression.Quest.Active is not null` 时，计算下一北京时间周一 `00:00:00+08:00` 时间戳 `nextWeekResetUnix` 并纳入 `naturalStep` 最小值竞争；
   - 效果：每周最多切分 1 次自然窗口，零性能损耗；同时保证 `CanBulkAdvance` 在合并数百轮采集/制造计时窗口横跨周一零点时，精准在零点切开——零点前完成的轮次计入上周额度，零点后立即重置 `WeeklyMeritEarned = 0` 并恢复功德产出，在线实时、重连快进与 `ComputeNode` 离线冷算结果 **100% 逐位一致**。
2. **三大结算钩子接入点**：
   - **采集与制造**：在计时行动单轮/批量产出结算点（`TimedAction` 实际发放 `yields` 物品后），若 `Active.Kind` 为 `Gather`/`Craft` 且行动类型与产出 `itemId == Active.TargetId` 匹配，直接将本次实际产出总量 `producedCount` 注入 `QuestSettlementRules.AdvanceProgress`，支持一次批量推进连结多轮；
   - **击杀**：在野外讨伐波次结算与非助战追忆副本波次结算（含组队参与会话 `ActionParticipationSettlement` 回流结算）中，统计本波被击败敌方单位命中 `Active.TargetId` 的数量注入同一结算函数；
   - **资产与账本同步**：任务轮次结算产出的 `item.gongde-bound`、`item.gongde`、`currency.spirit-stone` 生成标准 `AssetDelta` 并入当次模拟 `request.AddAsset`（修为经 `CreditExperience` 并入 `PlayerStatsDelta`），标记 `PlayerSectionKind.Progression` 脏段。
3. **两层持久化与迁移**：
   - 任务单轮结算与灵石刷新均遵循 `PersistLedger = false` 轻量口径，随 10 分钟在线安全检查点或关键边界同事务原子落盘，不写入 `economy.transactions` 不可变流水表；
   - 实装时同步推进 `SectionCodec.CurrentSchemaVersion` 与 `PostgresSchema.Version`（全部字段支持缺省零值解码，`MinReadableSchemaVersion` 保持不抬），登记 `docs/backend/db-version-changes.md` 并增量编写 `migrations/NNNN_vX_to_vY.sql`。

## 32.7 协议与前端交互规约

### 32.7.1 命令契约与快照映射
1. **快照下发**：`ProtocolSnapshotMapper` 在玩家状态快照/增量中映射 `quest` 视图 DTO（含导出计算的 `meritLevel`、`currentLevelMerit`、`meritToNext`、`weeklyMeritEarned`、`weeklyMeritCap`、`isWeeklyCapped`、免费刷新实时可用次数与下次恢复时间戳、下次付费刷新灵石费用、当前 `active` 与 4 条 `candidates`）。
2. **业务命令**（复用 `ExecuteAsync` 标准幂等命令信封）：
   - `quest.accept`：`{ "slotIndex": 0..3 }` —— 校验槽位存在且 `Accepted == false`，覆写 `Active` 并将该槽标为 `Accepted = true`；
   - `quest.abandon`：`{}` —— 清空 `Active`；
   - `quest.refresh`：`{ "allowPaid": true | false }` —— 优先消耗实时免费次数重置 4 槽；免费次数为 `0` 时校验 `allowPaid` 与灵石余额，同事务扣减灵石、递增当日付费次数并生成新 4 槽。

### 32.7.2 导航归属与高空间利用率 UI
1. **主导航独立入口**：
   - **桌面端**：左侧主导航栏「历练」分组新增独立**「任务」**（`TabId = 'quest'`）页签，紧随「历练」与「地图」；
   - **竖屏移动端**：并入底部一级分组 `explore`（历练组）的 `tabs` 子行，形成 **`历练 / 任务 / 地图`** 三子页一键切换，方便接取任务后就近切换挂机。
2. **紧凑响应式版式（遵循高空间利用率与强标识契约）**：
   - **顶栏功德状态条（1~2 行紧凑合流）**：左侧展示「功德等级 `Lv.X` 徽章 + 本级升级进度条（`current / next`）」；中部展示「本周功德 `earned / cap`」（达标时高亮道金印记**「功德圆满」**并悬浮提示圆满后每轮仍享微量修为与灵石）；右侧内联展示「免费刷新 `R/3`（未满附倒计时）+ 刷新按钮（付费态直接内联显示小灵石图标 + `UnitNumber` 费用）」。
   - **中部当前执行任务卡**：未接取时展示一行紧凑空态提示；已接取时单卡横向呈现——左侧目标视觉瓦片（采集/制造强制显式传入 `ItemTile itemId={active.targetId}`，击杀展示怪物头像徽标），中部「任务标题 + 概称剧情描述 + 轮次进度条 `progress / targetCount`（附已完成 `N` 轮标签）」，右侧「单轮奖励微型胶囊（`ItemIcon` 绑定功德 + 流通功德，圆满态切换显示修为 + 灵石）+『前往』快捷定位按钮 +『放弃』按钮」。
   - **下部候选任务网格**：桌面端 `2 × 2` 紧凑双列网格、竖屏单列紧凑流，每张卡以 3 行内呈现「类别/等级标签 + 目标图标与数量 + 概称剧情简述 + 单轮功德收益与『接取』按钮」；`accepted == true` 的槽位半透明置灰显示「已接取 · 刷新后补充」。
