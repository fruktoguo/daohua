## 29.1 定位与架构边界

1. **零 ECS / 八分段 / 冷挂机侵入**：兑换码批次、码池与玩家已领取记录均存放于 PostgreSQL `economy` 独立旁路表，不进入玩家八分段快照（`SectionCodec.CurrentSchemaVersion` 保持不变），不占用 `EcsWorldShard` 组件槽位，亦不进入冷挂机计算节点（`ComputeNode`）。
2. **双模式统一架构**：
   - **通用口令码（`universal`）**：运营自定义固定口令（如 `DAOHUA666`、`VIP-2026`），在 `economy.redeem_codes` 中占据唯一 1 行；支持配置全服总核销上限 `max_claims`（`NULL` 表示不限总人数）与过期时间 `expires_at`（`NULL` 表示永不过期），每名玩家限兑 1 次。
   - **批次单次码（`single_use`）**：运营指定数量（单批 `1 ~ 5000` 个）与可选前缀（`0 ~ 8` 位），由服务端以密码学安全随机数 `RandomNumberGenerator` 从 32 字符无歧义字母表 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（剔除易混淆字符 `0/O/1/I`）无模偏生成唯一码；每个单次码一码一用（核销后绑定 `redeemed_by` 与 `redeemed_at`），且**同一批次内每名玩家限兑 1 次**，杜绝单人囤积同批次活动礼包码。
3. **直接入账与两层持久化对齐**：
   - 核销成功时，在同一 `Serializable` 数据库事务内锁定批次与码行、写入永久防重记录 `economy.player_redeem_claims`、并调用 `PostgresEconomyRepository.CommitCoreAsync`（`transactionType = "ops.redeem"`，`PersistLedger = true`）直接入账 `economy.player_asset_balances`。
   - 经济流水归属第 ⑤ 类运营发放白名单（`ops.*`），由 `PostgresRetentionWorker` 自动保留 **30 天**后清理；而玩家防重表 `economy.player_redeem_claims`（窄主键 `(player_id, batch_id)`）永久保留，确保长期有效的通用口令码在 30 天流水清理后仍绝不会被二次重复领取。
   - 事务提交后立即调用 `IPlayerRuntime.ReloadWalletAndNotifyAsync` 热刷新在线玩家内存钱包并下推 `Assets` 差量快照，前端界面当场以图标化组件呈现本次获得的全部物品。
4. **机器人与防爆破隔离**：
   - `identity.accounts.is_bot = true` 的账号禁止兑换任何礼包码。
   - 兑换接口挂载独立 `"redeem"` 限流策略（每玩家/IP 每分钟上限 `10` 次），且在获取跨组件资产锁与玩家提交门之前先完成无锁索引预检，防止无效口令穷举占用核心并发门。

## 29.2 编码规约与奖励载荷

1. **口令归一化（`RedeemCodeRules.NormalizeCode`）**：
   - 去除首尾空白并将 ASCII 小写字母统一转换为大写，允许字符集为 `A-Z`、`0-9`、`-`、`_`，合法长度 `4 ~ 32` 字符。
   - 通用口令码与随机单次码共享同一主键空间 `economy.redeem_codes(code_normalized)`，从物理约束上杜绝跨批次撞码。
2. **多槽位奖励规格（`RedeemRewardDto`）**：
   - 单个批次支持 `1 ~ 12` 种奖励槽位，同 `(itemId, enhancementLevel)` 自动合并数量。
   - 奖励标的必须在当前 `GameDataCatalog` 配表内存在（支持 `currency.spirit-stone`、`item.gongde-bound`、常规材料/消耗品/秘籍残卷及装备）。
   - 装备类标的（存在于 `RawEquipments`）可选指定强化等级 `enhancementLevel`（`0 ~ 20`，映射资产变体 `""` 或 `"+1" ~ "+20"`）；非装备标的 `enhancementLevel` 必须为 `0`。所有奖励数量须为有限正整数（`1 ~ 1,000,000,000`）。

## 29.3 数据表结构（Schema v62）

1. **`economy.redeem_batches`（兑换批次主表）**：
   - `batch_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
   - `title varchar(120) NOT NULL`：礼包/批次名称（兑换成功时回显给玩家）
   - `mode varchar(16) NOT NULL CHECK (mode IN ('universal', 'single_use'))`
   - `rewards jsonb NOT NULL`：标准化奖励数组
   - `max_claims integer NULL CHECK (max_claims IS NULL OR max_claims > 0)`：总核销上限（`single_use` 恒等于该批生成码总数；`universal` 为 `NULL` 表示不限）
   - `claimed_count integer NOT NULL DEFAULT 0 CHECK (claimed_count >= 0)`：已核销次数
   - `created_at timestamptz NOT NULL`、`expires_at timestamptz NULL`、`disabled_at timestamptz NULL`
2. **`economy.redeem_codes`（全服唯一兑换码索引表）**：
   - `code_normalized varchar(32) PRIMARY KEY`
   - `batch_id bigint NOT NULL REFERENCES economy.redeem_batches(batch_id) ON DELETE CASCADE`
   - `redeemed_by uuid NULL REFERENCES identity.players(player_id)`（仅 `single_use` 核销后写入）
   - `redeemed_at timestamptz NULL`
3. **`economy.player_redeem_claims`（每玩家每批次永久防重核销表）**：
   - `player_id uuid NOT NULL REFERENCES identity.players(player_id)`
   - `batch_id bigint NOT NULL REFERENCES economy.redeem_batches(batch_id) ON DELETE CASCADE`
   - `code_normalized varchar(32) NOT NULL`
   - `claimed_at timestamptz NOT NULL`
   - `PRIMARY KEY (player_id, batch_id)`

## 29.4 接口契约与前端/运维交互

1. **玩家端 REST API**：
   - `POST /api/v1/redeem`（需 Cookie 鉴权会话 + `"redeem"` 限流）：入参 `RedeemCodeRequestDto(Code)`，严格从 `ClaimsPrincipal` 提取 `player_id`；成功返回 `RedeemCodeResponseDto(BatchId, Title, Code, Rewards)`，失败按明确业务码（`REDEEM_INVALID_CODE` / `REDEEM_NOT_FOUND` / `REDEEM_EXPIRED` / `REDEEM_DISABLED` / `REDEEM_EXHAUSTED` / `REDEEM_CODE_USED` / `REDEEM_ALREADY_CLAIMED` / `REDEEM_BOT_RESTRICTED`）返回标准 `ProblemDetails`。
2. **玩家端界面（「设置 → 账号」内嵌分组）**：
   - 在 `SettingsPage` 的「账号」页签内设立「礼包兑换」分组卡片（位于修士资料下方、安全设置上方），提供紧凑输入框与「兑换」按钮。
   - 兑换成功后即时触发全局轻提示，并在分组卡片内以 `<ItemTile>`（强制显式透传 `itemId`、`enhancementLevel` 与 `amount`，外包 `<ItemTooltipTarget>` 支持完整悬浮详情）展示本次入账的全部物品。
3. **运营端（`/ops` 面板 + `/ops/api` + `dev-tui`）**：
   - 后端 `OpsRedeemActions` 提供批次列表查询、码池明细导出、创建通用口令码、批量生成单次码与批次停用/恢复接口（全部受 `X-Ops-Token` 保护并写 `Ops.Audit` 审计日志）。
   - 前端 `/ops` 后台「系统 → 兑换码」专属视图支持可视化创建、单次码一键复制/导出 `.txt`、核销进度监控与停用恢复；`scripts/dev-tui.mjs` 同步提供 `:redeem` 指令集。
