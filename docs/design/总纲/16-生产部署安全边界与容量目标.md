# 第十六篇 生产部署、安全边界与 2c4g/40g 容量目标

## 16.1 生产运维拓扑与持久化
- **部署架构**：Release 多阶段构建 $\to$ CCR 不可变标签 + `prod` 标签 $\to$ 服务器 systemd timer 自动更新 $\to$ Caddy 反向代理 HTTPS/WSS 至回环 `127.0.0.1:15128`。
- **PostgreSQL 权威存储**：账号、玩家快照、Durable Outbox、市场账本与流水全量落库 PostgreSQL；Docker 命名卷 `daohua_daohua-postgres` 承载持久数据；每小时自动生成 gzip 压缩备份并生成 SHA-256 校验。
- **WAL 恢复窗口**：归档对象包含 WAL 段、时间线历史与备份历史文件，以 `<原名>.gz` 压缩原子写入；重复归档校验原始内容一致，PITR 解压恢复。仅 PostgreSQL 自行回收 `pg_wal`，禁止手动删除积压段。

## 16.2 2c4g/40g 容量目标与基准数据

下表是既有 Release 5800X 的历史基线，包含估算与局部引擎测量；原有“通过”只表示当时测试口径，不是当前真实业务链路或 2c4g 主机容量已验收。当前容量验收必须覆盖专用 PostgreSQL 库、5000 账号存储、100/500 个认证业务收发连接，以及冻结一小时欠债的 2000 名玩家经 ComputeNode → 主服独立 ECS 重演 → 原子落库的全部终态。必须同时记录 Server、ComputeNode、PostgreSQL 的 CPU、RSS、WAL、磁盘与网络证据；目标集合未全部成功、任务中止或资源证据缺失时失败关闭，禁止用 synthetic、少量样本或完成任务百分比替代。

| 场景 | 目标指标 | 历史基线 (Release 5800X / 2c4g 换算；非本轮验收) | 历史预算判断 |

## 16.3 三版本 ECS 实验的部署隔离边界

基准宿主（生产 `src/Server` 的 Development 基准模式）是本地/专用基准环境的独立进程，不属于当前生产拓扑，也不能共享生产数据库、数据卷、日志目录或端口。约定基准入口为 `127.0.0.1:5130`，数据库为 `daohua_bench_ecs`，运行产物写入 `artifacts/runtime/ecs`。这些名称只服务于隔离测试，不能替换正式 `daohua` 服务、`127.0.0.1:15128` 生产入口或 `daohua_daohua-postgres` 卷。

基准服务必须复用同一份游戏数据指纹和确定性种子，单独采样 CPU、分配、GC、RSS、数据库和网络开销。只有三套服务完成真实 HTTP/ WebSocket / PostgreSQL 边界验证、结果逐位一致、并通过单玩家到目标规模及离线补算门禁后，才能提交是否采用 ECS 的决策；在此之前不得把实验端口、实验镜像或实验数据库接入 Caddy、systemd 自动更新 timer、CCR `prod` 标签或生产持久卷。优化 ECS 的建议目标为相对 ECS-current 核心模拟 p95 降低 20%、每玩家分配降低 20%、GC 暂停增幅不超过 10%，达不到时如实记录，不能为了发布改写生产容量口径。

## 16.4 反多开与反小号账号约束

服务端权威执行设备注册与账号关联限制：默认稳定设备安装标识只能注册一个账号，同一设备主体最多关联两个账号。浏览器无法证明自然人身份；设备配置、IP、网段与指纹只参与综合风险判断，不能独立证明同一人。注册、登录与 Hello 均执行检测，拒绝登录不得签发会话或成功事件。

检测项必须独立动态启停，策略、稳定 HMAC 密钥、关联与审计落 PostgreSQL；软风险支持放行、复核与拒绝，配置相同或共享 IP 不单独硬封。前端只采集摘要，生产构建混淆提高分析成本，密钥与裁决不进入前端。Development 运维面板提供“账号检测”页与令牌保护的策略写入，生产沿用关闭 Ops 路由的边界。具体模块、事务和在线所有权见 [`anti-multi-open.md`](../../backend/anti-multi-open.md)。
