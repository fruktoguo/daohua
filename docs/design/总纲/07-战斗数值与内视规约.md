# 第七篇 战斗数值与内视规约

本文档记录角色内视体系、双数值类型定义规范、统一基准数值底座、非玩家单位（怪物）全量量化设计模型、六维根基换算规则、普通攻击规则、全量战斗属性分类、抗性减伤与对抗计算公式，以及核心生平记录规范。

## 7.1 强制数值类型架构规范 (全量使用 double)

根据系统与领域核心架构规则：
- **全部数值计算与储存一律使用 `double` 精度**（前端对应 JavaScript/TypeScript `number` 即 IEEE 754 double）。
- 杜绝任何整数截断导致的非预期突变，百分比结构体内部存储同样采用 `double` 点数。

### 7.1.1 固定数值类型 (Fixed Value / Flat Value)
- **底层表示**：直接使用 `double` 存储与结算。
- **涵盖属性**：全部基础战斗属性均为此类型。
  - 生命值 (HP)、灵力值 (MP)
  - 物理攻击、术法攻击
  - 护甲 (物防)、法抗 (法防)
  - 命中、闪避
  - 暴击、免爆
  - 破招、化解

### 7.1.2 统一百分比数值类型 (Percent Value)
- **底层表示**：内部统一存储为 `double Points`（点数），以 **100 点 = 100% 当量 (1 点 = 1%)** 作为基准缩放常数 $K = 100$。
- **支持曲线模式 (Curve Mode)**：
  - **`Linear`（线性模式）**：适用于增伤、免伤、仇恨增加、各类属性伤害增免。
  - **`NonLinear`（非线性/速率倒数模式）**：适用于冷却速度 (CDR)、行动速度 (攻速)、灵力消耗减少。

#### 百分比类型双模式换算模型对比表

设属性底层点数为 $x$：

| 点数 $x$ | 模式 (Mode) | 实际战斗乘区倍率 (Multiplier) | 面板展示百分比 (DisplayPercentage) | 业务行为说明 |
| :--- | :--- | :--- | :--- | :--- |
| **0** | Linear | $1.0\times$ | **0%** | 无增益 / 无减益 |
| **+100** | **Linear** | $1 + \frac{x}{100} = \mathbf{2.0\times}$ | $\mathbf{+100\%}$ | 增伤 100 点，伤害翻倍 ($2\times$) |
| **-100** | **Linear** | $\frac{100}{100 + \|x\|} = \mathbf{0.5\times}$ | $\mathbf{-50\%}$ | 负向除法软着陆，伤害减半 ($0.5\times$) |
| **0** | NonLinear | $1.0\times$ | **0%** | 基础冷却 / 消耗时间 |
| **+100** | **NonLinear** | $\frac{100}{100 + x} = \mathbf{0.5\times}$ | $\mathbf{50\%}$ | 冷却速度 100 点，CD 缩减 50% |
| **-100** | **NonLinear** | $1 + \frac{\|x\|}{100} = \mathbf{2.0\times}$ | $\mathbf{-100\%}$ | 冷却减速 100 点，CD 延长一倍 |

## 7.3 全量量化平衡与非玩家单位（怪物）设计模型

### 7.3.1 怪我同构建模原则 (Monster-Player Isomorphic Modeling)
系统杜绝“拍脑袋填表、来回人工调参、牵一发而动全身”的落后配表方式。整个数值体系是**完全参数化、闭环量化**的：
1. **完全对称数据结构（任何战斗单位同一模型）**：怪物、玩家、斗法镜像以及未来任何参战单位（含召唤物）在领域模型中完全同构——共用同一 `CombatantState` 属性池、同一 `SkillSlot` 技能槽、同一触发器求值器、同一 Buff 结算与同一普通攻击机制；不存在按单位身份分叉的专属属性、专属技能或专属效果管线；
2. **挂机基准波次怪物标准**（详见 [第十一篇](./11-数值量化模型集.md) §11.2）：
   - **妖兽 (Minion)**：**80% 全属性，300% 玩家生命**；
   - **精英 (Elite)**：**120% 全属性，500% 玩家生命**（每 5 波一次）；
   - **妖王 (Boss)**：**150% 全属性，2000% 玩家生命**（每 20 波一次）；
   - **底座口径**：「全属性 / 玩家生命」一律以同等级**期望玩家面板**为底座——即 `expected-attributes.json` 的 `levelExpected[].finalExpected`（基础数值池 × 六维 × 装备 × Buff 四乘区完全体，Lv1~127 每级锚点逐级求解，相邻整级插值）；**不是** `baseAttributeAnchors` 裸底座。怪物 `weights.*` 倾向权重在期望底座之上做微调。
3. **大世界单场质量预算生成**（详见 [第八篇](./08-大世界地图与质量预算遇怪系统.md)）：
   - 单场大地图历练按地图危险度预算区间 `[minBudget, maxBudget]` 结合怪物 `budgetCost` 进行动态抽取，支持 1~3 种特色怪群组合。

### 7.3.2 怪物属性倾向量化微调
在等阶基准之上，可通过倾向配置快速派生特色怪物：
- **玄甲巨兽型**：护甲 $\times 1.5$、生命 $\times 1.3$、攻速 $\times 0.8$
- **影蝠刺客型**：闪避 $\times 2.0$、暴击 $\times 1.5$、生命 $\times 0.7$
- **炽炎法王型**：术法攻击 $\times 1.6$、法穿 $\times 1.5$、护甲 $\times 0.6$

## 7.4 普通攻击机制 (Basic Attack)

任何战斗单位（玩家、怪物、斗法镜像、召唤物）在出手边界没有可施放功法技能时，回落普通攻击——普攻模型对所有单位完全统一：
- **行动速度**：默认为 `0` 点（对应 `0.0%`，无增减）。
- **伤害倍率**：造成 **100% 物理攻击伤害**（`1.0 * PhysicalAttack`）。
- **冷却时间 (CD)**：`0.0s`。
- **引导施法时间**：`1.0s`。
- **灵力消耗**：`0` 灵力。

## 7.7 战斗伤害与对抗计算公式

### 7.7.1 伤害结算链：大类抗性穿甲 + 分类增减伤 + 免伤
战斗伤害计算以**大类抗性平方穿甲**打底，再经攻方分类增伤、守方分类减伤、暴击与免伤点数依次修正：

1. **第一层：大类抗性非线性平方减伤（护甲 / 法抗）**：
   $$\text{DamageAfterCategory} = \frac{\mathbf{RawDamage^2}}{\mathbf{RawDamage} + \mathbf{RES} \times K + 1.0}$$
   - **原始伤害口径**：普攻 `RawDamage = 物理攻击 ×(1+普攻增幅点数/100)`；技能命中的单发威力在出手构造时按 `攻基 ×(1+技能增幅点数/100) × 技能倍率` 并入——两类增幅点数均在抗性穿甲之前放大单发威力，天然穿甲优势随之同步生效；
   - **动态抗性系数 $K$**：等于当前等阶 `Tier`，由 `BaseAttributeCatalog.TierAt(level)` 锚点计数推导（`baseAttributeAnchors` 起始等级 `1/18/30/42/54/66/78/90/102/114/126/127`，等级不超过 `level` 的锚点个数即为 `K`；T1 得 `1.0`、T2 得 `2.0`，直至 T12 段 `12.0`，详见基准表）。
   - **有效抗性 ($\mathbf{RES}$)**：计算穿透比例后实际起效的大类抗性。物理伤害对应守方护甲（`Armor`），术法伤害对应守方法抗（`MagicResistance`）；化解成功时 $\text{RES} \times 2$。
   - **公式特性**：单发原始伤害越高，天然穿甲能力越强；法系凭借超大 AP 具备极强天然破防优势。

2. **攻方增伤乘区（Linear 点数，正向线性）**：
   按伤害归属匹配生效，逐项线性乘算：
   $$\times\left(1+\frac{\text{物理增伤或法术增伤}}{100}\right) \times \left(1+\frac{\text{对应五行增伤}}{100}\right) \times \left(1+\frac{\text{总增伤}}{100}\right)$$
   - 物理/法术增伤按伤害大类匹配（普攻与物理技能吃物理增伤，术法技能吃法术增伤）；
   - 五行增伤仅在攻击携带对应五行属性时生效（`Element.None` 跳过该项）；
   - 普攻增幅与技能增幅不在本层——二者已并入原始威力基数（见第一层口径），不与后段增伤重复乘算。

3. **守方减伤乘区（NonLinear 点数，正向收敛）**：
   按承伤归属匹配生效，逐项收敛乘算，任意单项减伤永不归零伤害：
   $$\times\frac{100}{100+\text{物理减伤或法术减伤}} \times \frac{100}{100+\text{对应五行减伤}}$$
   - 与增伤同口径分类匹配：物理减伤抵物理伤害、五行减伤抵对应五行攻击。

4. **暴击判定与最终伤害**：
   $$\text{实际伤害} = \text{DamageAfterElement} \times (\text{是否暴击} ? (1+\frac{\text{暴击伤害点数}}{100}) : 1.0)$$

5. **总减伤（免伤点数）末位收口**：
   通用承伤减免，守方 `DamageAbsorptionPoints + BonusAbsorptionPoints + BuffAbsorptionPoints` 合并后：
   $$\text{最终承伤} = \text{实际伤害} \times \frac{100}{100 + \text{总减伤}}$$
   总减伤为负时反向增伤，结算下限截断为 $0$。

> **修正说明**：五行抗性（`MetalResistance` 等元素抗性字段与第二层抗性减免）为历史误植，已废除——五行防御统一由「五行减伤」百分比点数承担；配表与代码字段清理另行落地。

**公式特性解读**：
- **半伤线**：$\text{RES} \times K \approx \text{RawDamage}$ 处承伤正好减半——守方「有效抗性 × 等阶系数」就是攻方单发伤害的半价线；
- **境界压制**：$K$ = 守方等阶，低阶攻高阶时 $\text{RES} \times K$ 被放大、伤害平方级跌落，跨阶悬殊由公式本身表达，无需特例；
- **天然穿甲**：单发原始伤害越高穿透越强——同等总面板下「一刀大伤害」比「多刀小伤害」破防效率高，AP 大招是天然破防武器；
- **对抗而非固定值**：护甲/法抗不是减伤百分比，而是与攻方单发伤害对抗的「点数」，减伤效果取决于双方量级比。
### 7.7.2 技能消耗口径
技能配表的 `manaCost` 字段直接声明 MP 点数消耗，结算时按表值全额扣除，不再经任何系数放大或二次换算：
$$\text{最终灵力消耗} = \text{manaCost（配表点数）}$$
按此口径，Lv1 基础灵力上限（MP 50，六维为固定值加成、随修炼增长）即可覆盖全部 T1 技能消耗，10 门技能（含嘲讽、破阵子等支援类）全部可装配、可施放。

- **吟唱打断退还**：灵力消耗与冷却的生效语义挂在「吟唱完成结算」上——吟唱中途被打断（如团灭瞬间全场吟唱作废，见 §7.9.4）视为技能未释放，起手预扣的灵力全额退还且不进入冷却；只有完整吟唱并结算的技能才消耗灵力、进入冷却。

### 7.7.3 三大对抗机制与触发概率公式 (常数 $K = 100.0$)

**对抗数值而非固定百分比**：命中、闪避、暴击、免爆、破招、化解全部为「点数」属性，触发概率由**攻防双方点数**与常数 $K=100$ 共同决定，形如 $\frac{\text{我方点数}}{\text{我方点数} + \text{对方点数} + 100}$；不存在写死的百分比面板。双方等点数时概率低于 $50\%$ 并随总点数渐近逼近 $50\%$——常数项是收敛阻尼，数值膨胀天然不溢出，每点边际收益递减。

1. **闪避 vs 命中对抗 (先判定是否被闪避)**：
   攻击发起时，系统优先判定守方是否成功闪避：
   $$\text{闪避概率} = \frac{\text{守方闪避}}{\text{守方闪避} + \text{攻方命中} + 100.0}$$
   - **闪避成功**：本次攻击完全落空，造成 0 伤害；
   - **闪避失败 (即命中)**：进入后续伤害与暴击减免结算。$0$ 闪避对 $0$ 命中时闪避率为 $0\%$ (默认必中)。

2. **暴击 vs 免爆对抗**：
   命中后判定是否触发暴击：
   $$\text{暴击概率} = \frac{\text{攻方暴击}}{\text{攻方暴击} + \text{守方免爆} + 100.0}$$
   - **暴击成功**：伤害乘以暴伤倍率 `1+暴击伤害点数/100`（基础自带 50 点即 150%）。$0$ 暴击时暴击率为 $0\%$。

3. **破招 vs 化解对抗**（同一次 roll 双分支互斥，仅点数更高一方有机会触发）：
   - **破招触发**：攻方破招 > 守方化解时，按概率 $\frac{\text{攻方破招}}{\text{攻方破招} + \text{守方化解} + 100.0}$ 判定，成功时**命中值与暴击值实际计算效果翻倍**；
   - **化解触发**：守方化解 > 攻方破招时，按概率 $\frac{\text{守方化解}}{\text{守方化解} + \text{攻方破招} + 100.0}$ 判定，成功时**双抗（护甲/法抗）与闪避实际计算效果翻倍**。

破招/化解 ×2 修正落定之后、命中掷骰之前，命中与闪避等效还要再过一次**战斗经验对抗**修正（见 §7.7.6）。

### 7.7.4 攻击反应触发器域（吸血/吸蓝/反伤）

所有伤害（普攻、玩家技能、怪物技能、斗法镜像）统一汇流 `ResolveAttack` 单点结算；伤害落账后引擎把攻击方/受击方各一条 `OnHit` 触发器入队 `encounter.PendingTriggers` 并立即按入队序消费——ECS 宿主经 `RunSystem<IOnHitTrigger>(unitEntity)` 实体派发（标记组件 + `SystemOrder` 排序），无实体路径经 `InlineCombatTriggerSink` 内联数学，两路共用 `CombatTriggerMath` 同一实现，结果逐位一致：

- **命中判定与伤害结算**：判定前/落账前的结算链仍在引擎本体内按固定次序执行；
- **落账后衍生结算**（触发器域，`CombatTriggerMath`）：
  - **气血汲取**（Order 100，`OnHitLeechSystem`）：命中后按 `实伤 × HpDrainRatio` 回复攻击方气血，产出治疗衍生事件；
  - **灵力汲取**（Order 110，`ManaLeechSystem`）：按 `实伤 × MpDrainRatio` 从目标灵力池偷取，目标扣全额、攻击方只装得下的部分；
  - **伤害反弹**（Order 200，`ThornsSystem`）：受击方把 `实伤 × DamageReflectRatio` 弹回攻击方，计入受击方威胁值；
  - **受击涨威胁**（Order 300，`ThreatOnTakenSystem`）：受击方按 `原始伤害（减免前面板威力）× ThreatOnTakenRatio` 增加自身威胁；仅命中生效，未命中不算「受到伤害」。

效果强度统一打包在 `CombatantStats.Effects`（`CombatEffectProfile`）：玩家侧由装备 `specialMechanics.hpDrainRatio` / `mpDrainRatio` / `damageReflectRatio` 经属性解析汇入，怪物侧由配表同名字段直接声明；reactive 标记组件（`OnHitLeech`/`ManaLeech`/`Thorns`）由 `CombatTriggerSurface` 按 Effects 管理挂摘，参数永无双写。

**确定性约束**：触发器禁止另起随机源与墙钟读取，随机判定走 `CombatHitContext.NextRoll()` 独立通道（0~15 号通道为核心结算保留，触发器通道自 64 起）；触发器衍生伤害**直接落账、不回流管线**，杜绝递归触发；`UpdateOutcome` 永远在触发器结算之后运行，命中回血可救活自己。

### 7.7.5 百分比属性双曲线规约与修饰属性清单

**双数值类型（`PercentValue`）**：所有百分比修饰属性以 `double`「点数」存储（100 点 = 100%），按曲线模式换算为乘区。设计不变量：**点数在收益域恒定每点 1% 收益，百分比只是投影显示**——加成方向走分子线性、惩罚方向走分母渐近收敛，彻底规避"80%→90% 收益翻倍"与"堆满归零"两类断崖。

- **线性百分比（Linear）**：$+x \Rightarrow \times\left(1+\frac{x}{100}\right)$（+300 = +300%，×4）；负向软着陆 $-x \Rightarrow \times\frac{100}{100+|x|}$（−300 = −75%，×0.25）。适用全部增伤/增幅/汲取类。
- **非线性百分比（NonLinear）**：$+x \Rightarrow \times\frac{100}{100+x}$（+300 = 75% 缩减，时间/承伤 ×0.25，等价速率域每点线性 +1%）；负向线性放大 $-x \Rightarrow \times\left(1+\frac{|x|}{100}\right)$。适用减伤/缩减/速率类。

**伤害增减修饰 16 项**（增伤作用于攻方打出伤害，减伤作用于守方承受伤害）：

| 方向 | 属性（Linear 增伤 / NonLinear 减伤） |
| :--- | :--- |
| 大类 | 物理增伤/物理减伤、法术增伤/法术减伤 |
| 五行 | 金/木/水/火/土 增伤/减伤（10 项，按攻击携带的五行属性匹配，`Element.None` 均跳过） |
| 总增减 | 总增伤、总减伤（免伤点数） |

**特殊属性 10 项**：

| 属性 | 曲线 | 默认 | 语义 |
| :--- | :--- | :--- | :--- |
| 暴击伤害 | Linear 点数 | 50 | 暴击伤害倍率 = 1+点数/100（50 点即 150%） |
| 攻击速度 | NonLinear | 0 | 普攻读条时间 ÷(1+x/100)，仅作用于普攻 |
| 行动速度 | NonLinear | 0 | 所有读条时间 ÷(1+x/100)；普攻上与攻速乘算（双重除数） |

| 技能增幅 | Linear | 0 | 不带「普通攻击」tag 技能的增伤修饰 |
| 治疗增幅 | Linear | 0 | 仅放大角色主动治疗技能的回血量（不含自动回复） |

**特殊属性获取口径（玩家 vs 怪物）**：特殊属性对玩家是**获取型属性**——只能经装备 `specialMechanics`、内功、特质、Buff、建筑等明确手段获得，境界不产出、不保送；玩家面板中的此类点数全部可溯源到具体来源。怪物侧则把等级成长折算为「基准点数」注入同一通道，作为同构建模底座：配表等级换算的同额点数在 `GameDataCatalog` 解析时并入怪物 `modifiers`，与玩家走同一结算链（折算公式与逐阶等效值见 §11.1.4.3/§11.2.3.2）。

### 7.7.6 战斗经验对抗（命中/闪避等效修正）

战斗经验（`CombatExperience`）是独立的**对抗池**：只累积、不消耗，语义与入账口径见 §7.11。在命中/闪避等效计算末尾——破招/化解 ×2 修正之后、命中掷骰之前——附加一次双方战斗经验对抗修正：

- **经验比值**：记攻方战斗经验 `aCE`、守方战斗经验 `bCE`、防除零小量 `ε`，
  $$r = \mathrm{clamp}\!\left(\frac{aCE}{\max(bCE,\ \varepsilon)},\ 0.1,\ 10\right)$$
  双方战斗经验均 $\le 0$ 时视为**中立**，不做任何修正。
- **$r \ge 1$（攻方经验占优）**：攻方命中等效 $\times \min\!\left(2,\ 1+\frac{r-1}{8}\right)$，守方闪避等效 $\times \max\!\left(0.5,\ 1-\frac{r-1}{16}\right)$。
- **$r < 1$（守方经验占优）**：令 $s = 1/r \in (1, 10]$，攻方命中等效 $\times \max\!\left(0.5,\ 1-\frac{s-1}{16}\right)$，守方闪避等效 $\times \min\!\left(2,\ 1+\frac{s-1}{8}\right)$。
- **镜像对称**：占优方的增益走 $/8$ 斜率、封顶 $\times 2$；劣势方的衰减走 $/16$ 斜率、托底 $\times 0.5$。攻守互换视角后结论互换，公式自洽无特例。
- **示例**：攻方战斗经验为守方 5 倍（$r=5$）→ 命中等效 $\times 150\%$、守方闪避等效 $\times 75\%$；$r \ge 9$ 时封顶 $\times 200\%$ / $\times 50\%$。
- **接入位置**：修正只作用于 §7.7.3 第 1 条闪避对抗的两侧等效输入，不改暴击、破招/化解判定与伤害结算链，不新增随机抽取——随机数序列与 roll 通道分配不变，同种子回放逐位一致。
- **各单位取值**：玩家战斗经验取 `Progression.CombatExperience` 注入战斗面板（`CombatantStats.CombatExperience`）；怪物不入配表，按其配表 `level` 对应累计修为 $\sum_{i=1}^{level-1} \text{expToNext}[i]$ 派生（`RealmProgressionCatalog.CumulativeExpFor(level)`）；斗法镜像的战斗经验随撮合冻结面板（`DuelCombatant.Stats` → `DuelPlaybackState.OpponentStats`）携带，回放期不二次解析。

## 7.8 威胁（仇恨）与技能目标选择机制

### 7.8.1 威胁（Threat / 仇恨）定义与累积规则
- **定义**：单位在战斗中对敌方全体造成的总伤害，统一称为**“威胁”**（`double Threat`）。
- **基础威胁**：每场战斗开始时全体单位（玩家/盟友/敌人）基础威胁重置为 **100**（`CombatantState.BaseThreat`）；快照恢复沿用持久化值，不重复重置。
- **持续累积**：在整场战斗过程中持续累加，全部计算与存储均采用 `double` 精度；伤害/受击/嘲讽等增减直接改写基础存储值，**不在累积侧预乘增幅**。
- **嘲讽技能即时加成**：
  - 嘲讽类技能 `threatGain` 为**即时生效（Real-time Applied）**的基础威胁增量，直接加进存储值；
  - 嘲讽类战内 Buff 提供**限时威胁增幅点数**（如嘲讽 Buff 60s +400 点，冷却 55s 可无缝覆盖），与面板/修正增幅同乘区；
  - 嘲讽类战内 Buff 可携带**每秒周期性威胁累积**（`threatPerSecondMaxHpPoints`，如嘲讽 Buff 10 点）：沿全局 1 秒结算网格，每个整秒结算点为单位增加 `最大气血 × 点数×层数 / 100` 的基础威胁，直接改写存储值（与 `threatGain` 同通道、不预乘增幅）；与灵力回复同口径——倒地单位照常累积，复活后仇恨不回退；负值按减仇恨递减、0 托底；
  - 在计算有效威胁值时，直接按该百分比放大：
    $$\text{有效威胁值} = \text{基础威胁实际值} \times (1 + \text{威胁增幅点数}/100)$$
- **受击累积（特质类来源）**：除「打出伤害」外，`ThreatOnTakenPoints` 效果提供第二条累积通道——单位**受到伤害时**按攻击方面板原始伤害（减免链前原始威力 `AttackPower ×(1+普攻增幅点数/100)`）折算自身威胁；未命中不产生累积。

### 7.8.2 技能目标选择与命中概率分配规则
战斗中，除全体技能或明确锁定特殊类型（如生命最低友方、自身、特定指定单位等）的技能外，其余所有单体与非全体范围技能**均按候选目标的威胁值比例进行目标选择**。

#### 1. 单体技能 (Single-Target Ability)
- **总池计算**：将当前全体可选存活目标的有效威胁值求和作为总池值 $S$：
  $$S = \max\left(1.0, \sum_{i \in \text{可选目标}} \text{Threat}_i\right)$$
  *(设置保底值 $S_{\min} = 1.0$，防止除零异常)*
- **命中概率**：每个候选目标被选中的概率为其威胁值占总池的比例：
  $$P_i = \frac{\text{Threat}_i}{S}$$
- **全零回退规则**：当所有候选目标的威胁值均为 $0.0$ 时，退化为**完全等概率随机**选择其中一个目标（每个目标概率为 $1 / N$）。

#### 2. 非全体群攻技能 (Non-Full AoE Ability / Multi-Target)
根据技能机制设定，分为**可重复命中**与**不可重复命中**两种模式：

1. **可重复命中模式 (Repeatable Multi-Hit)**：
   - 技能进行的每一次打击判定，均独立在全体可选目标中按单体威胁权重概率池完整抽取一次；
   - 同一个目标可能在同一次技能中被连续命中多次。
2. **不可重复命中模式 (Unique Multi-Target)**：
   - 采用**动态缩减概率池（Sequential Elimination）**算法：
     1. 第一段在当前全体候选目标中按威胁比例抽取目标 $T_1$；
     2. 命中后将目标 $T_1$ 从候选池中剔除，剩余目标构成新的总池 $S' = \sum_{j \neq 1} \text{Threat}_j$；
     3. 后续攻击依次在剩余目标池中按更新后的威胁比例继续抽取，直至达到技能目标上限或候选池耗尽；
     4. 保证单次群攻中每个目标至多受到一次命中。

### 7.8.3 出手决策顺序与使用条件触发判定

#### 1. 出手决策顺序（目标先行）

**所有行动在选择使用什么技能之前，必须先进行威胁判定**——按 §7.8.2 规则以有效威胁权重确定性抽取本次行动的目标，锁定的单位即本轮判定的「**目标**」对象；此后才按槽位顺序遍历技能做可用性判定（触发条件 → 冷却就绪 → 灵力消耗），首个满足者进入吟唱，全部不可用时回落普通攻击。即出手序列为：

```text
威胁判定抽取目标 → 锁定为本轮「目标」对象 → 按槽序逐技能求值触发条件 → 命中首个可用技能进吟唱（预扣灵力）→ 否则普攻蓄势
```

实现落点：`DecideNextAction` 的 `primaryTarget` 入参即该锁定目标（`SelectEnemyTarget` 按 `EffectiveThreat` 抽取）；技能落账时的实际命中目标仍按 §7.8.2 在结算时刻抽取。

**敌方侧同构**：敌方出手与决策同样在 `PlayerAllies` 上按 `EffectiveThreat` 轮盘抽取目标（出手随机通道 18、决策 19）。玩家方当前恒为单成员（`PlayerAllies = [Player]`），`SelectTarget` 单存活成员提前返回不掷点——单盟友行为与「固定打玩家」逐位等价；多盟友（召唤物/组队）落地后威胁权重自动生效，受击涨威胁与威胁抑制类特质由此具备真实嘲讽/隐身语义。

#### 2. 使用条件三元组模型（技能与消耗品共用）

每条使用条件为「**对象 → 类型 → 比对方式**」三元组，条件列表全部满足才放行（AND，短路）；空表恒可用。技能与战斗消耗品（药品栏/通用栏）挂同一求值器，同一词汇表，杜绝身份分叉。

**第一层：对象**——决定条件作用域：

| 对象 | 作用域 |
|---|---|
| `self` 自身 | 施放/使用单位本身 |
| `target` 目标 | 本轮威胁判定锁定的单位（见上） |
| `ally` 友方 | 我方全体存活单位构成的集合 |
| `enemy` 敌方 | 敌方全体存活单位构成的集合 |

**第二层：类型**——随对象过滤的可选词表，两类：

- **单位状态值**（自身/目标可用，友方/敌方经成员选择后亦可用）：当前/缺失 气血与灵力（绝对值与百分比）、Buff 层数、控制类状态；
- **群体聚合值（仅友方/敌方可用）**：作用于集合而非单体——`生命值百分比最少/最多的成员`（先选出该成员再取其状态值参与比对）、`剩余存活数量`、`已阵亡数量` 等。此类类型对 `self`/`target` 不出现——单体对象没有"最少的成员"语义。

**第三层：比对方式**——按类型产出值分两种：

| 产出值类型 | 比对词表 |
|---|---|
| 数值（气血、百分比、层数、存活数等） | 大小等于：`>`、`>=`、`=`、`<=`、`<` |
| Boolean（控制状态活性等） | 是否：`是`（is-active）、`否`（is-inactive） |

**实现映射**：现 `SkillTriggerEvaluator` 的 `dependency` 词表即"对象 + 成员选择"的融合写法——单体对象 `self` / `target-enemy` / `ally-lowest-hp` / `ally-highest-hp` / `enemy-lowest-hp` / `enemy-highest-hp`，集合对象 `ally` / `enemy`（配 `alive-count`/`dead-count` 群体聚合条件）；`condition` 对应类型、`comparator` 对应比对方式（数值 `greater-than`/`equal` 等 + 布尔 `is-active`/`is-inactive`）。校验期按对象-类型-比对矩阵拒绝越界组合；运行时求值对非法输入一律返回 false 不抛异常。消耗品配置在 `usableInActionTypes` 之外声明 `triggers` 列表即接入本模型。

**消耗品求值上下文**：即时消耗品在自动激活边界求值、持续消耗品在遭遇入场补能时求值；施放方取玩家当前快照，战斗进行中敌方取当前波单位。「目标」对象在消耗品求值下按**当前存活敌方中有效威胁最高者**确定性解析（非随机抽取，避免消耗随机流）——与技能决策时刻的威胁锁定语义对齐：两者都是"本次判定时锁定的高威胁对象"。

## 7.9 角色状态世界常驻、自动回复与复活规约

### 7.9.1 世界常驻与状态连续流转原则
修士角色在修仙世界中处于持续常驻与状态连续推进状态。生命值（Hitpoints）与灵力值（Manapoints）由底层 `CombatResources` 权威持久化，**彻底移除任何不合理的瞬间重置与满状态重置事件**：
1. **移除战斗边界重置**：单场遭遇结束、战胜单只怪物、跨多波遭遇推进、进入新战斗时，严格保留玩家当前的实际生命与灵力残值，绝不在进入或结束战斗时回满。
2. **移除脱战无故回满**：取消战斗队列、手动移出战斗、切换到生活/采集/打坐行动时，存活玩家保持当前血蓝脱离战斗。

### 7.9.2 自然回复属性由基础属性表配置

角色在挂机、探索、炼丹、打坐、赶路及战斗各阶段均按回复属性结算自然回复。

- **配置是真源**：随境界成长的基础生命上限、基础生命回复 `HpRegen` 和基础灵力回复 `MpRegen` 均由基础属性表提供。调整基础回复数值应修改配置，不在服务端或前端硬编码百分比推导公式。配置归属与当前落地状态见 [基础属性模型 §11.1.5.1](./11-数值量化模型集.md#11151-自然回复基础值的配表边界)。
- **2% 的准确含义**：它是生命回复的配表选值依据，参考的是**对应境界的基础生命上限**，不是包含资质、装备、Buff 后的最终生命上限。配表时将对应点数写入基础回复属性；运行时代码读取该属性，不执行“基础生命上限 × 2%”或“最终生命上限 × 2%”。后续平衡只调整表中数值，不要求代码维持固定比例。
- **独立属性**：生命上限加成不会自动转化为回复加成。只有明确作用于回复属性的资质、装备、Buff 等，才按各自属性规则调整回复量；同一来源同时增加生命上限与回复时分别处理，不能重复计算。
- **灵力回复**：同样读取表中的独立回复属性；本次澄清不为灵力指定固定 2% 或其他比例。
- **不新增隐式规则**：不从“2%”推导运行时保底 1 点、向下取整或缺字段时按上限补算。回复保持 `double` 精度。
- **周期实现基线**：当前实现基线为 **5 秒整额回复周期**——`HpRegen`/`MpRegen` 每 5 秒一跳，整额结算表值回复量（`RegenTickMilliseconds = 5_000`）。表中回复量的时间单位按每跳整额理解，协议展示单位随快照口径下发。

**配表示例（仅解释语义，不指定周期或实际数值）**：某境界基础生命上限配置为 1,000，基础生命回复配置为 20。装备仅将最终生命上限提高至 1,500 时，该基础回复仍为 20；进入基础生命上限 2,000、基础回复 40 的境界时，读取新配置的 40。代码无需也不得为这个示例补入固定 2% 公式。

### 7.9.3 死亡状态下的资源回复规则
当角色生命值归零（$\text{Hitpoints} \le 0$）进入死亡状态（如处于战斗死亡倒计时或历练死亡阶段等待复活读条）：
1. **生命值保持为 0**：未完成复活前不产生任何自然回血，生命值严格保持 0。
2. **灵力持续自动回复**：死亡状态下经脉灵力依然正常运转，按灵力回复速率持续吸收天地灵气恢复，死亡期间积累的灵力在复活或脱战后完整保留。

该规则对一切战斗单位同构：原地复活遭遇的战内躺尸窗口中，阵亡单位（含怪物尸体）气血锁 0 不结算回血、灵力回复按 5 秒网格照常入账。

### 7.9.4 团灭分流规约：原地复活 vs 团灭即败

战斗终局判定统一为「一方全体阵亡」：敌方全灭即玩家胜（`PlayerWon`）；**玩家方全体阵亡 = 团灭**（当前玩家方为单人单位，团灭即玩家阵亡；未来队伍/召唤物扩展后按全体存活判定）。团灭发生后按遭遇声明的团灭规则 `onPartyWipe` 分流，这是战斗的两条正式分支而非模式特例：

| `onPartyWipe` | 适用模式 | 团灭后果 |
| :--- | :--- | :--- |
| `respawn`（原地复活） | 野外历练等常驻 PvE 遭遇（缺省值） | 战斗**不终结**：玩家原地躺尸读条，读满起身续打同一波残局 |
| `defeat`（团灭即败） | 斗法（PVP）、副本、闯关爬塔等 | `Outcome = EnemyWon` 终局，善后由各模式编排层处理 |

- **善后是模式级策略，不进战斗引擎**：引擎只负责产出 `EnemyWon` 终局信号。斗法的善后为暂存物归属结算 + 败绩冷却 + 拆场读条复活重新搜寻；未来副本/爬塔的善后（踢出副本、挑战失败计数、回退层数等）由各自编排层实现。
- 野外遭遇若配置 `defeat`，善后为复活点语义：拆场 → 复活读条（`playerRespawnMilliseconds`）→ 满血满蓝清冷却 → 波次重置回第 1 波重新搜寻。

#### 原地复活（`respawn`）分支细则

1. **阵亡瞬间**：双方正在吟唱的技能全部打断——未完成的吟唱视为未释放，退还起手预扣灵力且不进入冷却（§7.7.2）。
2. **躺尸窗口（时钟照走）**：战斗时钟照常推进。怪物因失去目标不再出手，但其技能冷却（绝对时间戳）自然流逝、面板回血与 Buff 周期回复按 5 秒结算网格照常、Buff 到期正常剥落；玩家气血锁 0，灵力回复照常（§7.9.3）。
3. **起身结算**：读条满（按战斗时钟计 `playerRespawnMilliseconds`）玩家原地起身，**仅恢复满生命值**；灵力、技能冷却、自动消耗品冷却不做任何额外重置——躺尸期间自然转好的即为已转好，自然回复的灵力即为已获得。起身瞬间双方重新蓄势出手。
4. **躺尸期间敌方全灭**：玩家阵亡前施加的持续伤害/反伤在躺尸窗口把怪物跳死全灭 → 照常判 `PlayerWon` 结算掉落与轮次，玩家起身（满血）后进入下一波搜寻。
5. **计数口径**：每次阵亡计一次败走（`totalDefeats`）与死亡（`deaths`）并发 `combat.lost` 事件；起身发 `combat.respawned`。
6. **无兜底**：实力不足时「阵亡→复活→再阵亡」可无限循环，直到玩家手动取消行动脱战（按脱战复苏 1 HP 处理）；怪物在躺尸期间持续回血，连败成本自负。

#### 复活结算总表

| 复活类型 | 触发时机 | 生命值结算 (HP) | 灵力/冷却结算 | 机制说明 |
| :--- | :--- | :--- | :--- | :--- |
| **原地复活** | `onPartyWipe=respawn` 遭遇中玩家阵亡读条完成 | **恢复满生命值** (`MaxHitpoints`) | 灵力不回满（保留死亡期间自然回复累计值）；技能与自动消耗品冷却按自然流逝处理 | 原地起身，续打同一波残局 |
| **复活点读条复活** | `onPartyWipe=defeat` 善后读条完成（斗法落败、defeat 遭遇战败等） | **恢复满生命值** (`MaxHitpoints`) | **恢复满灵力值** (`MaxManapoints`)、清空技能与自动消耗品冷却 | 重塑肉身；战场已拆，重新搜寻第 1 波 |
| **退出战斗脱战复苏** | 处于死亡状态下取消战斗队列、手动移出战斗、历练结束脱离战斗 | **恢复至 1 点生命** (`1 HP`) | **保持当前灵力**（不回满，保留死亡期间已回复灵力） | 仅给予 1 点重伤复苏血量防止脱战后立即死亡，绝不一键回满 |

- 若玩家退出战斗时处于**存活状态**（$\text{Hitpoints} > 0$），则生命值与灵力值均直接保持离开时的当前值，不触发任何复活与重置。

#### 受阻行动的濒死复苏兜底

气血归零（$\text{Hitpoints} \le 0$）驻留时，任何远征/讨伐行动推进到入场都会被判定「无法迎战」进入受阻停泊。由于死亡状态下生命值不产生自然回血（§7.9.3），受阻行动若只等待回血将**永远无法自愈**——因此受阻队首在每次推进复核时先按脱战复苏同口径归一 `1 HP`，再重跑准入续战；复苏后以 1 点残血重新入场，仍可能被再次击倒回到正常连败循环（§7.9.4.6 无兜底条款），但队列本身不再死锁。同理，插队顶替、移除、清空等使远征行动离队的操作，在玩家气血归零时一律按复苏 1 HP 处理。

### 7.9.5 战内 Buff 生命周期

战内 Buff（`CombatBuffState`）是随战斗授予的临时效果，生命周期以**整场战斗行动**为单位，而不是以单场波次为单位：

- **跨波存续（默认）**：波次清空时，单位战内 Buff 按战斗时钟剩余秒数折算为**跨波携带态**（`PlayerCombatBuffState`/`ExpeditionAllyState.CombatBuffs`），下一波入场按 `新时钟 + 定格剩余` 重注入；搜寻/复活等脱战相位时钟冻结不折算（与持续消耗品扣减同模型，§6.3）。玩家、盟友成员同口径——参与会话中盟友携带态随冻结成员镜像同步。
- **`resetOnWave` 特例开关**：配表 `buff.resetOnWave: true` 的 Buff 不进入跨波携带（波次清空即消散），默认 `false`。**战外 Buff、持续消耗品槽注入、特质授予（如隐身）等由外部真源每波重新注入的 Buff 恒视为每波重置**——携带会造成复活幽灵副本并逃逸其真实生命周期。
- **行动结束统一移除**：携带态只在整场战斗行动结束时移除——行动实例离队（移除/完成出队/插队顶替/队列清空/散场结算/迁地重锚）时统一清空；倒地、原地复活、波次轮转、斗法回放均不移除。
- **波中持久化**：战斗进行中的实时 Buff 随 `CombatantSnapshot.Buffs` 持久化（战斗时钟到期时刻），进程重启恢复精确还原，与携带态分工互不重叠。
- **详情面板口径**：战内 Buff 的威胁增幅点数折入属性面板的「威胁增幅」展示值（与 §7.8.1 有效威胁同乘区），面板与目标判定读取同一有效值。
- **作用范围**：战内 Buff 默认作用于持有者单体；**阵法类持续消耗品（`subCategory=formation`）的 Buff 全队生效**——注入己方全部在场单位而非仅使用者（单人与组队同口径：组队按各成员开打定格散布到盟友阵列，同 `buffId` 按成员序后者覆盖）。其余持续消耗品 Buff 仍只加使用者。

## 7.10 斗法（PVP）规约

斗法是历练战斗行动的可选玩法：玩家在战斗行动确认面板勾选「斗法」即同意参与 PVP 匹配，双方为实时结算的同一场战斗。

### 7.10.1 遭遇与匹配

- 勾选斗法的队伍（单人或多人队伍均按一个匹配单位）每次进入战斗按 `duel.settings.encounterChancePerBattle` 概率增加 1 点斗法遭遇计数（默认约两小时一次，允许随机波动）。
- 计数大于 0 时下次搜寻完成进入匹配等待，由撮合运行时在已加载玩家中随机选择实力相近的对手：实力按六维等级总和计算，仅允许 ±`powerBandRatio`（默认 30%）范围内匹配。
- 匹配等待对玩家静默：进入等待不产生任何提示，撮合成功才出现对手并写「斗法遭遇」日志；无候选对手时静默回退为正常波次，遭遇计数保留待下次再试。
- 在线与离线挂机玩家均参与行动与匹配；只有彻底离线（actor 未加载）不参与。
- 斗法失败一方进入 `defeatCooldownSeconds`（默认 3600 秒）冷却，期间不再判定计数与匹配。
- 无撮合能力的离线补算路径保留计数并回退为正常波次，不产生斗法。

### 7.10.2 剧本锁定与弃战

- 撮合成功瞬间冻结双方属性面板、功法槽位与暂存物品清单，一次性推演完整 `DuelScript`；战斗期间任何配置修改不生效，重新进入战斗行动才生效。
- 双方各自回放同一份剧本（`ViewerIsInitiator` 视角翻译）；任一方主动结束行动、调序挪下队首或发起移动即弃战判负，对方立即判胜。

### 7.10.3 收益与暂存区

- 勾选斗法期间战斗物品爆率总增 `dropChanceBonusPercent`（默认 +20%）；掉落的物品先进入暂存区，`stagedSettleSeconds`（默认 1200 秒）后入账；斗法进行中暂存区冻结。
- 暂存区按 `stagedBucketSeconds`（默认 300 秒）档位桶化存储：入账时刻向上量化到桶尾，同一物品同一桶合并为一条，结算时刻 = 桶尾 + `stagedSettleSeconds`——押存窗口为 20~25 分钟，绝不早于 20 分钟落袋；单物品最多 `stagedSettleSeconds/stagedBucketSeconds` 批，暂存列表规模有界。
- 斗法落败时，败方暂存区全部物品转移给胜方；胜方入账走自身模拟的 `AssetDelta` 事务，败方仅清自身分段。
- 每次新战斗行动会话重置本次收益账本，统计修为（`Experience`）、底蕴（`Foundation` 净变动）、战斗经验（`CombatExperience`）、六维经验（`RootExp`）与物品；归档最多保留 `maxBattleReports`（默认 10）条。
- 击杀收益为单参数 `experience`：同额经 `CreditExperience` 结算修为三池、等额累积战斗经验。配表 `experience` 为显式覆盖项——缺省按怪物 `level`+`rank` 派生（`RealmProgressionCatalog.MonsterKillExperience`）：`experience = expToNext[level] / 1000 × 0.9^(level-1) × rankMult`，份额以 Lv1 = 1/1000 为基准、每级指数衰减 10% 渐近 0（同级刷怪的修为条效率随等级递减），层次倍率小怪 1×、精英 3×、妖王 10×；等级超出 `expToNext` 配表上界时按末档非零修为条派生。多人同场击杀按在场玩家平分（共战会话语义见 [第二十一篇 §21.13](./21-同道与组队系统.md)，含掉落增幅加权归属与等级惩罚细则）。六维经验每个归属维度各得全额 `experience × mult_i × eff`（总量 = `experience × eff × Σmult`，非守恒；mult 缺省 1.0、可为 0；`eff = 1 + rootExpEfficiencyPerLevel × (参悟Lv − 1)`），未装内功六维全归属、各得全额（总量 6×），神通/外功不参与分配。修为类收益的 `amp` 另乘内功 `cultivationExpBonusPoints` 独立乘区（见 [第五篇](./05-技能神通与秘籍残卷体系.md) §5.3）。怪物战斗经验不入配表，按其 `level` 经 `CumulativeExpFor` 派生（见 §7.7.6）。

### 7.10.4 队伍斗法（整队为一个匹配单位）

斗法撮合以「单位」为粒度：勾选斗法的单人玩家是单人单位；档案勾选斗法、目标为讨伐且会话进行中的整支队伍是队伍单位（组织与会话语义见 [第二十一篇 §21.13](./21-同道与组队系统.md)）。单人单位与队伍单位同一撮合池、同一实力带口径。

- **开关与冻结**：队伍斗法开关 `pvpEnabled` 是队伍档案字段，仅队长可修改，队员只读可见；仅 `activityKind='combat'` 可为 true，档案目标改离讨伐时自动归位 false。会话创建时把开关冻结进参与规格（`ActionParticipationSpec.PvpEnabled`）；会话存续期间档案开关与冻结值不一致即散场重建（与目标漂移同口径），新会话按新值冻结。
- **单位实力**：单位实力 = 全体出战单位六维等级总和之和（单人即本人六维总和、队伍为全体成员之和），匹配仍限 ±`powerBandRatio`。
- **遭遇计数**：队伍单位的斗法遭遇计数随会话生灭、由会话权威状态承载，随会话每次进入战斗按 `encounterChancePerBattle` 递增；计数大于 0 时下次搜寻完成整队进入撮合等待，回退/等待口径与单人一致。
- **剧本多方化**：`DuelScript` 输入由双方各一名 `DuelCombatant` 扩展为两侧各 1~5 名名单；`DuelScriptEvent` 以双方单位下标定位出手/受击者；回放载荷携带本方名单（成员按 `SelfIndex` 定位自身单位）与对手名单，单方玩家对阵队伍时对手名单即对方全员。剧本撮合时一次性推演完毕，队伍单位全员按同一份剧本各自视角回放，与单人共用同一结算模型。
- **暂存区**：队伍单位每名成员持有个人暂存区；会话勾选斗法期间归属该成员的掉落进其个人暂存区。斗法落败时败方全体成员的暂存物池按胜方成员数均分转移（向下取整，余数按胜方名单顺序补足），入账与清理口径同单人。
- **弃战与冷却**：队伍单位任一成员取消准备、离队、被移出或离线逐出即散场——斗法进行中散场视同整队弃战判负，全体成员各入 `defeatCooldownSeconds` 冷却；单方弃战沿用现有口径。队伍单位再次进入撮合等待要求全体成员均无失败冷却。

## 7.11 成长体系四池与内视协议字段规约

### 7.11.1 四池权威语义

成长体系由四个独立池构成，互不替代、各有结算口径（字段宿主见 [第二篇 §2.2.2](./02-角色核心与常驻实体设计.md)）：

| 池 | 领域字段 | 语义 | 突破时 |
| :--- | :--- | :--- | :--- |
| **修为** | `PlayerProgression.Experience` | 当前层突破计量条（顶部进度条），`expToNext[realmLevel]` 封顶 | **清零** |
| **六维经验** | `PlayerLoadout.CoreAttributes`（`StaminaExp` 等六字段） | 六根各自经验，等级由 `RootAttributeCurve` 经 `RealmProgressionCatalog` 派生的 381 点成本表导出（§3.2.2） | 不清空 |
| **底蕴** | `PlayerProgression.Foundation` | 修为满层溢出沉淀池；未满层时按 1:1 兑换放大修为获取 | **不清空** |
| **战斗经验** | `PlayerProgression.CombatExperience` | 修为类收益按增幅前基础量等额入账，喂给 §7.7.6 对抗修正 | **不清空** |

另有累计口径一条：`LifetimeExperience`（历史修为类收益总量，增幅后口径、含满层转底蕴部分，单调递增永不清零），为前端「总修为」悬浮条数据源。

**修为类收益统一结算公式**（`PlayerProgression.CreditExperience`，连续收益 / 单轮奖励 / 击杀奖励与领域冥想路径共用单点）：记该笔收益增幅后量 `amp`、增幅前基础量 `base`、本层上限 `cap`：

$$\text{credited} = \min\!\left(3 \cdot amp,\ amp + Foundation,\ \max(0,\ cap - Experience)\right)$$
$$Experience \mathrel{+}= \text{credited};\quad Foundation \mathrel{+}= amp - \text{credited};\quad CombatExperience \mathrel{+}= base$$

- 满层时 `credited = 0` → 该笔收益 100% 沉淀为底蕴；
- 未满层时每 1 点底蕴兑换 1 点额外修为，单笔放大最高 3 倍（底蕴耗尽即止）；
- `Foundation` 记**净变动**（可为负：兑换消耗时底蕴减少）；`CombatExperience` 恒按 `base` 入账，满层溢出转底蕴的部分同样计入；
- 修为类收益指入账 `Experience` 池的全部收益（`experience` 类 yields、怪物击杀 `experience`、冥想修为等）；六维经验与物品不经过本结算。

## 7.12 特质系统规约

**特质（Trait）**是单位常驻持有的特殊效果标识：`trait.*` ID 集合随属性面板下发（`CombatantStats.Traits`），设计上分三类、实现上各走各的通道，不做统一抽象：

| 类别 | 生效方式 | 实现通道 |
| :--- | :--- | :--- |
| 纯属性增益 | 面板数值 | 特质 → 属性解析点数/固定值通道汇入面板 |
| 常驻修饰 | 反应/修饰参数 | 特质 → `CombatEffectProfile` 同族点数通道（如 `ThreatOnTakenPoints`），由既有触发器/公式消费 |
| 条件触发 | 时机判定 | 特质 ID 进 `CombatantStats.Traits`，由授予点/触发器按 ID 判定（如开战授予 buff） |

玩家侧载体：`PlayerProgression.TraitIds`（已解锁特质 ID 集合，存档持久化）→ `PlayerAttributeResolver` 折算并透传 → `CombatantStats.Traits`/`Effects`。怪物侧可由配表 `Stats.Traits` 同构声明。特质→效果映射第一版集中于 `CombatTraitRules`（Domain）：点数折算供属性解析调用，开战 buff 映射供遭遇创建调用；配表化（`traits` 词表）属远期扩展。

### 7.12.1 首批特质

- **看不到我（`trait.bukandaowo`）**：开战授予 `buff.yinshen`（持续 10 秒，`ThreatPoints = -100`）——`EffectiveThreat` 乘区归零，敌方针对此单位的威胁权重恒为 0。授予点只在 `CombatEncounterState.Create`（首次开战）；快照恢复由 Buffs 还原不重复授予，玩家复活不视为「开战」不补授。注意 §7.8.2 全零退化规则：若敌方全体候选目标威胁均为 0，退化为等概率抽取——「威胁为 0」是权重归零而非绝对不可选中。
- **力微饭否（`trait.liweifanfou`）**：折算 `ThreatOnTakenPoints = 100`——受到伤害时按攻击方面板原始伤害（减免链前）等额累积自身威胁（§7.8.1 受击累积通道），变相嘲讽。该点数通道对装备 `specialMechanics` 与怪物配表同构开放，不绑定特质 ID。
