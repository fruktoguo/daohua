# 第一篇 顶层哲学与产品定位

**一句话理念**：服务端权威 + 高确定性离散事件推进（DES）+ 长线挂机放置——玩家绝大多数成长由行动队列驱动，离线挂机与在线游玩得到**完全等价的确定性模拟结果**。

五条核心设计铁律（全项目上位约束）：

1. **怪我完全同构**：怪物与玩家在领域模型中完全同构，共享同一套属性池、技能装配、暴击破招对抗与抗性减伤公式，杜绝怪物隐藏补正。
2. **数值全域 `double`**：属性、收益率、倍率、伤害、时间与计数一律 IEEE 754 `double`，百分比存为点数，杜绝整数截断。
3. **离散事件飞跃推进**：不做固定帧轮询，跳跃至下一个到期时间戳做原子状态跃迁。
4. **长线数值闭环量化**：杜绝拍脑袋配表，技能、装备、丹药、怪物属性全部由顶层数学模型（期望属性池、部位权重、质量预算）确定性推导。
5. **本地开发兼容清零**：内测期直接废弃历史兼容包袱，不留双读双写与兼容适配器。

> 真源：[`01-核心哲学与顶层定位.md`](./design/总纲/01-核心哲学与顶层定位.md)（总纲第一篇）。

# 第二篇 角色系统：统一常驻实体

**一句话理念**：修仙者是一个**连续存在的统一常驻实体**——跑图、采集、炼丹、战斗、切磋全是同一个实体在经历世间万象，不存在"战斗模式角色"和"生活模式角色"两套壳。

核心设计意图：

- **拒绝孤立子系统**：彻底打破传统 RPG 把各玩法割裂为状态互不连通的临时模块的做法。气血、灵力、Buff/Debuff、修为、随身资产在时间轴上 100% 连续演进。
- **环境作用力模型**：行为不是模式切换，而是对常驻实体施加的作用力——一切玩法遵循「从 `PlayerAggregate` 读条件 → 计算影响 → 原地写回 → `MarkDirty`」的标准闭环。
- **跨玩法状态穿透**：战后残血保留、Buff/Debuff 实体级统一时间轴衰减、秘境/PvP 以即时状态真实入场、脱战复苏仅给 1 HP 绝不一键回满。
- **体征互锁**：行动队列准入受真实体征约束（气血衰竭无法迎战），Blocked 行动自动轮转让位。

设计红线：

- 严禁设立影子角色（任何玩法不得创建脱离主实体的临时战斗载荷）；
- 严禁跨玩法免费重置（进出玩法不得回满血蓝/清冷却）；
- 严禁浮点截断（微量回复走 `RegenCarrySeconds` 余量累加）；
- 状态演进必须纯函数确定性（禁系统随机数、系统时钟、异步 I/O）。

> 真源：[总纲第二篇 角色核心与常驻实体设计](./design/总纲/02-角色核心与常驻实体设计.md)（全篇，尤其 §2.1 哲学、§2.3 状态连续性、§2.6 红线）；战斗侧落地见总纲第七篇 §7.9。

# 第三篇 行动队列：时间驱动的成长容器

**一句话理念**：玩家的成长不绑定"在线操作"，而绑定**时间轴上的行动序列**——队列是修仙者日程表的权威表达，离线补算与在线推进走同一条确定性路径。

核心设计意图：

- **队列即一切**：采集、修炼、炼丹、历练、赶路全部建模为队列中的行动实例，按到期时间戳离散推进。
- **无限循环语义**：`RemainingRepeats == -1` 代表无限重复，任何模拟推进与单轮结算完成后**绝对不得自动出队**；只有正数次递减至 0、玩家显式取消或资源前置条件断绝才可移除。
- **前置体征准入**：行动开始推进前校验体征条件；Blocked 行动不建账、自动轮转，队列不为单个失败行动停摆。
- **离线=在线**：快进补算与实时推进共用 `SimulationEngine.AdvanceTo` 唯一真源，结果逐位一致。

> 真源：总纲第二篇 §2.4；`backend/logic-development-guide.md`。

# 第四篇 功法系统：内功基座与术法扩展

**一句话理念**：功法分两层定位——**内功是常驻心法基座**（决定灵气周天运转模式、属性转化倍率与基础回气速率），**术法是动态扩展的主动神通序列**（随境界解锁的战斗与辅助法术）。

核心设计意图：

- **1 内功位 + 3 术法位双向互斥**：0 号槽只收 `discipline=internal` 的心法内功，术法位只收 `discipline=spell` 的神通术法；配表用显式 `discipline` 字段划分门类。
- **参悟成长**：功法有独立参悟经验（立方曲线等级），装配等级恒等于已参悟等级，杜绝"槽位调级"的伪成长。
- **现状如实**：当前配表中 `internal` 是嘲讽/清平乐/破阵子等非伤害辅助技的过渡归类——"心法决定周天运转/回气"的理念定位已在文档中声明，真正的心法数值载体待后续配表落地，届时直接配 `discipline: "internal"` 即可。

> 真源：总纲第二篇 §2.2.4；[`04-技能神通与秘籍残卷体系.md`](./design/总纲/05-技能神通与秘籍残卷体系.md)（总纲第五篇，10 门神通清单与数值）；落地互斥规则见 `tasks/TASK-20260919-07.md`。

# 第五篇 装备系统：预算守恒量化配表

**一句话理念**：装备不是策划手填的数值孤岛，而是**部位权重 × 阶位基数 × 品质倍率的守恒预算分配**——每件装备的属性点由数学模型推导，可审计、可推导、可批量平衡。

核心设计意图：

- **6 部位 6.0x 严格守恒**：武器/衣服为 1.4× 权重（核心输出/核心生存），头盔/下装/鞋履/饰品为 0.8×（防护灵能/均衡防御/闪避机动/特殊回复），每件装备的主属性倾斜方向由部位定位决定。
- **两段式数据模型**：基础 14 属性百分比增幅 + 额外固定值与特殊机制（威胁、治疗提升等），显式配置不藏暗桩。
- **强化成长线性**：每级 +2%，+20 满级稳定 +40%。
- **锻造升阶闭环**：T2 = 2 件对应 T1 + 加工主料 + 怪物材料，旧装备是新材料，产出链自洽。

> 真源：[`03-装备标准化预算与锻造升阶体系.md`](./design/总纲/04-装备标准化预算与锻造升阶体系.md)（总纲第四篇，部位权重表与 T1/T2 全量清单）；总纲第十一篇 §11.1.3。

# 第六篇 战斗系统：怪我同构与确定性时间线

**一句话理念**：战斗是**同构单位在同一时间线上的确定性结算**——任何参战单位（玩家、怪物、斗法镜像、未来召唤物）共用同一 `CombatantState` 属性池、同一技能槽、同一触发器与 Buff 管线，无身份分叉。

核心设计意图：

- **怪物=基准×倾向**：普通 80% 属性/300% 生命、精英 120%/500%、领主 150%/2000%；玄甲巨兽、影蝠刺客等倾向模板在基准上量化派生，不做隐藏补正。
- **普攻/吟唱统一动作时间线**：全单位共用出手时钟推导，技能吟唱占用时间线、普攻填充空档；吟唱打断退还预扣灵力且不进入冷却。
- **对抗公式参数化**：闪避/命中、暴击/免爆、破招/化解三大对抗共用 `K=100` 的概率公式族（点数对抗非固定百分比）；伤害链为大类抗性平方穿甲 + 分类增减伤 + 免伤收口，百分比修饰统一走 Linear/NonLinear 双曲线点数（详见 `战斗设计.md` §7.1/§7.5）。
- **反应钩子管线**：吸血/吸蓝/反伤等效果走统一 `ResolveAttack` 插桩点的三阶段钩子，特性可排序扩展。
- **状态常驻进战斗**：血蓝跨战保留、死亡状态下灵力照回而生命锁 0；团灭按遭遇 `onPartyWipe` 分流——`respawn` 原地躺尸续打残局（怪物停手但回复/冷却照走、起身仅补满 HP、躺尸 DoT 全灭算胜、无兜底），`defeat` 终局判负由模式层善后。

> 真源：[总纲第七篇 战斗数值与内视规约](./design/总纲/07-战斗数值与内视规约.md)（§7.3 同构、§7.7 公式、§7.9 常驻与团灭、§7.10 斗法）；总纲第十一篇 §11.2。

# 第七篇 持续消耗品：动作耗时分摊

**一句话理念**：丹药药效的计量单位是**动作实际耗时**，不是自然时间——挂机断续、动作加速、中途切换都不侵蚀药效。

核心设计意图：

- **反传统 Buff 计时器**：传统放置游戏"吃药 5 分钟倒计时"对断续操作和动作加速极不友好；本设计让持续消耗品（引气丹、寻灵香等）仅在角色**实际执行对应动作**时按本次耗时扣减剩余时间。
- **状态保全**：不切槽则剩余时间永久驻留 `AutoUseSlot`，绝不随自然时间流逝。
- **透支免单**：剩余时间不足一次动作时消耗完当前物品并结算完整收益，不足部分免除（玩家小赚）。
- **切槽惩罚**：已开封物品被主动切换/卸下时直接作废不退，杜绝频繁切槽蹭药。

> 真源：[总纲第六篇 持续消耗品机制与生活制造体系](./design/总纲/06-持续消耗品机制与生活制造体系.md)。

# 第八篇 大世界：通用世界地点生态

**一句话理念**：**不存在与大世界割裂的"纯战斗副本"**——所有地点都是真实通用地理节点，承载自己的行动、生灵与可建设施。

核心设计意图：

- **节点三支柱**：每个 `WorldNode` 聚合 ①开放行动集合（采集/炼丹/历练）②驻留生物生态（NPC + 怪物池）③可建公共建筑列表；节点即生态聚合体，不是战斗入口的壳。
- **危险度预算归遭遇不归节点**：`[minBudget, maxBudget]` 战力预算、精英/领主周期、怪群权重池定义在遭遇配表，节点仅通过 `encounterIds` 弱引用——地图与遭遇解耦，同一生态可挂载到不同地理。
- **质量预算遇怪**：单场历练按预算区间确定性抽取 1~3 种怪群组合，精英每 5 波、领主每 20 波周期插入。
- **特色化分布**：每张地图有自己的生灵习惯与危险度，不替世界观做总解释。

> 真源：[总纲第八篇 大世界地图与质量预算遇怪系统](./design/总纲/08-大世界地图与质量预算遇怪系统.md)（§8.1 哲学、§8.3 解耦、§8.4 算法）；`world/maps.md`。

# 第九篇 节点建筑：全民共享公共设施

**一句话理念**：建筑是**节点级公共设施**——无建造者/所有者概念，同节点同种仅一座，任何人可发起建造、填充材料、升级，效果对同地所有玩家生效。

核心设计意图：

- **公共性优先**：刻意去掉"谁的地皮"维度——效果不区分贡献者，营造同地图玩家共建共享的聚集动力。
- **双进度条**：建造/升级需同时满足材料% 与时间%，总进度取 `min`；材料不足停滞、补足继续，按起始时刻惰性推算，无需后台 tick。
- **永久生效、无级上限**：建成即永久；升级期间维持旧级效果、完成瞬间跳变。
- **效果按强度预算接线**：七项 modifiers（采集/炼丹/修炼收益、行动加速、战斗回血/减伤）折算统一预算口径，数值调整只改配表不改规则。
- **状态归节点不归玩家**：真源在服务端节点注册表（`game.node_buildings`），玩家聚合内仅是最近已知投影，跨节点不泄漏。

> 真源：[总纲第九篇 节点公共建筑系统](./design/总纲/09-节点公共建筑系统.md)。

# 第十篇 经济与坊市：资产出聚合、市场单写者

**一句话理念**：随身资产与灵石**不放入玩家聚合分段**，由 `economy` 关系表 + `AssetWallet` 视图承载；坊市撮合是带 fence 的分区单写者事务，与玩家状态用同一事务证明一致性。

核心设计意图：

- **资产与角色状态分家**：材料、丹药、法宝、战利品支持全自动消耗、堆叠与事务内原子扣减，不经聚合分段脏标记链路。
- **灵石=通用硬通货**：坊市交易、传送法阵、阵法驱动的统一货币。
- **市场撮合强一致**：订单、冻结、成交、退款、手续费在 PostgreSQL 同一事务提交；`Serializable` + 行锁 + fence 分区租约保证同分片唯一写者；盘口内存投影可重建、永不当权威。
- **交易不入行动账本**：坊市买卖不属于"行动收益"，不计入统计账本。

> 真源：[`backend/commercial-persistence-architecture.md`](backend/commercial-persistence-architecture.md) §4；`backend/domain-data-architecture.md`；总纲第二篇 §2.2.5。

# 第十一篇 行动统计：三账本

**一句话理念**：收益反馈不只服务战斗——任意行动按**行动实例 / 离线会话 / 每日自然日**三本账持续记录，玩家在任何尺度都能看清"这段时间我得到了什么"。

核心设计意图：

- **战报泛化**：旧战斗战报泛化为全行动统计，统一 `PlayerBattleReport` 结构承载三类账本。
- **生命周期分明**：实例账本随行动建账、出队归档（保留 10 条）；离线账本在 Presence 转 Offline 时重置；每日账本按 UTC+8 自然日 rollover。
- **记账按实际入账量**：修为按秒累加、底蕴记瓶颈截断后的真实增量；Blocked 行动不建账；交易不入账。

> 真源：[总纲第十七篇 行动统计系统](./design/总纲/17-行动统计系统.md)。

# 第十二篇 社交与传音

**一句话理念**：聊天与日志是同源的"信息流"，按作用域分组呈现——世界、附近、好友、队伍、宗门各有频道，日志面板拆组承接系统与战斗事件。

核心设计意图：

- **频道作用域模型**：世界/附近/好友/队伍四类已落地，宗门占位；每作用域服务端保留 100 条。
- **日志事件带频道字段**：同一条事件可路由到对应分组面板，战斗、系统、社交各归其位。
- **好友/队伍轻量先行**：好友与队伍系统已落地（`social` schema），为后续组队玩法留接口但不提前实现假设中的需求。

> 真源：[总纲第十四篇 传音频道与日志分组](./design/总纲/14-传音频道与日志分组.md)。

# 第十三篇 世界观与叙事

**一句话理念**：**碎片化叙事**——不设总答案、不给完整故事；所有事件只从侧面进入，只给后果、残留、误读、传闻和现场痕迹。

核心设计意图：

- **时代定位**：太初时代是万法未立、炁序初显的世道——没有宗门、没有传承、没有写得完的功法，每个修行者独自摸一条看不见的线；底色不是绝望，是"刚学会的事开始变味"。
- **叙事红线（最重要）**：游戏内一切文案不得提及"道劫/旧灾/天穹残宫"等未来语汇；与《道劫余生》的关联只存在于设定文档与玩家自行发现的蛛丝马迹。
- **地图即叙事载体**：每张地图只提供自己的伤痕、习惯、规矩和活法；同一事件允许互相冲突的说法，不强制裁定真假。
- **系统与世界观解耦**：12 阶位是系统数值口径，剧情文案用"未入门/引炁/炼炁/凝炁"沉浸口径，各司其职。

> 真源：[`world/README.md`](world/README.md)（创作原则与红线）、[`world/lore.md`](world/lore.md)、[`world/story.md`](world/story.md)、[`world/maps.md`](world/maps.md)。

# 第十四篇 服务端与持久化架构

**一句话理念**：**应用内单写者热状态 + PostgreSQL 唯一权威持久化**——在线玩家聚合在内存中高频推进，section 快照合并写回；资产、订单、副作用在一个事务里证明一致性；不引入 Redis。

核心设计意图：

- **聚合 + ECS 分片单写者**：`PlayerAggregate` 按 `PlayerSectionKind` 八分段（命令内经文档往返重建）；运行时为 YuoCore ECS——同一玩家按 `PlayerId` 哈希固定路由到 `EcsWorldShard`（`YuoWorld`+`YuoFiber`），命令与模拟推进在分片 Fiber 内串行，`EcsPlayerRuntimeAdapter` 玩家级 `SemaphoreSlim` 保证跨边界串行；跨边界不得直接持有聚合或 `YuoEntity` 引用。
- **唯一真源推进**：挂机时间、产物结算、战斗模拟全部经 `SimulationEngine.AdvanceTo(state, now)`，杜绝第二套执行器。
- **latest-only 落盘**：高频变化只更新内存与 WebSocket，按合并后的 section 定时写回，不记逐 Tick 历史；写回失败必须保留可恢复证据。
- **明确禁止的三种形态**：每玩家一物理表（禁）、一行巨型 Blob 全量重写（禁）、Redis 作关键数据真源（禁）；可重建投影永不当权威。
- **ComputeNode 只做冷挂机补算**：高延迟节点执行确定性补算，不持玩家权威、不直连生产库。
- **容量预算**：2c4g/40g 目标 5000+ 账号、100+ 持续收发、500+ 高峰、2000+ 离线补算。

> 真源：[`backend/commercial-persistence-architecture.md`](backend/commercial-persistence-architecture.md)（持久化唯一权威）、[`backend/domain-data-architecture.md`](backend/domain-data-architecture.md)、[`backend/logic-development-guide.md`](backend/logic-development-guide.md)、总纲 [第十五篇 服务端领域数据架构](./design/总纲/15-服务端领域数据架构与聚合运行时规约.md) / [第十六篇 生产部署与容量目标](./design/总纲/16-生产部署安全边界与容量目标.md)。

# 第十五篇 前端与美术表达

**一句话理念**：前端是**服务端真值的呈现层**——不下注、不估算、不伪造协议载荷；视觉走"暗墨玄石"修仙美学与黑白单彩折面美术风格。

核心设计意图：

- **同源部署**：HTTP/WebSocket 默认 `window.location.origin` 同源，生产代码不硬编码开发端口。
- **真值渲染**：战斗属性、战报、数值一律渲染服务端下发的终值；前端禁止本地估算属性与结果。
- **公共组件强制收拢**：`FloatingPopover`/`RealmBadge`/`ItemTile`/`UnitNumber` 等统一模板（万进紧凑展示、四位分段悬浮），新界面先查公共组件文档再动手。
- **美术基调**：暗墨玄石深黑毛玻璃 + 古典修仙六色调（金/翠/灵蓝/朱红/紫/玄灰）；图像资产遵循黑白单彩折面规范（近黑、骨白、单点饱和强调色、纯黑底、96px 可读性）。

> 真源：[总纲第十三篇 前端UI设计系统与修仙交互规范](./design/总纲/13-前端UI设计系统与修仙交互规范.md)；[`frontend/common-components.md`](frontend/common-components.md)；美术规范见 `../.agents/skills/planar-art/` 与 `../art/`。

# 第十六篇 工程治理红线

**一句话理念**：内测期以**架构清晰为第一原则**——可以直接破坏旧数据与旧结构，但绝不留兼容层、不过度防御、不预先实现假设需求。

核心红线（详见仓库根目录 `../AGENTS.md`）：

- **兼容清零**：禁 migration runner、双读双写、兼容 DTO、legacy flag、fallback adapter；唯一例外是 `../migrations/` 手工 SQL 目录（可整体删除约束）。
- **禁止过度防御**：只在外部输入、跨边界数据、持久化载荷、明确领域不变量处校验；内部路径不层层判空、不吞异常、不静默兜底。
- **协议信封强对齐**：服务端改 `WireMessageType`/信封结构必须同提交对齐前端枚举解析并补往返单测。
- **数值唯一类型**：计算与存储全 `double`，百分比存点数。
- **文档即真源**：新增文档归入本目录对应子目录并登记 `README.md` 索引；临时草稿进 `临时设计讨论/`，定稿沉淀、废弃归档。
