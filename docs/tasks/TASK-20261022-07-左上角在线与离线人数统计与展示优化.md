## 需求背景与核心目标

当前游戏左上角角色名右侧仅存在一个绿色指示圆点加纯数字的胶囊（如 `[ ● 35 ]`）。
1. **歧义与误导**：当前数字由前端代码 `totalCount = (onlineCount ?? 0) + (offlineIdleCount ?? 0)` 计算得出，由于缺乏文本标识且采用翡翠绿色，玩家普遍误认为当前数字是「在线人数」；
2. **离线与总人数感知缺失**：现有服务端仅统计 48 小时内的离线挂机人数（`offlineIdleCount`），未统计全量离线修士总数，导致玩家无法直观感知服内真实总修士数量；
3. **优化目标（去除总数，只显在线、挂机、离线）**：
   - 服务端扩展真实离线修士状态细分：在线（`OnlineCount`）、挂机（`OfflineIdleCount`，48h收益期内）、离线（`OfflineCount`，超出收益期或完全离线）；
   - 左上角胶囊优化为三段式紧凑修仙胶囊：`● 7 在线 · 28 挂机 · 30 离线`，三种互斥状态三色区分（翡翠绿 / 亮金 / 弱灰），小屏自适应隐藏文本标签；
   - 鼠标 Hover 浮层（`FloatingTooltip`）结构化列出网络延迟、在线人数、挂机人数、离线人数，不展示总数行，界面纯粹干练。

## 技术方案

### 1. 服务端统计与协议（Server & Protocol）
- `ISocialRepository` / `PostgresSocialRepository`：
  - 单次查询 `identity.players p LEFT JOIN game.player_projection j` 统计非在线修士总数（`TotalOffline`）及 48 小时收益内挂机修士（`IdleOffline`）；
- `PlayerPresenceStatsService`：
  - 10 秒短缓存同步维护 `_cachedOfflineTotalCount` 与 `_cachedOfflineIdleCount`；
- `Protocol.Contracts`：
  - `PresenceStatsDto` 扩展 `int OfflineCount = 0`；
  - `PongResponse` 扩展 `int OfflineCount = 0`；
- `WebSocketRuntime`：
  - 心跳 Pong 与问候 HelloAck 同步下发 `OfflineCount`。

### 2. 前端状态与协议（Frontend Protocol & Store）
- `protocol.ts`：对齐 `PresenceStatsDto` 与 `PongResponse` 的 `offlineCount` 可选字段；
- `gameStore.ts`：扩展 `offlineCount: number | null` 及 `setPresenceStats` 操作；
- `gameClient.ts`：在 HelloAck 和 Pong 包中解析并存入 store。

### 3. 前端 UI 与交互（App.tsx & styles.css）
- 左上角保持极简状态指示灯（`.connection-dot`）：
  - 默认状态仅展示连接状态小圆点（翡翠绿/明金/暗灰），不直接平铺展开任何人数数字或文字标签，保持顶栏清爽不抢占道号空间；
  - 增强状态灯交互热区（`::after` 拓展 6px）与 Hover 微放缩动效（1.3x）；
- 鼠标 Hover 浮层（`FloatingTooltip`）结构化列出网络延迟、在线人数、挂机人数、离线人数，仅在玩家悬停时按需呈现。
