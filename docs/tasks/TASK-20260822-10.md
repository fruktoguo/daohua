## 2. 需求背景与核心目标

### 2.1 需求背景
在当前项目中，部分业务逻辑、战斗状态、条件判定、运行时临时变量、配置键、消息类型等存在使用 `string` 表示的情况。除必须进行持久化存储（如数据库主键、玩家唯一标识 UUID、持久化 JSON 存档中的必要标识等）之外的非储存字符串，若能替代为强类型（如 `enum`、静态强类型结构体、预定义位标志 `[Flags] enum`、值对象或 `ReadOnlySpan<char>` 等），将带来如下显著收益：
1. **内存与 GC 压力优化**：大幅消除每秒高频 tick / 战斗计算 / 增量同步中的临时字符串堆分配（如 `ToWire`、`ToLowerInvariant`、`Trim`、`Split` 等）。
2. **类型安全与编译期检查**：消除散落在各处的魔法字符串与潜在拼写错误风险，指令和 Payload 实现静态强类型绑定。
3. **网络与协议精简**：WebSocket 信封类型、动作进度、触发器规则由长字符串精简为紧凑枚举/单字节数字，高频增量补丁（Delta）包体可缩减 30%~45%。

### 2.2 扫描范围与分工
- `src/Domain`：领域模型、战斗引擎、世界目录、数值解析、市场模型等。
- `src/Protocol`：前后端通信协议契约、DTO。
- `src/Server`：服务器运行时、WebSocket 消息调度、持久化调度层、基础设施。
- `src/ComputeNode`：冷计算节点批处理模型与错误码。
- `frontend`：前端协议定义、客户端状态与 UI 组件比对。
