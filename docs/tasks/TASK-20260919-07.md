# TASK-20260919-07 · 功法面板修正：移除秘籍物品列表、已习得功法分内功/术法两组、功法 discipline 槽位互斥

## 需求

用户反馈功法面板三处问题：

1. 「已习得功法」区顶部混入背包秘籍/残卷物品使用列表（`ability.learn` 入口），要求移除（该入口已由 TASK-20260919-05 的背包物品操作菜单承接）；
2. 已习得功法列表不分组，要求按「内功心法 / 神通术法」两区展示；
3. 术法类功法可以装配进 0 号内功位——需要类别互斥约束。

经确认：配表新增显式 `discipline` 字段划分功法门类；槽位约束双向互斥（内功位只收内功，术法位只收术法）。

## 取舍说明

- 内功归类标准：当前配表全部功法均为战斗技，将非伤害辅助类（嘲讽/清平乐/破阵子）标为 `internal` 保持内功位可用；后续若新增真正的心法功法，直接配 `discipline: "internal"` 即可。
- 双向互斥会约束增益功法只能装内功位（当前仅 1 格）；如需内功类也可进术法位，改一处过滤与一处校验即可放开。
- 「技能 lv 一直 1」根因：装配槽 `slot.level` 是可调参悟等级但默认 1 且从不自动跟随；而服务端结算里等级只放大输出、灵力消耗不随等级变化，调低纯属负收益。故取消槽位等级输入框，改为展示已参悟等级的静态徽标，发送侧 `normalizeAbilitySlots` 统一把 `level` 回填为参悟等级——存量 1 级槽位在任意一次装配保存后自愈。
- `loadout.replace` 原有 4 个发送点（功法面板、战斗底栏、装备面板换装、背包使用装备），后两个此前完全绕过归一化，存量非法装配会让任意换装命令被服务端整体拒绝；已统一收口到 `sendLoadoutReplace`。
