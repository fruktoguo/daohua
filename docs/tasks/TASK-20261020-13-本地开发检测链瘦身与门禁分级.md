### 3.2 热重启 `scripts/dev-hot.mjs`

- **监听面**：`src/` + `config/game-data/` + `vendor/YuoCore/` = **592 个可监听文件 / 635 个 stat**，每秒全量遍历。
  其中 `src/Bench`(6) / `src/ComputeNode`(11) / `src/DataTool`(2) / `src/LoadTests`(13) 共 **32 个文件**不参与 `src/Server/Server.csproj` 构建，却会触发 Server 重建重启。
- **防抖**：默认 `SERVER_DEV_RESTART_DEBOUNCE_MS = 60000`。改一行 C# → 等 60s 静默 → 增量 build → SIGTERM 旧进程（至多等 30s）→ 新进程 → 重连。

## 4. 实施方案

### 4.1 `dev-hot.mjs`

1. 新增 `WATCH_ROOTS` 常量，收窄到 Server 真实编译闭包：`src/Domain`、`src/Ecs`、`src/Protocol`、`src/Server`、`src/Server.Clean`、`config/game-data`、`vendor/YuoCore`。可监听文件 592 → 560，且 Bench/ComputeNode/DataTool/LoadTests 的 32 个文件不再误触发。
2. 防抖默认 60000 → 3000ms。
3. 修复 `restartPending` 死状态：抽出 `drainQueuedRestart()`，在初次构建、重建、构建失败三条路径结束时统一消费排队变更，构建窗口内的改动不再丢失。
4. `buildAndRestart` 合并重复的 `onBuildExit` 分支，用 `stoppedBeforeBuild` 显式表达 Windows「先停进程再构建」的失败语义（失败时拉起上一次产物）。

### 4.2 启动探针合并

- `reset-outdated-players.sh`：把「漂移玩家数」与「platform 版本」合成单条 SQL（`<漂移数>|<版本>`），一次 `docker exec` 取回；保留迁移后的 `count_stale` 复检（语义不同，不可合并）。
- `seed-market-system-listings.sh`：把「连通性 + 建表状态 + 活跃系统卖单数」合成单条 SQL（`1|<表已建>|<活跃数>`），一次往返替代三次。

### 4.3 `verify.sh` 分级

- 新增 `--fast` / `--backend` / `--frontend` / `--help`，默认全量不变。
- `--fast`：跳过 Compose 校验与 `PostgresIntegration` 集成测试。
- 前端依赖安装改为「`node_modules` 缺失 或 `package-lock.json` 比 `.package-lock.json` 新」才重装，替代每次无脑 `npm ci`。
- 工具链版本检查按模式裁剪。

### 4.4 顺带修复：集成测试标签漂移

`--fast` 的 `--filter "Category!=PostgresIntegration"` 首次运行暴露真实缺陷：18 个已在 `[Collection("PostgresIntegration")]` 集合内的测试类，标签是逐方法零散添加的，且 `EconomyCommitTests`、`ChatAndSocialTests` 有方法漏标，导致 `--fast` 跑出 224 例却带 2 个必然失败用例（缺 `DAOHUA_MARKET_TEST_CONNECTION`）。

改为**类级唯一标签**：每个集成测试类在 `[Collection]` 后紧跟一行 `[Trait("Category", "PostgresIntegration")]`，删除全部方法级重复标签。分类真源由集合成员决定，不再依赖逐方法维护。

## 7. 副作用与后续注意

- `Ecs.Tests.EcsActionQueueMutationTests.ParticipationLeavesAllPersonalCapacityAvailable` 在全量首跑出现过一次失败，单独重跑 3 次均通过；该用例不涉及本次改动，属既有偶发抖动，未在本次处理。
- 本机 `PATH` 上的 `bash` 指向 **WSL 存根**（`/usr/bin/docker` 是另一个 daemon，仓库挂在 `/mnt/d`）。用 `bash scripts/*.sh` 会跑进 WSL 并误伤 Windows 侧 `frontend/node_modules`。脚本验证必须显式走 Git Bash：`powershell -NoProfile -Command "& 'C:\Program Files\Git\bin\bash.exe' scripts/verify.sh"`。
- `dev.ps1` 的 esbuild 探针只验证 esbuild 能否启动，不校验 `@esbuild/win32-x64` 与 `esbuild` 版本匹配，本次实测过该盲区（`esbuild/package.json` 0.27.7 在、`@esbuild/win32-x64` 目录空）。
