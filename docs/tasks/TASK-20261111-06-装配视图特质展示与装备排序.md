# TASK-20261111-06 装配视图特质展示与装备槽位排序

## 需求登记

- **提出时间**：2026-11-11 23:01:18
- **需求原文**：深度优化当前的各个显示。点击角色的展开的详情，里面没有显示特质，在装配里面显示特质；装备的显示顺序不太对，没有固定武器副手这个顺序，武器在最后面。
- **用户确认（2026-11-11）**：覆盖全部装配视图（战斗单位详情弹窗「装配」Tab、内视斗法页、队伍成员信息卡「装配」Tab）；特质仅展示已装配口径。

## 需求分析

### 问题 1：装配区不显示特质

- 战斗单位详情弹窗（`CombatArena → CharacterAttributeModal → CombatAttributePanel → UnitLoadoutSection`）与内视「斗法」Tab 共用装配视图，只渲染功法槽与已穿戴装备。
- 队伍成员信息卡（`PlayerCardModal`）装配 Tab 独立实现功法/战斗装备/技艺装备/战斗消耗品四组，同样无特质。
- 数据链路关键事实：`PlayerAttributes.Traits/TraitLevels` 与 `CombatantStats.Traits/TraitLevels` 本就携带已装配特质（盟友 `ActionParticipantSnapshot.Stats`、斗法镜像 `DuelCombatant.Stats`、队伍信息卡 `PlayerAttributeResolver.Resolve` 均同源），仅缺协议投影。

### 问题 2：装备顺序为穿戴先后序

- `Loadout.Equipment` 为追加序（后穿在后），前端各装配视图按数组原序渲染，武器等后穿装备落在末尾。
- 规范顺序对齐装备管理面板 `EquipmentPanel.ALL_SLOTS`：武器(含 two-hand) → 副手 → 头 → 衣 → 裤 → 饰品(归并 ring/neck/trinket/talisman) → 技艺工具 tool-*（采集/挖掘/炼丹/炼器/符箓/阵法/强化）。

## 实现方案

1. **服务端**：`src/Server/Clean/ProtocolSnapshotMapper.cs` 的 `ToAttributesDto` 两个重载（`PlayerAttributes` / `CombatantStats`）各补 `traits`、`traitLevels` 两个投影字段——一次改动覆盖本机 `combat.attributes`、盟友按需投影、斗法镜像 `opponentAttributes`、敌怪投影与 `PlayerCard.attributes` 全部链路；协议 record（`attributes` 为 object 透传）与领域模型零改动。
2. **前端协议**：`CombatAttributes` 增加可选 `traits?: string[] | null` 与 `traitLevels?: Record<string, number> | null`；`mapCombatAttributes` 白名单解析两字段（缺省容忍，怪物等无特质单位自然为空）。
3. **前端展示**：
   - `combatConstants.ts` 增 `resolveEquippedTraitViews`（traits × traitLevels → `{id, level, def}`，过滤未知 ID）；
   - 新增 `game/equipmentOrder.ts` 槽位序工具（`equipmentSlotRank` + `sortEquippedItemsBySlot`，缺配表稳定垫底）；
   - `UnitLoadoutSection` 增「特质」只读分组（`TraitBarItem mode="codex"`）并对装备排序；
   - `PlayerCardModal` 装配 Tab 增「特质」分组，战斗/技艺装备分别按槽位序排序。
4. **i18n**：新增 `insight.combat.loadoutTraits`；`loadoutEmpty` 文案扩展含特质；同步 `template.csv`。
