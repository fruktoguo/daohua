# TASK-20261008-02 · 万级数值取整失真修复（1.8万 显示成 1万）

- **分类**：Bug 修复 / 数值显示
- **提出时间**：2026-10-08 00:12:00
- **状态**：🧪 联调/验证中（前端 build 全绿；待 UI 目检）

## 需求分析

用户反馈详情中角色生命值 1.8万 显示成「1万」：血条扣减正常（进度条 scaleX 正确），但数值文本丢失万以下全部尾数。

## 根因

`formatInteger` → `formatUnitNumber(value, { maxDecimals: 0 })`，以及所有 `<UnitNumber maxDecimals={0}>` 调用点：

- `formatUnitNumber` 的 `maxDecimals` 应用在**万进制换算后**的值上：18000 → 除以 10000 得 1.8 → `floor(1.8)` = 1 → 「1万」，万以下尾数全丢。
- `<10000` 的分支（`formatWithinDigitLimit`）是对原值取整，行为正常——所以只有 ≥1万 的数值失真。
- 波及面：战场血条徽章（`ArenaResource`）、顶栏战斗血条文本（App.tsx）、附近/生态面板怪物属性、地图怪物卡、掉落数量徽标、全部 `formatInteger` 调用点（跳字、经验、掉落数量、建筑用量、预算区间）。

## 修复方案

- `formatInteger`：原值先 `Math.trunc` 向零取整，再交给 `formatUnitNumber` 默认精度（2 位小数 floor）缩写——「不出现小数」的约定保留在原值层，换算后的 1.8万/1.84万 属单位缩写惯例。负数用 trunc 与原实现（abs→floor→加负号 = 向零取整）行为一致。
- 8 处 `<UnitNumber maxDecimals={0}>` 调用点删除该 prop，恢复默认 `maxDecimals=2`。
- `formatNumber(..., { maxDecimals: 0 })` 的百分比/系数场景（speedPercent 等 <10000 值）走原值取整分支，行为正常，不动。

## 改动清单

- `frontend/src/game/format.ts`：`formatInteger` 实现改为 trunc 原值 + 默认精度，注释说明 maxDecimals=0 的陷阱。
