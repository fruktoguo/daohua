## 1. 需求目标与范围

针对正式服因 `WAL archive`、高频挂机/战斗/制造/掉落写入 `economy.transactions` 与 `platform.section_flush_queue` / pg_wal 写放大导致磁盘打满与 503 的根因，彻底落实以下持久化治理架构：

1. **两层持久化 + 严格 5 类白名单规范**：
   - 玩家状态与资产余额表（`game.player_state_heads`、`game.player_state_sections`、`economy.player_asset_balances`）仅保留当前最新状态与余额，禁止承载行为流水。
   - 所有日常单人高频行动（采集、制造、炼器、强化、秘术、修炼、旅行、PVE 战斗与掉落、`ability.learn`、`item.use`、`progression.heaven_gate`、`item.discard`、`item.sell`、`tutorial.skip`）一律**不写入** `economy.transactions` / `transaction_lines`（`PersistLedger: false`），在线常规 `AdvanceAllAsync` 模拟仅更新内存运行态/钱包并推 WebSocket，**零逐 Tick 落库**。
   - 完整日志/账本流水**严格白名单化**，仅持久记录以下 5 类关键业务：
     1. 市场挂单与成交（`market`、`market.orders`、`market.trades`、`market.settlement_claims`）；
     2. 系统商店购买与绑定功德消费日志（`shop.buy`、`player.unlock_avatar`、`economy.shop_daily_purchases`）；
     3. 玩家账号与角色登入、上线与离线审计（`identity.audit_events`：`auth.account.*` + `player.online` / `player.offline`）；
     4. 完整 PVP 斗法日志表 `game.duel_logs`（Schema `v57` 新增：记录参战双方 ID/昵称/战力、节点、胜负/认输标识以及双方本场损益道具明细）；
     5. 邮件领奖与跨玩家/宗门/组队消耗品/运营发放资产交互（`mail.claim`、`participation.assets`、`building.contribute`、`invitation.*`、`doudizhu.settlement`、`zongmen.*`、`ops.*`；组队战斗个人掉落 `participation.settlement` 维持 `PersistLedger = false`）。
2. **关键节点原子刷盘 + 10 分钟在线安全兜底**：
   - 在线常规推进在内存中合并积累脏 `Sections` 与 `_pendingSimulationDeltas`，仅在以下边界原子同事务持久化并推升 `StateVersion`（确保「状态前进与资产增量同生共死」，绝不单边推进 `LastSimulatedAt`）：
     1. 登录/冷挂机重算装载（`LoadOwnedAsync`）；
     2. 下线/驱逐释放（`RemoveAsync(flush: true)`）；
     3. 优雅停机/显式强刷（`FlushAllAsync` / `FlushAsync(force: true)` / `DisposeAsync`）；
     4. 在线每 **10 分钟**（`Storage:OnlineCheckpointIntervalSeconds = 600`）安全兜底或存在不可丢回执时；
     5. 任何读库对账或库事务类命令执行前（`ReloadWalletAsync`、`ReconcileParticipationOwnedAsync`、商店/市场/捐献等命令、`SocialRuntime.DouDiZhuStart`）；
     6. PVP 斗法正常结算或认输完结时。
3. **统一 30 天滚动留存与高速批删**：
   - `PostgresRetentionWorker` 周期由 1 小时缩短为 **5 分钟（300 秒）**，每轮最多连续排空 8 批。
   - `economy.transient_idempotency`（短期防重键）保留 **2 小时**；非白名单历史 `economy.transactions` 立即分批清除。
   - 所有白名单流水与日志表（白名单 `economy.transactions`、`game.duel_logs`、`market.trades`、无外键引用的终态 `market.orders`、终态 `economy.reservations`、`economy.shop_daily_purchases`、`identity.audit_events`、`identity.account_risk_events`、`market.settlement_claims`）统一滚动保留 **30 天**，超期自动删除（依赖周期备份留档）。
   - `platform.compute_jobs` 已结束任务保留期收紧至 **2 天**。
4. **生产 WAL 与硬盘空间加固**：
   - `deploy/compose.prod.yaml` 关闭连续 WAL 归档（`archive_mode=off`）并移除无用的 `/var/lib/postgresql/wal-archive` 挂载；单机 `2c4g/40g` 拓扑以整点热备 + 每日基线 + 计算节点拉取为准，彻底切断 WAL 归档雪崩写满磁盘通道。
   - 加固 `wal-archive.sh`、`market-ledger-archive.sh`（自动销毁 >30 天历史归档月分区）、`migrate-prod-db.sh`（pre-migration dump 仅保留最新 5 份）、`ccr-auto-update.sh` 与 `deploy-prod.sh`（停用 `daohua-wal-archive.timer`、限制 journald `200M`、清理旧镜像层）。
