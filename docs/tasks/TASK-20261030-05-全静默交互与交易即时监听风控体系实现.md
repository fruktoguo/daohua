# TASK-20261030-05 全静默交互与交易即时监听风控体系实现

## 1. 任务背景与核心目标

在 2026-10-30 生产环境「神」倒金洗钱事件分析中，确立了防范工作室与脚本小号的根本原则：摒弃过度复杂、容易误伤、消耗过大资源的重型硬件指纹方案，收敛为**基于即时信息（Immediate Information）的持续事件监听与实时事务熔断**。

**核心目标**：
1. **前端交互层持续监听**：基于原生事件字段实现轻量级、零性能开销的主动探针：
   - 全局捕获阶段拦截非信任点击（`event.isTrusted === false`，直接扼杀脚本注入点击）；
   - 前驱移动轨迹即时监测（拦截无移动轨迹的瞬移点击）；
   - 触控面积与压力即时判定（抓出 Android 模拟器与无障碍脚本的死板零面积虚拟点击）。
2. **服务端坊市即时熔断机制**：从交易底层彻底断绝洗钱倒金通道：
   - **挂单价格倍率强校验**：普通材料/物品挂单价格不得超过系统回收价的 50 倍，防止以低级垃圾材料作为“天价运钞车”；
   - **撮合关联即时熔断**：在买单撮合成交（`ApplyFillAsync`）的瞬间，比对买卖双方的即时信息，命中「同设备 / 邀请上下级」关系时直接拒绝撮合，彻底阻断定向套现。
3. **服务端 WebSocket 指令发包即时监测**：
   - 记录连接最近连续指令包到达时间间隔，检测死板定时间隔（方差接近 0 的机械脚本循环），即时限流或阻断。
4. **全门禁验证**：补充单元测试，通过 `scripts/verify.sh` 全量门禁校验并闭环提交。

## 2. 详细技术方案设计

### 2.1 前端交互持续监听（`interactionGuard.ts`）

1. **`isTrusted` 全局监听**：
   - 在 `window` 捕获阶段注册 `click` 与 `pointerdown` 监听器；
   - 检查 `event.isTrusted`：凡是由 `element.click()`、`dispatchEvent` 触发的合成事件，`isTrusted` 恒为 `false`，当场阻止冒泡并记录异常。
2. **移动轨迹前驱即时核验**：
   - 持续监听 `pointermove` 与 `touchmove`，记录最后移动时间戳；
   - 点击触发时，若前驱移动时间戳与点击时间戳差距过大（如 > 3000ms 或从未发生过移动），标记为瞬移点击异常。
3. **触控面积与按压力度检测**：
   - 针对 `pointerType === 'touch'`：检测 `radiusX`、`radiusY`（或 `width`、`height`）与 `force`；
   - 若接触椭圆完全为 0（如 `radiusX === 0 && radiusY === 0`），标记为自动化虚拟触控。

### 2.2 服务端交易与撮合即时熔断（`PostgresMarketRepository.cs`）

1. **挂单价格倍率熔断**：
   - 在 `PlaceOrderAsync` 挂单入库前，获取其系统回收价（若为普通材料，`sellPrice` 缺省视为 1）；
   - 若挂单价格 `price > sellPrice * MaxMaterialPriceMultiplier`（默认 50 倍），直接拒绝挂单（抛出 `ArgumentException("挂单价格严重偏离基准价值。")`）。
2. **撮合关联即时熔断**：
   - 在撮合执行 `ApplyFillAsync` 时，已知 `fill.BuyerId` 与 `fill.SellerId`；
   - 校验：
     1. `fill.BuyerId == fill.SellerId`（不可自买自卖）；
     2. 买卖双方是否属于同一主体（`PersonKey` 相同）；
     3. 买卖双方是否存在邀请关系（查 `social.player_invitations` 中是否存在双方邀请记录）；
   - 命中任一条件，事务直接拒绝该成交，阻止小号向大号买单倒金。

### 2.3 服务端 WebSocket 指令发包即时监听（`WebSocketRuntime.cs`）

- 对活动连接维持固定容量（如 5 项）的指令接收时间戳环形缓冲区；
- 统计时间差序列的标准差；
- 若包间隔方差小于 5ms（典型的 `setInterval` 或机械 sleep），即时标记并触发限流。
