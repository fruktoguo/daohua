## 需求与口径对齐

1. **业务目标**：在宗门「同门」成员列表中，为已彻底离线（超过最大离线挂机时长）的成员展示简化离线时长（`xdxh` 格式），并区分三态存在感，便于宗门管理者识别长期不活跃成员。
2. **三态与阈值规则**：
   - 阈值由服务端基于权威最大离线挂机时长（当前为 `PlayerLifecycleRules.OfflineIdleLimit = 48h`，后续可随规则扩容而不要求前端硬编码）动态判定；
   - **在线（`online`）**：`OnlinePresenceRegistry.IsOnline(memberId) == true`，展示绿点；
   - **挂机中（`idle`）**：不在线且距离线锚点未满最大离线挂机时长，展示琥珀色状态点与「挂机中」标签，不显示离线时间；
   - **已离线（`offline`）**：不在线且距离线锚点已满/超过最大离线挂机时长，展示灰点与 `离线 xdxh`（起算点为实际断线时刻 `offline_since`，缺失时依次兜底 `last_active_at` / `created_at`；例如超过 48h 即从 `2d0h` 起算，整天保留 `0h`，若小于 24h 显示 `xh`）。
3. **实现边界**：
   - 不改动数据库表结构，不推进持久化 Schema 版本；
   - 仅改动宗门同门列表与对应协议、投影查询、i18n 词条与回归测试。
