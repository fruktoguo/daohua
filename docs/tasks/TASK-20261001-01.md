# TASK-20261001-01 行动详情弹窗产出按轮合并显示 + 引气入体配表残留收益清理

## 需求

- 提出时间：2026-10-01 00:01:58
- 用户反馈：行动详情弹窗「产出」区对 `cultivation.draw-qi` 同时显示 `修为 +1/秒`、`灵力 +1/轮`、`修为 +10/轮` 三个胶囊，同资源分裂且单位混用。要求：产出只显示每轮口径，直接展示 `修为×10 灵力×10`，有加成时直接显示加成后的数值。
- 用户裁定：收益应在一轮完成后入账，不按每秒结算；每轮产出口径为修为 10 + 灵力 10。

## 根因分析

- 配表 `config/game-data/actions/cultivation.json` 的 `experience 1/秒` 是旧 `qi`（灵气）收益残留：TASK-20260930-01（灵气池废案）任务书要求「移除 `kind:"qi"` 收益」，但合并提交时只改名为 `experience`，导致修为实际入账 20/轮（1×10s + 10），且前端按 `per` 拆成两颗「修为」胶囊。
- `mana 1/轮` 系 TASK-20260915-06 按旧文档口径补入，与用户/早期设计「10s 获 10 修为与 10 灵力」不符，调整为 `mana 10/轮`。
- 前端 `resourceYields` 逐条透传配表 yields，未按 kind 聚合为单轮总量。

## 方案

- 配表三处同源修正：`cultivation.json`、`GameDataCatalog.Default`（Domain 内置兜底）、`frontend/src/game/ids.ts`（前端兜底），统一为 `experience 10/轮 + mana 10/轮`。
- 前端 `calculateActionYieldPreview` 的 `resourceYields` 按 kind 聚合为单轮总量（`per:second` 条目按 `durationSeconds` 折算后并入），胶囊渲染 `×N`（加成后值，保留 1 位小数）。
- 清理 i18n `yieldPerSecond`/`yieldPerRepeat` 词条与 template.csv 行。
- 文档同步：`06-持续消耗品` §6.4.1/§6.4.2/§6.7、`logic-development-guide.md` 结算描述、总纲 index.html 镜像（sync-master-viewer）。
- 测试断言更新：修为 20→10/轮、灵力 1→10/轮、按秒推进相关断言。
