# TASK-20261006-05 讨伐行动迁地重锚：移动后跟随驻留地点续猎 + 「条件不足」阻断 + 行动统计名本地化

## 需求

- 提出时间：2026-10-06 16:52:00
- 需求原文：在落霞桃林进行讨伐任务，移动到青云山门后，行动统计显示「讨伐青云仙山」与实际地点不符；移动后仍在进行上一个地点的讨伐任务且不报地点不符。要求：讨伐任务移动后不再报「地点不符」，直接开始新地点的讨伐；没有目标地点时报「条件不足」；所有显示正确更新，讨伐后的地点为新地点。

## 分析

- `combat.hunt-qi-beast`「讨伐 青云仙山」的 `availableNodeIds` 覆盖青云仙山 7 个节点，节点遭遇各不相同（落霞桃林→`encounter.sunset-ridge`，青云山门→`encounter.twilight-pass`）。
- 远征状态 `action.Expedition` 只在首次准入（`InitializeCombatAction` 内 `Expedition is null`）时解析一次遭遇；移动到另一合法节点后地点校验仍通过，旧遭遇远征原样续跑——即在青云山门继续打落霞桃林的怪。
- 行动统计（StatsPanel）标题直接渲染 `currentReport.actionName`（服务端存的定义名「讨伐 青云仙山」），未走 `localizeActionDisplayText` 驻留地点本地化，与队列/战斗区口径不一致。
- 现状地点门禁：开轮 `availableHere` 失败 → `TryEnqueueAutoTravel`（开关开）或 `action.blocked`「当前位置不允许执行该行动。」——对讨伐行动需替换为「跟随玩家」语义。

## 实现要点

- `CombatExpeditionState` 新增 `IsPinned`（true=钉死/CreateEncounter 手动入战，地点无关恒可续跑；false=池选，跨异池节点须重锚）与 `OriginNodeId`（池选产出节点，仅诊断信息）。缺省 false 恰好覆盖旧存档——v15 及更早载荷两字段均缺失，解码即池选口径，无需回填。存档 schema v15→v16（`migrations/0016_v15_to_v16.sql`，仅标签推进）。
- `CombatActionRules` 新增 `ExpeditionServedHere`（驻留节点遭遇池是否仍供给当前远征遭遇；斗法相位与地点无关恒视为可续）与 `ReanchorExpeditionIfMoved`（迁地重锚：普通相位作废远征由初始化就地重开搜寻；Respawning 相位保留「待起身」语义改挂新地点遭遇复活时长）。
- `EcsPlayerActionContext.NodeEncounterIds`：节点实体成员关系仅在会话提交时迁移，会话内 `World.NodeId` 已先于实体更新——实体节点与 `World.NodeId` 不一致时返回 null 回退 WorldGraph，避免抵达新节点后仍读到旧节点遭遇池。
- `TryStartActionCore`：准入成功后对 `CombatEncounter` 行动执行重锚；讨伐行动地点校验失败时跳过 `TryEnqueueAutoTravel`，阻断文案改「条件不足，行动受阻。」。
- `ActionExecutionRules.Pipeline.PrepareQueue`：准入前记录远征迁地标记，准入成功且仍挂接旧战斗实体时经 `ReleaseCombatBattle` 释放（模拟内挂起路径的遗留实体），`e.Battle` 置空。
- `frontend/src/components/StatsPanel.tsx`：当前账本标题先按 `actionId` 回查目录定义名（`resolveActionDefinition`，与 CombatArena 同口径）、再经 `localizeActionDisplayText` 按驻留地点本地化——存档 `actionName` 滞留旧地点本地化文本时不再卡死；历史战报（RecordsPanel）保留原始记录名不做地点重写。
- 测试：`tests/Domain.Tests/CombatRelocationTests.cs`（迁地重锚/战斗中作废/同池续跑/复活相位保持/条件不足且跳过自动移动）；`tests/Ecs.Tests/EcsCombatRelocationTests.cs`（旅行插队释放旧战斗实体 + 新节点遭遇池重锚）。
- 文档：总纲 02 篇 §2.4.2 自动移动补讨伐例外；08 篇 §8.5 地点约束段补讨伐迁地语义。
