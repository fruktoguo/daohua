## 需求

用户提供一张 5 列网格排列的 26 格物品图标大图（前 5 行各 5 个，第 6 行 1 个居中），
并按「从左到右、从上到下」给出了 26 个物品名称的对应顺序。要求：

1. 把大图拆分为多个独立小图并压缩；
2. 让前端正确加载这些图片，替代原来的纯文本名称；
3. 形成通用规则：**物品 ID 有图就加载图，没有就回退文本，且适用于全部物品展示位。**

## 实施方案

### 一、切图（离线脚本，不进仓库）

脚本 `/tmp/split_item_icons.py`（Python + Pillow + numpy），流程：

1. **背景识别**：`min(R,G,B) >= 228` 视为白底候选。
2. **外边界 BFS**：从图像四边向内洪水填充，只把**与画布边连通**的白像素判为背景，
   因此图标内部的奶白色书页不会被误挖空。
3. **行/列投影切分**：行投影阈值 `60`、列投影阈值 `20`。
   阈值取 60 的原因：残卷四周散落的**碎片**会在行方向把相邻两行粘连，阈值过低时 6 行会并成 5 段
   （实测阈值 20/60/120 均可得 6 段，阈值 200 会把第 6 行整行吃掉）。
4. **透明通道**：背景置 `alpha=0`；紧邻背景的一圈按亮度做**羽化**（`(255-min)/60` 线性映射），
   消除 JPEG 压缩在深色底上留下的白描边。
5. **缩放压缩**：长边缩放到 `128px`（物品瓦片为 64px，128px 即 2 倍图），
   保持原始宽高比（残卷/秘籍非正方形），量化到 256 色后以 `optimize=True` 存 PNG。

产物：`frontend/src/assets/items/<itemId>.png`，共 26 张、合计 `167KB`（单张 5.3–8.0KB）。

### 二、前端图标注册表（通用规则落地点）

新增 `frontend/src/game/itemIcons.ts`：

- 用 `import.meta.glob('../assets/items/*.png', { eager: true, query: '?url', import: 'default' })`
  在**构建期**扫描目录，把文件名（去掉 `.png`）登记为物品 ID → 图标 URL 的映射。
- 导出 `resolveItemIconUrl(itemId)`（无图返回 `undefined`）与 `hasItemIcon(itemId)`。

这样「有没有图」完全由**文件是否存在**决定，新增图标只需丢一个文件，
不需要维护任何清单、开关或兜底分支，天然满足「适用于全部」。

### 四、样式

- `styles/selection-grid.css` 新增 `.item-tile-icon`：**绝对定位铺满瓦片**
  （`top/left:0; width/height:100%; box-sizing:border-box; padding:5px; object-fit:contain`）。
  瓦片本身是 `display:grid`，若让图标参与网格流会与左上角品类丝带、右上角 Lv、右下角数量**争抢行高**；
  绝对定位后丝带（`z-index:3`）与角标照旧叠在图标之上，且瓦片 `overflow: visible` 不裁剪。
- `styles.css` 新增 `.item-reference-icon`（16px、`vertical-align:-0.2em`、右间距 3px）。
- `styles/floating-popover.css` 新增 `.daohua-floating-card-title-group` 与
  `.daohua-floating-card-title-icon`（24px）。
  标题行是 `justify-content: space-between` 的三子元素布局，直接插图标会把标题挤到中间，
  因此用 group 包裹「图标 + 标题」，保持徽章仍然靠右。
