# TASK-20261112-15 技能/消耗品统一触发器调度底座

## 需求

用户提出：技能与消耗品应走完全一致的「固定触发器」模型——按各自条件推导出订阅哪些事实（敌方变化、生命值变化、人数变化等），边界结算完只唤醒订阅命中的激活触发器；蓝量/血量不足、CD 未竟、库存为零时槽位设为非激活，避免每边界全槽扫描；两者共用同一实现。

## 方案

### 架构（条件→依赖→唤醒→求值）

```
触发条件 JSON ──TriggerWakePlanner──▶ SlotWakeMask 订阅位
                                        │
战斗边界结算 ──CombatFactTracker──▶ CombatFactDelta（单位通道 diff + 集合/外部/时钟事实）
                                        │
                CombatBoundaryHookDispatcher（内嵌 tracker）
                   ├─ FoldPendingWake → 各单位逐槽 SkillWakePending 累积
                   └─ afterBoundary(context, delta)
                          ├─ 消耗品：mask.WakesOn → 仅唤醒命中槽（首趟），级联后续趟全量
                          └─ 技能：出手边界 DecideNextAction 内逐槽 pending∩mask==0 → 复用判定
```

### 词表→订阅位映射（`TriggerWakePlanner.ResolveSingle`）

| 对象 | 条件 | 订阅位 |
| --- | --- | --- |
| self | hp/mana 族 | Self.Hp/Mana \| Self.Stats（百分比读上限） |
| self | buff-stacks | Self.Buff + Facts.External（外部视图不可 diff 兜底） |
| self | is-*/status | 空（静态/恒零，一次首评后缓存） |
| target(-enemy) | 任意 | 对方侧 Alive\|Threat\|condCh + 对方 List（身份随威胁/存活/名单变） |
| *-lowest/highest-hp | 任意 | 本侧/对方侧 Alive\|Hp\|Stats\|condCh + List |
| ally/enemy 集合 | 数量/存在性 | 侧 Alive + List |
| ally/enemy 集合 | *-percentage | 侧 Alive\|Hp/Mana\|Stats + List |
| battle | elapsed-seconds | Facts.Elapsed（每边界恒置位，等价旧语义） |
| 词表外 | 任意 | Full 全量兜底 |

消耗品槽位在条件掩码上追加 `Facts.External`（钱包脏/面板刷新兜底）与雷击符 `Self.Mana`（灵力门槛跨越唤醒）。

### 激活/休眠状态机

- **条件不满足**：槽位保持订阅，事实不翻转即不占判定；
- **CD/持续未竟**：`PendingConsumableWake`/`ConsumableWakeUnix` 精确唤醒边界全量复查（既有机制）；
- **库存为零**：会话共享钱包变更置 `_walletDirty` → `hook.MarkExternal()` 并入下一边界增量 → 含 External 位的槽位唤醒；单人钱包窗口内定值，天然无需唤醒；
- **判定缓存**：技能 `verdicts/pending/targets` 逐槽独立累积（CD 拦下的槽位不因别的槽消费增量而丢唤醒）；`encounter.WakeTracking` 为假时恒全量重评（周期模式/无钩子路径自动退化）。

### 关键正确性约束

1. `MatchesAll` 为纯读求值，跳过不改变随机流/事件序列——掩码只是「注定相同结果的判定」的跳过证明；
2. 目标按出手计数重掷 → `SkillVerdictTargets` 引用不一致即重评；
3. `CombatFactTracker` 构造时作废全部既有判定缓存（追踪前未折叠的变化必须强制重评）；
4. 级联首趟掩码、后续趟全量（自身激活翻转的事实不在边界增量内）；
5. 数组长度变化置 `AllyList`/`EnemyList` 集合事实，新增单位快照槽全通道翻转。
