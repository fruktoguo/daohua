## 需求

用户提出：在 mac 本地弄一个类似生产 Caddy 的东西，这样访问本地开发环境不需要输入端口。

用户裁定：

- 协议：**HTTP 80**（最简，不引入本地 CA）。
- 域名：**`daohua.localhost`**（浏览器按 RFC 6761 自动解析到回环，无需改 `/etc/hosts`）。
- 集成方式：**接入 `dev.sh`**（随本地启动自动拉起、退出级联清理）。
- 运行方式：**Docker 化 Caddy**——排查发现本机**未安装 Homebrew**（`/opt/homebrew`、`/usr/local/bin/brew` 均不存在），改由容器运行 Caddy，同时免去 `sudo`（容器端口转发由 Docker Desktop 处理）。

## 现状分析

- 生产部署已用 Caddy（`deploy/daohua.yuohira.com.caddy`，反代 `127.0.0.1:15128`），本地缺同构入口。
- 本地前端 dev server 固定 `127.0.0.1:15172`（`strictPort`），后端 `127.0.0.1:5128`；`/api`、`/ops/api`、`/ws` 由 Vite 代理到后端。
- 本机 `caddy`、`mkcert`、`dnsmasq`、`brew` 均未安装；80 与 443 端口空闲；Docker 可用。
- 实测 Vite 7 接受 `Host: daohua.localhost`（HTTP 200），无需追加 `server.allowedHosts`。

## 方案

1. 新增 `deploy/caddy-local.Caddyfile`：`http://daohua.localhost` 反代到 `host.docker.internal:{$DAOHUA_FRONTEND_PORT:15172}`。
   - 用 `host.docker.internal` 而非回环地址：Caddy 在容器内，回环指向容器自身，必须经 Docker Desktop 的宿主机别名才能访问宿主上的 Vite。
   - Caddy 自动处理 WebSocket 升级，覆盖游戏 `/ws` 与 Vite HMR。
2. `scripts/dev.sh` 在前端就绪后尝试以容器方式拉起 Caddy（`docker run -d --rm --name daohua-local-caddy -p 80:80`）；Docker 不可用、80 被占用或容器启动失败时**跳过并提示**，不阻断启动；`cleanup` 用 `docker stop` 级联停止。
3. 文档同步：`README.md` 本地前端章节、`AGENTS.md` 脚本清单、任务登记。

## 安全与前提

- 容器端口转发由 Docker Desktop 处理，**不需要 `sudo`**；本机无需安装 Caddy 或 Homebrew。
- 本地 Caddyfile **不**复制生产的 `/ops`、`/api/metrics`、`/readyz` 等私有路径拦截（本地面板与诊断端点需要可用）；生产拦截仍以 `deploy/daohua.yuohira.com.caddy` 为准。
- `DAOHUA_LOCAL_PROXY=0` 可显式关闭本地域名入口。
- 首次运行需拉取 `caddy:2-alpine` 镜像。

## 验收

- `dev.sh` 在 Docker 不可用 / 80 被占用 / 正常三种情况下行为正确（提示或拉起，均不阻断）。
- 实测（本机已完成）：`http://daohua.localhost/` 200、`/ops` 200、`/ops/api/overview` 200、`/api/v1/meta` 200。
- `dev.sh` 退出后 80 端口释放（容器 `--rm` 自动删除）。
