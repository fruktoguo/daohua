## 2. 需求与核心意图
用户反馈：
> “优化，我希望日志中，如果是完全相同的日志，可以在后面加上一个小胶囊，就是乘多少多少多少，相当于把完全重复的日志直接合并一下。”

在长时间挂机修炼（引气入体）、批量采集灵草矿石、连续击杀同类低阶妖兽时，日志面板中往往会产生大量连续且完全重复的条目（如反复刷屏“获得 伴灵草 × 1”）。
这导致两个严重问题：
1. **视觉噪音高**：大量相同的文本挤占日志视口，关键历史日志（如境界突破、稀有装备掉落、重大遭遇）被迅速滚出视口；
2. **缓冲容量被刷空**：受限于前端日志内存环形缓冲（100条），100 次相同的采集会把之前的所有其他事件全部挤丢。

因此，需要在前端日志系统（数据服务层 `gameLogService` 与渲染展示层 `GameLogPanel`）落地**完全相同日志连续折叠去重机制**，并在重复项末尾以修仙金石微光的小胶囊标识倍率（如 `× 3`、`× 42`），同时显示最新触发时刻并在悬停气泡中提供精确重复频次说明。

## 3. 技术架构与设计方案

### 3.1 相同项判定规则
- **判定标准**：以日志模板语义源码 `template` 作为唯一判定依据（`curr.template === prev.template`）。
- **连续折叠（Consecutive Deduplication）**：
  - 仅合并连续产生的相同日志；
  - 一旦中间插入其他不同日志（如打怪日志中断了采集日志），后续再产生的采集日志将开启新的条目，严格保证时间线的因果时序与因果连续性。

### 3.2 数据层支持 (`gameLogService.ts`)
- 在 `GameLogEntry` 中扩展：
  ```ts
  export interface GameLogEntry extends StoredGameLog {
    segments: readonly LogSegment[]
    count: number // 重复次数，默认为 1
    latestTimestampMs: number // 最新一次发生的时间戳
  }
  ```
- 增量与快照折叠算法：在 `GameLogService` 维护的最新队列中，若追加的日志与当前末尾日志的 `template` 完全一致，则直接对末尾日志的 `count` 进行递增（`count += 1`），更新 `latestTimestampMs` 为最新事件时间戳，不占用新的缓冲槽位。
- 这样 500 次挂机采集仅消耗 1 个槽位，历史其它不同事件得以完好保留！

### 3.3 表现层与胶囊组件 (`GameLogPanel.tsx` & `styles.css`)
- 当且仅当 `count > 1` 时，在日志内容尾部渲染 `.log-repeat-capsule`。
- 胶囊文案采用国际化与视觉紧凑规范：`× ${count}`。
- 时间戳展示更新后的 `latestTimestampMs`，Tooltip 提示 `连续发生 ${count} 次 (首发: ... 末次: ...)`。
- 遵循玄门古籍修仙美学，暗金色微光边框与半透明墨色背景（`--gold-bright` 与 `--gold-dim` 微光阴影），与已有的 `.log-reference` 和 `.value-capsule` 风格完全一致。
