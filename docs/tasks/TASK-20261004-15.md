# TASK-20261004-15 · 强化模型对齐 1.05^N 指数 + 装备 +N 徽标 + 背包装备消失回归修复

- 提出时间：2026-10-04
- 分类：数值模型修正 / 前端体验 / Bug 修复
- 状态：🧪 验证中

## 需求分析

用户提出三项：

1. **强化效果为每级 +5% 指数提升**：设计真源 `expected-attributes.json` 各阶位 `enhancementMultiplier` 实际值均为 1.05^期望等级（+3→1.1576、+20→2.6533），但公式标签、总纲 §4.2、`PlayerAttributeResolver` 与前端悬浮卡均按旧的「每级 +2% 线性」口径实现/书写——实现与文档双双偏离权威基准，按用户口径统一回 1.05^N 指数。
2. **强化等级显示在物品左下角（+0 不显示）**：悬浮卡标题与物品瓦片补 +N 徽标。
3. **背包不显示装备（回归）**：`RightSidebar` 的「已装备隐藏」过滤按整个 `itemId` 剔除，引入 +N 变体后同物所有强化等级行被株连隐藏。

## 关键修改

### 强化模型 1.05^N 指数（文档先行）

- `docs/design/总纲/04-装备标准化预算与锻造升阶体系.md` §4.2：公式改为「强化总倍率 = 1.05^等级」，+20 ≈ 2.653×。
- `docs/design/总纲/20-技艺体系与符箓阵法强化规约.md` §20.4.1：同步指数口径。
- `.agents/skills/data-designer/SKILL.md` §5.4：技能内嵌公式同步。
- `config/game-data/expected-attributes.json`：`enhancementMultiplierFormula` 标签修正为 `1.05 ^ EnhancementLevel`（数值本已一致）。
- `src/Domain/Combat/PlayerAttributeResolver.cs`：`flatStats`/`baseStatRatios` 乘区改为 `Math.Pow(1.05, enhancement)`；`specialMechanics` 不缩放（不变）。
- `frontend/src/components/ItemDisplay.tsx` `describeEquipmentEffects`：同口径 `Math.pow(1.05, level)`。
- `tests/Domain.Tests/AttributeRevisionCacheTests.cs`：+5 断言更新为 `50 × 1.05^5`。

### 装备 +N 徽标与悬浮卡标题

- `ItemTile` 新增 `enhancementLevel` Prop：>0 时左下角 "+N" 胶囊徽标（`.item-corner--bottom-left` 金色），+0 不显示；`bottomRightLabel` 覆写语义不变。
- `ItemTooltipCardContent` 标题：`enhancementLevel > 0` 时追加 `+N`。
- 透传落点：`ItemCard`（背包变体行）、`EquipmentPanel`（已装备槽位）、`MarketEnhancementPicker`（强化等级选择行）、`MarketOrderModal`（挂单预览）、`ItemGridPicker`（网格挑选与使用槽位两处）。

### 背包装备消失修复

- `RightSidebar`：`equippedIds`（itemId 集合）改为 `equippedCounts`（`itemId#level` → 件数）Map；行过滤条件改为「钱包持存 − 同级已装备件数 ≤ 0 才隐藏」。
- `InventoryItemCell`：`equipped` 判定改为「同级已装备件数 ≥ 钱包持存」（全数穿戴）；新增 `bagItem` = 扣减已装备后的背包可支配数量，用于瓦片/悬浮卡数量与丢弃/回收弹窗上限。
