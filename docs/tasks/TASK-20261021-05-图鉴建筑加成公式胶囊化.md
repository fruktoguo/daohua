## 需求

用户报：万象图鉴「建造」分类里，多数建筑 Hover 悬浮卡没有正确显示加成数值。以丹房为例，应显示为「炼丹行动速度增加 10% + 2%×建筑等级」这一类**公式形态**；其余建筑同理。加成的属性名需要用胶囊高亮。

## 根因

`frontend/src/components/CodexPage.tsx` 的 `CodexBuildingEntry` 手写了一串字段 if 链：

1. **只读 `building.modifiers`**（等价于 `baseModifiers`，即 Lv.1 静态基准），完全忽略 `growthModifiers`。因此所有建筑看起来都是恒定加成，玩家无法得知升级收益——这正是「没有正确显示加成数值」的直接来源。
2. **字段覆盖不全**：只处理 6 个字段，漏掉 `gatheringSpeedRatio` / `miningSpeedRatio` / `forgingSpeedRatio` / `talismanSpeedRatio` / `formationSpeedRatio` / `enhancementSpeedRatio` / `combatManapointRegen` / `monsterWeakenRatio` / `explorationSpeedRatio` / `alchemySpeedRatio`。实测 11 座建筑全部只显示部分或不显示效果。
3. **单位与符号错误**：`combatHitpointRegen` 被写成 `/秒`，配表与总纲 §9.4 均为「每 5 秒固定值」（`/5秒`）；`monsterWeakenRatio` 被写成正号 `+`，实际是折减语义应为 `-`。
4. **纯文本渲染**：未走 `PillBonusLabel` 胶囊体系，属性名/数值无色调区分，违反「属性加成必须胶囊高亮」的统一视觉规范。
5. 同一卡片内的「建筑类型 / 建筑等阶 / 公共设施 · xx」为硬编码中文字面量，绕过 i18n。

## 方案

### 1. 数据层：新增公式解析（`src/game/buildingCalculations.ts`）

- `BuildingBonusDescriptor` 增加 `glyph` 字段（属性小图标 ID，指向 `frontend/src/assets/glyphs/` 现有资源），15 个修饰项逐个登记。
- 新增 `BuildingBonusFormula` 与 `getBuildingBonusFormulas(definitionOrModifiers, resolveLabel?)`：
  - 遍历 **全量** `BUILDING_BONUS_DESCRIPTORS`（不再手写字段链，新增修饰项字段只需在描述表登记即自动出现在图鉴）；
  - 同时输出 `baseText`（Lv.1 基准）与 `growthText`（每级增幅），完整表达总纲 §9.4 的 `Effect(L) = Base + Growth × (L − 1)`；
  - 缺 `growthModifiers` 时按 `extractModifiers` 既有口径回落基准值（与服务端 `GameDataCatalog.BuildingDefinition.Modifiers` 同语义）；
  - 复用 `formatBuildingModifierValue`，因此单位（`/5秒`）与负号（怪物削弱）自动正确。

### 2. 视图层：图鉴悬浮卡（`CodexPage.tsx`）

- 删除手写 if 链，改用 `getBuildingBonusFormulas`。
- 每一行：`PillBonusLabel`（`StatGlyph` 属性小图标 + 名称胶囊 + 色调下划线数值）+ 其后「每级 +2%」成长小字，即用户要求的「基准 + 每级增幅」完整形态。
- 无任何修饰项时回落到配表 `effect` 文案，不留空块。
- 分类名、`建筑类型` / `建筑等阶` / `公共设施 · xx` 全部改走 i18n（`combat.nearby.group*` 与新增 `app.codex.building*`）。
- 原 `lines` 属性移除：效果已进 description 区块，避免同一信息在卡片里出现两次。

### 3. 样式（`styles/codex.css`）

新增 `.codex-building-bonus-list`（纵向排列）、`.codex-building-bonus-row`（换行自适应）、`.codex-building-bonus-growth`（每级增幅小字）。整体复用现有 `pill-tone--*` 与 `.capsule-label` / `.underlined-value`，不引入新色彩体系。

### 4. i18n

`app.codex` 新增：`buildingType` / `buildingTier` / `buildingSubtitle` / `buildingBonusGrowth`；模板 CSV 自动重新导出。
