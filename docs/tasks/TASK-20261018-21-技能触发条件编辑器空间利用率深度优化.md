# TASK-20261018-21 技能触发条件编辑器空间利用率深度优化（行级规整排布与轻量原位微标签控件）

## 1. 任务背景与核心诉求

用户在配置功法与战斗消耗品的施放触发条件时（`CombatTriggerEditor` 模态窗），反馈当前界面空间浪费极其严重：
1. **正方形超大区域占比浪费严重**：
   - 现行实现中由于 ChoiceMenu 继承了网格选择器的正方形宽高比规则（`aspect-ratio: 1` 且宽度拉伸至 100%），导致每个仅有一两句短语的选择项（如「观察对象：自身」、「判断属性：生命百分比」、「比较方式：不高于」）被放大为近 200px × 200px 的超大正方形方块；
   - 周围大量留白，视觉极度空洞、笨拙。
2. **两行割裂导致单卡片高度失控**：
   - 三个正方形占据首行后，第四个字段「阈值 (%)」被孤立排在第二行首列，右侧 2/3 区域全部闲置；
   - 单条规则卡片高度膨胀至近 260px，弹窗内部列表仅能勉强容纳 1.5 条条件，配置 4 条条件时需频繁滚动翻找，整体空间利用率极低。
3. **Modal 叠 Modal 交互沉重**：
   - 原先每个正方形按钮点击后还会呼出第二层全屏模态遮罩对话框（ChoiceMenu 内部弹出 `Modal`），交互链路严重被打断，缺乏紧凑的原位选择流畅感。
4. **深度优化目标**：
   - 彻底摒弃 200px 庞大正方形，重构为**精致紧凑的微标签行级表单（Compact Inset-Label Row Form）**；
   - 单条条件的所有参数（观察对象、判断属性、比较方式、数值阈值、可选 Buff）规整排布在**同一水平行**内，高度从 260px 缩减至约 44px~52px（降幅超过 70%）；
   - 4 条触发条件在弹窗中**一屏尽览、零滚动**，空间利用率与信息密度成倍提升；
   - 下拉选择改为原位轻量浮层菜单，免除全屏弹窗遮罩干扰；响应式支持移动端优雅自适应折行。

## 2. 技术设计方案

### 2.1 紧凑微标签字段组件 (TriggerSelectField & TriggerValueField)
- 设计专属触发条件字段组件，取代臃肿的 `ChoiceMenu`：
  - **外壳尺寸**：高度固定为 40px（触屏 42px），边框轻微修仙暗金描边（`rgba(201, 180, 109, 0.22)`），背景 `rgba(255, 255, 255, 0.03)`，圆角 6px；
  - **内部排布**：两行紧凑结构（上方 9px 语义微标签 Label，如 `对象`、`属性`、`判定`、`阈值`；下方 12px 粗体当前值 + 优雅小下拉三角 `▾`）；
  - **原位浮层菜单**：点击展开基于轻量 Popover 或绝对定位的原位下拉列表，带有修仙暗墨微光背景、选中高亮与滚轮支持，点选后立刻更新并自动收起，点击外部自动关闭，彻底消灭二级 Modal。

### 2.2 单行规整流网格排布 (Compact Single-Row Grid)
- 结构调整：
  ```
  .combat-trigger-card
    ├── .combat-trigger-card-header (条件序号徽章 + 自然语言高亮摘要 + 右侧删除按钮)
    └── .combat-trigger-fields (并排 4 列网格 / 自适应 5 列)
          ├── 观察对象 (1fr)
          ├── 判断属性 (1.4fr)
          ├── 比较方式 (1fr)
          ├── [Buff选择] (1.2fr，仅 buff-stacks 激活)
          └── 阈值数值 (1fr，带 % / 点 / 层 动态单位后缀)
  ```
- 整张卡片纵向高度压缩至约 74px~80px，4 条条件总高约 320px，在弹窗可用高度内完美容纳，用户无需滚动即可纵览并自由调整全部 4 条条件。

### 2.3 动态单位与自适应折行
- 针对百分比属性动态渲染 `%` 单位，固定数值属性渲染 `点`，Buff 层数渲染 `层`；
- 移动端小屏幕（$\le 640\text{px}$）自动降级为紧凑两列双行网格，避免挤压溢出。

### 2.4 状态层数统一语义与具体状态自然语言呈现
- **去除独立状态比较分支**：移除未实装的预留控制项（`stun-status`、`blind-status`、`silence-status`），将全部 Buff 统一收拢至“状态层数（buff-stacks）”判定；
- **默认判断为大于 0**：选择状态层数时，比较方式默认设为 `greater-than`（大于），阈值默认设为 `0`（即“有该状态”，无该状态则为“等于 0”）；
- **注入具体状态名称与“当...时”自然语言模板**：`describeCombatTrigger` 与 `resolveTriggerBuffName` 深度联动，顶部总览与卡片头部完整呈现形如 `当 目标 的 凝神茶 状态层数 大于 0 时` 的流畅修仙句式，彻底告别单薄的“状态”二字；
- **状态选项扩展**：全面录入引气、凝神茶、赤焰符、止血散、顺气丸、隐身等常用战斗状态。
