## 需求原文

> 不对啊，草庐这加25%修炼别给我删了，然后我希望，地图里面查看地点，能看到玩家建筑，而不是只能看到系统的。

## 需求分析

- 「草庐加 25% 修炼」= 云巅草庐 `building.peak-cottage`（绝顶道庐）陈设卡，文案「吐纳修炼效果提升 25%」
  对应节点 `cultivationMultiplier: 1.25` 真实数值——用户裁定保留，TASK-20261013-07 误删恢复；
  抚琴石台（静心悟道）仍为纯陈设，维持移除。
- 「查看地点能看到玩家建筑」= 大地图选中任意节点时，「地标与设施」块目前只渲染配表陈设
  `selectedNode.buildings`；玩家公共建筑（`world.nodeBuildings`）只下发当前节点，其它节点看不到。
- 玩家建筑是节点级共享动态数据（`NodeBuildingRegistry` 注册表 + `game.node_buildings` 表），
  不属于配表目录、也不属于单个玩家分段，不宜塞进 `world` 快照段（会引起全玩家校验和抖动）。
- 方案：新增只读端点 `GET /api/v1/world/node-buildings`，由注册表已发布快照按节点返回
  `{buildingId, level, targetLevel}` 索引（沿用读路径惰性完工口径）；前端地图面板挂载时拉取，
  并在 `world.nodeBuildings` 变化（本节点建造/升级/贡献反馈）时刷新，合并进地点详情建筑块。

## 实现方案

1. `NodeBuildingRegistry.AllBuildingsAsync(now, ct)`：`EnsureLoaded` 后遍历已发布快照节点，
   逐个走 `BuildingsForAsync`（含惰性完工结算），返回 `nodeId → NodeBuildingSnapshot` 字典。
2. `Program.cs`：`GET /api/v1/world/node-buildings`（RequireAuthorization）投影
   `Record<nodeId, [{buildingId, level, targetLevel}]>`，等级用 `EffectiveLevel`，配表缺失条目跳过。
3. 前端 `apiClient.ts` 新增 `fetchNodeBuildingIndex`；`types.ts` 新增 `MapNodeBuilding` 摘要类型。
4. `WorldMapPanel`：挂载拉取索引 + `world.nodeBuildings` 引用变化时刷新；地点详情建筑块在
   陈设胶囊后追加玩家建筑胶囊（`名称 Lv.N` / 建造中 / 升级中 → 复用 `buildingLevelValue` 等 i18n key，
   名称/描述/效果文案由建筑目录 `state.buildings` 解析）；当前节点优先用快照实时数据。
5. 配表：恢复 `node.cloud-peak` 的 `building.peak-cottage` 陈设卡。
6. 设计文档 §9.5 增补地图浏览与端点说明；校验：Release 构建 + 三套测试 + DataTool strict + 前端构建。
