## 背景与根因

v0.2.10 部署后主服日志持续出现两类线上症状，经查均为**潜伏存量缺陷**，非本次发布引入：

1. **组队会话战斗远征状态误判无效**（`fix(combat)`）：
   `CombatExpeditionState.IsValid` 强制 `PlayerRespawnAtSeconds` 仅限 Combat 相位，
   但组队会话设计本就把「本机成员倒地复活剩余读条」跨波携带进 Search/InitialSearch 相位
   （`AdvancePreparationResources` 逐段递减、入场时折算回战斗时钟）。
   队长倒地由队友清波 → Search 相位携带复活剩余秒数 → IsValid 判无效 →
   每个推进拍抛 `DomainException` 且状态不保存 → 会话自 2026-11-11 01:12 UTC 起永久卡死。
   修复：IsValid 放宽至 `Combat / InitialSearch / Search` 三相位；新增队长倒地跨波采样回归测试。

2. **玩家快照 schema 版本不受支持（客户端整批锁死）**（`fix(protocol)`）：
   客户端门禁为严格全等 `schemaVersion !== SNAPSHOT_SCHEMA_VERSION`，
   任何 codec 版本推进（含可缺省 additive 升级）都会锁定全部旧构建客户端。
   根治：协议引入「读者地板」`minReaderSchemaVersion`——服务端声明仍可解码的最老客户端版本，
   客户端接受一切地板不高于自身版本的载荷。additive 升级不抬地板、旧客户端透明续用；
   破坏性升级抬地板后干净拒绝。契约已登记 `AGENTS.md` 与 `migrations/README.md`。
