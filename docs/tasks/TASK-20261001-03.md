## 需求

在审计结论基础上直接开始持续化架构工作，优先把已存在的 OOP 队列变更和统计副反应收敛到 ECS 同步执行入口。普通命令、普通推进、批量推进必须共享同一规则；不把网络、数据库、事务、协议或纯公式强行改为 System。

## 设计先决

- 总纲 18 的目标是 System 持有规则本体、Component 持有状态本体；宿主继续持有输入、事务和持久化边界。
- 队列的 `-1` 无限循环、队首激活、战斗取消回血、战报归档、状态版本和脏段顺序属于不可改变的不变量。
- 统计记账仍按行动账本→离线账本→UTC+8 每日账本顺序同步更新；载荷使用已经结算的增量，System 不重新计算收益。
- `EcsActionExecutionComponent` 的快速批量路径不能因为新增 tag 而漏执行副反应；必要时由同一规则服务显式进入同步派发。
