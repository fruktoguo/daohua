## 1. 需求背景与核心目标

### 1.1 背景现状
- 目前项目在 `tools/combat-simulator.html` 存在一个早期的非权威独立演示页面，但其顶部明确声明：“非权威演示工具，数值与真实引擎脱钩……硬编码属性锚点，不读取配表，亦不建模灵力消耗与敌方出手，输出结论不可作为线上数值依据”。
- 随着游戏技能触发器体系（`SkillTriggerEvaluator`）、五行抗性平方穿甲模型（`ResolveHit`）、多盟友组队战斗（Allied Combat）、灵力回复与技能消耗规则以及怪物生态预算刷怪（`EncounterWaveSelector`）的成熟，玩家与数值设计迫切需要一个能够在**玩家浏览器本地离线运行、逻辑与服务端后端 100% 逐位一致**的完整战斗模拟器。

### 1.2 核心业务需求
1. **参战人员选择与导入**：
   - 支持一键导入自身当前的完整战斗属性、装备、技能槽与 triggers 触发条件。
   - 支持一键导入当前队伍中的队友属性与装配（若存在）。
   - 支持手动增删改 1~5 人阵容的参战单位，支持微调基础/特殊属性与技能配置。
   - 支持配置方案导入与导出（JSON）。
2. **环境与时长指定**：
   - 支持选择全游戏大地图任一节点（自动解析其生态与遭遇池）或指定遭遇战。
   - 支持设置模拟推进时长（快捷选项：10分钟、1小时、4小时、8小时、24小时，或自定义秒数）。
   - 支持指定确定性随机种子（Seed）或随机生成。
3. **完全一致的后端逻辑对齐**：
   - 确定性随机流：SplitMix64 位运算算法（`DeterministicRoll.Next`）。
   - 遭遇与怪物波次生成：预算轮盘、精英波间隔、Boss波间隔（`EncounterWaveSelector`）。
   - 技能与动作决策：槽位优先、触发条件求值、灵力扣减与吟唱读条、普攻回落（`CombatActSystem` 与 `SkillTriggerEvaluator`）。
   - 伤害与抗性结算：破招/化解 -> 命中/闪避 -> 暴击/免暴 -> 抗性平方穿甲 -> 攻方增伤 -> 守方减伤（`ResolveHit`）。
   - 周期回复与状态推进：5秒回复网格，生命与灵力自然回复，Buff 结算。
   - 搜寻与复活推进：波次搜寻读条、团灭复活读条。
   - 收益掉落计算：怪物掉落表抽取（`DropTable`）、击杀经验与修为分配。
4. **主要测试与评估指标**：
   - **战斗胜利波次**：总场次、胜场、败场/团灭数、胜率、最高通关波次、妖怪击杀明细（普通/精英/Boss）。
   - **战斗收益**：掉落物品汇总清单（图标、品质、数量、每小时产出速率）、总修为经验、每小时经验速率。
   - **灵力缺口深度分析（核心亮点）**：
     * **灵力缺口时间占比**：技能 CD 已好且触发条件满足，但因灵力不足无法施放的总卡蓝等待时间占战斗总时间的百分比。
     * 各技能卡蓝触发次数与累计延迟施放秒数。
     * 平均灵力水平与最低灵力谷值。
     * 智能诊断与平衡优化建议。

## 2. 架构设计与技术方案

### 2.1 运行模式与前端架构
- **纯前端 TypeScript 高性能确定性仿真器**：
  无需向服务端发送网络模拟请求，无需 WebAssembly 额外编译负担与依赖。在浏览器 JS 引擎中，推演 24 小时的离散战斗事件仅需数十毫秒。
- **目录结构划分（`frontend/src/game/simulator/`）**：
  - `deterministicRng.ts`：确定性随机数生成器（采用 BigInt 实现无符号 64 位运算，完全复刻 `DeterministicRoll.Next`）。
  - `skillTriggerEvaluator.ts`：技能触发条件求值器（完全复刻服务端的 `SkillTriggerEvaluator.MatchesAll` 与条件解析）。
  - `combatSimulatorCore.ts`：确定性战斗核心推进器（包含单位属性换算、动作决策、伤害结算、5s回复、Buff管理）。
  - `expeditionSimulator.ts`：波次与远征调度器（包含地图遭遇池解析、怪物阵容抽取、搜寻读条、复活读条、掉落与经验结算）。
  - `manaDeficitTracker.ts`：灵力缺口分析追踪器（精确按技能槽打点卡蓝开始/结束区间，统计时间占比与耗蓝占比）。
  - `simulatorTypes.ts`：模拟器配置、参战人员、地图遭遇、指标报表等完整类型定义。

### 2.2 核心算法对齐矩阵

| 模块 | 服务端 C# 实现文件 | 客户端 TypeScript 对齐实现 | 关键一致性保证 |
| :--- | :--- | :--- | :--- |
| **随机流** | `src/Domain/Combat/DeterministicRoll.cs` | `deterministicRng.ts` | 64 位 BigInt 混合，同 (seed, side, count, channel) 必得相同 53 位浮点值 |
| **波次生成** | `src/Domain/Combat/EncounterWaveSelector.cs` | `expeditionSimulator.ts` | 预算轮盘、强度上限、每5波精英、每20波Boss完全一致 |
| **条件求值** | `src/Domain/Combat/SkillTriggerEvaluator.cs` | `skillTriggerEvaluator.ts` | 全部对象（self, target-enemy, ally, enemy）、属性（hp%, mp%等）与比较符逐词一致 |
| **动作决策** | `src/Ecs/Systems/CombatActSystem.cs` | `combatSimulatorCore.ts` | 槽位顺序扫描、CD判定、条件短路、灵力扣除、吟唱与普攻读条计算 |
| **伤害计算** | `src/Ecs/Combat/DeterministicCombatEngine.cs` (ResolveHit) | `combatSimulatorCore.ts` | 破招化解、命中闪避、暴击免暴、抗性平方减伤 `raw²/(raw + res*K + 1)`、各乘区增减伤 |

| **掉落与奖励** | `src/Ecs/Systems/CombatActionRules.cs` | `expeditionSimulator.ts` | 掉落判定主种子递推、数量抽取专用盐位 XOR、经验分配 |

### 2.3 灵力缺口（Mana Deficit）量化模型
- **定义**：
  在任意战斗时刻 $t$，对于角色的任意可用技能槽 $i$：
  - 判定条件：$CooldownUntil_i \le t$ 且 $Triggers_i$ 求值为真；
  - 缺蓝状态：$CurrentQi < QiCost_i$；
  - 若满足上述条件，则进入**灵力不足等待区间** $[t_{start}, t_{end}]$，直到 $CurrentQi \ge QiCost_i$ 成功起手，或战斗结束/目标死亡触发条件不满足；
  - 该区间的时长 $\Delta t = t_{end} - t_{start}$ 累加至该技能的卡蓝总时长 $T_{deficit, i}$。
- **全场灵力缺口时间占比**：
  $$\text{Qi Deficit Ratio} = \frac{\bigcup_{i} \text{DeficitIntervals}_i}{\text{Total Combat Active Time}} \times 100\%$$
- **智能诊断等级**：
  - `< 2%`：**灵力充沛（流畅释放）**，技能循环顺畅无阻；
  - `2% ~ 15%`：**轻度卡蓝（偶有滞涩）**，在爆发期存在短暂等蓝；
  - `15% ~ 40%`：**中度缺蓝（输出受阻）**，技能因缺蓝出现显著施放延迟；
  - `> 40%`：**严重枯竭（蓝量瘫痪）**，长时间处于普攻平砍，急需补回蓝内功、药品或调低消耗。
