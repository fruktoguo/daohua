## 2. 问题根因分析

1. **攻击动作驱动源错位**：
   - 当前攻击方（玩家或敌方）出招动作 `actionMotion` 依靠 `useEffect` 监听 `action?.completesAtUnixMilliseconds` 计算未来倒计时播放。
   - 当服务端结算完一轮攻击下发快照时，`completesAtUnixMilliseconds` 实际上代表的是下一次攻击的截止时间；这导致当次造成伤害的动作未被当次事件驱动，甚至在攻速较慢时几秒后才突兀挥刀。
2. **受击与跳字 0ms 抢跑（因果倒置）**：
   - 受击方在接收到快照的第 0ms 瞬间扣血、弹出跳字浮字、爆出血条切片并播放受击震颤；
   - 而攻击方的突进与出招动画在 CSS 中有前摇蓄力过程（挥砍突进到达最远刀锋点约需 200ms，施法聚能爆发约需 280ms）；
   - 结果表现为：刀未出手，受击方已扣血跳字；随后攻击者才慢半拍冲上去挥刀，严重缺乏打击感与攻防节奏。

---

## 3. 实施方案

1. **事件驱动攻击方立即起手（Attacker Motion on Event）**：
   - 当 `recentEvents` 或斗法回放事件到达时，识别 `attackerId`，立即令攻击方触发对应动作动画（`attack` 突进挥砍或 `cast` 施法蓄力），告别依赖未来倒计时的错位。
2. **受击方击中帧锁步调度（Hit-Frame Lockstep）**：
   - 普攻挥砍击中帧定为 200ms，施法爆发击中帧定为 280ms。
   - 受击方的受击受挫（`impact` 红闪与晃动）、伤害跳字（`ArenaResource.effects`）、血条破裂切片（`shards`）与闪避身法（`dodging`）精确延迟至对应击中时刻触发，做到刀刃砍中或道法轰击的瞬间完美卡点爆开。
3. **独立保底机制**：
   - 无显式事件的持续伤害（DoT）或气血自然变动，仍走即时响应通道，保证常规扣血/回血不漏。
