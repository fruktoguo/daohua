## 需求

用户裁定玩家三态为核心主旨（总纲 §1.2 第 5 条，不再变更）：

1. **在线**：全部运算服务端实时进行，事件实时推送。
2. **离线挂机**（未超离线上限）：队伍中有人在线 → 全员强制实时；全员离线 → 小时级批次冷算，主服与计算节点按负载分配；未到批算点即回线 → 主服即时完全补算。
3. **彻底离线**（超离线上限）：退队、行动队列暂停；进入时补算「断线 → 上限边界」全部收益（可非实时），登录免补。
4. **切换阈值**：连续离线 5 分钟才进入离线挂机。

## 设计决定（实现口径）

- **离线锚点** `OfflineSinceAt`：随 settings 分段持久化，与 `Presence` 同生命周期——转离线时写入断线时刻，转在线时清空。实体创建时（运行时装载、冷算、主服验证三路同一 `EcsWorldShard.CreatePlayer`）统一规范化：持久化为在线的必是崩溃残留（装载即意味本进程刚取得所有权）→ 按离线处理、锚点取 `LastSimulatedAt`；离线但缺锚点（v30 旧档）→ 锚点取 `LastSimulatedAt` 并标脏落盘。
- **只有连接生命周期改在线状态**：握手 `AttachConnectionAsync` 转在线；宽限到期卸载转离线（锚点 = 断线时刻）。社交强拉、HTTP 快照、注册装载一律不改在线状态，取消社交层「按注册表复位」补丁。
- **收益封顶** = `min(请求起点 + 48h 保险丝, OfflineSinceAt + 48h)`；`offline.capped` 事件只在跨越封顶边界的那次请求发一次。48h 改为 Domain 常量 `PlayerLifecycleRules.OfflineIdleLimit`，不再可配。
- **读模型** `game.player_projection.offline_since`：逐出、会话离线截止、冷扫描统一以它判定离线时长；`last_active_at` 不再参与任何生命周期判定。
- **宽限**：断线后实体常驻、在线位保留、按在线实时推进；宽限内重连直接复用；到期才注销在线位并卸载。
- **批算**：冷扫描取「离线、无运行时租约、无会话绑定/待消费结算、距上次结算 ≥ 批算间隔」的玩家，目标 = `min(当前, 锚点 + 48h)`；到达封顶边界即入队终末批（目标 = 边界）。扫描不再受计算节点配置门控。
- **本地执行器**：主服消费同一 `compute_jobs` 队列，复用验证器的独立重演结果直接写回（与节点结果同一落库事务）；节点派发只领取积压超过阈值的任务。
- **组队**：有人在线的活跃会话，离线成员常驻装载实时消费；全员离线会话按批算间隔推进，推进后逐成员强拉消费结算；散场同样强拉消费离线成员终局结算。
- **已知边界**：服务器崩溃（非优雅停机）时在线玩家的投影在线标记残留到其下次被装载；单实例部署下宽限期内换实例重连需等宽限到期释放租约。
