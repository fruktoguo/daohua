## 1. 需求与问题背景

用户反馈在坊市（`MarketPage`）操作时存在严重的交互割裂与状态重置：
1. 当用户切换了一级 Tab（如材料/装备/功法）、二级子 Tab（如矿石/防具/残卷）、输入了搜索关键词并滚动到某一位置后，点击物品进入标的挂购详情；
2. 点击“返回列表”，界面全部重置为“全部”分类、空搜索词，列表滚动位置也强制重置回顶部（0）；
3. 当用户从坊市切换到游戏其他主面板（如储物袋、内视、历练、技艺），再切回坊市时，之前的浏览选择和详情视图也被全部抹除重置。

用户要求：
**“希望这个界面的数据保持不变，不管是切换界面还是怎么”**。

---

## 2. 核心瓶颈分析

1. **局部组件内部状态易失性**：
   - `primaryTab`、`subCategory`、`query` 均作为 `MarketBrowseGrid` 的局部 `useState` 存放；
   - 当 `selectedItemId !== null` 时，条件渲染直接将 `MarketBrowseGrid` 从 DOM 中彻底卸载（Unmounted），导致所有局部 state 和滚动位置被垃圾回收。
2. **顶层页面卸载与上下文丢失**：
   - `App.tsx` 中 `{activeTab === 'market' && <MarketPage />}` 在切换面板时将 `MarketPage` 彻底销毁；
   - `MarketPage` 内部的 `selectedItemId`、`activeTab` 随之丢失，导致再次切回坊市时一切从零初始化。
3. **滚动位置缺少恢复机制**：
   - `.market-browse-grid` 容器的 `scrollTop` 未作记录与恢复，重新进入时必定位于 0。

---

## 3. 技术解决方案架构

### 3.1 独立轻量状态管理中心 `frontend/src/game/marketStore.ts`
基于项目统一的 Zustand 架构，建立 `useMarketStore`：
- `primaryTab: PrimaryCategory`（默认 `'all'`）
- `subCategory: string`（默认 `'all'`）
- `query: string`（默认 `''`）
- `scrollTop: number`（默认 `0`）
- `activeTab: MarketTab`（默认 `'browse'`）
- `selectedItemId: string | null`（默认 `null`）
提供对应的更新 Action，保证无论是组件局部卸载还是整页切换，状态都在内存中常驻。

### 3.2 滚动位置无缝记忆与还原 (`Scroll Restoration`)
- 在 `MarketBrowseGrid` 中挂载 `gridRef`；
- 在 `onScroll` 时记录最新 `scrollTop`；
- 在组件挂载与依赖项稳定后，通过 `useLayoutEffect` 将 `gridRef.current.scrollTop` 瞬间平滑对齐；
- 配合既有的 `content-visibility: auto` 与 `contain-intrinsic-size`，确保滚动高度计算 100% 准确，无视觉抖动。

### 3.3 详情与浏览视图切换保持
- `selectedItemId` 同步由 store 保留，并可在需要时一键返回，也可以记忆当前处于详情还是浏览列表；
- 点击返回时清除 `selectedItemId`，列表及其分类 Tab、搜索文本、滚动位置完整保留。
