## 需求理解与实现预期

### 1. 业务目标
优化战斗与详情页的「统计」弹出面板（`StatsPanel`），在保留既有详细账本的基础上，新增默认展示的「简要」速率收益面板，直观反馈玩家当前行动的每日灵石收益（xxx万/天）、每小时战斗场次、每小时修为与经验产出，并支持队伍成员间相互查看当前行动收益。

### 2. 核心逻辑预期
1. **视图 Tab 切换**：
   - 增加【简要】与【详细】双模式 Tab，默认为【简要】模式。
   - 【详细】模式：保持既有 `ReportBlock` 完整内容（基础信息、物品得失、经验与升级、斗法暂存与结果）。
2. **【简要】模式计算与展示**：
   - 根据当前行动账本自开始以来的真实流逝时间（$T_{\text{hours}} = \frac{T_{\text{seconds}}}{3600}$）进行速率换算。
   - **战斗频次**：若为战斗行动或存在遭遇/击杀，展示每小时战斗次数（$N_{\text{encounters}} / T_{\text{hours}}$ 次/小时）。
   - **每日灵石收益**：提取获得物品列表，按照物品市场参考价（坊市成交均价 > 系统回收价 > 0）估算总灵石价值，按 $V_{\text{daily}} = \frac{V_{\text{total}}}{T_{\text{hours}}} \times 24$ 计算并格式化呈现「xxx万/天」。
   - **经验与修为**：计算并展示「每小时经验」（`combatExperience / hours`）与「每小时修为」（`experience / hours`）。
3. **队友行动收益查看**：
   - 当玩家在队伍中且队友数量 > 0 时，统计面板顶栏增设成员切换页签（[我]、[队友名1]、...）。
   - 选择队友时，经由现有的 `PlayerCardRequest` 流程查询队友信息卡，服务端在 `PlayerCardDto` 中携带其当前行动账本 `CurrentReport`。
   - 队友面板同样支持【简要】与【详细】展示；若队友未处于行动中，优雅展示空态。

### 3. 边界与不变量
- 不修改战斗与行动调度核心结算引擎。
- 协议扩展遵循 `Contracts.cs` 契约，以可选参数（`CurrentReport = null`）形式无缝兼容旧客户端。
- 前端严格遵循公共组件规范（`docs/frontend/common-components.md`）与 i18n 覆盖门禁。
