- 新增物品「功德」：分可交易与不可交易两种，本期只作占位（后续再接入实际消耗用途）。
- 奖励规则（本次需求数值，勿与 daojie-yusheng 参考实现混淆）：
  - 被邀请者注册成功：+1000 绑定功德、+10000 灵石；
  - 邀请者（对方注册时）：+1000 绑定功德；
  - 被邀请者突破至练气期（境界等级 19）：双方各 +1000 绑定功德；
  - 被邀请者突破至筑基期（境界等级 31）：双方各 +2000 绑定功德。

## 设计定稿

- 物品：`item.gongde`（功德，isTradable=true 占位）与 `item.gongde-bound`（功德·绑定，
  isTradable=false、sellPrice=0）。采用 `item.` 前缀进入物品目录，绑定物由此获得
  目录名/描述/isTradable 契约，`market.place` 服务端补 IsTradable 拦截，`item.sell`
  由 sellPrice<=0 天然拒绝。
- schema v13：`identity.players` 增 `invite_code varchar(16) NOT NULL`
  （volatile DEFAULT 兼作存量回填与测试直插兜底，注册路径仍显式写随机码）
  + 唯一索引 `ux_players_invite_code`；新增 `social.player_invitations`
  （invitee_id 主键、inviter_id、invitation_code、highest_realm_level、
  qi_rewarded、foundation_rewarded）。
- 注册事务内：风控 → 账号 → 按邀请码解析邀请者（新码尚未入库，天然不可能自邀）
  → 玩家行（含自身邀请码，撞唯一索引整体重试新码）→ 会话 → 邀请关系 +
  `PostgresEconomyRepository.CommitCoreAsync` 双方注册奖励 → outbox → 提交。
  无效邀请码回滚并报 INVALID_INVITATION_CODE。
- 里程碑：`progression.breakthrough` 成功后调 `IInvitationRepository.GrantMilestonesAsync`，
  Serializable 事务内 SELECT FOR UPDATE 邀请行 → 到期的里程碑逐一 CommitCoreAsync
  入账（幂等键 `invitation.milestone.{qi|foundation}:{inviteeId}`）→ 翻转领取标记与
  highest_realm_level，同库同事务保证钱与标记同生同灭；崩溃/失败下次突破幂等重放。
  在线邀请者经 `_walletReloadRequired` 失效 + 日志缓冲 + LogBatchEmitted 通知；
  离线者下次加载自然读到余额。
- HTTP：`RegisterRequest` 增 `invitationCode`；新增 `GET /api/v1/invitation`
  （RequireAuthorization + player_id 会话声明）返回本人邀请码与被邀请人列表。
- 前端：LoginPage 注册表单增邀请码输入，`?invite=<code>` 打开时自动切注册页并预填；
  SocialPage 增「邀请」子 Tab（邀请码/链接复制 + 被邀请人境界进度列表）；
  `SocialSubTab` 扩 `'invite'`；i18n 词条与 ids.ts 物品元数据同步补齐。
