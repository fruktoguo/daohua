## 需求理解与实现边界

### 1. 业务目标
针对标的卡片和组件重构中暴露出的隐蔽失误（重构卡片时因属性可选漏传 `itemId`，导致瓦片图片图标大面积静默退化为纯文本兜底），结合道化太初前端的整体设计架构与公用组件体系，沉淀一份权威、严密、前置的前端规则文件 `frontend/AGENTS.md`，并在根目录 `AGENTS.md` 中强化对应的红线约束，从制度和门禁层面根除同类错误。

### 2. 核心规约范围
1. **前端整体设计与架构边界**：
   - 纯 React + Vite 客户端，服务端权威，确定性计算同构；
   - 公共组件唯一真源文档 `docs/frontend/common-components.md`，统一模板强制收拢。
2. **实体视觉呈现强标识契约（硬红线）**：
   - 凡展示物品、装备、材料、功法、技能、Buff 等实体，一律图标化展示（`ItemTile`、`ItemIcon`、`ItemReference`）；
   - **强 ID 绑定防降级红线**：上下文持有实体 ID 时，必须无条件显式向组件传递 `itemId` / `abilityId`，严禁仅传 `name` 导致图标解析丢失退化为纯文本瓦片；
   - **类型系统防呆原则**：组件核心字段明确要求，业务调用端禁止假定参数可选而漏传。
3. **角标与数据维度隔离规范**：
   - 严格区分数量（`amount`，前置 `×`）与单价/自定义标签（`bottomRightLabel`，无 `×`）；
   - 样式类名严格匹配模式（`.is-onsale-mode` / `.is-bid-mode` / `.is-price-mode`），并具备完备的深浅主题适配。
4. **关键渲染路径静态契约防回归门禁（测试硬防线）**：
   - 凡核心交易网格、背包、仓储、制造等卡片组件，必须在单测中登记源码级 AST / 匹配断言，任何漏传核心属性在测试期即被阻断。
5. **状态管理与交互不变量**：
   - Zustand store 严禁空方法，保持输入焦点与滚动位置，无障碍 aria-label 完整支持。
