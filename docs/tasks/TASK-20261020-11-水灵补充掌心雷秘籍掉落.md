# TASK-20261020-11 水灵补充《掌心雷》秘籍/残卷掉落

## 1. 任务背景与核心需求

用户需求：「让水灵的掉落也掉掌心雷，但不放」。

拆解为两条硬约束：

1. **投放**：水灵（`enemy.water-spirit`）掉落表增加 `item.tome.palm-lightning` / `item.fragment.palm-lightning`。
2. **不装配**：只投放物品，**不**把 `ability.palm-lightning` 塞进水灵技能槽——水灵的战斗行为保持仅施放甘露。

## 3. 口径依据（总纲先行核对）

- `docs/design/总纲/08-大世界地图与质量预算遇怪系统.md` §8.3 掉落梯度规范：**普通小怪整本秘籍 0.001、残卷 0.02**。水灵为 minion，直接沿用该口径，与木灵/火灵完全同规格。
- `docs/design/总纲/04-装备标准化预算与锻造升阶体系.md` §4.6.3 普通妖兽 **Common EV : Rare EV = 20 : 1**：破碎灵核单价 12，Common EV = 12.0；20:1 要求 Rare EV ≈ 0.6，即**两对**秘籍（每对 0.001×100 + 0.02×10 = 0.3）。木灵（掌心雷 + 吐纳功）、火灵（轰炎 + 清心诀）均为两对，而水灵此前只有甘露一对（Rare EV 仅 0.3，实际落到 40:1）。补入掌心雷一对后水灵回到 20:1，与木灵/火灵严格对齐。

结论：本次改动既是用户需求，也顺带修平三灵之间的掉落期望比值差异。

## 4. 实现内容

### 4.1 设计文档（先行）

`docs/design/总纲/04-装备标准化预算与锻造升阶体系.md` §4.6.3：

- 该条目由「T1 木灵 / 火灵」扩为「T1 木灵 / 火灵 / 水灵」，逐怪列出两门秘籍构成（木灵：掌心雷 + 吐纳功；火灵：轰炎 + 清心诀；水灵：甘露 + 掌心雷）；
- 明确写入 **「掉落投放与怪物技能槽解耦」** 的设计约束：水灵只投放《掌心雷》秘籍/残卷而**不装配该技能**，技能槽仍为甘露。防止后续维护者看到「掉掌心雷」误以为水灵该施放掌心雷。
- `docs/design/总纲/index.html` 由 `scripts/sync-master-viewer.mjs` 重新生成内嵌快照，保持查看器与篇目一致。

### 4.2 配表

`config/game-data/monsters/tier1_minions.json` 的 `enemy.water-spirit.dropTable` 在甘露两对之后追加：

| 物品 | dropChance | 数量 |
| :--- | :--- | :--- |
| `item.tome.palm-lightning` | 0.001 | 1 |
| `item.fragment.palm-lightning` | 0.02 | 1 |

`skills` 段**未改动**，仍为单一 `ability.ganlu`。

物品本体（`manuals.json` 售价 100/10、图标与 i18n 词条）早已存在，无需新增。

### 4.3 回归门禁

`tests/Domain.Tests/CombatSkillTests.cs` 的 `GanluAbilityScalesWithSpellAttackAndFollowsMaxKeepStackingPolicy` 追加三条断言：

- 水灵掉落表含 `item.tome.palm-lightning` 且概率为 0.001；
- 含 `item.fragment.palm-lightning` 且概率为 0.02；
- 水灵技能槽**不含** `ability.palm-lightning`（锁定「只投放、不装配」这条不变量，防止后人把掉落误当技能来源回填）。
