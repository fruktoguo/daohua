# TASK-20260923-05 · 计算节点反向拨入链路（compute-link.v1）

- 提出时间：2026-09-23 03:10:00
- 状态：进行中

## 需求

用户要求计算节点平台改为通用动态模型：计算节点通过指定网址/IP **主动连接**主服务器
（类 P2P 反向拨入，odin 在 NAT 后免隧道直连），节点组动态增删（热插拔），主服按
在线节点动态分配任务，节点全部离线时主服仍正常工作。

## 设计（compute-link.v1）

- 服务端新增 `/internal/compute-link` WebSocket 端点：`X-Compute-Token` 鉴权 +
  hello 握手（nodeName / maxConcurrentBatches / gameDataFingerprint）。
- `ComputeNodeRegistry`：在线节点注册表，按剩余并发容量挑选节点；节点断开即在飞批次
  整批退回 pending（沿用 compute_jobs 租约/退避语义）。
- `ComputeDispatcherWorker` 改造：claim 到期任务 → 注册表取节点 → 经 WS 推批次 →
  结果按 SourceStateVersion CAS 落库；无节点时任务保持 pending。
- ComputeNode 新增客户端模式：`ComputeNode:UpstreamUrl` + 既有 Token，
  ClientWebSocket 重连退避拨出，批次执行复用 `DeterministicBatchEngine`。
- 批次载荷沿用 compute.v1 契约；hello 指纹不匹配拒绝注册，防旧版本节点吃新配表任务。
- 静态 `ComputeNode:Endpoints` HTTP 轮询路径移除（内测无兼容包袱）；
  节点本地 HTTP `/internal/v1/compute/advance-batch` 保留为独立调试口。
- compose.prod.yaml 的 compute-node 改为 upstream 拨入（loopback）；odin 拨
  `wss://daohua.yuohira.com/internal/compute-link` + 生产 COMPUTE_TOKEN。
