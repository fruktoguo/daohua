## 1. 需求背景与核心目标

1. **全缩放比一致构图与零挤压重叠**：解决大世界地图画布在系统高 DPI 缩放、浏览器缩放或不同窗口比例下采用「容器 `%` 画布 + 固定 `px` 节点」导致的非等比拉伸、低有效像素下节点相互挤压重叠的问题，使用户无论在何种显示比例与分辨率下都能获得完全一致的相对构图效果。
2. **紧凑修仙牌匾与可选地标图像支持**：将大地图节点由固定 `92px × 34px` 框改为按地名长度紧凑包裹的修仙牌匾；并建立 `frontend/src/assets/nodes/` 节点图像自动发现机制，节点有图时渲染为「上方折角灵境图像框 + 下方紧凑名称牌匾」地标，无图时自动保持纯紧凑牌匾形态。

## 2. 已确认设计方案

1. **统一等比基准像素世界坐标系（`worldMapVisibility.ts` + `WorldMapPanel.tsx`）**：
   - 确立固定基准像素坐标换算：`WORLD_UNIT_X = 9.6`、`WORLD_UNIT_Y = 6.4`（即 `100 × 100` 世界单位恒定等于 `960 × 640` 基准像素，固定 3:2 比例）。
   - 所有节点、文字、SVG 区域界框/名牌、单层 SVG 贝塞尔道路与线宽、玩家浮标均在基准像素空间绘制，通过 `.world-map-canvas` 统一的 `transform: translate(panX, panY) scale(fitScale * relativeZoom)`（`relativeZoom ∈ [0.45, 2.6]`）整体等比缩放，移除 `vectorEffect="non-scaling-stroke"` 与嵌套 `<svg preserveAspectRatio="none">`。
   - 引入 `reprojectViewportOnResize`：容器尺寸或 DPI 缩放改变时，按新 `fitScale` 与原焦点锚点、原 `relativeZoom` 实时重投影 `pan` 与 `scale`，保证不同缩放下画面相对构图严格不变。
   - `.expedition-content` 启用 `@container map-shell (max-width: 660px)` 响应退栈，高显示比例窄空间下自动切换纵向布局，防止右侧详情栏挤压地图舞台。
   - 宗门驻地投影（`zongmenMap.ts`）移除 `Math.min(95, ...)` 硬编码钳位，按基准像素安全净空在 8 个候选偏移方向中挑选无碰撞坐标。
2. **紧凑牌匾与节点图像自动发现（`nodeIcons.ts` + `WorldMapPanel.tsx` + CSS）**：
   - 新增 `frontend/src/assets/nodes/<nodeId>.{webp,png,svg}` 资源目录与 `frontend/src/game/nodeIcons.ts`（宗门节点 `node.zongmen.*` 可回退 `node.zongmen`）。
   - `vite.config.ts` 将 `/assets/nodes/` 与 `/assets/buildings/` 一并纳入 `assetsInlineLimit` 独立缓存策略。
   - `MapNodeButton` 在有图时显示 `.world-map-node-media`（上方折角小景图像框）+ `.world-map-node-plaque`（下方压脚牌匾）；支持普通、关口（`.is-gateway`）、首领（`.has-boss`）、秘境（`.is-secret`）、宗门（`.is-sect`）、赶路终点（`.is-destination`）、当前驻留（`.is-current`）以及深/浅双主题样式。
