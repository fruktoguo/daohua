# TASK-20260917-05 · 战斗显示回归修复与战报弹窗化

## 任务信息

- 提出时间：2026-09-17 19:45
- 状态：✅ 已完成
- 分类：Bug 修复 / 前端协议映射 / UI 改版

## 问题现象（用户实测截图反馈）

1. 顶部行动条不显示双方总生命值与百分比（显示 `0/1万(0%)`、`1/1` 兜底值）。
2. 战斗详情内行动条（出手/施法进度）不渲染，战斗过程视觉上不推进（日志正常滚动，服务端结算正常）。
3. 战斗收益战报平铺在详情页底部，要求收进详情右上角按钮，点击弹出独立弹窗。

## 根因

- 多敌同场战斗重构（8198a9f / a9f6325）后，服务端 `expedition` 载荷改为裸领域 `CombatExpeditionState`，不再下发 `playerMaxHitpoints`/`enemyMaxHitpoints`/`enemyName`/`playerAction`/`enemyAction` 等展示派生字段。
- 前端 `mapExpedition` 只解析了新字段，但顶栏 `CombatActionProgress` 与 `CombatArena` 仍消费旧字段 → 血量兜底为 1、行动条恒为 null。
- `mapExpeditionDuel` 读取字段名与领域 `DuelPlaybackState` 序列化名不一致（`isInitiator`/`outcome` vs `viewerIsInitiator`/`viewerOutcome`），且未解析 `opponentHitpoints`/`opponentMaxHitpoints`。

## 实施方案

1. `network/snapshot.ts`：`mapExpedition` 透传 `battleElapsedSeconds`/`playerNextAttackAtSeconds`；`mapExpeditionDuel` 修正字段名并解析对手血量与剧本事件（出手时刻推导行动条）。
2. `game/types.ts`：`ExpeditionProgress`/`ExpeditionDuel` 补字段。
3. `App.tsx` 顶栏 `CombatActionProgress`：己方血量取 `expedition.playerHitpoints` / `combatResources.maxHitpoints`；敌方总量 = `enemies[]` 当前血量和 / 配表 maxHitpoints 和；斗法相位取 `duel.opponentHitpoints/opponentMaxHitpoints`。
4. `CombatArena.tsx`：由 `playerNextAttackAtSeconds - battleElapsedSeconds` 与攻速（玩家 `combatAttributes.attackIntervalMilliseconds`、怪物配表 `attackIntervalMilliseconds`）合成 `CombatActionState`；斗法相位按剧本下一出手事件推导。
5. `CombatDetailsPage`：战报面板改为详情头部右上角按钮 + `Modal` 弹窗承载 `BattleReportPanel`（新增 `ghost-button`/`battle-report-modal` 样式）。
6. 附带修复：技能冷却/吟唱在同次重构中也断了数据源——`ToCombatSection` 补发 `skills.cooldowns`/`castingAbilityId`/`castRemainingMilliseconds` 与 `consumableCooldownMilliseconds`；前端 `mapCombat` 解析入 `CombatResourceState`，`AbilitiesPanel` 冷却遮罩与玩家吟唱条恢复。
7. i18n 词条与构建/契约检查验证。
