- **分类**：全栈新功能 / 领域账本 / 协议对齐 / 前端改版
- **状态**：✅ 已完成（2026-09-19）

## 需求（用户原文转述）

1. 有正在进行的行动时，刷新页面自动进入「详情」页（combat Tab）。
2. 详情页右上角「战斗收益战报」改为「统计」，非战斗行动同样可用。
3. 统计面板分段展示：
   - **获取经验**：已有经验类型全覆盖——修为（境界经验）、底蕴、六维、功法技能经验；若期间有等级提升需写明（境界/六维/功法）。
   - **获取和失去物品**：获得与消耗/丢失分开列。
   - **行动信息**：本行动已执行轮次、累计时长；战斗类另含遭遇场次、普通/精英/首领击杀数、死亡次数（斗法胜负保留）。
4. 统计边界（用户补充裁定）：
   - 账本绑定**队列中的行动实例**：一个任务不管重复多少次都算一个行动，持续记录；实例出队即归档。
   - 每个玩家持有**三个统计**：当前行动统计、离线统计（关闭网页离线挂机期间全部收益，每次离线会话重置）、每日统计（自然日重置）。
   - 交易（坊市）不计入统计。
   - 技艺经验：本期不建生活技艺经验模型，只统计已有经验类型。

## 技术方案

### 领域层（src/Domain）

`PlayerBattleReport`（PlayerDuel.cs）扩展字段，三个账本共用同一结构：

- 经验：`Qi` `Experience` `RootExp`（已有）+ `AbilityExp: List<PlayerReportAbilityExp{AbilityId,Experience}>` + `LevelUps: List<PlayerReportLevelUp{Kind,TargetId,FromLevel,ToLevel}>`（kind: realm/root/ability）
- 物品：`Items`（获得，已有）+ `ItemsLost`（失去：行动输入、自动消耗品、斗法暂存被缴）
- 行动信息：`Cycles`（完成轮次）、`Encounters`（战斗遭遇场次）、`NormalKills/EliteKills/BossKills`、`Deaths`、`DuelWins/DuelLosses`（已有）、`DayIndex`（仅每日账本用）

`PlayerDuelState` 改为：

- `ActionReports: Dictionary<Guid, PlayerBattleReport>`——按行动实例 Id 各持一本账（轮转出队首不清零，出队才归档）
- `OfflineReport`、`DailyReport`（含 DayIndex，UTC+8 自然日）——单例账本
- `Reports` 归档历史保留（10 条）；`CurrentReport` 属性保留为「队首行动账本」便捷访问

`PlayerAggregate`：

- `RecordStats(actionInstanceId, atUnixSeconds, apply)`：同一记账 apply 同时作用于 ①实例账本 ②`Presence==Offline` 时的离线账本 ③每日账本（先按 UTC+8 日界 rollover 再入账）；统一 `MarkDirty(Duel)`。
- `EnsureActionReport(...)`：队首行动开始推进时按实例 get-or-create（受阻 Blocked 不建账）。
- `ArchiveReportForAction(instanceId, endedAt)`：实例从队列移除时归档；挂接在 `RemoveAction`、travel 去重 RemoveAt、`CompleteOrRequeueHeadAction` 三处出口。
- `SetPresence` 转入 Offline 时 `OfflineReport` 重置（StartedAt=LastSimulatedAt）。
- `Breakthrough` / `GrantAbilityExperience` / `RemoveStagedItems` 记录等级提升/技能经验/物品失去（经 RecordStats，at=LastSimulatedAt 或传入时刻）。

`SimulationEngine` 记账点（全部经 `player.RecordStats(action.Id, atUnix, r => ...)`）：

- `ApplyContinuousReward`：每秒收益 Qi/Experience 实际入账量。
- `CompleteRepeat`：qiGain/experience 实入账、Item 产出（+）、Inputs（−）、Cycles+1。
- `ApplyCombatRewards`：Qi/Experience/RootExp 入账；掉落（+）或 StageItem（+，暂存也计获得）。
- `DistributeRootExp`：六维入账 + 等级提升检测（RootAttributeCurve.LevelFor 前后对比）。
- 波次生成处 Encounters+1；波次胜利 Cycles+1；分级击杀 NormalKills/EliteKills/BossKills+1；讨伐失败与斗法败北 Deaths+1；斗法胜/负 DuelWins/DuelLosses（既有）。
- 自动消耗品扣件（PrepareSustainedAutoUse）ItemsLost+1。
- 旧的「队首变更即归档」检查（AdvanceToCore 头部）与 `AdvanceCombatAction` 内 `BeginBattleReport` 移除，改为 EnsureActionReport。

`PlayerRuntime`：加载路径把 `SetPresence(Online)` 移到首次 `AdvanceSimulationAsync` 之后，使重连补算期间 `Presence==Offline`、离线收益正确归因离线账本。

### 持久化文档（PlayerStateDocument.cs）

- `PlayerBattleReportDocument` 追加：`ItemsLost`、`AbilityExp`、`LevelUps`、`Cycles`、`Encounters`、`NormalKills`、`EliteKills`、`BossKills`、`Deaths`、`DayIndex`（均可空/默认 0，向后宽松校验）。
- `PlayerDuelStateDocument` 追加：`ActiveReports`（实例账本列表）、`OfflineReport`、`DailyReport`。`CurrentReport` 导出时取队首实例账本（导线兼容）。
- Export/Import/IsValid 同步更新；离线/每日账本 ReportId 固定为 `"offline"`/`"daily"`，ActionInstanceId 为 Guid.Empty，ActionId/ActionName 允许空串。

### 协议与前端（frontend/）

- wire `duel` section = PlayerDuelStateDocument JSON（camelCase），新增字段随文档自动下发：`offlineReport`、`dailyReport`、`activeReports`，`currentReport` 仍是队首账本。
- `types.ts`：`BattleReport` 增加 `itemsLost`、`abilityExp`、`levelUps`、`cycles`、`encounters`、`normalKills/eliteKills/bossKills`、`deaths`、`dayIndex`；`DuelState` 增加 `offlineReport`、`dailyReport`。
- `snapshot.ts`：mapBattleReport/mapDuel 解析新字段（缺省容错）。
- `gameStore.applySnapshot`：首个快照且 `queue.entries.length > 0` 时 `useUiStore.setActiveTab('combat')`（仅页面首次加载触发一次）。
- `BattleReportPanel` → 重构为统计面板（重命名 StatsPanel）：分区「当前行动 / 离线挂机 / 今日统计」，每区三小节（获取经验[含等级提升]、物品得失、行动信息）；斗法暂存区与近期战报历史保留；按钮文案改「统计」。
- `battleReportStore` 本地缓存读取时为新字段补默认值（旧缓存不崩）。
- i18n `combat.report.*` 词条更新 + 新增分区词条；CSS 增补小节样式。
