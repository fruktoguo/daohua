## 核心目标

1. **顶栏传书角标与中心替换视图（横竖屏统一）**：
   - 在顶栏右上角（`.topbar-actions` 内部紧邻昼夜切换 `TaijiToggle` 左侧）常驻放置邮件角标按钮，竖屏窄屏下保留显示并自适应压缩左侧 `.realm-progress` 境界进度条宽度，杜绝挤压重叠。
   - 存在未读邮件或未领取附件时展示红点提示；点击邮件按钮将中间主内容区切换为 `<MailPage />`，再次点击或切换任意侧栏/底栏导航标签即可退出邮件视图。
2. **完整邮件生命周期**：
   - 支持已读/未读状态、单封领取附件与一键领取全部可领附件、单封删除与删除全部已读。
   - 含未领附件的邮件在前后端双重校验下禁止删除，防止误删损失资源。
   - `/ops` 后台提供向指定玩家发件、全服群发公告（含仅面向发件前已创建角色的门槛开关）与公告撤销能力，写入运营审计日志。
3. **双轨存储与零冷计算/零 ECS 侵入优化**：
   - 全服群发邮件只在 `social.broadcast_mails` 落 1 行并由 `MailRuntime` 全局共享不可变快照，不在 `social.player_mails` 为全服角色复制 N 份行或常驻内存对象。
   - 玩家针对群发邮件的状态仅在产生交互时按需于 `social.player_mail_states` 落最多 1 行（以 `bigint[]` 紧凑保存 `read_ids` / `claimed_ids` / `deleted_ids`），每次写入自动按活跃公告 ID 交集压实，不活跃角色零数据库行、零堆内存占用。
   - 不改动 `SectionCodec`（保持 v43）与 `EcsWorldShard` / `ComputeNode`；仅在个人领奖时通过 `IParticipationAssetBoundary` → `PlayerCommitGates` → `Serializable` 事务入账 `economy.player_asset_balances` 后通过 `IPlayerRuntime.ReloadWalletAndNotifyAsync` 同步在线玩家钱包。
   - `identity.accounts.is_bot = true` 机器人账号屏蔽群发接收、红点推送与领奖操作。
   - 列表与正文分离（列表不查/不下发 `body`），全服群发通过单次预序列化 `WireMessageType.MailSummary`（`{ forceRedDot: true }`）节流广播在线非机器人会话，零群发数据库风暴。
