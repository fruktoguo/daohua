## 2. 需求背景与核心目标

### 2.1 需求背景
1. **角色级 `Style` 与 `DamageType` 冗余**：
   在最初构建战斗原型时，`CombatLoadout`（玩家战斗装配方案）上附带了 `Style`（默认 `Sword`）与 `DamageType`（默认 `Physical`）两个全局字段。实际战斗推演中，伤害属性是由技能（`ability.DamageType`）或武器（`equipment.DamageType`）决定的，挂在角色身上违背了“伤害属性属于技能/武器”的正统设计，属于历史遗留包袱。
2. **新号生成写死初始动作队列**：
   `SimulationEngine.CreateDefaultState` 中写死了采集凝血草、炼制引气丹、吐纳引气 3 个动作队列及自动使用引气丹，导致所有新角色创建后自动塞满任务，与干净起步的设计相违背。
3. **历史别名与兼容残留**：
   `IdConstants.cs` 中残留大量 `兼容旧引用的长弓/灵枪/重盾/灵茶/云锦糖别名`，以及部分类中残留历史字符串重载与过渡兼容代码。

### 2.2 核心目标
1. **移除 `CombatLoadout` 中的 `Style` 与 `DamageType`**：
   - 彻底从领域模型 `CombatLoadout`、协议 DTO `CombatLoadoutDto`、前端类型 `CombatLoadout` 及接口中移除这两个字段。
   - 普攻伤害属性由穿戴武器 `equipment.DamageType` 决定（无武器时兜底物理 `Physical`），技能伤害属性 100% 由 `ability.DamageType` 决定。
   - 玩家攻击形态由武器流派 `equipment.Style` 决定（无武器时为体修/肉身 `Body`）。
2. **清理 `CreateDefaultState` 初始队列与自动使用硬编码**：
   - 新建角色生成完全纯净的初始状态：空动作队列、空自动使用槽，无写死任务。
3. **清理 `IdConstants.cs` 中所有历史别名与过渡兼容层**：
   - 移除所有旧武器/道具别名，统一为正式修仙配置名；
   - 更新全部引用点（LoadTests、测试用例等）。
