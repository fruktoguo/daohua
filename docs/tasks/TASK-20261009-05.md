## 期望目标（一句话）

一次组队讨伐会话是一个**队伍级权威计算单元**：同一场战斗只被模拟一次，全体成员共享其状态与结果流；任一成员在线即实时推进，全员离线才挂起为冷算。**废除**当前「共享剧本、每名成员各自确定性重放」的执行模型。

## 必须保持的规则层（不可变更）

1. **开战条件不变**：成员数=开启槽位、全员就绪、全员位于目标节点，目标节点由队伍档案决定。
2. **冻结面板不变**：开打时定格每名成员的战斗输入（属性/功法槽/定格血蓝/持续消耗品 Buff），会话中不吃实时面板变化。
3. **散场规则不变**：成员变动（离队/移出/槽位收窄）、取消准备、目标节点漂移、解散均终止会话；散场按权威时刻收尾。
4. **收益口径不变**：经验按参与平分并叠个人等级惩罚；掉率按全员增幅放大、掉落按权重归属；每人只入账自己的份额。
5. **倒地复活口径不变**：会话内按遭遇规则原地复活；散场时刻仍倒地的成员以 1 点气血起身（灵力不回）。
6. **前端表现不变**：每名成员看到的仍是同一场战斗——盟友阵列、波次、相位、事件流、战报、详情投影；改的只是数据来源（权威会话的成员侧投影），不是形态。

## 变化的核心（要改的）

1. **战斗不再在成员模拟内推进**：会话持有唯一权威战斗状态（波次/相位/事件流/各成员战斗态/寻敌进度）；成员侧不再各自推演同一 spec。
2. **成员侧持有「会话引用 + 个人结算」而非「可自推演的行动」**：队首参与绑定可保留为引用锚点（队列语义/协议识别），但其 expedition 战斗态来自权威会话投影，成员推进不再消费战斗预算。
3. **结算投递**：会话对每个成员产出其个人份额——战斗终态血蓝、掉落归属、经验与账本统计、事件日志、战报归档；投递到各成员自身状态上下文落账（成员状态的单写者属性保持）。
4. **在/离线语义**：任一成员在线→会话实时推进；**全员离线→会话挂起并记录时刻**，任一成员回线后按墙钟对齐补齐（冷算）。成员个体离线不拖垮会话——离线成员在会话内按冻结面板继续被模拟（与现行同规则），其个人结算待回线或对账时落账。
5. **散场与终局结算**：会话终止时按权威时刻给每名成员结算终态并落账（含倒地→1 血复活口径）；已离线成员的结算可延迟到其装载/对账窗口落账。
6. **崩溃与重启恢复**：会话权威状态必须有恢复路径——持久化战斗状态，或持有可重放恢复的最小输入（推荐持久化战斗态，避免重启重算全场）；成员侧只保留「已消费到哪个结算点」游标。

## 实施方案

- **权威宿主**：`ActionParticipationRuntime` 按会话串行持有唯一 `ActionParticipationSessionEngine`；独立于队长、成员与玩家分片。玩家按 ID 哈希分片，同节点不代表同分片。
- **成员投递**：会话检查点与个人结算 inbox 原子交付；适配器在成员玩家 gate/Fiber 内消费，资产、分段与回执原子提交。社交开场/散场只请求对账，不重复插入旧规格。
- **绑定**：成员存档只保留会话引用、结束时刻与消费序号；冻结规格只在权威检查点持久化，展示按需附加当前本人视角。
- **调度**：自然边界进入既有运行时唤醒链；至少一人在线实时推进，全员离线不执行战斗，回线由会话统一补齐墙钟。
- **容量目标**：战斗推演成本由 N×单场 降为 1×单场 + 每成员一次结算投影；离线成员不复制推演。

## 验收方向

1. 同一场会话在服务端只有一次战斗推演（可断言/计数证明，N 名成员不产生 N 份战斗预算）。
2. 各成员观察到的战斗一致：波次/击杀/倒地/复活/事件顺序逐帧相符。
3. 成员中途离线→回线：直接对齐权威会话当前态，不补演整场。
4. 散场/离队/取消准备/节点漂移后每名成员结算正确，倒地成员按既定口径复活。
5. 崩溃重启后活跃会话恢复或按散场兜底收尾，不出现半结算会话。

## 背景（为什么改）

当前模型为「共享剧本、各自推演」：每名成员的模拟各自重放同一场战斗，成本为 N×单场，且复活/结算等副作用挂在成员各自推进时机上（已暴露出散场倒地复活延迟的边角缺陷，TASK-20261009-03 以就地恢复缓解）。队伍作为整体算一次是更直接的模型，并把结算时点收敛到会话权威边界。
