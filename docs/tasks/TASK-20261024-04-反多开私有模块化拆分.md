# TASK-20261024-04 反多开私有模块化拆分

## 需求复述与目标

把反多开子系统（及未来其他不适合开源的部分）从主仓库剥离到兄弟私有仓库 `DaoHua-Private`，主仓库可安全开源；本地开发与生产部署同时加载两个仓库，按「兄弟目录存在即拼装」的模块化机制产出完整版。

兼容矩阵（硬性要求）：

| 组合 | 结果 |
| --- | --- |
| 开源后端 + 开源前端 | 正常连接（开源自建场景） |
| 完整后端 + 开源前端 | 必须拒绝（专用客户端关闭码 4009） |
| 完整后端 + 完整前端 | 正常连接 |
| 完整前端 + 开源后端 | 优雅降级放行（开源后端忽略模块声明） |

已裁定事项：历史清洗采用「本地/私有远端留完整历史备份 + 开源仓库 squash 重发」，**不在本任务范围**，开源发布前单独触发并先备份。

## 技术方案

### 1. 仓库拓扑

```
D:\Project\Vibe\DaoHua          ← 主仓库（开源）
D:\Project\Vibe\DaoHua-Private  ← 私有仓库（反多开实现 + 私有测试）
```

兄弟目录约定，不注册 submodule（主仓库 Git 零痕迹）。构建脚本探测 `../DaoHua-Private`（或显式 `DaoHuaPrivateRoot` / `DAOHUA_PRIVATE_ROOT`）：存在即拼装完整版，不存在构建纯开源版。

### 2. 服务端：源码注入 `DaoHua.Server.Clean` 程序集

- 主仓库新增 `src/Server/Clean/Admission/`：`IHelloAdmissionHook`（准入/释放/TabGuard 下发三面）、`HelloAdmissionVerdict`（含踢线通知字段，主仓库不含任何反多开常量）、`OpenHelloAdmissionHook`（默认开放语义：无条件放行、首会话登记、多连接并存）、`IHostModuleStartup` + `HostModuleDiscovery`（启动期反射发现注入的模块装配入口）。
- `Server.Clean.csproj` 增加 `DaoHuaPrivateRoot` 属性（默认探测 `../../DaoHua-Private`）与条件 `Compile Include` 注入 `$(DaoHuaPrivateRoot)/server/**/*.cs`，复用该工程既有的显式 Compile 模式；零循环引用、无需独立 csproj。
- 私有实现 `AntiMultiOpenAdmission` 改为实现 `IHelloAdmissionHook`：策略由参数传入（不再持有 Registry），并新增**无条件模块声明校验**（Hello 未携带 `moduleDeclaration` 或不匹配 → 4009 拒绝），保证「完整后端拒绝开源前端」与策略开关无关。
- `Program.cs` 默认注册开放钩子，随后扫描 `IHostModuleStartup` 覆盖；`WebSocketRuntime` 只依赖接口。
- `WebSocketSession.DeviceFingerprint` 改名 `AdmissionDeviceKey`（中性化）。

### 3. 协议：HelloRequest 模块声明字段

`HelloRequest` 新增可选 `ModuleDeclaration`；私有前端构建期内嵌模块 ID 常量，开源 stub 恒为 null。开源词典新增 `common.net.dedicatedClientRequired`（4009 提示，开源前端连官方服被拒时可见）；4005-4008 常量与语义随实现移入私有仓库。

### 4. 前端：稳定出口 + vite 正则 alias + junction 挂载

- 主仓库新增 `frontend/src/private/`：`contract.ts`（契约类型）、`stub.ts`（开源 stub：全 no-op、4009 映射、指纹 null、声明 null）、`impl.ts`（默认 re-export stub）、`index.ts`（唯一稳定出口）。
- 私有实现挂载点 `frontend/src/private-impl/`（.gitignore）：dev/verify 启动时由 `scripts/sync-private-modules.mjs` 把 `../DaoHua-Private/frontend/antiMulti` 以 junction/symlink 挂载（目录深度与原 `src/antiMulti` 一致，内部相对 import 零改动）；构建期混淆插件路径同步改为 `/src/private-impl/`。
- `vite.config.ts` 探测挂载点存在时以正则 alias 把 `private/impl` 重定向到私有实现入口；tsc 始终按 stub 类型检查主仓库文件，私有文件自身被 include 检查并以契约对象做 satisfies 级导出面校验。
- `accountSignals.ts` 移至 `frontend/src/network/`（登录风控信号采集留主仓库），仅浏览器指纹函数经契约出口取自私有实现。
- 调用点（`App.tsx`/`gameClient.ts`/`account.ts`）import 统一改到稳定出口。

### 5. 构建与部署

- `Dockerfile` publish 传 `-p:DaoHuaPrivateRoot=/src/Private`：路径不存在时 MSBuild 通配零匹配自动开源版，单 Dockerfile 双口径；`docker-build-prod.sh` 改为 staging 复制（主仓库 + 私有仓库 → `src/Private` + `frontend/src/private-impl` 真实目录），`compose.yaml`（开源本地口径）零改动。
- `verify.sh` 增加完整口径段（存在私有仓库时）：私有后端测试项目 + 完整版前端构建；开源口径不变。
- `dev.sh`/`dev-hot.mjs`：启动前同步挂载点，热重启监听闭包纳入 `DaoHua-Private/server`。

### 6. 安全边界（明确声明）

模块声明是客户端自声明，挡无心之失与普通用户；真正的对抗价值在于指纹算法与裁决策略移出开源仓库提高伪造成本，服务端权威裁决不依赖前端诚实。
