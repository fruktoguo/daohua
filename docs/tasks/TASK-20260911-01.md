## 需求与方案

用户先反馈「上游持续消耗品改动完全没有效果」，随后追问「正在修炼为什么药效没激活」。核查后确认这是**两个互相独立的缺陷**，两者叠加造成「改了什么都没反应」的观感：

1. **前端：倒计时遮罩样式被战斗冷却规则整段覆盖。**
   遮罩元素同时挂 `combat-ability-cooldown` 与 `item-slot-duration-overlay` 两个类，
   而 `main.tsx` 的样式导入顺序是 `styles.css` → `selection-grid.css` → `expedition.css`。
   两条规则权重相同（均单个类），后加载的 `expedition.css` 在 `background`（含扇形起点角）、
   `color`（含倒计时文字色）、`font-size` 上全胜，只有 `box-shadow` 幸存。
   方案：遮罩元素去掉 `combat-ability-cooldown` 类，改为由 `item-slot-duration-overlay` 独占；
   7px 圆角与溢出裁剪继续由 `styles.css` 的分组规则提供，不丢。

   随后按用户反馈校正扇形约定：**起点必须为 12 点方向，边界顺时针扫过（右 → 下 → 左），暗区代表剩余时长。**
   原实现为 `from -0.25turn`（起点落在 9 点方向）且边界逆时针倒扫。
   正确写法必须把暗区锚定在 `1turn` 一侧、由 `(1 - 剩余比)` 起算：

   ```css
   conic-gradient(from 0turn, transparent calc((1 - var(--cooldown-ratio)) * 1turn), rgba(8, 15, 17, 0.86) 0)
   ```

   反例（会被写成逆时针倒扫）：`conic-gradient(from 0turn, 暗色 calc(ratio * 1turn), transparent 0)`。

   再按反馈在槽位外侧补一圈**淡金虚线弧**，同样**与扇形同起点、同方向、同角度**（剩余越少虚线弧越短）。
   做法是把它挂在遮罩的 `::after` 上并画到槽位以外，因此遮罩需 `overflow: visible`
   （背景与文字仍由 `border-radius` 收圆角，无需 overflow 裁剪）；虚线交给
   `border: 1px dashed` 由浏览器绘制，可见范围复用与扇形**完全一致的 conic 公式**做遮罩，
   从而逐帧天然同步、无需额外 JS：

   ```css
   .item-slot-duration-overlay::after {
     content: ''; position: absolute; inset: -5px;
     border: 1px dashed color-mix(in srgb, var(--gold-bright) 72%, transparent);
     border-radius: 12px; pointer-events: none;
     mask-image: conic-gradient(from 0turn, transparent calc((1 - var(--cooldown-ratio)) * 1turn), #000 0);
   }
   ```

2. **领域：仿真进位余数把「动作开始扣件」判定永久锁死。**
   `SimulationEngine` 的周期起点判据曾写成
   `ProgressSeconds <= eps && Progression.SimulationCarrySeconds <= eps`。
   `SimulationCarrySeconds` 只记录亚秒残差，全仓库**没有任何重置点**；
   一旦因离线补算变成非零（本例 `0.6965839999875751`），该判定恒为 false，
   持续消耗品（引气丹 / 通脉丹 / 寻灵香 / 地火引）**永久无法在动作开始时扣件激活**。
   方案：周期起点判据改为只依赖行动自身进度 `ProgressSeconds`，彻底删除全局相位依赖。
   **原有业务语义保留**：本轮若已结算过整秒收益（进度 > 0），中途补货不得追溯激活，须等下一轮周期起点。

本次为本地开发阶段修复，按项目硬规则**不引入任何历史兼容**：旧存档无需迁移，`carry` 非零不再影响激活。

## 行为变更说明（需知悉）

`SustainedConsumableDoesNotActivateMidActionAfterStockArrives` 已改写为
`SustainedConsumableDoesNotActivateAfterCycleHasAwardedSeconds`。
原因：原用例断言的是「本轮仅流逝 0.5 秒、尚未结算整秒时补货也不得激活」，
该期望只有在全局相位恰为 0 时才成立——正是本缺陷的来源。
改写后的用例断言与相位无关的等价语义：**本轮一旦已结算整秒收益就不再接受中途补货激活**，
并额外校验下一轮起点扣件后整段收益确实吃到倍率。原语义的保护强度未降低。
