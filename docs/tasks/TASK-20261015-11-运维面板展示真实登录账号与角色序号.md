# TASK-20261015-11 运维面板展示真实登录账号与角色序号

## 1. 任务背景与核心需求

用户反馈在运维面板已加载玩家列表中：
```text
玩家 ID   账号   道号   在线状态   状态版本   上次模拟   队列动作   资产条目   操作
21137139-1167-45a7-b2b8-0b45a4b3ae86   9f9fd673-d865-4933-a89e-772edf05bfab   supermiao   在线   450,076   2026/10/15 15:59:53   1   21   详情
```
存在「玩家 ID」与「账号」均为不可读 UUID 的现象，且无法看到玩家真实的登录账号名与直观身份。

### 根因分析
1. 数据库中真实登录用户名保存在 `identity.accounts.login_normalized`，角色自增编号为 `identity.players.player_seq`。
2. ECS 内存运行时出于轻量设计，仅保留了实体标识 `PlayerId`（UUID）与账号归属 `AccountId`（UUID），并未载入 `login_normalized`。
3. 运维端 `/api/players` 直接从 ECS 内存快照透传字段，前端 `DataViews.tsx` 将 UUID 冠以「账号」表头直接展示，产生语义与视觉错位。

### 目标与交付物
1. **服务端读侧模型丰富**：在 `OpsStorageInsights` 中补充 `GetPlayerIdentitiesAsync` 批量查询方法，基于已加载玩家列表从 `identity.players` JOIN `identity.accounts` 关联读取 `login_normalized` 与 `player_seq`（做容错兜底，无 DB 或异常时不阻断）。
2. **运维端点协议对齐**：
   - `/api/players` 与 `/api/players/{playerId:guid}` 补充下发 `account`（真实登录账号名）与 `sequenceId`（自增编号）。
3. **前端运维面板展示优化**：
   - 玩家列表表头重构：`序号`（如 `#1`）+ `道号`（如 `supermiao`）+ `登录账号`（如 `supermiao`）+ `在线状态` + `状态版本` + `上次模拟` + `队列动作` + `资产条目` + `玩家 ID`（短码+提示）+ `操作`。
   - 玩家详情弹窗补充展示角色编号、登录账号、账号 ID 与玩家 ID 的明确区分。
4. **运维控制台（dev-tui.mjs）同步对齐**：
   - `players` 指令展示序号、道号与登录账号，`player` 指令详情增强，支持按登录账号和 `#序号` 检索玩家。
