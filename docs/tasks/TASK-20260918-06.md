## 二、设计定稿（用户逐项拍板）

### 2.1 归属与共享

- **纯公共设施**：无建造者概念；同节点同种建筑仅一座；任何人可发起建造、填充材料、发起升级。
- **效果对同地所有玩家生效**（公共增幅）。
- 建筑状态脱离玩家分段，改为**节点级共享注册表**：`nodeId → 建筑实例列表`，实例含 `buildingId / level / 材料进度 / 建造起始时刻 / 建造中目标等级`；独立持久化（新增 `node_buildings` 表或等价存储）。

### 2.2 建造流程（双进度条）

- 每条建造/升级任务有两条进度：**材料%** 与 **时间%**。
- 建造自动推进：建造进度 = `min(材料%, 已耗时/本级所需时间)`；材料不足时停滞，补足后继续；不需要后台 tick，按起始时刻+材料进度惰性推算。
- 时间需求：Lv N 建造需 `600 × (1 + 0.2×(N-1))` 秒（基础 10 分钟，每级 +20% 线性，51 级 = 110 分钟）。
- 材料需求：Lv N = 基础清单数量 × `1.1^(N-1)`（指数 +10%）；材料清单为 `itemId + 数量` 列表，初版占位。
- 建成永久生效；升级 = 发起新一轮双进度条（目标 N+1）；升级期间维持旧级效果；无等级上限；同地建筑总数受节点可建列表限制。
- 未建成（进度 <100%）不生效；升级中按旧等级生效，完成瞬间跳变。

### 2.3 节点可建列表

- 地图节点 JSON 二选一：`buildableTemplate`（模板名）或 `buildableList`（自定义建筑 ID 数组）；都不写 = 该节点不可建（前端隐藏加号卡）。
- 建筑配 `group` 字段：`production` / `combat` / `other`；模板 `all`/`production`/`combat`/`other` 按组映射。

### 2.4 交互

- 建筑卡：名称 + 等级 + 效果；建造中显示双进度缩略；点击弹详情 Modal（等级、效果、双进度条、材料清单、提交材料入口、升级按钮）。
- 提交材料独立界面：每种材料一个数量输入，范围 `[0, min(背包剩余, 本级所需剩余)]`，提交前二次确认。
- 候选弹窗：按 `group` 分组列出全部可建建筑；未解锁（境界不足）灰显并标注所需境界。

### 2.5 效果模型与数值

- 建筑配表新增结构化 `modifiers`：产出/收益类按百分比预算（1% = 1 点），回血按回复预算（1 点回复 = 4 点预算），行动加速/减伤属特殊属性人工参考同阶位范围。
- 效果随等级线性成长：`effect(N) = base × N`。
- 结算接线：行动/战斗结算时按「当前节点全部已建成建筑」汇总 modifiers；由运行时在每个模拟步前从共享注册表解析注入，保证多玩家建造即时生效且离线补算一致。

4. **效果接线**：行动速度/产出、炼丹炼器、修炼收益、战斗回血与减伤按节点汇总 modifiers 注入结算。

6. **验证**：dotnet build/test、frontend build、DataTool validate、契约脚本。
