# TASK-20260919-05 · 储物袋物品交互：左键操作菜单 + 右键直接使用 + 丢弃/系统回收服务端命令

- 提出时间：2026-09-19 18:31:19
- 状态：✅ 实现完成，待验收

## 需求

用户反馈：背包物品无法交互。要求左键单击物品弹出悬浮操作按钮列表（使用、丢弃、出售），右键物品直接使用。

## 方案

### 前端

1. `frontend/src/components/InventoryItemCell.tsx`（新增）：背包格子交互收拢组件。
   - 悬停保留 `ItemTooltipTarget` 详情卡片（复用 `ItemCard` 原渲染）；
   - 左键经 `FloatingPopover`（`trigger="click"` + `displayContents` + `placement="right-start"` + `size="auto"`）弹出操作菜单，条目按物品类型动态裁剪：
     - **使用**：`item.tome.*`/`item.fragment.*` 发 `ability.learn`（参悟研习）；装备发 `loadout.replace`（剔除同槽位及双手/单手互斥装备后推入，`enhancementLevel` 恒 0）；
     - **交易**：可交易物品/装备跳转坊市浏览页并选中标的（`useUiStore.setActiveTab('market')` + `useMarketStore`）；
     - **回收**：配表 `sellPrice > 0` 且非 `currency.*` 的物品走 `item.sell`，条目 hint 显示单价；
     - **丢弃**：任意持有物品走 `item.discard`，`tone="danger"`，已装备物品禁用；
   - 右键经 `FloatingPopover` 新增 `onContextMenu` 透传触发器属性：可用物品立即使用，不可用仅屏蔽浏览器菜单；
   - 丢弃/回收共用 `ItemQuantityDialog`（`Modal` + `QuantitySelector` + `confirm-dialog` 结构），回收模式展示单价与合计灵石。
2. `frontend/src/components/RightSidebar.tsx`：`InventoryPanel` 物品渲染由 `ItemCard` 换为 `InventoryItemCell`。
3. `frontend/src/components/FloatingPopover.tsx`：新增 `onContextMenu` 触发器回调属性。
4. `frontend/src/i18n/domains/app.zh.ts`：新增 `app.inventoryPanel.*` 词条区块（使用/交易/回收/丢弃/弹窗标题描述/确认按钮）；`template.csv` 由 `export-i18n-csv.mjs` 重新生成。
5. `frontend/src/styles.css`：新增 `.inventory-dialog-total` 回收合计金色行。
6. `docs/frontend/common-components.md` §18 登记 `InventoryItemCell`。

### 服务端

7. `src/Server/Clean/PlayerRuntime.cs` 命令 switch 新增 `item.discard` / `item.sell` 合并分支：
   - 必须携带 `requestId`（幂等去重 + 持久化回执）；
   - 校验 `itemId`/`quantity`（`double`，>0 有限值）；物品须在 `gameData.Items` 或 `RawEquipments` 中存在；
   - 已穿戴装备（`Loadout.Equipment`）拒绝处置（`ITEM_EQUIPPED`）；
   - `item.sell` 仅允许 `SellPrice > 0` 的普通物品（装备与 `currency.*` 拒绝，`ITEM_NOT_SELLABLE`）；
   - `EnsureWalletFreshAsync` 后校验钱包持有量（`INSUFFICIENT_ITEM`）；
   - 通过 `economy.CommitAsync` 单事务扣物品（负 delta）+ 回收时贷记 `currency.spirit-stone`（`sellPrice × quantity`，double），事务内联 `CommandReceipt`，幂等键 `item.discard|item.sell:{playerId}:{requestId}`；
   - 事务后 `RefreshWalletAfterDurableMutationAsync`，快照 `Assets` 即权威余额；
   - `ShouldPersistReceipt` 纳入两条新命令（跨重连幂等回执）。

### 测试

8. `tests/Server.Tests/PlayerRuntimeTests.cs` 新增 6 个回归测试 + `CreateDisposalCatalog` 测试目录：
   - `DiscardItemDeductsQuantityAtomically`：按量扣减、事务 delta 与快照一致；
   - `DiscardItemRejectsOvershootMissingAndInvalidQuantity`：超库存/不存在/零数量均拒绝且无事务；
   - `SellItemCreditsSpiritStonesInSameTransaction`：2.5 单价 × 4 = 10 灵石同事务入账；
   - `SellItemRejectsUnsellableEquipmentCurrencyAndMissingRequestId`：无价物品/装备/货币/缺 requestId 拒绝；
   - `SellItemIdempotentReplayDoesNotDoubleApply`：同 requestId 重放返回 `IDEMPOTENT_REPLAY` 且不重复入账；
   - `EquippedItemCannotBeDiscardedOrSold`：已穿戴装备拒绝处置。

## 设计取舍

- 不新增 `item.use` 服务端命令：物品「使用」语义按类型分流到既有权威路径——秘籍/残卷走 `ability.learn`，装备走 `loadout.replace`；丹药等消耗品按既有设计通过行动自动使用槽生效，暂不提供手动即嗑入口。
- 「出售」实现为系统回收（按配表 `sellPrice` 兑灵石），玩家间交易走既有坊市挂单 `market.place`，菜单中「交易」项跳转坊市标的详情完成挂售。
