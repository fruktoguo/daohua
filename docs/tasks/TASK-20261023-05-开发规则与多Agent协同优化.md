## 1. 需求分析与理解

### 1.1 需求背景与痛点
此前开发规则中简单写了「多 Agent 并行开发优先」及 `.agents/rules/subagent-first.md` 中的「杜绝单线程串行硬扛」，导致在实际执行中容易产生以下偏差：
1. **需求理解未闭环**：收到需求后直接动手修改，缺少向用户复述并确认自身理解的机制，容易因隐式假设导致开发成果与预期偏离；
2. **小型需求过度并发**：对于仅涉及单文件、几行逻辑微调或单一模块的小型任务，机械化并发派生多个 Subagent，带来显著的上下文拆分开销、文件写冲突以及信息割裂；
3. **大型需求分工不透明**：进行多 Agent 协作时未向用户先行明确各 Agent 的职责切片与负责模块，导致黑盒调度。

### 1.2 用户的核心诉求与复述
1. **需求理解与复述**：每次用户提出新需求后，AI 必须首先理解并复述需求，给出自己的明确理解，与用户达成预期共识后再展开行动；
2. **小型需求单 Agent**：对于小型需求，严禁开展多个 Agent 进行，必须由主 Agent 保持单一上下文独立完成；
3. **大型需求多 Agent 先行声明**：对于真正需要多 Agent 协同的大型需求，必须在启动前先行向用户表明每个 Agent 的具体负责情况与边界。

### 1.3 核心修改范围
1. **`AGENTS.md`**：
   - 第 1 节「语言与沟通」：补充「需求理解与复述优先」条目；
   - 第 4 节「修改前检查」：强化第 4 条为「复述理解需求、评估规模并确定调度策略」；
   - 第 6 节「实现规则」：将「多 Agent 并行开发优先」重构为「需求规模与 Agent 协同分级机制（小型严禁多 Agent，大型先声明负责情况）」。
2. **`.agents/rules/subagent-first.md`**：
   - 纠正原先无差别强制并发的激进表述；
   - 明确小需求/大需求的分流判定；
   - 规范多 Agent 启动前的「职责声明矩阵」契约。
