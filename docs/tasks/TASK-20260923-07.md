# TASK-20260923-07 · 战斗演武画廊原型深度重建

## 需求

用户要求深度修复优化 `docs/design/战斗演武画廊.html` 程序化特效原型：

1. 界面必须与真实游戏界面完全一致；
2. 修复布局不稳定/跳变问题，与真实场景保持一致；
3. 特效按真实技能 id 与行为拆分为多组特效脚本，原型正式化；
4. 自行验证能否正常测试与播放。

## 需求分析（2026-09-23 06:38 完成）

### 旧原型诊断

- **特效全体不可见**：JS 会生成 `fx-*` / `vfx-node` / `dmg-float` / `arena-action-fx` / `arena-impact-fx` / `arena-resource-slice` / `is-hit` / `is-defeated` 等节点与类名，但样式块中 0 条对应规则（脚本实测 24 个关键 selector 全部 MISSING），所有特效渲染为空 div。
- **界面与真实不符**：自造 gallery-header + 双列布局 + 3v3 假阵型（己方 3 人占用 slot-1/4/7），而真实 `CombatArena` 为「己方仅 1 号位玩家 + 8 空槽 / 敌方按 ENEMY_DEPTH_SLOTS [1,4,7,2,5,8,3,6,9] 纵深铺位」；资源条/行动条 DOM 与真实组件结构不一致。
- **布局跳变**：自造 grid + 卡片库收缩展开，特效节点定位依赖自造坐标系。
- **数据失真**：技能数值/吟唱时长/目标类型为自编数据，怪物技能（monster-* 系）为虚构——真实模型为全单位共用同一套 ability.* 管线。
- 单文件 1.5MB，内嵌 base64 头像，不可维护。

### 重建方案

新建多文件工程 `docs/design/战斗演武画廊/`（旧文件作废删除）：

- `index.html`：完整复刻真实 App 骨架（topbar 玩家块+队列中战斗态、sidebar 导航、详情页 expedition-duel：arena + controls + CombatLoadoutPanel 装配区、right-column 右栏 tabs + 日志面板）。样式**直接 `<link>` 引用 `frontend/src/{styles,selection-grid,expedition,floating-popover}.css`** 保证永不漂移；头像与功法图标相对路径引用 `frontend/public/avatars/*`、`frontend/src/assets/items/ability.*.webp` 真实资源。
- `vfx/core.js`：特效引擎——overlay/跳字层坐标系、粒子工厂、弹道投射物、震屏、注册表 `DaohuaVFX.register(abilityId, handler)`。
- `vfx/catalog.js`：真实功法目录镜像（10 个 `ability.*` 的 castMilliseconds/manaCost/targetType/effectType/系数，来自 `config/game-data/abilities/*.json`）。
- `vfx/feedback.js`：通用战斗反馈组——普攻动作（`is-action-attack`/`arena-action-fx--attack`）、施法前摇（cast）、受击震颤（`is-hit`/`arena-impact-fx`）、血条碎裂（`arena-resource-slice`）、跳字、暴击印章、力竭阵亡（`is-dead`）、脱战调息回元。
- `vfx/abilities/<id>.js` ×10：每个真实技能一个脚本文件，自含专属 CSS 注入 + 演出函数，注册到引擎。
- `sandbox.js`：演武沙盘状态机——单位 HP/MP、行动条按真实 castMilliseconds 驱动、按 targetType 解析目标（single/allEnemies/allAllies/lowestHitpointsAlly/self）、扣灵力、伤害/治疗结算、Buff 方块（`arena-actor-buff-list`/`arena-buff-square` 真实结构）、阵亡、脱战回元。
- `gallery.js`：页面装配——功法槽/功法目录网格点击即演武、右栏「演武」控制台（出手方向己→敌/敌→己、自动轮播、通用反馈按钮、重置）、`?autotest=1` 自检模式（全量特效轮跑 + 错误收集写入 DOM 供无头验证）。
