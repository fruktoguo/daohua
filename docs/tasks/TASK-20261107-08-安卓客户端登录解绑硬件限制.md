# TASK-20261107-08 · 安卓客户端登录解绑硬件限制与同机型误杀彻底修复

## 1. 任务背景与核心目标

- **业务背景**:
  玩家在手机端（尤其 TapTap 移动端/WebView）登录时，偶发弹出「连接已断开，当前设备同时在线的账号数量已达上限。」并被强行断开连接（错误码 4006）。
  排查发现：由于移动端离线音频渲染限制，客户端未上报 `browserFingerprint`；服务端 `AccountRiskRequestContext` 错误将粗粒度硬件规格 `config:{DeviceConfigHash}`（屏幕分辨率+CPU核数+GPU型号+Android系统）降级作为自然人主体身份键 `personKey`。
  因市场上主流安卓机型配置高度一致，全国买同款手机的玩家全被判定为同一人；而在默认策略 `MaxAccountsPerPerson = 2` 下，前 2 位玩家创号后，第 3 位及后续所有同机型真实玩家登录时均被 `PERSON_ACCOUNT_LIMIT` 单项硬拦截并以 4006 踢下线。
- **核心目标**:
  1. **线上即时止血**: 调整生产数据库动态策略，关闭 `accountAssociation` 并清空由 `config:` 推导的错误 `person` 历史记录，秒级放行受阻玩家；
  2. **代码层安卓客户端解绑硬件限制**:
     - 在 `AccountRiskRequestContext.cs` 识别 Android 客户端环境（User-Agent 包含 `Android` 等）；
     - 安卓客户端**绝不将 `DeviceConfigHash` 降级赋给 `personKey`**（置为 null），彻底解绑硬件配置与自然人主体关联；
     - 在 `WebSocketRuntime.cs` 中，安卓客户端的在线防多开配额 `quotaKey` **绝不回退到 `DeviceConfigHash`**，杜绝不同玩家因同款手机被塞进同一在线配额桶；
     - 保持 `singleSession`（单账号同账号互踢）与 TapTap OpenID 凭据体系健全，确保安全防线；
  3. **单测覆盖与门禁全绿**: 编写针对 Android 客户端环境与硬件配置信号的单元测试，确保无回归。

## 2. 详细技术实现方案

### 2.1 服务端信号收集 (`src/Server/Clean/AccountAbuse/AccountRiskRequestContext.cs`)
- 增加 `IsAndroid(HttpContext context, AccountRiskClientSignals? client)` 辅助判定：
  - 检查 `context.Request.Headers.UserAgent` 是否包含 `Android`（不区分大小写）；
  - 或 client 的 platform 标记。
- 在推导 `personKey` 时：
  - 针对 Android 客户端：仅当具备强唯一的 `BrowserFingerprint` 或可信设备 Cookie 时推导；**若无强唯一标识，直接置为 null**，严禁使用粗粒度 `config:{DeviceConfigHash}`；
  - 针对非 Android 端（PC/Web 端），亦优化消除 `config:` 直接充当自然人主体的逻辑（硬件配置已在 80 分软风险中计 45 分，不单独作为自然人硬杀指标）。

### 2.2 服务端准入配额 (`src/Server/Clean/WebSocketRuntime.cs`)
- 在获取防多开配额主体键 `quotaKey` 时：
  - `quotaKey = riskSignals.DeviceId ?? (isAndroid ? null : riskSignals.DeviceConfigHash) ?? hello.DeviceFingerprint;`
  - 安卓客户端若没有唯一设备 ID，不塞入粗粒度配置桶，由账号自身的 `singleSession` 保证一人一号。

### 2.3 测试回归
- 在 `tests/Server.Tests/AccountRiskBoundaryTests.cs` 中补充 Android 客户端同硬件配置多账号登录不触发 `PERSON_ACCOUNT_LIMIT` 拦截的确定性回归测试。
