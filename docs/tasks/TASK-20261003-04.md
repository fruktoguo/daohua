## 统一契约（所有实施方必须严格遵守的字段名）

### 技艺标识

`TechniqueId` 字符串七值：`"alchemy"|"forging"|"talisman"|"enhancement"|"formation"|"gathering"|"mining"`。`TechniqueCatalog`（Domain 静态表）提供 `All`、`IsValid`、`LevelFor(cumulativeExp, catalog)`（累计经验按 `RealmProgressionCatalog.ExpToNext` 逐段推进）、`SpeedBonusRatio(level)=0.05*level`。

### 状态与持久化

- `PlayerLoadoutState.TechniqueExperiences: VersionedDictionary<string,double>`（key=TechniqueId）。
- `PlayerLoadoutDocument` 增 `TechniqueExperiences: Dictionary<string,double>`（缺省空）。
- Loadout wire DTO 增 `techniqueExperiences: Record<string, number>`；前端 `types.ts` LoadoutState 同步。
- `ActionIntent` 增 `string? TargetItemId`、`string? AuxItemId`；`action.enqueue` 载荷增 `targetItemId`/`auxItemId`；队列文档与队列快照行同步携带。`Parameters["targetLevel"]`（double）为强化目标等级可选参。
- `SectionCodec.CurrentSchemaVersion` +1、`PostgresSchema.Version` +1，新增 `migrations/` 迁移文件推进 schema_version 标签（新字段均可缺省解码）。
- 存档强化等级资产变体：variant 字符串为 `"+"+level`（如 `"+3"`），`AssetKey("equipment.x","+3")`。装备命令 `loadout.replace` 的持有校验：`enhancementLevel>0` 时校验 `AssetKey(itemId, "+"+level)` 余额，0 级校验基础键。

### 配表字段

行动 JSON 增 `"technique": "<TechniqueId>"`（可省）；`ActionDefinition` 增 `string? Technique`。

消耗品 JSON 增：
- `"durable": bool`（仅 `isContinuous:true` 时有意义：不消耗不耗竭、槽位持有即生效）；
- `"strike": { "manaCostRatio":0.05, "manaDamageRatio":0.2, "spellAttackRatio":2.0, "element":"wood" }`（即时打击，无吟唱）；
- buffs 元素增 `"hpRegenPostRatio"`/`"mpRegenPostRatio"` 可选数值（后段回复乘区）。

`ActiveBuff` 增 `HpRegenPostRatio`/`MpRegenPostRatio`；`CombatBuffState` 同步。
回复公式收口：`regen = (Stats.Regen + Σbuff.Regen) × (1 + Σbuff.RegenPostRatio)`（战斗 5s 格与属性解析同构）。

### 强化结算（领域纯函数 `EnhancementRules`）

- 目标等级 `t = currentLevel + 1`；上限 20。
- 耗时 `5 + t` 秒/次（再受强化技艺速度加成）；技艺经验入账 = 该基础耗时秒数。
- 成本/次：`item.enhance-essence × max(1, floor(t/2))` + `currency.spirit-stone × t×10`。
- 成功率：`t≤10` → 表 `[0.5,0.45,0.45,0.4,0.4,0.4,0.35,0.35,0.35,0.35]`；`t≥11` → `0.3×0.95^(t-11)`，clamp `[0.01,0.5]`；技艺等级 `L≥t` 时 `+(0.01×L)` 加性，`L<t` 时 `×0.9^(t-L)`；终值 clamp `[0,0.99]`。
- 判定用确定性随机：`DeterministicRoll.Next(seed, 0, completedRepeats, channel)`，seed 取行动实例 Id 前 8 字节转 int64。
- 成功 → 变体 `+t`；失败：`AuxItemId` 指定保护材料且余额≥1 → 每轮消耗 1 且 `t-1`（下限 0）；否则归零。保护材料裁决：装备 `enhanceProtectionItems` 非空 → 取列表内任一物品；未配置 → 同装备无强化基础件代护（+0 装备以自身裸件代护时须持有 ≥2）。
- 已装备物品强化时同步更新 `Loadout.Equipment` 槽位等级记录。
- `Parameters["targetLevel"]` 存在且当前等级已达 → 行动提前完成出队。

### 技艺经验授予

`CompleteRepeat` 中：`definition.Technique is {} t` → `GrantTechniqueExperience(t, definition.DurationSeconds)`（强化行动按当次实际基础耗时）。走与 `GrantAbilityExperience` 同构的升级循环 + LevelUp 记录（kind `"technique"`）。

### 雷击符打击路径

`ActivateInstantConsumables` 扩展：触发器满足+冷却过+持有 → 校验 `Manapoints ≥ manaCostRatio×MaxManapoints` → 扣灵力 → 计算 `raw = manaDamageRatio×MaxMana + spellAttackRatio×SpellAttack` → 走守方减伤链（`raw²/(raw+MR×ResistanceScale)` → 攻方 Spell/Wood/Total/Skill 增伤 Linear → 守方 Spell/Wood 减伤 NonLinear → 免伤收口），无命中/暴击掷点 → 作用目标（`PrimaryEnemy` 语义=最高有效威胁，回退首个存活）→ 有 live battle 直接扣 `battle.Enemies[i].Hitpoints`（结果判定交给下一战斗边界）；无 live battle 更新文档快照 `State.Hitpoints` 并重算 `expedition.Outcome` → 扣物品+写冷却+记事件 `consumable.strike`+统计扣物。

### 聚灵阵盘部署路径

`durable` 持续消耗品：槽位 Enabled 且钱包持有 ≥1 即生效。
- 战斗外：资源边界刷新阶段为 durable 槽位注入/清除 `ActiveBuff`（`ExpiresAtUnixSeconds=+∞`，`SourceItemId`=物品 id；槽位移除/禁用/无货时清理同 Source 的 durable buff）。
- 战斗中：`InjectSustainedCombatBuffs` 扩展 durable 槽位 → `CombatBuffState`（后段回蓝乘区字段同步注入）。
