# TASK-20260927-04：300 人离线上线结算性能收敛

- 提出时间：2026-09-27 09:10:00
- 需求分析完成时间：2026-09-27 09:10:00
- 状态：✅ 已完成

## 目标

固定 300 人、离线 12 小时、真实 WebSocket Hello 上线结算作为主性能场景，持续优化当前 ECS 与优化 ECS。目标是优化 ECS 登录结算墙钟进入 OOP 的 3 倍以内；如果经证实受数据库、运行时或业务边界限制无法达到，则记录每个瓶颈和可证明的优化上限，不改变结算语义。

## 当前基线

- 100 人 Gathering：OOP 7.1 秒、当前 ECS 287.5 秒、优化 ECS 144.8 秒。
- ECS `EcsPlayerRuntimeAdapter` 存在跨所有玩家共享的 `_loadGate`，覆盖数据库加载、实体创建、离线补算和提交前路径；这会把并发上线串行化。
- ECS 每名玩家仍会在自己的 World shard 内多次进入 owner gate，并为每个自然边界触发一次 Fiber/System Tick。

## 优化顺序

1. 移除跨玩家 `_loadGate`，保留玩家级锁和 shard owner gate。
2. 运行 300 人三版本基线，记录登录墙钟、`core.simulation`、System Tick、owner wait、数据库和连接失败。
3. 优化 ECS shard 并行度与活动实体查询，确认不会因为增加 shard 改变结果顺序或数据库语义。
4. 若仍超过 3 倍，评估批量加载/批量 ECS Tick；每一步都运行 exact 结果与持久化对比。
5. 记录无法继续优化的真实瓶颈，避免用降低准确性、减少玩家数或跳过上线结算掩盖问题。
