## 2. 需求背景与核心痛点

当前代码库处于开发早期，不存在历史数据兼容负担。但现有 `src/Domain/Models` 及宿主事务逻辑存在以下痛点：
1. **大而全的单体实体**：`PlayerState` 聚合了过多互不相关的领域状态（如背包、修炼、行动队列、属性、战斗资源等），未充分发挥 YuoCore ECS 细粒度组件与按需组合能力。
2. **时间权威与离散事件调度需理清**：行动队列推进需完全收拢到 `SimulationEngine.AdvanceTo(target)`，由分片优先队列提供轻量唤醒调度，避免多头时间权威与忙轮询。
3. **快照持久化边界需要更清晰的版本与安全控制**：持久化写入需保证单调递增版本号与 CAS 防覆写，配置与快照必须具备一致性校验，拒绝非法或过期结构，不提供迁移包袱。
4. **跨边界事务与锁依赖**：部分业务交互存在多层外部锁或粗粒度同步，需逐步收拢为 Actor 消息请求-应答与补偿机制。

### 本任务硬约束

1. **本地开发阶段兼容清零**：不设计、不实现旧数据、旧快照、旧 schema、旧 API/WebSocket、旧客户端或旧组件模型的兼容路径。允许直接改表、改快照、删旧模型、清空本地数据和一次性切换协议。
2. **禁止过渡双轨与 Fallback**：禁止双读双写、旧快照迁移器、legacy flag、fallback adapter、兼容 DTO、旧字段回填或过渡分支；新组件、新快照和新 Protocol 在同一变更中直接成为唯一权威。
3. **行为基线不等于历史兼容**：当前 `SimulationEngine` 只用于识别仍应保留的业务结算语义；已确认的 cap 缺陷直接修正，不为旧实现结果保留错误行为。
4. **禁止过度防御式编程**：只在外部输入、跨边界数据、持久化载荷和明确领域不变量处做必要校验；内部状态机、单 Fiber 所有权和类型系统已保证的路径禁止层层重复判空、重复校验、吞异常、静默回退或增加假设性兜底分支。
5. **测试最小充分且非重复**：测试只覆盖关键业务不变量、真实高风险边界、幂等/CAS/跨边界契约和用户可见入口；禁止为了覆盖率编写无分支 getter/转发代码或重复排列组合断言；smoke 只验证真实跨边界入口与健康状态，禁止搬运领域逻辑。

## 3. 技术重构方案总览

基于 YuoCore 架构哲学（Fiber 独占单线程 World、多泛型 System、Actor 跨边界、StateSync 差量同步与异步 Persistence），重构为**四层数据体系、业务前缀法与 ECS 后缀法命名规约及状态权威明确的离散事件架构**：

1. **确立精细化命名规约**：
   - **业务子项与执行器采用帕斯卡前缀法**：任务数据统一 `Task*`（`TaskBase`, `TaskGathering`, `TaskCultivation`, `TaskAlchemy`, `TaskCombat`, `TaskTravel`），静态执行器统一 `Executor*`（`ExecutorGathering`, `ExecutorCultivation`, `ExecutorAlchemy`, `ExecutorCombat`, `ExecutorTravel`）；
   - **ECS 核心基座保留自然后缀法**：组件统一 `*Component`（`ActionQueueComponent`, `InventoryComponent`, `CultivationComponent`, `CombatResourcesComponent`, `PlayerStatsComponent`, `SyncDirtyComponent`），系统统一 `*System`（`ActionExecutionSystem`）。
2. **Definitions 只读配置层**：`sealed record` + `FrozenDictionary`，启动加载后只读不可变。
3. **状态权威明确的离散事件引擎**：
   - 以 `SimulationEngine.AdvanceTo(target)` 和 `LastSimulatedAt` 作为唯一时间/结算语义；
   - 保留现有 shard `PriorityQueue + generation + SimulationScheduleSignal`，Fiber mailbox 只负责命令投递，调度器只负责唤醒；
   - 全部阻塞、完全离线和无任务状态不安排立即重试，避免忙循环；不对 CPU 或 GC 作未经测量的绝对承诺。
4. **当前版本快照持久化层**：Fiber 安全点生成显式 `SnapshotEnvelope`，包含当前 schema version、状态版本和 `GameDataFingerprint`，旧版本直接拒绝，不提供历史迁移，再写入带版本 CAS 的 durable outbox。
5. **Actor 消息事务与 Saga 补偿**：挂单/撤单等跨边界事务由外部分布式大锁改造为 Actor 消息请求-应答与补偿机制。
