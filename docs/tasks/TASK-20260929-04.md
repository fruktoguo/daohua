## 需求

用户明确裁定成长体系四个池子的语义：

1. **修为（顶部进度条）**：当前境界突破计量条（`Experience`），满层后截断、突破清零。
2. **六维经验**：`CoreAttributes` 六维各自经验（不变）。
3. **底蕴（Foundation，新增独立池）**：修为满层后继续获得的修为 100% 转为底蕴；
   当可继续获得修为（层境未满）时，消耗底蕴使该笔修为获取最高达 3 倍
   （每点底蕴兑换 1 点额外修为，底蕴耗尽即止）。突破不清空。
4. **战斗经验（CombatExperience，新增独立池）**：每次获得修为类经验（`Experience` 收益）
   时，按**增幅前基础量**等额入账战斗经验（不受任何加成增幅）；底蕴溢出部分同样计。

战斗效果：攻击者与被攻击者的战斗经验做对抗——
`r = clamp(aCE / max(bCE, ε), 0.1, 10)`；双方均 ≤0 视为中立。
- `r ≥ 1`：命中等效 `×min(2, 1+(r-1)/8)`、守方闪避等效 `×max(0.5, 1-(r-1)/16)`；
  r=5 → 150% / 75%；r≥9 封顶 2 倍 / 0.5 倍。
- `r < 1`：对 `1/r` 做镜像（命中降、闪避升），下限/上限同为 0.5 / 2。
- 修正在命中闪避等效计算末尾应用（破招/招架 ×2 之后、掷骰之前），
  不改变随机数序列与后续暴击/伤害流程。

同时要求：
- 两个池子在领域层真实持久化、经协议下发，前端词条显示「底蕴」「战斗经验」。
- 规则补充进 AGENTS.md：难以自然英译的修仙专用词，代码标识符直接使用拼音。
- 新建名词对照 Markdown，审计全库命名与中文语义是否错位。

## 方案要点

- `PlayerProgression` 增 `Foundation`/`CombatExperience`（double，≥0，有限校验）。
- `PlayerProgressionState` 末尾追加同名字段（内测直接改存档，schema 版本升 v4）。
- 领域单源结算：`PlayerProgression` 上提供 `CreditExperience(baseGain, amplifiedGain, cap)` 静态结算，
  供 `SimulationEngine` 三条入账路径（连续收益 / 单轮奖励 / 击杀奖励）与领域聚合内冥想路径共用：
  `credited = min(3·amp, amp + Foundation, max(0, cap - Experience))`，
  `Experience += credited`，`Foundation += amp - credited`，`CombatExperience += base`。
- `CombatantStats` 增 `CombatExperience`（init 字段，默认 0，校验 ≥0 有限）：
  玩家在战斗单位构建/刷新点由 `Progression.CombatExperience` 注入（绕过属性缓存）；
  怪物按 `RealmProgressionCatalog.CumulativeExpFor(level)` 派生（新增累经验表访问器）；
  斗法镜像随 `CombatantStats` 冻结透传。
- `DeterministicCombatEngine.ResolveAttack`：命中/闪避等效末尾按上述公式对抗修正。
- 战报 `PlayerBattleReport` 增 `Foundation`（底蕴净变动）/`CombatExperience`（战斗经验入账）。
- wire progression 段下发 `foundation`/`combatExperience`；历史错位键 `spirit` 更名 `experience`。
- 前端 Stats/snapshot/内视 pill 全部接线真值；词条「底蕴」「战斗经验」。
