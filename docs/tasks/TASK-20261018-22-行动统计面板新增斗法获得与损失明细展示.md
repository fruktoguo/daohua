# TASK-20261018-22 行动统计面板新增斗法获得与损失明细展示

## 1. 任务背景与核心目标

- **当前痛点与自洽性问题**：
  1. 当前行动统计面板（`StatsPanel`）底部仅展示「斗法暂存区」（`stagedTotals`），展示当前队首战斗行动中等待到期落袋的押存物品。
  2. 当斗法（PVP）推演结束时：
     - 获胜方：缴获对手暂存区物品，原样混入当前行动的全局「物品获得」（`items`）中，与野怪击杀掉落杂糅，无法辨识哪些物品是斗法战果；
     - 落败方：被缴扣除自身暂存区物品，原样混入当前行动的全局「物品失去」（`itemsLost`）中，与行动消耗、自动丹药混杂；且暂存区被清空后，暂存区直接隐藏，玩家无法查看被缴明细。
  3. 用户明确提出：在当前统计底下的斗法暂存区旁边，增加斗法的损失和获得展示，与斗法暂存区放在一起，且斗法的损失与获得分开统计。
- **核心目标**：
  1. **领域与账本层细分统计**：`PlayerBattleReport` 新增 `DuelItemsGained`（斗法缴获物品）与 `DuelItemsLost`（斗法被缴物品）细分集合；全局 `Items` 与 `ItemsLost` 保持全量语义不变。
  2. **结算与往返一致性**：在胜负判定与弃战判负结算时，将对手押存快照与本方押存快照原子记入细分集合；支持持久化文档 `PlayerBattleReportDocument` 往返与全量快照/增量同步。
  3. **前端呈现**：在 `StatsPanel` 底部斗法区域，与斗法暂存区并列/聚合展示「斗法获得」与「斗法损失」，复用统一规范的 `ItemReference` 复合胶囊，获得与损失分列/分组清晰统计。

## 2. 需求拆解与技术方案

### 2.1 设计真源与设计规约 (`docs/design/总纲/17-行动统计系统.md`)
1. §17.3 账本字段：
   - 新增 `DuelItemsGained`（wire 键 `duelItemsGained`）：斗法缴获物品明细。
   - 新增 `DuelItemsLost`（wire 键 `duelItemsLost`）：斗法被缴物品明细。
   - 保持 `Items`（全量收益，含野怪掉落与斗法缴获）和 `ItemsLost`（全量失去，含材料、药品与被缴）不变。
2. §17.4 记账点：
   - `CombatActionRules`: `CombatOutcome.PlayerWon` 结算对手押存快照时记入 `DuelItemsGained`。
   - `ActionReportBook.RemoveStagedCombatItems` 移除押存快照时记入 `DuelItemsLost`（含回放落败与弃战判负）。
3. §17.5 协议与前端：
   - 随 `PlayerBattleReportDocument` 协议下发，前端缺省空列表容错。

### 2.2 领域与 ECS 记账层 (`src/Domain`, `src/Ecs`)
1. `PlayerBattleReport` (`src/Domain/Player/PlayerDuel.cs`):
   - 增加 `List<PlayerReportItem> DuelItemsGained { get; } = [];`
   - 增加 `List<PlayerReportItem> DuelItemsLost { get; } = [];`
   - 增加 `AddDuelItemGained(ItemId, double)` 与 `AddDuelItemLost(ItemId, double)` 方法（同物品数量累加聚合）；
   - 在 `ResetBucket` 清空两列表；在 `HasContent` 纳入判定。
2. `PlayerStatsDelta` (`src/Domain/Player/PlayerStatsDelta.cs`):
   - 增加 `public IReadOnlyList<DuelStagedItem>? DuelItemGains { get; init; }`；
   - 在 `ApplyTo(PlayerBattleReport report)` 中：
     - 若 `StagedItemLosses` 非空，逐件调用 `report.AddItemLost` 与 `report.AddDuelItemLost`；
     - 若 `DuelItemGains` 非空，逐件调用 `report.AddItem` 与 `report.AddDuelItemGained`。
3. `CombatActionRules` (`src/Ecs/Systems/CombatActionRules.cs`):
   - `PlayerWon` 分支调用 `player.RecordStats` 时传入 `DuelItemGains = playback.OpponentStagedSnapshot`。
4. `PlayerStateDocument` 校验边界 (`src/Domain/Player/PlayerStateDocument.cs`):
   - `IsValidReportDocument` 增加对 `DuelItemsGained` 和 `DuelItemsLost` 的安全结构校验。
5. 编解码与持久化 (`src/Domain/Player/PlayerDuelStateCodec.cs`, `SectionCodec.cs`, `PostgresSchema.cs`):
   - `ExportReport` 导出 `DuelItemsGained` 和 `DuelItemsLost`；
   - `ImportReport` 恢复两字段；
   - 版本按规范推进至 35，补齐 `migrations/0035_v34_to_v35.sql`。

### 2.3 前端呈现层 (`frontend`)
1. **类型与映射** (`frontend/src/game/types.ts`, `frontend/src/network/snapshot.ts`):
   - `BattleReport` 增加 `duelItemsGained: BattleReportItem[]` 与 `duelItemsLost: BattleReportItem[]`；
   - `snapshot.ts` 使用 `mapBattleReportItems` 映射新字段；
   - `battleReportStore.ts` 的 `normalizeStoredReport` 对旧缓存安全补齐 `storedArray`。
2. **统计面板 UI** (`frontend/src/components/StatsPanel.tsx`):
   - 提取 `duelItemsGained` 与 `duelItemsLost`；
   - 与 `stagedTotals` 整合于统一紫调斗法区域（`.battle-report-staged`）：
     - 若有暂存物品：展示「斗法暂存区」及对应复合胶囊；
     - 若有斗法战果（获得或损失）：以分列（`battle-report-item-columns`）展示「斗法获得」与「斗法损失」；
     - 暂存区、获得、损失三者任一非空均渲染斗法展示卡，皆空时安全隐去；
   - 补齐 i18n 词条（`combat.report.duelItemsGained`、`combat.report.duelItemsLost`）。
