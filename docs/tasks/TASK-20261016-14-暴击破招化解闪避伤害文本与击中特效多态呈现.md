## 2. 问题根因分析

1. **特殊对抗标签与伤害文本样式单一**：
   - 暴击、破招、化解（原称拆招）、闪避的伤害浮字此前仅附带统一格式的纯数字，暴击数字排版与普通伤害缺乏阶梯差距；
   - 当同时触发「破招」与「暴击」时，原先简单三元选择导致暴击被破招覆盖，错失仙侠战斗中“破招致胜触发双倍暴击”的极致高光反馈；
   - 术语未完全对齐设计真源中统称的「化解」。
2. **立绘与受击受挫特效未区分命中性质**：
   - 受击方 `impact` 受击特效无论普通命中还是暴击均只有统一红色光效；
   - 暴击缺乏震撼的金色冲击波与立绘金光闪烁，缺乏刀刀到肉的暴击反馈。

---

## 3. 实施方案

1. **i18n 词典规范化**：
   - 将 `combat.arena.parry` 统一命名为「化解」（对齐设计总纲 §7.7.3 与 §19 名词对照表）；
   - 补充 `combat.arena.breakCrit` 复合标签「破招·暴击」。
2. **多态伤害文本排版与徽标（CombatArena.tsx）**：
   - **暴击 (Crit)**：金色徽标 `[暴击]` + 醒目大字 `-XXX!`，末尾带惊叹号；
   - **破招 (Break)**：烈橙徽标 `[破招]` + 刚劲锐角字 `-XXX`；
   - **破招·暴击复合 (Break+Crit)**：金橙烈焰复合徽标 `[破招·暴击]` + 特大震撼字体 `-XXX!!`；
   - **化解 (Parry)**：冰蓝银月徽标 `[化解]` + 柔和小字 `-XXX`，体现力量被卸除化解；
   - **闪避 (Dodge)**：水绿飘逸文字 `闪避`（若同时有化解，前缀显示 `[化解]`）。
3. **纯文本多态呈现与视觉动效（CombatArena.tsx & expedition.css）**：
   - 根据用户明确需求：不使用 emoji/符号图标，以纯文本与排版样式做彻底区分，杜绝生硬符号；
   - **差异化字体与多态标签呈现**：
     - **暴击 (Crit)**：金色 `#fbbf24`、21px 大字、末尾感叹号 `!`、金色描边徽标 `[暴击]`、`arena-resource-float-crit` 放大跳字动效；
     - **破招 (Break)**：烈橙 `#fb923c`、18px 刚劲字、烈橙描边徽标 `[破招]`；
     - **破招·暴击 (Break+Crit)**：金橙烈焰 `#f59e0b`、23px 特大字、双感叹号 `!!`、金橙渐变徽标 `[破招·暴击]`；
     - **化解 (Parry)**：冰蓝 `#93c5fd`、13.5px 柔和小字、0.92 不透明度、冰蓝徽标 `[化解]`，视觉上明确表达伤害被大幅削减；
     - **闪避 (Dodge)**：水绿 `#2dd4bf`、14.5px 飘逸字 `闪避`（若同时化解则带 `[化解]` 徽标）、`arena-resource-float-dodge` 身法滑行；
   - **刀光冲击刃芒多态**：暴击金色电芒 `.arena-impact-fx--crit`、破招碎甲裂片 `.arena-impact-fx--break`、化解水波涟漪 `.arena-impact-fx--parry`。
4. **实体 ID 匹配缺陷修复（isActorMatchingId）**：
   - 根因：远征敌人 `actorKey` 格式为 `enemy:waveNumber:index:enemyId`，原逻辑错误以 `waveNumber` 对应 `targetIndex`，导致非 0 波次或非 0 号位敌人完全无法匹配事件，表现为“完全没显示”；
   - 修复：正规化解析 `actorParts` 与 `entityParts`，正确提取敌人索引与盟友下标，全覆盖波次怪、盟友与斗法对手。
5. **多段连击技能（连环等）逐段独立弹字与血条切片**：
   - 根因：原 `batchCounts` 混入 damage 与 crit 等瞬态值致连击段计数不连续，且保底 `useLayoutEffect` 未检测事件流接管，导致多段伤害被直接聚合成单条总数值；
   - 修复：
     1. 服务端 `ProtocolSnapshotMapper` 在 `recentEvents` 中透传各段击中后的真实剩余气血 `targetHp`；
     2. 前端事件流按 `comboCounts` 依段次错开节奏（每段 110ms）与车道偏移，逐段独立爆出弹字；
     3. 连击每段根据该段伤害与 `targetHp` 在血条对应物理区间精准生成切片碎裂效果，血条阶梯式下降；
     4. `useLayoutEffect` 保底逻辑在有事件流接管时自动抑制重复合并飘字。
