## 关键问题：源图并非严格均匀网格

先按「边长 = 宽/列、高/行」的**朴素等分**试切（1374/6 = 1145/5 = 229），结果自检显示多格「留白边距 0px」。
把等分线叠加到源图上目视确认：**等分线确实切到了图标** —— 第 1、2、4 行底部都有图标被切掉约 6~13px。

原因是这三张 AI 生成图的排布**间距不均匀**：

- 图1 各图标带在垂直方向的实际中心为 `136 / 363.5 / 588 / 824 / 1025`，相邻间距 `227.5 / 224.5 / 236 / 201`，标准差很大；
  且**第 4 行与第 5 行之间几乎没有空隙**（行投影在 y=929 处仍有 10px 内容，是两行图标尖端相接）。
- 因此不存在一组均匀分界线能同时把所有图标完整包住。

## 最终方案：内容间隙定位 + 分界线屏蔽越界

仍输出**规则的等边正方形网格**（不是逐图标抠图），但网格的位置来自内容间隙而非朴素等分：

1. **带定位**：对 alpha>32 的掩膜做整行 / 整列投影，取出连续的「有内容区段」= 图标带；
   若相邻两带粘连（band 数少于声明行/列数），在最宽区段的**中间低谷**再切一刀（图1 的 4/5 行即由此分开）。
2. **分界线**：取相邻图标带**空隙的中点**作为网格分界线（图1 行分界 ≈ 250.5 / 469.5 / 709.5 / 929）。
3. **方格边长统一**：`边长 = 全体图标带最大边长 + 2×8px`，三个图集分别为 **244 / 242 / 396**；
   每个方格以「所属图标带中心」定位，因此图标在方格内居中、四周留白保留。
4. **越界屏蔽**：当方格边长大于该带区段（相邻两行无空隙时必然发生），方格会压到邻居图标上；
   此时按第 2 步的分界线把越界的那一条 **alpha 直接置 0**。因为分界线落在内容低谷，
   抹掉的只是邻居的尖端若干像素，本图标本体不受影响。
5. **边界补齐**：方格超出源图的部分用透明像素补齐，保证每张都是同尺寸正方形。
6. **两级输出**：从同一份全分辨率方格重采样出 256 PNG 母版与 64 WebP 网页版，详见下一节。

## 两级资产管线（追加需求，已落实）

用户确认：**工程保留 256 PNG，网页使用 64 WebP**。切图脚本改为一次产出两级：

| 级别 | 尺寸 | 格式 | 输出目录 |
| :--- | :--- | :--- | :--- |
| 工程母版 | 256×256 | 全彩 RGBA **无损 PNG** | `<out>/工程_256png/` |
| 网页版 | 64×64 | **WebP**（有损 q=90，method=6，带 alpha） | `<out>/网页_64webp/` |

两级都从同一份全分辨率方格**一次性 LANCZOS 重采样**，避免「256 → 64」的二次缩放损失。

同时去掉了上一版的 256 色量化：量化会把不透明区 alpha 退化成 253（脏 alpha）且有损，
而全彩无损 PNG 单张仅 62~88KB，工程母版没有压体积的必要。

### 体积与画质实测（64 张）

| 方案 | 合计 | 单张均 |
| :--- | ---: | ---: |
| 工程母版 256 全彩 PNG | 4.3MB | 62~88KB |
| 网页版 64 WebP 有损 q=90 | 178KB | 2.8KB |
| 网页版 64 WebP 无损（对照） | 298KB | 4.7KB |

**画质测量口径很重要**：WebP 有损会往**完全透明像素里填任意 RGB**，若直接算整图 PSNR，
会得到中位仅 23dB 的荒谬结论。正确做法是分通道、分区域量：

- alpha 通道 PSNR **57~62dB** —— 边缘透明度几乎无损；
- 可见像素（`alpha > 8`）RGB PSNR **24~38dB，中位 30.8dB** —— 64px 下有轻微柔化。

结论：若图标总量只有几十~几百张，**建议改 `--web-lossless`**，全套仅多约 120KB，可彻底消除画质争议；
当前已按用户要求交付 q=90 有损版，如需无损只需重跑一条命令。
