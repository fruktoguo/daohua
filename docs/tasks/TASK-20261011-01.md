## 期望目标（一句话）

把队伍面板里混用的「斗法/参战就绪」概念纠正为设计真源语义：**斗法 = 队伍级 PVP 撮合开关**（仅讨伐目标显示、仅队长可改、会话冻结），**准备 = 成员个人就绪**；并让勾选斗法的队伍真正作为一个匹配单位进入撮合池，与单人斗法玩家（或其他斗法队伍）进行确定性多对多剧本战斗。

## 现状问题（分析结论）

1. **UI 语义错误**：顶部「参与斗法/暂不参战/退出斗法」按钮与成员卡底部「参战就绪」都切换同一个 `member.ready`——根本没有队伍级 PVP 开关。
2. **生产撮合断链**：旧版 `PlayerActor` 撮合器（`TryMatchDuelAsync`）在 ECS 重构（`c3c6d86`）中被删除未移植；`DuelAdvanceOptions(MatchingEnabled: true)` 全仓仅在测试出现——当前生产单人斗法只攒遭遇计数、永不撮合。
3. **斗法模型是 1v1**：`DuelScriptEvent`/`DuelPlaybackState` 以单方对手建模；队伍斗法需要多对多（N-vs-M）剧本与回放。
4. **会话固定 PVE**：`ActionParticipation` 队首意图硬编码 `PvpEnabled: false`，会话引擎无斗法相位、无会话级遭遇计数，spec 无斗法字段。

## 设计口径（已落入 §7.10.4 与 §21.13 交叉引用）

- **匹配单位**：斗法撮合以「单位」为粒度——单人勾选斗法且会话外的玩家 = 单人单位；`pvpEnabled` 且目标为讨伐、会话进行中的整队 = 队伍单位。单位实力 = 全体出战单位六维等级总和之和。
- **队伍斗法开关**：`social.parties.pvp_enabled`，档案级字段，仅队长经 `party.update` 修改；仅 `activityKind='combat'` 可为 true，目标改离讨伐自动归位 false；会话创建时冻结进 spec，会话中修改触发散场重建（与目标漂移同口径）。
- **遭遇计数**：队伍单位计数器随会话生灭（会话权威状态承载）；单人沿用 `PlayerDuel.EncounterCharges`。
- **剧本多方化**：`DuelScript` 输入由两名 `DuelCombatant` 扩展为两侧名单（各 1~5 名）；事件携带双方单位下标；回放载荷携带本方名单（成员各自定位 SelfIndex）与对手名单。
- **暂存区**：队伍单位每名成员持有个人暂存区；败方全体暂存物按胜方成员数均分转移（向下取整，余数顺序分配）。
- **弃战与冷却**：队伍单位任一成员取消准备/离队/被踢/离线逐出即散场——斗法进行中散场 = 整队弃战判负，全体成员各入失败冷却；单人沿用现有口径。
