# TASK-20261007-01 节点公共建筑拥挤衰减：按等级承载人数 + 超编线性衰减 + 建筑 tab 使用人数展示

## 需求

- 提出时间：2026-10-07 09:03:12
- 需求原文：当前建筑增益无视人数、统一加成。新增设定——公共大地图建筑有等级相关使用人数上限：一级最多支持 100 人使用，每超过 100 人效果减少 10%（不降至 0%），超过 1000 人减少 50%，近似线性增长；上限每级 +10% 人数基数。「支持使用」指玩家正在执行该建筑增益的相关行动（如采集建筑只统计正在采集的玩家数），不是身处节点即计入。地图建筑 tab 显示每座建筑当前使用人数与超出百分比，使用人数需含承载上限（如 50/100）。

## 分析

- 建筑效果链路：`NodeBuildingRegistry`（共享注册表，`game.node_buildings`）→ 每拍 `RefreshNodeBuildingsAsync` 投影进玩家 `World.NodeBuildings`/`NodeBuildingEffects`（持久化、离线/冷挂机沿用最近已知投影）→ `EffectiveNodeBuildingEffects` 在 `ActionExecutionRules.Timed`（耗时÷(1+ratio)、收益×(1+ratio)）与 `PlayerAttributeResolver`（战斗回血/减伤）消费 → `ProtocolSnapshotMapper` 下发 `buildingEffects`/`nodeBuildings`。
- 「正在使用」的权威判据：玩家行动队列中 `Running` 状态行动的 `ActionKind`，归属节点取 `current_node_id`（在边上时其 Running 行动是赶路，天然不计入）。
- 现成读模型：`game.player_action_queue`（flush/compute 两条写路径事务性全量重建，含 `action_id`+`status`）与 `game.player_projection.current_node_id`（同事务顺带维护）——`JOIN ... WHERE status='running' GROUP BY node, action` 即得 (节点,行动)→人数 计数，**无需新增写路径**；在线/离线玩家一视同仁。
- ComputeNode 回写路径（`ApplyComputeResultInTransactionAsync`）补挂 `UpsertProjectionAsync`：补算迁地后 `current_node_id` 不再滞留旧节点（顺带修复既有投影滞后）。
- 读侧：注册表内新增 TTL（15s，对齐 15s 脏龄去抖）刷新的使用计数缓存；每拍投影携带「按服务行动类别人数衰减后的效果集 + 每座建筑 usage(使用数/承载/效率)」。
- 衰减是软指标、非资产结算：读模型最终一致（秒级滞后），单人模拟只消费持久化投影，确定性语义与建筑等级投影同口径。

## 实现要点

- `NodeBuildingRules`：`CrowdCapacity(level)=100+10×(level-1)`（一级 100、每级 +10% 基数线性）；`CrowdEfficiency(level,users)=1`（users≤cap）否则 `1-min(0.5,(users-cap)×0.001)`（每超 1 人 -0.1%，即每 100 人 -10%，减幅封顶 50% 于 cap+500）；`ServedKinds(modifiers)` 由非零修饰项映射服务行动类别（探索/炼丹/修炼/战斗）；`AggregateEffects` 增人数参重载，每座建筑整体缩放 `level×efficiency`；`NodeBuildingUsage(BuildingId,ActiveUsers,Capacity,Efficiency)` 记录下发。
- `game.player_projection` 不加列：边上行者 Running 行动即赶路，行动类别过滤天然排除；仅排除 `presence='suspended'`。
- 快照：`world.nodeBuildings[]` 增 `activeUsers`/`capacity`/`efficiency`；world 分段新增 `nodeBuildingUsages`（可缺省解码），存档 schema v16→v17（仅标签推进，`migrations/0017_v16_to_v17.sql`）。
- 前端建筑卡与详情：`使用中 {n}/{cap}`；超载时 `超出 +x% · 效果 -y%`。
- 设计真源：总纲 09 篇 §9.4 增拥挤模型、§9.5 增展示字段、§9.6 增读模型一致性约定。
