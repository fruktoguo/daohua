# TASK-20261010-01 · dev.sh TUI 升级为运维控制台

## 需求

用户反馈当前 `dev.sh` 的 TUI 实现较差：

1. 日志信息无法滚动回看（只有尾部固定行数）；
2. 无法按 错误 / 警告 / 普通日志 级别切换过滤；
3. 希望 TUI 能力接近 `http://daohua.localhost/ops` 运维面板——像 agent 操作台一样既能输入指令执行操作，也能查询服务端信息。

## 需求分析

- 旧架构瓶颈：dev.sh 前台 shell 只把白名单单键（a/s/b/f/r/q）逐字转发给 TUI，TUI 拿不到方向键、翻页键、鼠标与文本输入，无法支撑滚动与指令输入。
- 新架构：dev.sh 把 `/dev/tty` 按键**原始字节流**转发给 TUI（含 ANSI 转义序列与 UTF-8 多字节），由 `dev-tui.mjs` 统一解析终端输入协议，支撑完整的按键 + 文本行输入。
- 指令层复用现有 `/ops/api/*` 数据端点（127.0.0.1:5128，Development-only），无需后端改动；写操作令牌自动读取 `appsettings.Development.json` 的 `Ops:Token`，与 `/ops` 页面同口径二次确认。

## 方案落地

- **输入协议**：`run_tui_input_loop` 改为字节转发器；TUI 实现 CSI/SS3 转义序列、SGR 鼠标滚轮（1006）、控制键与 UTF-8 文本解码。
- **日志视图**：事件缓冲 1000→8000 行；`↑↓/j/k` 单行、`PgUp/PgDn/Space` 翻页、`g/G` 顶/底、鼠标滚轮滚动；底部自动跟随；长行按终端宽度折行。
- **级别过滤**：`e` 仅错误、`w` 警告及以上、`i` 全部；与 `a/s/b/f` 来源过滤叠加；指令回显输出不受过滤影响。
- **指令模式**：`:` `/` `Enter` 进入；行编辑（Ctrl+A/E/K/U/W）、↑↓ 历史、Tab 补全、Esc 取消。
- **指令集**：
  - 查询：`overview/health/players/player <id|名>/sessions/scheduler/storage/compute/config/logs [级别] [n] [关键词]/errors`
  - 市场：`market book|orders|trades|metrics`、`catalog`
  - 写操作（y 确认 + 令牌）：`kick/flush/unload/drain/sell/buy/cancel`、`token`
  - 本地：`help/open/clear/quit`
- **非 TTY**：保持原普通日志流回退不变。
