# TASK-20261015-18 装备强化起护等级、感悟补全与单品锁定修复

## 1. 任务背景与核心问题

强化系统目前存在三个影响游戏体验与数值结算的核心问题：
1. **强化保护无法自定义起护等级**：当前前端与协议仅有使用保护的二元开关（`auxItemId`），服务端每轮无差别消耗保护材料。从 +0 强化到 +1 失败亦回退 +0 本身无需保护，且从 +1 到 +2 等低级阶段消耗稀缺保护材料造成巨大资源浪费；玩家无法指定从哪一级开始使用保护（最低应为 +2）。
2. **强化「感悟」缺失与经验预览错误**：非战斗行动统一遵循「产出 / 感悟 / 耗时」布局，强化单轮结算服务端已实现入账强化技艺经验与六维·神识经验（总纲 §20.1.2 / §20.1.4），但前端强化页面未呈现标准「感悟」面板，技艺经验错用单轮耗时（秒数）展示，神识经验完全漏报，行动卡及演武场中强化行动亦缺乏对应感悟与产出投影。
3. **多件同名装备循环被轮番强化（无法锁定单品）**：玩家背包若持有多件同名基础装备（例如 10 把铁剑 +0），设定目标为 +5 时，因意图携带静态 `initialLevel = 0` 且无单品锁定追踪，每轮均匹配背包中仍存在的 +0 件，导致系统重复将 10 把铁剑轮番强化至 +1，而非锁定单件装备持续向上冲阶。

## 2. 详细技术方案

### 2.1 保护起始等级（起护等级，最低 +2）
- 服务端 `EnhancementRules` 新增 `ProtectFromLevelParameter = "protectLevel"`（默认 2，合法范围 `[2, MaxLevel]`）。
- `EnhancementRules.Resolve` 裁决保护材料时：
  - 若未携带保护材料或当前强化等级 `current < protectLevel`：本轮不检查、不消耗保护材料，失败走 `FailReset`（归零）。
  - 若 `current >= protectLevel`：必须消耗保护材料，失败走 `FailProtected`（保级）。
- 前端 `EnhancementPage.tsx` 在启用保护材料时展示起护等级选择器（最低 +2，上限 `targetLevel`，步长 1），单轮预览与产出根据当前等级是否达到起护阈值精确反映材料消耗与失败保级/归零结果。
- 词条入库：`app.zh.ts` 与 `template.csv` 补充 `app.enhancement.protectLevel` 等键名。

### 2.2 强化感悟标准展示（强化技艺经验 + 六维·神识）
- 依据总纲 §20.1.2 与 §20.1.4，单轮基准经验由被强化装备等阶换算境界等级（`CraftingRecipeRules.ResolveItemLevel` / `convertTierToLevel`）与当次单轮耗时（`5 + nextLevel`）推导：
  - 强化技艺经验：`Math.Max(1, Math.Round(BaseExperienceForLevel(itemLevel) * (duration / 10)))`
  - 六维·神识经验：`Math.Round(BaseExperienceForLevel(itemLevel) * (duration / 10))`
- 前端 `EnhancementPage.tsx` 移除旧有的错误 `expGainLabel`（秒数冒充经验），替换为统一的 `<dt>{t('app.action.insights')}</dt>`，包含六维·神识徽标与强化技艺徽标。
- `CombatArena.tsx`（演武生活卡片）针对 `enhancement` 类型行动，依据 `queueEntry.targetItemId` 动态解算并展示强化产物与感悟信息。

### 2.3 单品锁定追踪（消除轮番冲 +1 Bug）
- `IPlayerActionState` 与 `QueuedAction` 新增可变属性 `int? EnhancementCurrentLevel { get; set; }`。
- `QueuedActionState` 载荷扩展可选字段 `int? EnhancementCurrentLevel = null`。
- 在 `ActionExecutionRules.Timed.cs` 中：
  - 开轮准入 `TryStartActionCore`：通过 `Resolve` 确定初始强化等级并存入 `action.EnhancementCurrentLevel`。
  - 单轮结算 `CompleteEnhancementRepeat`：每次判定完成后将 `resultLevel` 写入 `action.EnhancementCurrentLevel`。
  - 下一轮推进时，`EnhancementRules.Resolve` 优先使用 `action.EnhancementCurrentLevel` 作为当前等级，只针对该特定变体等级进行准入和转移，彻底杜绝回退扫描背包中其他低级同名装备。
- 当 `action.EnhancementCurrentLevel >= targetCap` 时触发 `Check.TargetReached`，提前成功出队。
