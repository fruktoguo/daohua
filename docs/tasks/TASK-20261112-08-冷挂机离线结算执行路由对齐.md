# TASK-20261112-08 冷挂机离线结算执行路由对齐

## 背景与需求

生产排查离线挂机收益归零问题时发现：`compute_jobs` 的实际执行者与原始设计意图不一致。

- **设计意图（用户明确裁定）**：
  1. 非即时的每小时统一离线结算（`compute_jobs`）——**分布式计算节点优先**；
     没有分布式节点接入时，才由主服本地执行器兜底，且**仅在中低负载时**执行（高负载让位在线服务，离线欠债顺延由登录即时补算兜底）。
  2. 玩家上线的即时补算——**强制本地执行**（现状已符合：登录路径内联 `RunPlayerOnceAsync`，不经任务队列）。
- **现状（偏离）**：`LocalComputeExecutorWorker` 以 `minPendingAge=0` 先到先得、消费全部任务；`ComputeDispatcherWorker` 只领取 pending 超过 `ComputeNode:OverflowAfterSeconds`（300s）的积压。生产实测 6094 个成功任务全部 <60s 完成，odin 节点零负载。

## 变更面

- `ServerOptions`：移除 `ComputeNode:OverflowAfterSeconds`/`ComputeOverflowAfter`，新增 `ComputeNode:LocalFallbackMaxCpuPercent`（默认 50，合法区间 1..99）。
- `ComputeDispatcherWorker`：领取口径由溢出阈值改为即时（`minPendingAge=0`），有节点容量即优先派单。
- `LocalComputeExecutorWorker`：注入 `ComputeLinkRegistry`，领取前判 `NodeCount==0` 且进程 CPU 低于阈值；节点在场或高负载时不领取。
- `OpsPanel`：compute 配置快照字段 `overflowAfterSeconds` → `localFallbackMaxCpuPercent`。
- `ComputeLinkLoadScenario`：移除已无意义的 `ComputeNode__OverflowAfterSeconds=0` 环境设置。
- 总纲 18 §14.4 段：执行路由描述改为「节点优先 / 本地低负载兜底 / 即时补算强制本地」。

## 验收

- 定向单测/集成测试通过（compute 相关套件）。
- 行为预期：节点在线时本地执行器不消费任务；节点断开后本地在 CPU 低于阈值时接管。
