# TASK-20261005-01 七技艺工具系统全栈落地

## 需求

- 七技艺（炼丹/炼器/符箓/强化/阵法/采集/挖掘）各配一件可装备工具；
- 本批为「最低一级工具」：每件提供对应技艺行动 +10% 速度加成；
- 工具由炼器制造：炼器页新增「技艺」分组承载全部工具配方；
- 数据结构为后续品阶工具预留空间（加成数值配表化、装备 tier 字段、槽位命名规范）。

## 现状调研结论

- 七技艺已在 `src/Domain/GameData/TechniqueCatalog.cs` 定义：alchemy/forging/talisman/enhancement/formation/gathering/mining；
- 前端 `EquipmentPanel` 底部仅 4 个纯占位工具槽（采矿/伐木/炼丹/炼器），无物品、无穿脱、无服务端支持；
- 装备穿戴走 `loadout.replace`：服务端按装备配表 `slot` 字符串做唯一互斥校验；装备上限 16；
- 行动耗时结算点 `ActionExecutionRules.Timed.TimedActionDuration`：建筑速度乘区与技艺等级乘区（每级 +5%）同点除法；
- 强化裁决 `EnhancementRules.Resolve` 只要求目标命中 `RawEquipments`——工具进装备目录后必须拦截强化，否则强化白烧灵石零收益；
- 前端行动耗时预览（actionCalculations）只算了建筑速度，技艺等级加成未并入（本任务顺带补齐该口径）。

## 设计定稿

### 物品模型

工具作为装备目录条目（`equipment.` 前缀，进 `RawEquipments`）：

- `slot = "tool-<techniqueId>"`：七种专属槽位字符串，`LoadoutCommand` 的 slot 唯一互斥校验天然生效；
- `techniqueBonus = { "technique": "<techniqueId>", "speedRatio": 0.1 }`：绑定技艺与速度加成，数值配表化为品阶扩展留空间；
- `tier = 1`，不配 flatStats/baseStatRatios（战斗属性零贡献）；
- 命名遵循「本名不拼品阶前缀」规则（expected-attributes.json namingRule），未来高阶工具以新 id/新名承载。

### 速度加成结算

`TimedActionDuration` 技艺分支扩展：装备的 `techniqueBonus.technique` 命中行动 `Technique` 时将其 `speedRatio` 加进同一除数——

```
duration /= 1 + 0.05×技艺等级 + Σ装备工具speedRatio
```

与技艺等级加成同点加算，保持确定性、不跨技艺叠加。槽位互斥保证同技艺至多一件工具。

### 制造

`forging.json` 末尾新增 7 条 `forge.tool-*` 行动（type=alchemy，technique=forging），产出 `equipment.tool-*`；前端炼器页 `FORGING_SUB_TABS` 新增 `technique` 分组（按产出物 slot `tool-` 前缀过滤）。

### 边界规则

- `LoadoutCommand` 装备上限 16 → 24（11 战斗槽 + 7 工具槽 = 18 覆盖并留余量）；
- `EnhancementRules.Resolve` 拦截 `slot` 以 `tool-` 开头的目标（拒绝强化，文案「技艺工具无法强化」）；前端强化页候选同步过滤；
- `StaticGameCatalogMapper.Equipments` 透传 `techniqueBonus`，前端 `CombatEquipmentDefinition`/`EquipmentSlot` 类型同步；
- 行动耗时前端预览补齐「技艺等级 + 工具」折算，工具作为 type='speed' 加成明细展示。
