## 需求分析

用户提出两项组队体验优化：

1. **创建队伍时的选择默认值**：目标类型默认「讨伐」（现状已是 `PartyActivityKind.Combat`，保持）；地图节点默认玩家当前节点。现状 `CreateSection`/`MatchSection` 用 `useState(defaultNodeId)` 只在挂载瞬间取一次值——挂载时 `world.nodeId` 为 null（行进在边上/快照未装载）即永远停在「不限」，且玩家在表单打开期间移动后默认值不更新。修复为「未手动选择过节点时始终跟随 `world.nodeId`」。
2. **组队讨伐中的「停止」语义**：当前参与行动条目的停止/移除入口（顶栏停止钮、队列行 ×、战斗页终止钮）一律弹提示「请在队伍页取消准备或离队」，路径长且不直观。用户要求「停止则取消准备」——即触发 `party.unready`（会话中取消参战按 §21.13 名册冻结规则散场），散场后挂起的个人队首行动由服务端自动恢复续跑（`EnqueuePriority` 挂起 + `EndActionParticipation` 收尾机制已就绪，无需后端改动）。

## 设计边界

1. 表单节点跟随以「脏标记」实现：用户手动选过节点后以手选值为准（含显式选回当前节点，视为恢复跟随）；`LeaderProfileModal` 从队伍快照初始化、`LobbySection` 筛选默认「不限」均为刻意设计，不动。
2. 参与行动恒为 CombatEncounter 行动：停止入口只影响 `QueueCenter`（顶栏停止 + 队列行 ×）与 `CombatArena` 战斗终止钮三处；`WorldMapPanel` 的旅行停止不涉及。
3. 散场影响全队，沿用 `social.confirm.quitSessionTitle/quitSessionDesc` 确认弹窗（与队伍页「退出斗法」同一文案、danger 样式），确认后 `unreadyParty()` 派发 `party.unready`。
4. 队列行 ↑↓ 移动钮对参与条目仍禁用（服务端 `queue.move` 同口径拒绝），tooltip 保留 `social.session.cancelHint`；`queue.clear` 在会话中服务端仍拒绝（语义是清空个人队列而非散场，不合并进「停止」链路）。
5. 散场→恢复为纯服务端链路：`party.unready` → 仲裁散场（member-unready）→ `EndActionParticipation` 写权威时刻 → 模拟推进到该时刻移除队首参与条目 → `ActivateHead` 恢复挂起的个人行动；前端无额外动作。
