## 一、需求原文与解读

用户提出四点：

1. 「战斗属性和预览不应该显示小数」——战斗属性详情（基础/特殊属性、百分比、回复、攻击间隔）与行动收益预览的展示层一律取整，仅改显示不改领域结算。
2. 「当前地图的附近纵向没有自动滚动列表，底下的看不到了」——`.nearby-layout` 缺 `overflow-y: auto` 与高度链，需补齐滚动。
3. 「附近拆分一下吧，变为多个tab，分别是 怪物 人物 建筑」——附近面板内部分类 Tab：怪物（普通+精英+首领）、人物（NPC+附近玩家）、建筑。
4. 「开始完善建筑功能」——建筑列表类似行动列表无限增长；系统建筑/玩家建筑仅边框区分；末尾固定一个加号占位卡，点击弹出「此地可建造且已解锁」建筑候选；先落地少量建筑；建筑后续用于增幅行动效能（采集速度/收益、炼丹炼器速度、战斗回血与减伤），具体效果数值后续再讨论。

## 二、方案设计

### 2.1 数值取整（纯展示层）

- `formatNumber(v, { maxDecimals: 0 })`：战斗面板基础属性、气血/灵力数值、怪物面板数值、行动预览收益（向下取整）。
- 百分比：`Math.round(ratio * 100)` → `+N%`，统一替换 `Math.round(v*1000)/10` 一位小数写法（CombatArena、ItemDisplay、format.ts `abilityPercent`）。
- 攻击间隔：`Math.round(ms/1000)` → 整数秒。
- `PercentValue.format()` 默认精度 `decimals = 0`。
- `InsightPage` 回复合计 `Math.floor`。

### 2.2 附近面板 Tab + 滚动

- `NearbyPanel` 内部新增三段 Tab：`monsters`（普通+精英+首领）/ `people`（常驻人物+附近玩家）/ `buildings`，本地 `useState` 管理，不进全局 Store。
- `.nearby-layout` 改为 `display:flex; flex-direction:column; height:100%; overflow:hidden` 弹性列；标题与 Tab 条 `flex:0 0 auto`，新增 `.nearby-scroll` 内容区 `flex:1; min-height:0; overflow-y:auto`，解决底部被裁剪问题。

### 2.3 建筑功能（全栈最小闭环）

- **配表**：新增 `config/game-data/buildings/buildings.json`（`building.*` 前缀条目，`requiredRealmLevel` 解锁、`availableNodeIds` 地点限定、`effect` 展示文本）。初版建筑覆盖采集/炼丹/炼器/战斗方向。
- **领域**：`BuildingDefinition` 进 `GameDataCatalog`；`PlayerWorldState.Buildings`（`PlayerBuildingState{BuildingId, NodeId}`）随 World 分段持久化；`PlayerAggregate.BuildBuilding` 校验与去重。
- **协议**：`WorldSection` 增 `playerBuildings` 字段（实体 DTO，kind=building）。
- **服务端**：`/api/v1/catalog/buildings` 端点；`building.build` 命令（`HandleBuildBuildingCommand`）：目录解析、境界解锁校验、地点限定校验、同地重复校验；快照映射输出本节点玩家建筑。
- **前端**：`BuildingDefinition` 类型 + catalog 拉取 + `world.playerBuildings` 解码 + `sendBuildingBuild`；建筑 Tab 渲染系统建筑（原边框）与玩家建筑（异色边框），末尾加号卡 → Modal 候选列表 → 点击发送命令，快照回推自动刷新列表。
- **DataTool**：buildings 进全局 ID 收集与 `availableNodeIds` 节点引用校验。
- 效果接线（采集速度等）暂不实施，待用户讨论后再接入 `PlayerAttributeResolver`。
