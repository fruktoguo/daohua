## 2. 需求背景与核心目标

### 2.1 需求背景
1. **历史单一扁平 `DamageType` 枚举局限**：
   原有代码中 `DamageType`（Physical, Water, Nature, Fire）将伤害的大类形态（物理/法术）与五行元素混为一谈，导致无法表达“火系物理伤害（如烈火刀法）”或“纯物理术法（如飞剑符法）”，也导致护甲（Armor）与法抗（MagicResistance）的防御结算逻辑与五行抗性混淆。
2. **普通攻击与技能伤害规则正本清源**：
   - **普通攻击**：默认固定造成纯物理伤害（无属性 `DamageCategory.Physical, Element.None`），只吃目标的护甲减免，除非拥有特殊附魔或特殊状态；
   - **技能伤害**：完全由技能自身配置决定；
   - **双正交维度结算**：
     - **伤害大类 (`DamageCategory`)**：`Physical`（物理） / `Spell`（术法） -> 决定基础攻击力加成底座（物攻/法攻），并对抗目标对应的【护甲 Armor】或【法抗 MagicResistance】；
     - **五行属性 (`Element`)**：`None` / `Metal` / `Wood` / `Water` / `Fire` / `Earth` -> 决定是否享受攻方对应五行增伤加成，并对抗守方对应的五行抗性/减免。

### 2.2 核心目标
1. **领域枚举重构**：
   - 新增 `DamageCategory`（`Physical = 0`, `Spell = 1`）；
   - 新增 `Element`（`None = 0`, `Metal = 1`, `Wood = 2`, `Water = 3`, `Fire = 4`, `Earth = 5`）；
   - 彻底废弃单一扁平的 `DamageType` 枚举。
2. **技能、怪物与装备配置契约升级**：
   - `abilities.json`、`monsters.json`、`equipment.json` 中统一声明 `category` 与 `element`；
   - 技能与原型定义中更新为 `DamageCategory Category` 与 `Element Element`。
3. **战斗伤害推演流水线重构 (`CombatSimulator.cs`)**：
   - 第一层：大类基础数值计算（物理受力道/物攻加成，法术受神识/法攻加成）；
   - 第二层：大类防御减免（物理穿透 vs 护甲 Armor，法术穿透 vs 法抗 MagicResistance）；
   - 第三层：五行属性结算（攻方五行增伤 × 守方五行减伤/抗性）；
   - 第四层：暴击、免爆、易伤、伤害吸收。
4. **协议传输、前端展示与全量测试门禁同步更新**。
