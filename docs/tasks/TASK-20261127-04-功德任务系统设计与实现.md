## 1. 需求摘要

参考《银河奶牛放置》任务板的「贴合进度抽取 + 刷新博弈」框架，结合《道化太初》长线挂机定位设计**功德任务系统**：
- **核心结构**：任务列表（候选槽）+ 接取任务（单槽激活）+ 无限循环结算（每完成一轮发放奖励，任务不消失）；
- **三大任务类型**：采集（采摘/伐木/采矿）、制造（炼丹/提纯/锻造/制符/阵盘）、击杀（讨伐妖兽），仅统计接取后亲自行为产出/击杀数量；
- **进度上下浮动与刷新**：围绕玩家当前境界/技艺进度上下浮动抽取（不保证每次顺手可做），支持冷却免费刷新与灵石阶梯重随；
- **简易功德无限养成体系**：主奖励为 **20% 流通功德（`item.gongde`）+ 80% 绑定功德（`item.gongde-bound`）**；通过任务获取的功德直接驱动**功德等级（`MeritLevel`）**无限升级，等级越高每周可获取功德上限越高；触及周上限后显示**「功德圆满」**，圆满后继续循环不再给功德与功德经验，改为发放少量基础灵石与修为；
- **概称剧情委托描述**：每条任务附带简短世俗/修行委托剧情介绍，**严禁出现具体地名或具名 NPC**，统一采用「邻近城镇」「周边村落」「往来商队」「城中医馆」等通用概称。

## 2. 已锁定的核心设计决议

1. **命名与架构边界**：
   - 规避已废弃前缀 `Task*`，代码与协议统一使用 `Quest` / `Merit`（`PlayerQuestState`、`QuestCandidate`、`ActiveQuest`、`QuestKind`、`MeritLevel`）；
   - 状态随 `progression` 分段持久化并接入 `ActionExecutionRules` 与 `CombatActionRules`，确保在线实时、重连快进与 `ComputeNode` 48h 离线冷算结果逐位一致；
   - 遵循两层持久化规范：单轮任务收益走内存钱包与检查点/边界落盘（`PersistLedger = false`）；市场机器人（`is_bot = true`）隔离屏蔽。
2. **候选池、浮动区间与双轨刷新**：
   - 固定 `4` 个候选槽 + `1` 个激活执行槽；接取候选槽后原槽标记已接取，须待下次刷新统一补满（防零成本接取洗槽）；
   - 锚定当前进度在 `[-6, +4]` 级窗口浮动抽取，越级委托享每级 `+5%`（封顶 `+20%`）单轮功德加成；单轮目标数量按 `600s`（10 分钟）无加速基础时长 × `{0.85, 1.0, 1.15}` 浮动系数折算；
   - 免费刷新上限 `3` 次、每 `4 小时`（`14,400s`）整点守恒恢复 `1` 次；免费次数耗尽后可按 UTC+8 自然日阶梯消耗灵石刷新（`500 × 2^c`，封顶 `16,000` 灵石）。
3. **功德无限养成与「功德圆满」模型**：
   - 唯一养成真源 `LifetimeQuestMerit`：每通过任务实际获得 `1` 点功德同步 `+1`；
   - 升级需求曲线：`MeritToNext(L) = 300 + 100(L - 1) + 15(L - 1)^2`（`Lv.1 → ∞` 无封顶）；
   - 每周功德上限（UTC+8 周一 `00:00` 重置，升级实时扩容）：`WeeklyMeritCap(L) = 500 + 100(L - 1)`；
   - 单轮基础功德：`M_raw(L) = round((15 + 2(L - 1)) × k_diff)`（满额所需轮数随等级向 `50 轮/周` 渐近收敛，锁定周常约 6~8 小时舒适挂机时长）；
   - 功德拆分：`bound = round(0.8 × M)`，`tradable = M - bound`；触达周上限显示**「功德圆满」**，后续循环轮次仅发微量基础修为与灵石。
4. **全概称剧情模板与主导航页签**：
   - 按 8 个任务细分子类配置通用概称剧情模板池（城镇/村落/聚落/商队/驿站/医馆/丹坊/铁铺），零具体地名绑定；
   - 前端入口设为桌面左侧主导航独立**「任务」**（`quest`）页签，竖屏底部并入「历练」分组子行（`历练 / 任务 / 地图`）。
