# TASK-20261109-01 秘法技艺与物品转化系统

* **业务目标**：将现有强化技艺入口调整为「秘法」，在其下提供装备强化、物品化灵、装备分解、功法残卷转化四类操作。
* **已确认规则**：
  1. 「点金」改名为「化灵」；说明为「炼化物品，换取灵石」。
  2. 物品化灵将有回收价的普通物品或装备变为灵石，数量为当前系统商店回收单价的 3 倍；强化装备按对应变体回收价计算。
  3. 装备分解返还锻造配方递归展开后的基础原材料；每种材料单独按 `floor(数量 × 0.70)` 计算，强化等级不增加返料。
  4. 功法残卷每次消耗一张并独立判定：5% 产出对应整本秘籍，95% 固定产出 100 灵石，不再按功法等级或品阶计算。

## 1. 现状调研

- `docs/design/总纲/20-技艺体系与符箓阵法强化规约.md` 将强化作为七项独立生活技艺之一；技艺等级每级为对应行动提供 5% 速度加成。装备强化还使用该等级结算成功率，并发放技艺经验。
- 前端 `EnhancementPage` 已有未穿戴装备选择、目标强化等级、保护材料、重复次数、费用/成功率/结果预览、行动队列和强化记录。入口位于桌面侧边栏与移动端「技艺」子栏。
- 现有 `item.sell` 由服务端按库存扣除物品并在同一经济事务中发放灵石。普通物品使用配表 `sellPrice`；装备回收价由锻造材料成本推导，并包含强化等级折价。它与拟新增的 3 倍化灵应保持结算语义清晰。
- 装备锻造行动配有 `inputs` 与 `yields`；装备材料成本解析会递归展开前置装备配方，可作为分解材料来源。70% 后的材料数量及取整方式尚未定义。
- 功法有对应的 `item.fragment.<id>` 和 `item.tome.<id>`；物品配表有品阶 `tier`。玩家功法等级由个人累计经验推导，未习得功法没有个人参悟等级，因此公式中的「功法等级」需明确未习得时的处理。

## 2. 命名建议

建议将「点金」改为 **「化灵」**，用「炼化物品，换取灵石」作为简短说明。它比「点金」更贴近灵石语境；「灵石回收」虽直白，但容易与现有系统回收操作混淆。

## 3. 已确定的边界

1. 装备强化保留为秘法页内的原有操作；只调整门类显示名，`enhancement` 技艺标识与既有经验键不变。
2. 三个新操作即时结算，不进入行动队列、不授予技艺经验；只有装备强化继续使用原技艺速度、经验和成功率结算。
3. 化灵不处理货币或已穿戴装备；分解仅处理有锻造配方的装备，已穿戴装备不可处理。
4. 分解强化装备时只按白板锻造配方返料；当前按每次一件分解。
5. 转化仅支持功法残卷，每次一张；不提供批量转化。
