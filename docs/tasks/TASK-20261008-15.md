# TASK-20261008-15 自动消耗品物品栏域模型收拢（栏域标识取代行动大类）

- 提出时间：2026-10-08 22:51:00
- 发起方式：用户口述需求（历练页出现修炼+历练两组物品栏引发的模型澄清）
- 状态：✅ 已完成（2026-10-08，verify.sh 全绿）

## 1. 需求原文要点

- 物品层级：可使用物品 → 消耗品 → 自动使用消耗品（入栏）/ 手动使用消耗品（不入栏）。
- 自动使用消耗品按「物品栏类型」分支：
  - **历练栏**：修炼、采集、挖掘、探索等非制造技艺行动共栏，引气丹/通脉丹等原「修炼物品」并入，槽位 6 个；
  - **制造技艺栏**：炼丹/炼器/符箓/阵法/强化各自独立一栏，每栏 3 槽；
  - **战斗栏**：药品栏 3 槽 + 通用栏 3 槽（现状不变）。
- 某个物品栏支持什么物品由栏位类型决定；物品自身声明可进入的栏位类型集合。

## 2. 现状模型（改造前）

- 槽位按行动大类（`ActionKind`）分键：`cultivation`/`exploration`/`alchemy`/`combat`/`enhancement`（每组 3 槽，战斗 potion+general 各 3）。
- 炼丹/炼器/符箓/阵法全部共用 `alchemy` 栏；`usableInActionTypes` 取值 = 行动大类名。
- 历练页渲染 `cultivation` + `exploration` 两个无标签托盘，用户无法区分。

## 3. 目标模型（栏域标识 `AutoUseBar`）

引入「栏域标识」词汇（槽位 `actionType` 字段、配表 `usableInActionTypes` 值、命令 `queue.auto_use.configure.actionType` 统一承载）：

| 栏域标识 | 覆盖行动 | 槽数 |
| :--- | :--- | :--- |
| `exploration` | `ActionKind.Cultivation` + `ActionKind.Exploration`（采集/挖掘/探索类全量） | 6 |
| `alchemy` / `forging` / `talisman` / `formation` / `enhancement` | `ActionKind.Alchemy` 按行动 `technique` 归属对应栏；强化行动归 `enhancement` | 各 3 |
| `combat` | `ActionKind.Combat` | 药品栏 3 + 通用栏 3 |

- 行动 → 栏域映射：修炼/历练→`exploration`；炼丹大类行动→`technique` 同名栏域（配表校验要求 alchemy 类行动必配制造技艺）；强化→`enhancement`；战斗→`combat`；赶路→无栏。
- `usableInActionTypes` 值域改为栏域标识集合：引气丹/通脉丹 `cultivation`→`exploration`；其余物品值不变（`exploration`/`alchemy`/`combat` 本来就是合法栏域）。
- 持续消耗品生效守卫：物品对运行中行动大类 `GetMultiplier(kind) <= 1` 时不充能、不扣剩余时长——引气丹挂历练栏跑采集不白烧，行为与合并前一致。
- 槽位协议字段名（`actionType`/`group`/`slotIndex`）不变，存档结构不变、不 bump schema 版本；旧档 `cultivation` 键槽位在聚合恢复边界按非法栏域过滤丢弃（非法枚举值边界校验，非兼容层）。
- `queue.auto_use.configure`：actionType 校验改为合法栏域；`slotIndex` 上限按栏域（exploration 6、其余每组 3）；potion 组仍仅 combat+药品即时消耗品。
