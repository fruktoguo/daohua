# TASK-20260924-05 战斗消耗品分组与使用条件模型

## 需求

1. 非战斗行动可用消耗品一律为持续消耗品（按动作耗时扣减，不变）。
2. 战斗域消耗品分两组栏位：药品栏 ×3（仅药品类即时消耗品）+ 通用栏 ×3（任意战斗消耗品，符咒/阵法/特殊道具/药品）。
3. 通用栏物品支持直接消耗与持续消耗两种模式；持续消耗按战斗存活时钟扣减——战斗进行中与玩家死亡等待期间扣，寻敌/波间搜寻/退出战斗不扣。
4. 技能与消耗品共用「对象-类型-比对」三元组触发条件模型；对象=自身/目标/友方/敌方，类型按对象过滤（集合对象有群体聚合类型），比对=数值大小等于 / Boolean 是否。
5. 所有行动出手前先威胁判定锁定本次「目标」，触发条件的 target 对象即该锁定单位。

## 实现

### 领域
- `AutoUseSlotState` + `Group`（`potion`/`general`，每组 `MaxSlotIndex=2`，战斗域共 6 槽）；`ConfigureAutoUse` 按 `(ActionType, Group, SlotIndex)` 键控并拒绝非战斗域 potion 组。
- `ItemDefinition` + `Category`（装载 `category`）；`ConsumableDefinition` + `Triggers`（装载 `triggers`，`GameDataCatalog` 归一化时逐条 `ValidateTrigger`）。
- `SkillTriggerEvaluator`：依赖词表加集合对象 `ally`/`enemy`；条件加 `alive-count`/`dead-count`（仅集合对象）；比对加 `equal`；校验期按 对象-类型-比对 矩阵拒绝越界组合（Boolean 条件仅 is-active/is-inactive）。
- `SimulationEngine`：
  - 即时消耗品激活加共享触发求值（惰性装配玩家快照 + 当前波敌方快照；「目标」= 存活敌方有效威胁最高者，不消耗随机流）；
  - `RechargeCombatSustainedSlots` 遭遇入场补能（空槽扣 1 件充入时长，触发条件不满足则本场不启用）；
  - `InjectSustainedCombatBuffs` 生效 Buff 注入战斗单位（时长 = 槽位剩余时长，耗尽自然过期）；
  - `DrainCombatSustainedSlots` 按战斗实际推进秒数扣减（含躺尸等待；寻敌/复活读条/脱战不经过此路径）。

### 服务端/协议
- `queue.auto_use.configure` + `group` 参数；potion 组校验 `category=pill` 且非持续消耗品。
- `ProtocolSnapshotMapper` 消耗品冷却数组扩为 6（前 3 药品栏、后 3 通用栏）。

### 前端
- `AutoUseSlot` + `group`；快照映射战斗域 6 槽（potion 0-2 / general 3-5）；战斗面板渲染两组栏位；药品栏拾取过滤 `category=pill && !isContinuous`。
- 配置编辑器：`CombatTriggerEditor` 接入物品消耗品 `triggers`，依赖/条件/比对按矩阵联动过滤；词表补 ally/enemy、alive-count/dead-count、equal/is-active/is-inactive、状态条件。

### 配表
- `item.zhixue-powder`：`triggers=[self current-hp-percentage <= 60]`；`item.shunqi-pill`：`triggers=[self current-mana-percentage <= 50]`。
