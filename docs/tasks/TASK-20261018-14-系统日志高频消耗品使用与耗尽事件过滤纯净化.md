## 需求背景与核心痛点
玩家在挂机修炼、采集、炼丹或战斗时，系统日志中充斥着大量的机械化、高频重复事件：
- `auto-use.depleted`（“xxx 的持续时间已耗尽。”）
- `auto-use.activated`（“自动使用 xxx，可生效 xxx 秒。” / “自动使用 xxx，造成 xx 点伤害。”）
每隔数秒或数分钟即刷屏一条，在挂机一段较长时间后，系统日志（`system` 频道）与综合日志（`all` 分组）中 80%~90% 的历史记录被此类消耗品自动化杂音淹没，导致关键、低频且具备实际价值的系统通知（如行动完成与产出、装备强化、地点抵达、斗法推演、新手引导赠礼、坊市成交等）被严重冲顶丢弃。
丹药的生效状态与剩余时长已经在顶部/侧边栏 Buff 悬浮窗中提供高可见度的实时读秒，无需在系统日志中高频刷屏。

---

## 解决方案与技术方案
1. **协议层与映射层日志频道分流拦截**：
   - 在 `Protocol.LogChannels.FromEventCode` 中，将 `auto-use.*` 前缀事件（自动消耗品生效、持续时间耗尽、托管清单等高频推进事件）明确解析为 `null`（不归属于任何公开日志频道）；
   - 在服务端 `SimulationLogMapper.ToLogEvents` 中，当 `channel is null` 时直接跳过，不再构造 `LogEventDto`，不再写入玩家 `PlayerLogBuffer`，亦不再通过 WebSocket 向客户端下发，从源头彻底杜绝网络流量与日志污染。
2. **设计真源对齐**：
   - 同步修订 `docs/design/总纲/14-传音频道与日志分组.md`，在 §14.2 中明确 `auto-use.*` 作为高频内部状态推进事件，不输出至战报系统日志，保持系统日志纯净聚焦于低频关键事件。
3. **前端防守与过滤**：
   - 前端 `gameLogService` 保持与协议同步，确保即便收到包含 `auto-use.` 模板的旧消息亦不展示于系统或综合列表。
4. **门禁与测试保护**：
   - 更新 `Server.Tests/ChatAndSocialTests.cs`，断言 `LogChannels.FromEventCode("auto-use.*")` 返回 `null`；
   - 在 `Server.Tests/SimulationLogMapperTests.cs` 中增加测试用例，断言 `auto-use.activated` 与 `auto-use.depleted` 事件不会物化为日志 DTO，亦不进入缓冲区。
