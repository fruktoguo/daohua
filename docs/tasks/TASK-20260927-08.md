# TASK-20260927-08 优化版 ECS 内核框架级正确性深度验证

## 背景与目标

性能目标（OOP 三倍内）达成后，用户要求对优化版 YuoCore ECS 做实现级正确性验证：组件增删/替换、系统成员引用更新、稠密索引错位、生命周期派发等框架级 bug 必须清零。用户明确**基线不是绝对 oracle**——差分差异双向存疑，逐条判定归属；**优化版修复所有已确认缺陷（含共有缺陷），`vendor/YuoCore`(main) 基线代码不动**。

## 已确认并修复的缺陷

### 优化版独有

| 缺陷 | 证据 | 修复 |
| --- | --- | --- |
| `_activeEntities` 快照不感知销毁，索引复用后按索引命中新实体组件 | 审计 + 2 单测复现 | `SetActiveEntities` 校验成员槽位 `ReferenceEquals`；迭代/`m_Run` 跳过 `IsDisposed` |
| `EntityIndex` 在 Dispose 中段释放，回调内新建实体复用导致槽位互踩 | 审计 | 索引延后到 Dispose 完毕回收；`AllocateEntityIndex` 复用前 `SweepEntityStores` 兜底 |
| `RunEntity` 无身份校验（只查 `IsUsable`） | 审计 + 差分 3918 幽灵回调 | `CanRunComponent`：`ReferenceEquals(comp.Entity, entity)` 归属校验 |
| 成员集残留 `EntityIndex=-1` 死实体，压实越界 `IndexOutOfRangeException` | 差分实测 | 压实/重建清死成员（同步 `Entities.Remove`）；`AddEntity`/`CheckValidEntity` 拒收 |

### 与基线共有（仅优化版修复）

| 缺陷 | 修复 |
| --- | --- |
| `DestroyComponent()` 缓冲回放 `IDestroy` 被 `IsUsable` 吞掉 | `CanRunComponent`：`RunType==IDestroy && !IsDisposed` 放行 |
| `[SingleComponent]` 二次 `SetComponent` 分裂视图 | 同键不同实例按完整替换语义先销毁旧实例再指向新实例 |
| `systemsOfBaseComponent` 在 `Refresh`/`SystemSort` 不清理 → 基类派发成倍重复 | `SystemSort` 三表三索引同步清空重建 |
| `Parent?.ChildComponents` 对已释放父实体 NRE | `?.` 空安全（与 `AddChildComponent` 口径一致） |
| `YuoComponent.Dispose`/`entity.Dispose` 重入：组件 IDestroy 回调内再 Dispose → 内层置空 `EntityData` → 外层 `UnRegisterEntity` NRE | `_isDisposing` 守卫：处置不可重入，外层统一完成 |
| `ComponentStore.Set` 缺负索引保护 | `entityIndex<0 → return`（与 `Remove`/`Get` 一致） |
| `world.OnDestroy` 退出 `RemoveChildComponent` NRE（stderr `Game Exit NullReferenceException`） | `RemoveChildComponent` 空安全 |

## 遗留已知共享语义（未修，上游 quirk，两版一致）

- 孤儿组件（`Entity=null`）在系统成员集中瞬态滞留至压实清理，期间按成员集收到 IUpdate（两版台账各数百条，优化版更少）；框架语义上属"销毁→成员清理存在窗口期"的固有行为
- 对已释放实体直接调用 `SetComponent`/`AddComponent` 字典侧仍会写入（僵尸条目），与基线一致——稀疏存储已防护不越界、不串读
- 迭代顺序为加入序（优化版）vs HashSet 序（基线）：无契约承诺，属实现差异
