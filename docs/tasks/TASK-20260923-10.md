# TASK-20260923-10 · 设计理念总集沉淀（docs/DESIGN.md）

## 需求分析

用户希望项目有一份"设计理念总集"：不是数值规约与实现细则的堆积，而是把每个子系统**为什么这样设计**（意图、哲学、红线）集中成一份可快速通读的文档，并放在 `docs/` 文档文件夹根目录便于查阅。

现状盘点：

- 理念层内容已存在但分散：`总纲.md` 第一篇（五条铁律）、`角色核心设计.md` 全篇（统一常驻实体哲学 + 设计红线）、`战斗设计.md` §3.1/§9（怪我同构、世界常驻）、`通用地图与遇怪系统.md` §1（通用世界地点）、`持续消耗品系统.md` §1（动作耗时分摊动机）、`节点公共建筑系统.md` §1（公共设施定位）、`world/README.md`（碎片化叙事红线）、`backend/`（聚合单写者与持久化架构决策）。
- 缺口：没有单一入口按系统串起"设计意图"；功法系统等处理念浓度偏低。

## 方案

1. `docs/` 根目录新建 `DESIGN.md`：按系统分篇，每节固定结构为「一句话理念 → 核心设计意图 → 红线/不变量 → 真源文档链接」。
2. 总集只做意图层索引，不复制数值表与规则细节；与专题文档冲突时以专题文档为准（在文首声明）。
3. `docs/README.md` 索引补一行指向总集，保持文档导航完整。
