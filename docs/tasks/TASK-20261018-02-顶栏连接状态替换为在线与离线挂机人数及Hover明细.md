# TASK-20261018-02 顶栏连接状态替换为在线与离线挂机人数及Hover明细

## 1. 任务背景与核心目标

根据用户指示与修仙世界观生命周期规则：
- 游戏总共分为三个状态：
  1. **在线挂机**（Online Idle）：当前连接在主服的活跃在线修士；
  2. **离线挂机**（Offline Idle）：断线未超过 48 小时离线收益上限（`offline_since + 48h > now`）的挂机修士；
  3. **彻底离线**（Completely Offline）：断线超过 48 小时收益封顶边界的修士，不计入统计。
- 将左上角（顶栏道号与境界徽章旁）原有的单点绿色连接小圆点，替换为展示**在线人数**的胶囊徽章。
- **直接在外面显示的在线人数**：包含「在线挂机」与「离线挂机」的总人数（即总挂机/活跃修士数）。
- **Hover 浮层**：展示延迟、在线人数（在线挂机）与挂机人数（离线挂机），同时保留连接状态感知。

## 2. 需求拆解与技术方案

### 2.1 统计口径与性能设计
1. **在线挂机人数 (`onlineCount`)**：
   - 权威真源：`OnlinePresenceRegistry`（服务端常驻单例）；
   - 直接读取其并发注册表计数，0 数据库开销。
2. **离线挂机人数 (`offlineIdleCount`)**：
   - 权威真源：PostgreSQL 读模型 `game.player_projection`；
   - 判定条件：`presence = 'offline' AND offline_since IS NOT NULL AND offline_since + interval '48 hours' > now() AND presence <> 'suspended'`，并排除当前已在线的玩家 ID；
   - 性能保护：引入短时缓存（如 10 秒去抖刷新），避免高频 Ping 击穿数据库。
3. **彻底离线**：不满足上述条件的修士恒不计入统计。

### 2.2 协议与通信管道
1. **信标协议 (`src/Protocol/Contracts.cs`)**：
   - 在 `PongResponse` 结构中规范化定义 `serverTime`、`onlineCount`、`offlineIdleCount`；
   - 在握手 `HelloResponse` 中亦支持透传 `presenceStats`（`onlineCount`, `offlineIdleCount`），让客户端完成握手时即可瞬时展现；
2. **握手与心跳协同 (`frontend/src/network/gameClient.ts`)**：
   - 客户端在握手就绪后立即触发初次 `sendPing`，并在收到 `Pong` 时解析并写入 `useGameStore`；
   - 鼠标 hover 到人数徽章时触发 `pingNow()`，实现毫秒级即时测速与人数刷新。
