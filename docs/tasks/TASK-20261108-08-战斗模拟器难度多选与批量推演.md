## 1. 需求分析与目标

### 1.1 需求背景
目前战斗模拟器中，讨伐历练难度为单选按钮（单值 `difficulty: number`，默认档 0 或 T1~T5 单一选定）。当玩家想要横向对比同一地点（或多个地点）在不同难度下的收益、胜率与伤亡情况时，必须反复修改难度配置、重新推演并人工记忆对比，操作繁琐且无法直观横向比对收益曲线。

### 1.2 核心业务逻辑预期
1. **难度配置面板支持复选框多选**：
   - 难度选择由单选改为复选框（Checkbox）模式，支持同时勾选任意多个难度档位（默认、T1、T2、T3、T4、T5）。
   - 提供「全选难度」与「仅默认」等便捷快捷操作，默认勾选默认难度档（`[0]`）。
   - 保障至少选择 1 个有效难度，避免空选导致推演空白。
   - 标题栏清晰展示已选难度数量徽章，下方动态提示选中的难度加成概览。
2. **多节点 × 多难度组合推演**：
   - 在用户点击「开始挂机推演」时，推演引擎将选中的地点节点集合与选中的难度档位进行交叉遍历，批量生成所有组合的挂机战斗报表。
3. **对比总览与明细结果同构展示**：
   - 数据模型引入全局唯一结果标识 `itemKey`（如 `${nodeId}#${difficulty}`），杜绝同节点多难度的 key 冲突。
   - 横向对比大表格完整展示所有地点在各个难度下的胜率、每日灵石收益、经验产出与击杀速率，直观呈现难度梯度效益。
   - 节点详细剖析支持通过地点与难度复合胶囊进行毫秒级精准切换。
4. **门禁与单测闭环**：
   - 补充前端单测与契约验证，确保全量门禁（`scripts/verify.sh`）绿灯通过。

## 2. 详细设计与实现方案

### 2.1 数据与类型契约（simulatorTypes.ts）
- `SimulatorNodeComparisonItem` 增加唯一标识 `itemKey?: string`（格式 `${nodeId}#${difficulty}`）。
- `MultiNodeSimulatorReport` 增加 `selectedItemKey?: string`，`reports: Record<string, SimulatorReport>` 支持以 `itemKey` 为键存放。

### 2.2 前端配置面板（SimulatorConfigPanel.tsx）
- `SimulatorConfigPanelProps` 属性改造：
  - `difficulty: number` -> `difficulties: number[]`
  - `onChangeDifficulty: (difficulty: number) => void` -> `onToggleDifficulty: (tier: number) => void`、`onSelectAllDifficulties: () => void`、`onResetDifficulties: () => void`。
- 渲染层：难度项采用带 Checkbox 的卡片式/标签式交互，勾选状态清晰醒目。

### 2.3 模拟器主弹窗调度（CombatSimulatorModal.tsx）
- 维护 `difficulties` 状态数组（默认 `[0]`）。
- 推演遍历 `selectedNodeIds` × `difficulties`，并生成带 `itemKey` 的对比项与详情字典。

### 2.4 结果展示页（SimulatorResultsView.tsx）
- 基于 `itemKey` 进行选区高亮与报告精准索引。
- 横向对比总览表与详情切换胶囊无缝兼容单节点多难度条目。
