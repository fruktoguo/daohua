## 需求分析

用户提出组队表单体验优化：当前队伍目标「地点」为单一下拉框，选项是全部地图节点平铺（标签「区域 · 地点」），节点多时查找困难。要求拆为「区域」「地点」两个级联下拉框；同时**保留创建/匹配表单未手选时默认跟随玩家当前地点**的既有设定（`useCurrentNodeField` 脏标记机制）。

## 设计边界

1. 协议约束：`nodeId` 为空串 = 不限，否则必须是已知节点 ID——**不存在区域级「不限」语义**（§21 目标节点行）。因此级联口径定为：
   - 区域下拉：「不限」+ 全部地图区域；
   - 区域 = 不限 → 地点固定「不限」（提交 `nodeId=''`）；
   - 区域 = 某图 → 地点列出该区域全部节点，切换区域时自动落到首节点（避免「区域已选但地点不限」的虚假语义——协议表达不了「该区域任意地点」）；
   - 区域为派生态：由 `value.nodeId` 反查所属 map，不新增表单字段，`nodeId` 仍是唯一提交值。
2. 复用范围：`PartyProfileFields` 为无队伍三表单（匹配/大厅/创建）与队长「修改队伍」弹窗共用控件，级联改造一次生效四处；`LeaderProfileModal` 从队伍快照初始化、`LobbySection` 默认「不限」均为既有刻意设计，不动。
3. 跟随逻辑不变：`useCurrentNodeField`/`useDefaultNodeId` 继续按 `world.nodeId` 工作，玩家移动时区域下拉随行派生，无需改动。
4. 展示侧不动：列表/档案摘要的「区域 · 地点」合成标签（`nodeNames` + `nodeLabel`）保持原样；`PartyProfileFields` 不再使用 `nodeNames`，移除该入参。
