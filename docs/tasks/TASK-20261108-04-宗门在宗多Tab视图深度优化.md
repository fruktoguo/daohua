## 1. 需求背景与核心理解

用户要求继续深度优化宗门界面，当玩家**已经拥有宗门**时，将原本上下堆叠平铺的在宗面板拆分为顶部的 3～4 个独立二级选项卡（Tab）：
1. **概览（Overview）**：查看宗门全局信息，包括宗门字号前缀、全名、驻地地点、大殿等级、成员规模与修仙门规介绍，以及进入驻地/传音/迁址/解散/退宗等核心宗务操作；
2. **同门（Members）**：同门弟子花名册，展示成员在线状态、道号与职位，有权限管理者可调整职位、移交宗主或逐出宗门；
3. **拜帖（Applications，权限条件展示）**：**仅当角色拥有同意入宗审批权限（`myRole <= 3` 即长老及以上）时展示**。普通弟子界面仅显示 3 个 Tab（概览、同门、建筑）；管理者在该 Tab 进行招募道友邀请与待审批拜帖处理；
4. **建筑（Buildings）**：宗门驻地与大殿设施，展示大殿等级、容量扩充加成规则、升级材料需求（百炼铁、赤铜精）与驻地营造说明。

## 2. 方案设计与实现边界

1. **子 Tab 状态与权限拦截**：
   - 定义 `ZongmenSubTab = 'overview' | 'members' | 'applications' | 'buildings'`；
   - 根据 `own.myRole <= 3` 动态计算可见 Tab 集合；
   - 权限收回时自动回退至默认 `overview`，防止越权展示。
2. **子面板组件拆分**：
   - `ZongmenOverviewSection`：宗门介绍卡片、四格信息指标（字号/地点/等级/规模）、快捷行动（进入驻地/传音）与宗务管理；
   - `ZongmenMembersSection`：同门列表、在线高亮、职位管理与移交/逐出；
   - `ZongmenApplicationsSection`：招贤邀请输入框、待批拜帖列表（同意/拒绝）、空列表兜底；
   - `ZongmenBuildingsSection`：宗门大殿图元卡片、等级效果公式、升级所需材料、驻地专属设施指引与前往驻地。
3. **视觉与公共规范**：
   - 顶部 Tab 采用与组队页一致的 `.market-tabs.zongmen-sub-tabs`；
   - 词条收拢进 `social.zh.ts` 与 `template.csv`。
