## 1. 核心需求与对齐结论

1. **会话级内存缓存**：页面未刷新前，保留模拟器的全部配置、环境快照、目标地图/节点/难度/时长/随机种子、页签状态（含一级页签与配置子页签）及已完成的推演结果；关闭弹窗仅取消进行中批次回合（`cancelRun()`），不清空已有配置与结果，页面刷新后恢复默认。
2. **顶层页签拆分与独立「详细属性」子页签**：
   - 顶层保留「配置」与「结果」两页签。
   - 「配置」内拆分为 5 个子页签：`基础与特质`、`详细属性`、`装备`、`功法`、`消耗品`。
   - `基础与特质`展示境界（`realmLevel`）与战斗经验（`combatExperience`）、核心六维、灵根、复活冷却与特质；`详细属性`单独复用 `CombatAttributePanel` 展示当前选中成员在目标节点预览环境下的完整属性明细与增益。
3. **复用游戏原生布局（无数量/获取限制）**：
   - **装备**：复用右侧 `EquipmentPanel` 的三栏 `.equipment-stage`（左：武器/头冠/下装；中：`CharacterAvatar` + `RealmBadge`；右：法器/甲胄/饰品；不放无关战斗的生活工具槽位），点击开 `ItemGridPicker` 可选配表全部装备（无背包数量、境界门槛限制），支持自定义强化等级（`+0~+20`）与一键卸下。
   - **技能/功法**：复用战斗详情 `CombatLoadoutPanel` 的 `.combat-slot-grid--abilities`（0 号内功槽 + 1~4 号招式/术法槽）+ `ConditionedTile` + `AbilityGridPicker` + `CombatTriggerEditor`，可选配表全部功法（保持内功/外功互斥规则），支持自定义功法等级（`1~127`）并正确同步写入 `abilityExperiences`（解决从高等级往回调低无效的问题）。
   - **消耗品**：复用战斗详情 `AutoUseSlotGroup` 的双组 6 槽位（药品栏 0~2 + 通用栏 3~5）与 `ItemUseSlot` + `ItemGridPicker` + `CombatTriggerEditor`，完全无关背包数量（隐藏库存数字与不足置灰态，移除数量输入框），仅保留物品选择、条件触发编辑与槽位启停。
4. **结果与逻辑缺陷修复**：
   - **真实修为计算**：结果总览、排行冠军与成员详情中的修为数值统一使用纯净产出的真实修为（`lifetimeExperience` 增量），不计入居底蕴燃烧导致的 3 倍虚高，也不受当前境界修为上限截断。
   - **非战斗节点过滤**：结合 `simulatorRunner.resolveCombatAction` 的 `availableNodeIds` / `excludedNodeIds` 匹配规则，从可选地图/节点中剔除没有可用讨伐行动的节点（如 `node.tea-house` 望云茶肆），避免出现「目标节点没有可用讨伐行动。」报错。
