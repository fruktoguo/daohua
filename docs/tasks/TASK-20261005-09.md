# TASK-20261005-09 引导任务化增强：跳过确认/补发/重学

## 需求

- 跳过引导需二次确认，明示「剩余奖励直接发放」与「设置→引导可重学」。
- 跳过不是放弃奖励：剩余未领的阶段赠送与终奖应直接入账。
- 设置页提供「引导」分类，可重新学习引导；重学不重复发放已领奖励。

## 设计要点（总纲 §22）

- **奖励游标** `TutorialRewardsStep`（settings 分段持久化）：推进仅当 `nextStep > 游标` 才入账；skip 把它一并推到 Done；restart 只重置 `TutorialStep`。
- **`tutorial.skip`**：`PendingSkipGrants` 合并游标+1..Done 未领赠送/终奖 → 命令内经济事务发放 + 结构化 `tutorial.grant` 类入账日志同帧推送；事务拒绝时 `RestoreUncommittedPlayer` 回滚 ECS settings。
- **`tutorial.restart`**：重置步骤为起点，游标不动；入 `ShouldPersistReceipt`。
- **前端**：跳过改为引导层内确认卡（业务 Modal z70 够不到引导层）；Esc 开合确认；restart 复活靠「步骤递减检测」（正常只增不减，不能用 milestone 非空判断——确认跳过瞬间 patch 未回会误复活）。
- **持久化**：`SettingsDocument.TutorialRewardsStep` 缺省解码 0；v14 载荷按 `tutorialStep` 回填游标下限（防升级后重复领取）；schema v15 + `migrations/0015_v14_to_v15.sql`。
- **连带修复**：前端 `SNAPSHOT_SCHEMA_VERSION` 14→15（否则快照 head 校验抛错被静默吞、卡「正在同步」）；`check-frontend-contracts.mjs` 模拟帧同步。
