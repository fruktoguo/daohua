## 1. 需求复述与理解

用户针对战斗详情面板提出了两项明确的视觉与自适应交互优化需求：

1. **阵型缩放单行自适应（当一方是 3 人时，自适应按一行适配）**：
   - **现状痛点**：目前 `computeArenaFormationScale` 硬编码 `slotHeight = (height - 2 * gap) / 3`，强行假设九宫格 3 行全部被占满。但实际上己方与敌方排布顺序均为 `[1, 4, 7, 2, 5, 8, 3, 6, 9]`；当单位数 $\le 3$ 时，所有单位全部坐落在九宫格的正中间行（Row 2：前排中 1、中排中 4、后排中 7），上行 Row 1 和下行 Row 3 完全为空。旧逻辑将高度除以 3，导致 1~3 人的队伍被过度缩放到 50%~60%，非常局促且违背空间利用常理。
   - **预期目标**：重构阵型垂直缩放算法，支持根据该侧实际参战人数推导实际占用的行数（$\le 3$ 人占 1 行，4~6 人占 2 行，7~9 人占 3 行）。当一方为 3 人及以下时，垂直方向按 1 行的可用高度进行适配（`slotHeight = height - 2 * gap`），结合横向 3 列计算，缩放比例自然恢复为饱满舒展的 1.0~1.05。
   - **双侧解耦**：两侧阵容（盟友侧与敌怪侧）独立计算 scale 并各自应用到 `.arena-formation--allies` 与 `.arena-formation--enemies`，互不拉低。

2. **底部消耗品与技能托盘紧凑贴边（消除多余上下空白）**：
   - **现状痛点**：底部快捷配置栏包含「消耗药品」「通用物品」「功法」三个卡槽组。原实现为了给 Hover 浮现的框外条件调节按钮预留容纳空间，在 `.combat-slot-tray` 上增加了高达 `padding: 34px 0;`，加上 `.combat-loadout` 的 `padding: 5px 0;` 和各个子容器 padding，导致整体上下留白超过 80px，卡片容器上下空余出大片死黑区域，严重挤压上方战斗主舞台的视口高度。
   - **预期目标**：大幅压缩托盘的上下内边距至贴边级别（如 2px~4px），消除多余上下留白；优化桌面端 overflow 规则，使条件浮现按钮与悬浮卡在不依赖巨额 padding 的情况下依旧完整显示不被裁切，实现真正的「紧凑贴边」，同时将节省出的空间全额还给战斗主画面。

## 3. 二轮反馈优化：独立双侧分排与防裁切彻底治理

### 3.1 用户反馈与根因分析
1. **底部托盘被裁切**：首轮为实现贴边添加了 `.expedition-content--duel { margin-bottom: -12px }`，导致托盘底部被外层 `.panel.expedition-page { overflow: hidden }` 强行裁切掉 12px，卡片底边和数量字样被吞；同时 4px 内边距过窄缺乏呼吸感。
   - **处置**：彻底移除负下边距，`.combat-loadout` 与 `.combat-slot-tray` 调整为 `4px 0 6px` 与 `8px 0 12px`，底边保留 18px 舒适净空，DOMRect 与真实截图实测底边完整无裁切。
2. **第一排名字与第三排行动栏被遮挡/裁切**：
   - **几何根因**：旧缩放高度比例超出九宫格单槽高度，导致第 1 排卡片向上突入容器顶部被 `overflow: hidden` 裁切名字，第 3 排卡片向下突入底部被裁切行动条；
   - **遮挡根因**：浮动按钮 `.combat-arena-controls` 原先绝对定位在 `bottom: 12px; right: 12px`，恰好悬浮压在敌方第 3 排右侧槽位上，强行遮挡怪物的行动条。
   - **处置**：
     - `computeArenaFormationScale` 基准高度严格对齐 CSS 184px，卡片总高数学证明恒 $\le \text{slotHeight} - 4$，留出充裕上下安全边距；
     - `.combat-arena-shell` 采用 `grid-template-rows: auto minmax(0, 1fr)` 架构，顶部操作条 `.combat-arena-top-actions` 独立成行，将「终止当前行动」右对齐移入顶栏，彻底释放战场下层与九宫格内部空间，零遮挡零压盖。
3. **双侧完全解耦与真实 2 排布局**：
   - 移除 `Math.min(allyScale, enemyScale)` 对全局容器的强制统一下发，双方各自推导 `allyScale` / `enemyScale` 与 `allyRows` / `enemyRows`；
   - CSS 新增 `.arena-formation--rows-1`（单行 1fr 居中展开）、`.arena-formation--rows-2`（两行 50%/50% 垂直等分，隐藏无用第 3 排空槽，真正 2 排布局）、`.arena-formation--rows-3`（标准三排九宫格）；
   - 己方 1 人时保持 1.05 满额单行，敌方 2 排时自适应展开为 0.65 且等分两排，各按各的尺寸与排数舒展，互不干扰拉低。
