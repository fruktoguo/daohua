# TASK-20260920-02 地图目标地点怪物悬浮详情卡

## 需求

- 提出时间：2026-09-20 00:08:35
- 世界地图选中地点后，右侧「栖息生灵」区的怪物胶囊此前只有名称；需要 Hover 悬浮详情卡。
- 详情字段：怪物名称、境界等级、品阶、掉落物、击败获得经验、简要战斗属性（生命值、灵力值、双攻、双防）。

## 现状勘察结论

- 地图节点怪物列表来自 `/api/v1/catalog/maps`：`StaticGameCatalogMapper.ToNode` → `ResolveMonster`，产出的是 `CombatantDefinition` 形态（`enemyId` 键）。
- 前端 `WorldNodeDefinition.monsters` 却声明为 `NearbyMonsterDefinition[]`（`monsterId` 键）——**既有类型失配**，`key={monster.monsterId}` 实际恒为 undefined。
- `ResolveMonster` 存在口径缺陷：`maxManapoints`/`magicResistance`/五行抗性/`experience` 均从原始配表 JSON 顶层读取（配表并无这些字段），恒为 0 或回退到 `budgetCost`；真实值在 `catalog.CombatMonsters[id]` 的解算结果中。
- 附近面板 `NearbyPanel.MonsterCard` 已有 `FloatingPopover + FloatingInfoCard` 悬浮卡片先例，可复用模板。
- 双攻/双防口径复用 `resolveEnemyCombatAttributeModel`（术法系攻强记入术法攻击，否则记入物理攻击），与斗法属性面板完全一致。
- 境界名展示复用 `calculateRealmInfo(0, level)`（凡人段凡胎~叩仙门 / 修真段练气~渡劫）。

## 实现方案

1. `StaticGameCatalogMapper.ResolveMonster`：补充 `level`/`tier`/`budgetCost`/`drops`/`qiReward`/`rootExpReward`；`maxManapoints`/`magicResistance`/五行抗性/`experience` 改从 `CombatMonsterDefinition` 解算结果取值；`EmptyMonster` 同步补齐缺省字段。
2. `frontend/src/game/types.ts`：`CombatantDefinition` 增补 `level?/tier?/budgetCost?/drops?/qiReward?/rootExpReward?`；`WorldNodeDefinition` 三个怪物列表字段改类型为 `CombatantDefinition[]`。
3. `WorldMapPanel.tsx`：怪物胶囊包 `FloatingPopover`（hover）+ `FloatingInfoCard`：
   - 标题=名称 + 位阶徽记（妖兽/精英/妖王色调）
   - 副标=`{小境界名} Lv.{level} · 阶位 {tier}`
   - 属性网格：生命值/灵力值/物理攻击/术法攻击/护甲/法抗（复用 `insight.combat.*` 词条）
   - 掉落物行（`findItemInCatalog` 解析物品名）与击败收益行（修为/底蕴/六维）
4. `combat.zh.ts`：`combat.map` 域新增 `monsterSubtitle`/`monsterDrops`/`monsterReward`/`monsterNoDrops` 键。
5. 验证：`dotnet build` + `npm run build`（tsc）。
