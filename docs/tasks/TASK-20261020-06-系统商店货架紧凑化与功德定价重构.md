## 1. 需求背景与核心意图

用户明确提出三项优化：
1. **导航位置调整**：将主界面「商店」顶级页签从「坊市」之后移动至「图鉴」（万象图鉴）之后；移动端底部导航同步移至图鉴之后。
2. **定价与货币调整**：
   - 每日限购档觉醒石：由 1,000 灵石调整为 **100 功德**；
   - 不限购档觉醒石：由 2,000 灵石调整为 **1,000 功德**；
   - 货币由灵石（`currency.spirit-stone`）改为功德（同时支持绑定功德 `item.gongde-bound` 与流通功德 `item.gongde`，且严格优先扣除绑定功德）。
3. **视觉与交互重构**：
   - 解决目前货架条目（320px+ 大卡片）尺寸过于臃肿的问题；
   - 调整为紧凑的物品格子货架：只展示物品 Item 格子，格子底部展示价格；
   - 格子支持 Hover 弹出标准浮层详情（效果/机制）；
   - 点击物品格子后，弹出独立的二次确认购买模态弹窗（展示物品效果、单价、数量选择、功德余额与总价计算、确认购买与取消）。

## 2. 详细技术方案

### 2.1 导航与布局位置
- `frontend/src/App.tsx`：
  - PC 端左侧主导航：将商店 `<button>` 移至万象图鉴（`codex`）之后；
  - 移动端底部导航 `BOTTOM_TABS`：将 `shop` 移至 `codex` 之后；
  - 主内容区 `<Suspense>` 挂载顺序同步移至 `CodexPage` 之后。

### 2.2 配表与服务端结算
- `config/game-data/shop/offers.json`：
  - `shop.awakening-stone.daily`：`unitPrice: 100`；
  - `shop.awakening-stone.open`：`unitPrice: 1000`；
- `src/Server/EcsPlayerRuntimeAdapter.cs`：
  - `shop.buy` 货币结算：
    - 读取玩家钱包中 `item.gongde-bound` 与 `item.gongde` 余额；
    - 计算总功德 `totalMerit = boundBalance + normalBalance`；
    - 校验 `totalMerit >= totalPrice`，不足时返回 `INSUFFICIENT_RESOURCE`（"功德不足。"）；
    - 优先扣除绑定功德：`deductBound = Math.Min(boundBalance, totalPrice)`，`deductNormal = totalPrice - deductBound`；
    - 生成对应资产扣减 `AssetDelta` 并与物品增量同行提交 Serializable 经济事务；
- `docs/design/总纲/24-系统商店与每日限购.md`：
  - 同步定价为 100 功德 / 1000 功德与优先扣除绑定功德的结算规则；
- 测试同步：
  - 更新 `tests/Domain.Tests/ShopCatalogTests.cs` 对内置配表价格（100 / 1000）的断言；
  - 补充/验证功德扣减单测。

### 2.3 前端紧凑格子货架与二次确认购买弹窗
- `frontend/src/components/ShopPage.tsx`：
  - 页面顶部：展示当前可用功德（绑定功德 + 流通功德）；
  - 货架展示：紧凑网格（`.shop-shelf-grid`），每个条目为一个 `.shop-item-slot`：
    - 顶部/主体：`ItemTooltipTarget` + `ItemTile` 标准物品格子，含品质色边框与角标（若限购且已售罄显示售罄暗态与角标）；
    - 底部：`.shop-item-price` 价格标签（如 `100 功德` / `1,000 功德`）；
    - 交互：Hover 触发标准物品效果详情；点击条目弹出 `ShopBuyModal`；
  - 二次确认弹窗 `ShopBuyModal`：
    - 基于项目公共规范 `Modal`（`size="small"`）；
    - 标题为「购买物品」；
    - 居中展示物品瓦片、物品名称、品质徽记、当前储物袋持有数量；
    - 限购信息（如「今日限购 1 件 / 今日已购」）；
    - 单价（`100 功德` / `1,000 功德`）；
    - 数量选择器 `QuantitySelector`（不限购商品允许调整数量，上限按余额与 999 收敛；每日限购商品固定 1 件）；
    - 需支付功德与持有功德实时对比；
    - 确认购买按钮（二次确认）与取消按钮。
