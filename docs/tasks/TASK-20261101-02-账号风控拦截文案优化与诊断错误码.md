## 需求背景与目标

### 1. 痛点
- 当前注册/登录触发风控拦截时，返回提示为粗糙的「注册受限，请稍后重试。」或直接暴露「该设备已达到可注册账号上限。」等技术细节；
- 过度模糊导致正常受误伤玩家（如宿舍、同 WiFi 下拉新开黑）反复无效重试；而直白技术词又容易指导脚本刷子切 IP 或清缓存；
- 玩家截图到官方 QQ 群反馈时，管理员无法直接从截图判断具体拦截根因（是同 IP、同机型、设备硬上限还是脚本频控），必须手动登录生产数据库查询审计表。

### 2. 目标
- **统一文案**：面向玩家统一显示礼貌、清晰且提供解决出口的引导文案：
  `当前环境未能通过安全校验，如果是正常游玩，请在QQ群中联系管理解决（错误码：SEC-xxxx）`
- **非明文诊断码**：文案末尾携带非明文技术代号，管理员看到群截图即可秒级反查拦截原因：
  - `SEC-D01`：Device（设备硬限制，同一物理设备已注册过账号）
  - `SEC-P01`：Person（主体硬限制，同一人/主体账号已达上限）
  - `SEC-B01`：Bot（自动化脚本/无头浏览器沙盒）
  - `SEC-S01`：Signal（环境信号缺失）
  - `SEC-<分值>-<标签组合>`（软风险累计超标）：
    - `N`：Network（IP / 网段关联过多）
    - `C`：Config（机型硬件配置关联过多）
    - `F`：Fingerprint（浏览器指纹关联过多）
    - `V`：Velocity（频控超限）
    - 例如 `SEC-100-NC`：100分，IP+同机型所致；`SEC-80-N`：80分，纯同一IP所致。
