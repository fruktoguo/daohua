## 一、需求背景与核心理解

### 1.1 用户需求原文
“当前的apk,怎么没法长按显示hover信息啊?”

### 1.2 核心理解与影响范围
- **业务目标**：在 Android 安装包（APK）及所有移动端/触屏设备上，玩家长按任何带有 hover 提示属性的标的（包括物品、装备槽位、功法技能、怪物卡片、词条与状态标签），均可稳定、灵敏地呼出完整详尽的悬浮属性卡片与附属副卡（`FloatingPopover` 体系）；长按抬起手指后保持卡片舒展呈现，且**绝对不误触**底层挂载的业务按钮（如装备穿脱、技能升级、物品使用或交易购买）。
- **根因分析**：
  1. `FloatingPopover.tsx` 此前仅在 `onContextMenu` 事件上尝试识别长按，错误假设触屏端会原生派发该事件；
  2. Android 壳工程 `MainActivity.java` 为屏蔽浏览器原生划选菜单配置了 `setLongClickable(false)` 与 `setOnLongClickListener(v -> true)`，从 View 系统底层截断了长按手势；
  3. 全局 CSS 包含 `-webkit-touch-callout: none`，在移动 WebKit/Blink 内核中进一步抑制了长按上下文菜单与事件派发。
- **核心逻辑预期**：
  1. **Pointer/Touch 标准手势状态机**：由组件内部自主维护按压手势识别，按压 350ms 触发，手指大幅滑动（>10px）或页面滚动时平滑取消；
  2. **触感反馈**：长按触发瞬间调用轻量微振动（`navigator.vibrate(15)`）；
  3. **捕获阶段防误触物理隔离**：长按触发后，在捕获阶段（Capture Phase）彻底掐灭随后的模拟 `click` 事件，子组件的原生业务 `onClick` 绝对不被误触发；
  4. **全端平滑兼容**：桌面端鼠标 hover 与点击行为 100% 保持不变，纯展示型标签（无按钮包裹）在移动端依旧支持轻触查看，空白处点击或滑屏时静默收起。
- **实现边界**：
  - 重点收拢于 `frontend/src/components/FloatingPopover.tsx`；
  - 协同审查 `tools/android-shell/.../MainActivity.java` 与全局 CSS；
  - 同步更新公共组件文档 `docs/frontend/common-components.md` 与 `docs/frontend/floating-popover.md`。
