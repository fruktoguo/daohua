# TASK-20261004-10 反多开与反小号完整模块

## 1. 需求与目标

- 提出时间：2026-10-04 14:40:33
- 需求分析完成时间：2026-10-04 14:40:33
- 目标：同一自然人最多拥有两个账号；单一设备最多注册一个账号；对并发多开、设备复用、网络复用和高风险注册行为进行服务端联合判断，避免轻易批量创建几十个小号。
- 所有检测项必须模块化、可独立动态启停，并由开发运维面板查看状态、调整策略和查看账号检测记录。

## 2. 实现边界

1. 账号注册限制：注册事务内执行设备/网络风险判定与“设备最多一个注册账号”约束；为同一操作者保留最多两个账号的可配置上限，服务端权威拒绝，不能由前端绕过。
2. 风险信号：设备配置哈希、设备 ID、IP、网络特征及现有浏览器设备指纹作为风险证据；原始敏感值不回传运维页面，持久化哈希/脱敏摘要和命中原因。
3. 动态策略：独立模块开关、阈值和处置动作集中在服务端配置/数据库策略中，注册和登录路径读取当前策略；不把安全判断放在前端。前端仅采集必要信号并使用构建混淆提高分析成本，不宣称可防止浏览器调试。
4. 运维面板：增加“账号检测”页签，展示策略开关、风险命中统计、账号/设备关联摘要和近期拒绝记录；策略修改等写操作沿用既有运维令牌与二次确认。
5. 兼容口径：当前为本地内测阶段，不新增旧格式兼容层；新增 schema 由权威 `PostgresSchema.Sql` 直接建立，必要的兼容 SQL 仅放 `migrations/`。

## 3. 实际模块拆分

- `AccountRiskModels`/`AccountRiskHasher`/`AccountRiskRequestContext`：动态策略、可信请求信号与稳定 HMAC；配置仅参与软评分，主体只由设备 ID 推导。
- `PostgresAccountRiskRepository`：策略快照、按序事务锁、风险评分、关联和审计的权威存储；注册与登录复用同一评估入口。
- `PostgresAccountRepository`：在账号事务中执行风控；拒绝注册不创建账号，拒绝登录不签发会话与成功事件。
- `AntiMultiOpenAdmission`/`DeviceQuotaRegistry`：同账号在线所有权和同设备在线额度；Hello 与观测共用策略快照。
- 前端 `antiMulti/`：多维采集、稳定安装 ID、辅助指纹等待上限、标签页互斥及动态解除；生产构建混淆。
- 运维 `AccountAbuseView`：十个模块开关、硬额度、软权重/阈值、放行/复核/拒绝、计次和脱敏关联。

## 4. 关键不变量

- 注册限制必须与账号、玩家、审计记录在同一 PostgreSQL 事务内原子提交；并发注册不能突破设备或账号上限。
- 风险信号缺失时按策略明确拒绝、降级或人工审阅，禁止静默放行或凭空填默认值。
- 运维查询不得泄露密码、会话令牌、原始设备指纹或完整 IP；日志只保留脱敏值。
- 多实例部署时注册限制和审计必须共享数据库，不依赖单进程内存。
- 前端混淆只作为提高逆向成本的辅助措施，服务端策略和数据库约束必须独立成立。
