## 2. 需求背景与核心目标

### 2.1 现状与问题分析
1. **配表冗余占位严重**：
   - 在 `config/game-data/items.json` 中，所有 20 种功法秘籍（`item.tome.*`）与残卷（`item.fragment.*`）以及部分丹药/材料，均平铺式携带了大量 `hitpointRestore: 0`, `manapointRestore: 0`, `buffs: []`, `defaultCombatTriggers: []`, `cooldownSeconds: 0`, `recoverySeconds: 0`, `triggerHpRatio: 1.0` 等完全不使用的战斗丹药默认参数。
   - 功法秘籍与残卷在底层 `SimulationEngine.UseItem` 走的是独立的功法解锁与经验加成特化逻辑，除 `usableInActionTypes` 用于判定可用动作环境外，根本不消费上述丹药参数。
2. **导出工具重新写回冗余字段**：
   - 独立数据工具 `src/DataTool/Program.cs` 在执行 `export-defaults` 时直接将运行时解算出的 `ItemDefinition[]` 全量序列化为 JSON，导致运行时填充的默认值（`0`、`false`、空数组）被重新格式化写回至配表中。
3. **数据模型缺乏缺省忽略机制**：
   - `ConsumableConfig` 与 `BuffEffectConfig` 包含大量非必填属性，但由于历史原因未统一以 `null` 作为缺省忽略标志并在解算时统一兜底。

### 2.2 核心优化落地
1. **最简配表原则（Lean Configuration）**：
   - 精简 `config/game-data/items.json`，功法秘籍与残卷仅保留 `usableInActionTypes`。
   - 丹药与持续消耗品仅显式保留生效属性，剥离 0/1.0/空列表等无意义默认值（文件体积由 27.6KB 精简至 16.6KB，瘦身 40%）。
2. **领域模型与解算统一缺省处理**：
   - `ConsumableConfig` 与 `BuffEffectConfig` 的可选字段统一使用可空类型（缺省为 `null`），并在 `DataBudgetResolver` 中统一进行解算与默认值赋能。
3. **DataTool 导出机制改造**：
   - 引入 `ToItemConfig`、`ToConsumableConfig`、`ToBuffEffectConfig` 转换与 `JsonIgnoreCondition.WhenWritingNull`，确保后续执行工具导出时产出的 JSON 永远保持最简干净形态，从根源上杜绝冗余字段再生。
4. **数值规范与设计文档同步**：
   - 在 `.agents/skills/data-designer/SKILL.md` 中补充「6.3 物品配表最简原则 (Lean Configuration Principle)」。
