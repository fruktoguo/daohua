## 背景与测量依据

实测 `top -o power` / `sample` / `lsof` 定位：Edge 打开 `daohua.localhost` 页面时，Renderer 常驻 ~45% CPU、GPU 进程 ~62%（三条光栅线程满载 + CVDisplayLink 满刷新率推帧），连带 WindowServer ~45 能耗分。根因是前端存在多个**常驻 60fps JS 渲染循环**，挂机游戏又永远有进行中的行动 → 循环永不退出。

## 能耗点清单（实测+代码审计）

| 位置 | 机制 | 当前代价 |
| --- | --- | --- |

| `AbilityCooldownOverlay`（App.tsx:1570） | rAF 每帧 `setProperty('--cooldown-ratio')` + textContent | 冷却期间逐帧样式重算+conic-gradient 重绘 |

| `ArenaBuffSquare`（CombatArena:416） | 每个 Buff 一个 rAF 写 strokeDashoffset | N 个 Buff = N 条 60fps 循环 |
| `.status-progress-glow` → `progress-slide` | keyframes 动画 `left` 属性 | 每帧强制 layout+paint（应改 transform） |

既有良好先例：`SmoothActionFill`（CombatArena:206）已用 WAAPI `fill.animate()` + 同步锚点±250ms 复用判据；`@property` 已有 `--gold-angle`/`--ring-phase` 两例。

## 方案

1. **`useSmoothProgressRef` 重写内部实现**（签名/调用点零改动）：
   - 填充条改 WAAPI `fill.animate(scaleX)`：单段线性动画，时长压缩为「当前显示位置→服务端预期完成时刻」，天然吸收单调不后退保护（displayed>target 时速率<1 减速对齐而非跳回）与平滑追赶（速率封顶 2.2x 代替逐帧 dt 滤波）；无限循环（remainingRepeats<0）走「当前段 finite 动画 → onfinish 换 iterations:Infinity 整圈」。
   - 文本/百分比/元数据改 100ms `setInterval` + 内容比对后才写 DOM（显示精度 0.1s 恰好匹配）。
   - 暂停/非 running：静态 scaleX + 单次写文本，与原语义（回退到 baseProgress 冻结帧）一致。
2. **`--cooldown-ratio` 注册 `@property`**（`inherits: true`、`initial-value: 0`），两处遮罩驱动改 WAAPI 动画 + 100ms 文本 interval。
3. `ActionCountdownBadge` rAF → 100ms interval（已有变化比对）。
4. `ArenaBuffSquare` 环形倒计时 rAF → WAAPI `strokeDashoffset` 线性动画（仅剩到期/同步时重建）。
5. `progress-slide` keyframes `left` → `transform: translateX`（等效几何换算）。
6. 不改：WorldMapPanel（已有 document.hidden 检查且仅旅行中跑）、vfx emit（600ms 有界）、CSS transform/opacity 类氛围动画（合成器友好）、Modal 内面板 tick（关窗即停）、心跳/防多开定时器（网络必需）。
