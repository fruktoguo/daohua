# TASK-20260930-10 本地开发存档版本漂移自愈

## 需求

- 提出时间：2026-09-30 18:45:10
- 用户反馈：本地库中旧玩家的 `action_queue` 等 section 载荷仍是旧 `schema_version`，代码只允许当前版本，WebSocket 会话反复抛「section schema 版本不受支持」刷屏；希望自动解决而非每次手工清库。

## 现状问题（代码分析）

- `PostgresSectionRepository.LoadAsync` → `SectionCodec.Decode` 对非当前 `CurrentSchemaVersion`（现为 5）的 section 行直接抛 `InvalidDataException`，玩家每次连接都失败。
- 同文件 55-59 行：`identity.players` 存在但 `player_state_heads` 缺失时返回空 bundle，`EcsPlayerRuntimeAdapter`（`Head.StateVersion > 0 || Sections.Count > 0` 为 false）走新玩家默认聚合初始化——即删除 head/sections 后玩家自动重建角色，账号与角色名保留。
- 按玩家清理全域数据的既有口径在 `src/Bench/Program.cs`（584-600 行）：command_receipts / section_flush_queue / integration_outbox / transaction_lines+transactions / settlement_claims / reservations / asset_balances / asset_instances / runtime_leases / projection / action_queue / sections / heads。
- 规约红线：禁止运行时迁移/兼容路径；本地开发允许直接清空旧数据。因此自愈只能落在 dev 工具链，不进运行时装配。

## 方案（v3 定稿：合一迁移链 + 交互确认）

> v1 方案为「检出即自动清零」，实施后直接删除了 56 名玩家（含真实账号）的游戏域数据且未留备份，造成不可恢复损失。v2 曾尝试存档迁移独立成 `NNNN_save-vX_to_vY.sql` 双轨文件，用户裁定与既有 `NNNN_vX_to_vY.sql` 链合并、不搞第二套命名——v3 定稿。

- **单一迁移链**：`migrations/NNNN_vX_to_vY.sql` 一条链，`platform.schema_version` 升格为「本地库内容版本」（涵盖表结构与存档标签）；存档 `SectionCodec.CurrentSchemaVersion` 升级时 `PostgresSchema.Version` 同步 +1，对应迁移文件里内嵌 `UPDATE ... SET schema_version` 标签推进。
- `migrations/0004_v4_to_v5.sql` 示范：表结构 `player_seq` + 存档标签 v4→v5（`autoTravelEnabled`/`anchorNodeId` 可缺省解码、`schema_version` 不参与校验和，载荷原样保留）一文件完成。
- `scripts/reset-outdated-players.sh`（重构）：
  - 提取 `SectionCodec.CurrentSchemaVersion` 与 `PostgresSchema.Version`；
  - 双通道 psql（docker exec 优先、本机 psql fallback）；仅回环地址库、空库静默；
  - 检测「存档行漂移」或「platform 版本落后」→ 自动调用 `migrate-local-db.sh` 执行迁移链；
  - 迁移执行失败 → exit 1 中止；复检仍漂移 → `/dev/tty` 交互确认，输入 `RESET` 才重置；拒绝或无 TTY → exit 2 中止；
  - `--dry-run` 只检测与预告，不做任何写操作。
- `scripts/migrate-local-db.sh`：补本机 psql fallback（原先只支持 docker exec 通道）。
- `dev.sh`：处置脚本失败或被拒绝一律中止启动（不再告警后继续），防止带着必然崩溃的旧存档拉起服务端。
- 已知盲区（合一模型固有）：迁移链按库级版本推进，链已走完后才出现的旧版本行（如手工导入旧备份）无可重放文件，只能走交互确认清零——单人本地开发下几乎不触发。
- 规则修订：`AGENTS.md` 兼容清零硬规则追加「清零前必须先尝试迁移、不可迁移须交互确认、禁止无人值守删除」；迁移目录条款改为单链合一 + 同步 bump 约定。

## 范围

- `scripts/reset-outdated-players.sh`（重构）、`scripts/migrate-local-db.sh`（psql fallback）、`scripts/dev.sh`（调用点改中止语义）、`migrations/0004_v4_to_v5.sql`（追加存档标签 UPDATE）、`migrations/README.md`（合一规约）、`AGENTS.md`（规则+清单）
