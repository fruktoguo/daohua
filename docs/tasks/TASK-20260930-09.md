# TASK-20260930-09 坊市挂单弹窗交互修复与盘口列表精简

## 需求

- 提出时间：2026-09-30 18:30:11
- 用户反馈：
  1. 发起买卖的物品数量选择档位太怪，改为「1」（输入框左侧）与「最大」（输入框右侧）两个档位，最大值自适应——买按持有灵石、卖按持有数量；
  2. 发起买卖弹窗会自动重建，输入框焦点被打断（违反「高频状态更新不得整体重建面板，必须保持输入焦点」红线）；
  3. 盘口列表价格与数量列 hover 都显示「数量」；笔数列不显示，买卖列表只留价格、数量两列，横向各占一半。

## 现状问题（代码分析）

- `MarketOrderModal` 数量选择器走 `QuantitySelector presets=[1,5,10,50,100]`，档位语义与可用上限脱节。
- 焦点被抢根因链：`MarketPage` 内联 `onClose={() => setOrderModalSide(null)}` 每次渲染新引用 → `MarketOrderModal`(memo) 失效 → `Modal` 的 `useEffect`（deps 含 `onClose`）反复 cleanup → `previouslyFocused?.focus()` 把焦点拉回唤起按钮、rAF 又聚焦关闭按钮。叠加轮询/快照高频重渲染，输入框焦点持续被打断。
- `MarketOrderModal` 初始化 `useEffect` 依赖 `bestAsk/bestBid`：盘口 3s 轮询刷新即重置用户已输入的价格与数量。
- `MarketBookPanel` `MarketRows` 三列（价格/数量/笔数），价格列 `UnitNumber` 未传 `tooltipLabel`，默认显示「数量」。

## 方案

- `QuantitySelector` 新增 `leadingPresets`（输入框左侧档位钮）与 `maxShortcut`（右侧「最大」钮，点击填入 `max`）；词典加 `market.selector.max`。
- `MarketOrderModal`：数量改 `leadingPresets={[1]} maxShortcut`（max=quantityLimit 已按买=灵石/价、卖=持有量自适应）；初始化价格改为 `useState` 惰性初始化并删除初始化 effect，行情刷新不再重置输入。
- `Modal`：effect 内 `onClose` 经 ref 调用，deps 移除 `onClose`，父级重渲染不再触发焦点还原/焦点陷阱重挂。
- `MarketPage`：`onClose` 改 `useCallback` 稳定引用，恢复 memo 效果。
- `MarketBookPanel`：删笔数列与表头，价格列 `tooltipLabel` 改「单价」；`.market-level` 网格 3 列改 2 列。`MarketLevel.orderCount` 协议字段保留（apiClient 仍用于汇总活动挂单数）。
- i18n：zh 词典删 `market.book.ordersColumn`、增 `market.selector.max`；`public/locales/template.csv` 重新导出同步。
- `docs/frontend/common-components.md`：QuantitySelector 条目补充新能力说明。
