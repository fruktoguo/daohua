# TASK-20261018-10 功法与战斗消耗品条件按钮交互演进（Hover留存、展开互斥大按钮与战斗物品条件接入）

## 1. 任务背景与核心诉求

用户在使用功法面板与战斗配置时明确指出交互体验细节与深层需求：
1. **Hover 条件按钮保留，展开选择时互斥隐藏**：
   - 瓦片未展开时，鼠标 Hover/聚焦仍需保留框外小条件按钮（提供鼠标直观反馈与快捷进入）；
   - 但当点击槽位展开待选弹窗（`is-picking` 展开状态）时，必须将瓦片上的 Hover 条件按钮**彻底隐藏**，由待选弹窗顶部 Header 右侧的大号条件按钮接管；
   - 彻底避免遮挡问题，且任何时刻界面上**绝不出现两个条件按钮**。
2. **待选弹窗大号伴随条件按钮翻倍放大**：
   - 展开选择面板时，弹窗顶部 Header 右侧呈现醒目的大号「⚙ 触发条件」胶囊按钮；
   - 按钮尺寸翻倍放大：高度提升至 32px（触屏端 36px，原先仅 18px），字号提升至 13px，暗金微光胶囊质感，`has-triggers` 态微光高亮；
   - 点击该大按钮直接唤起 `CombatTriggerEditor` 并顺畅关闭选择弹窗。
3. **战斗详情页内的消耗品物品条件接入，其他窗口纯净无冗余**：
   - 用户明确指示：“希望详情里面的物品也有条件，但是其他窗口的物品就不需要有条件了”；
   - 战斗详情面板（`AutoUseSlotGroup bar="combat"`：药品栏与通用栏）接入触发条件逻辑：未展开时支持 Hover 浮现小条件胶囊，展开选药弹窗时顶部伴随大号条件按钮，并对接 `CombatTriggerEditor`；
   - 探索、炼丹、炼器等非战斗行动窗口的持续增益物品槽及背包物品完全不渲染任何条件按钮，保持纯粹简洁。

## 2. 技术设计方案

### 2.1 Hover 浮现与展开互斥隐藏架构 (`selection-grid.css` & `ConditionedTile.tsx`)
- `ConditionedTile.tsx` 恢复框外条件按钮与 `onPlacementChange` 上下视口翻转避让逻辑；
- 在 `selection-grid.css` 中建立互斥规则：
  ```css
  :is(.abilities-slot-card, .combat-slot-card, .auto-use-slot).is-picking .item-slot-inline-action--condition {
    display: none !important;
  }
  ```
  槽位一旦进入待选状态，瓦片上的小按钮瞬时隐形，由弹窗大按钮接管。

### 2.2 待选弹窗伴随大按钮全域接入 (`CandidatePicker.tsx`, `AbilityGridPicker.tsx`, `ItemGridPicker.tsx`)
- `CandidatePicker` 顶部 Header 右侧渲染大号条件按钮（`.candidate-picker-condition-btn`）；
- `AbilityGridPicker`（功法选择）与 `ItemGridPicker`（物品选择）统一向 `CandidatePicker` 透传 `conditionAction`（含 `label`, `hasTriggers`, `onClick`）。

### 2.3 战斗详情页物品槽条件接入 (`App.tsx`)
- `AutoUseSlotGroup` 判定 `isCombat = bar === 'combat'`；
- 仅战斗栏域的槽位绑定 `conditionCount`、`onCondition` 与 `ItemGridPicker` 的 `onEditCondition`，并挂载 `CombatTriggerEditor`；
- 非战斗栏域跳过所有条件逻辑，不产生任何条件按钮与状态开销。
