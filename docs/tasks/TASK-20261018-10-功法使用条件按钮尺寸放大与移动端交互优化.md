# TASK-20261018-10 功法使用条件按钮尺寸放大与展开选择伴随交互优化

## 1. 任务背景与核心诉求

用户在使用功法面板与战斗配置时明确指出交互体验痛点与重构需求：
1. **彻底移除瓦片悬浮条件按钮**：
   - 原先在瓦片框外 hover 浮现的条件按钮体验割裂，鼠标滑脱率高；
   - 且当用户点击槽位展开选择功法弹窗时，选择弹窗会直接把槽位和 hover 浮出来的条件按钮完全遮挡；
   - 用户明确指示：“原先 hover 的条件就直接移除吧，这样就只会显示一个”。
2. **在展开选择时直接显示放大一倍的条件按钮**：
   - 当点击槽位展开选择功法弹窗（`AbilityGridPicker` / `CandidatePicker`）时，在选择弹窗顶部旁边直接显示醒目的大号条件按钮；
   - 按钮尺寸翻倍放大：高度提升至 32px（触屏端 36px，原先仅 18px），字号提升至 13px，暗金微光胶囊质感，`has-triggers` 态微光高亮；
   - 点击该大按钮直接唤起 `CombatTriggerEditor` 并顺畅关闭选择弹窗；
3. **已学功法目录瓦片直达**：
   - 在已学功法列表中，同样移除 hover 浮现的小按钮，支持直接轻点任意已学功法瓦片直达该功法的触发条件编辑器，触屏与桌面交互完全统一闭环。

---

## 2. 技术设计方案

### 2.1 彻底清理瓦片 hover 框外悬浮按钮 (`ConditionedTile.tsx` & `selection-grid.css`)
- 从 `ConditionedTile` 中彻底移除 `condition` 渲染逻辑与 hover 浮出动画；
- 瓦片本体专注展示属性详情悬浮卡与参悟进度副卡片，恢复视觉极简纯净，绝无 hover 遮挡。

### 2.2 展开选择弹窗大号伴随按钮 (`CandidatePicker.tsx` & `AbilityGridPicker.tsx`)
- `CandidatePicker` 新增 `conditionAction` 契约，在弹窗顶部 Header 右侧直接渲染大号条件按钮（`.candidate-picker-condition-btn`）；
- `AbilityGridPicker` 透传 `onEditCondition` 与 `triggerCount`，根据当前槽位已装配功法动态绑定条件编辑与数量徽章；
- 按钮尺寸翻倍放大（高度 32px / 触屏 36px，字号 13px，大内边距），点击即入条件编辑。

### 2.3 已学功法瓦片点击直达 (`AbilitiesPanel.tsx`)
- 已学功法瓦片转为 `button` 交互单元，直接点击即可唤起对应功法的触发条件编辑器。
