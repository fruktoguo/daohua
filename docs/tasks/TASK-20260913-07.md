## 需求

用户提出：

> 我观察到这玩意怎么有200多K？不能再压缩了吗？

指 `frontend/src/assets/items/`：90 张 64×64 WebP（q90）合计 **267.2 KB**，平均 2.97 KB/张。

量化一下这个体积值不值得动：入口 JS 是 367.60 kB，图标 267 KB —— 图标资产和整个应用 JS 同一个量级，
确实值得压。

## 实测：从无损参考出发横扫编码档位

**基准必须是无损的**，否则「有损→有损」二次压缩会污染结论。做法：用 `art/sheets.json` 以
`--web-lossless` 重出图集来源的 64 张 64px 无损图；遗留 26 张从 `art/legacy_128/` 按长边补正方形后
LANCZOS 缩到 64。得到 90 张无损 64px PNG 参考。

（体积为 90 张口径；RGB PSNR 只在 `alpha > 8` 的可见像素上算 —— 有损编码会往全透明像素里填任意 RGB，
整图算会把结论毁掉。）

| 档位 | 体积 | RGB 中位 | RGB 最低 | alpha 中位 |
| :--- | ---: | ---: | ---: | ---: |
| **线上现状：WebP q90** | **267.2 KB** | 31.02 dB | 24.23 dB | 无损 |
| WebP 无损（不降色） | 456.3 KB | 无损 | — | 无损 |
| WebP q90 + alpha_q80 | 242.3 KB | 31.02 dB | 24.23 dB | 55.05 dB |
| WebP q80 + alpha_q75 | 193.6 KB | 29.47 dB | 23.84 dB | 52.64 dB |
| WebP q75 + alpha_q70 | 150.5 KB | 28.54 dB | 23.56 dB | 42.54 dB |
| 降色 256 + 有损 q90 | 239.3 KB | 28.49 dB | 21.21 dB | 38.83 dB |
| 降色 256 + 有损 q80 | 181.4 KB | 27.58 dB | 21.03 dB | 38.80 dB |
| 降色 128 + 有损 q70 | 137.5 KB | 26.76 dB | 20.39 dB | 37.13 dB |
| **降色 256 + 无损** | **168.1 KB** | **35.15 dB** | **32.50 dB** | 38.83 dB |
| 降色 192 + 无损 | 166.4 KB | 35.10 dB | 31.43 dB | 38.83 dB |
| 降色 128 + 无损 | 158.4 KB | 34.66 dB | 29.55 dB | 37.96 dB |
| 降色 256 + 原 alpha + 无损 | 300.9 KB | 35.15 dB | 32.50 dB | 无损 |
| 调色板 PNG-256（同像素） | 226.4 KB | 35.15 dB | 32.50 dB | 38.83 dB |

### 三个结论

1. **「降色 + 无损」是全局最优，同时打赢体积和画质。**
   降色 256 + 无损 = **168.1 KB / RGB 35.15 dB**，比现状（267.2 KB / 31.02 dB）
   **小 37%、RGB 反而高出 4.13 dB**。
2. **「降色 + 有损」是最差的组合**：同体积段（181.4 KB）RGB 只有 27.58 dB，比不降色的 q80
   （193.6 KB / 29.47 dB）还差。降色与有损是**两次独立损失**，叠加后既不加体积收益又毁画质。
3. **保留原始 alpha 不值得**：边缘完美（alpha 无损）的代价是 300.9 KB，比 168.1 KB 多 79%。
   而 38.83 dB 的 alpha 误差约 2.9/255，10 倍放大下看不到任何边缘异色。

### 顺带查清：现状真正的毛病是有损 WebP 的半透明像素

10 倍逐像素对照（无损参考 / 线上 q90 / 降色256无损）显示，**现状不只是「糊」，还有明显的偏色与脏边**：
有损 WebP 在**全透明像素里填了任意 RGB**，那些像素本身不可见，但边缘处 alpha 30~100 的半透明像素
颜色被带偏 —— 表现为沿轮廓一圈发白的噪点、以及整张图褪色发灰。
**降色 + 无损恰好没有这个毛病**（调色板保证颜色一致，无损保证不被二次重采样）。

## 改动

### 1. 切图工具新增 `--web-palette N`

`icon-sheet-grid-slice/scripts/slice_grid_sheet.py`：

- 新增 `--web-palette N`：网页版先 `quantize(colors=N, FASTOCTREE, dither=NONE)` 再编码；`0` = 不降色（默认）。
- 与 `--web-lossless` 组合使用。脚本汇总行会打印 `256色 + 无损` 这样的实际档位。
- **没有把降色设成默认**：对渐变/写实风格的图标降色会明显掉画质，这个开关只对平涂图标有利，
  所以由调用方显式选择；本项目标准命令写进 SKILL.md。

### 2. 90 张全部重出

- 图集来源的 64 张：`slice_grid_sheet.py art/sheets.json --web-palette 256 --web-lossless`
  （仍走原图全分辨率方格直出），再按 `art/icon_ids.json` 映射为资源 ID。
- 遗留 26 张：`art/legacy_128/` 按长边补正方形 → LANCZOS 64 → 降色 256 → 无损 WebP。
- **扩展名不变，仍是 `.webp`** —— 注册表、`vite.config.ts`、所有组件一行代码都不用改。

### 3. 旧版备份

`/tmp/items_web_q90_backup/`（90 张 q90 版），回滚一条 `cp`。
