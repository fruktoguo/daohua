## 需求分析

用户观察：队伍中有角色死亡后，结束战斗再进入，该角色没有立刻复活。设计意图为「退出战斗后死亡角色立刻复活，但不完整恢复，只恢复 1 滴血」。

勘察结论——单人路径本就如此（队列变更管线 `RecoverHitpoints`：移除死亡中队首远征时气血回 1），缺陷为组队特有：

- 散场时 `DissolveSessionAsync` 对每个成员只调用 `EndActionParticipation` **写权威散场时刻**，参与条目的实际移除（携带 `RecoverHitpoints` 复活结算）推迟到该成员下次模拟推进时才发生。
- **离线成员**：被 `ApplySessionMutationAsync` 强制装载写完散场时刻即卸，不推进——气血停在 0 直到下次上线补算。
- **快速再入场**：散场与新开打之间成员未推进模拟时，`StartSessionAsync` 先采集冻结面板（`InitialHitpoints=0`）后扫残留绑定——成员以倒地定格进新场。

## 设计边界

1. 复活时机提前到 `EndActionParticipation`（领域层）：写权威散场时刻的同时，气血 ≤0 的成员恢复到 1 点并标脏 Combat 分段——散场、看门狗兜底、装载对账三条路径共用同一方法，天然全覆盖。
2. 不恢复灵力；不移除绑定——尾段结算与正式出队仍在推进到散场时刻进行；移除时 `RecoverHitpoints` 的 `Hitpoints <= 0` 检查自然变 no-op，不重复结算。
3. 会话中已原地复活的成员（HP>0）不受影响；散场后自然回复照常生效。
4. 设计文档 §21.13.1 补充该口径（文档先行）。
