## 需求背景

`expedition.enemies[].attributes` 与 `expedition.duel.opponentAttributes` 此前随每个被触碰的快照全量重发（白名单投影），但属性面板只在玩家点击单位详情时才有展示需求，未点击时纯属带宽冗余。用户明确数据分层：

- **该推**：血/蓝当前值、出手时刻（行动条）、威胁——战斗视图持续展示所需。
- **不该推**：其余战斗属性——仅点开详情那一刻才需要，敌怪、斗法对手、未来队友一视同仁按需获取。
- 图鉴/地图/生态等战前查看继续走前端静态目录反查（`CombatantDefinition.attributes`），不变。

## 实施方案

- 协议新增 `WireMessageType.UnitInspect`（仅 WebSocket 上行，火忘帧无回执）：载荷 `{side, index}` 表达观察目标，`{side:null,index:null}` 清除；`WebSocketSession` 记连接级观察目标，断开自然销毁。
- `ProtocolSnapshotMapper`：enemies/duel 属性块仅对观察目标命中下标投影；`maxHitpoints`/`maxManapoints`（血蓝条分母）与 `opponentMax*` 常驻快照标量。观察期间属性随快照持续下发（真实时）。
- 前端：`gameClient.sendUnitInspect` + HelloAck 后重放最近目标；`CombatArena` 用 useEffect 将 `inspectedActor` 同步为观察目标；`ExpeditionEnemy`/`ExpeditionDuel` 类型与注释同步（白名单投影 → 按需投影）。
- 玩家自身不变（`combat.attributes` 已有 `WireAttributesChanged` 门控）。
