## 1. 现状问题与设计对齐

- **多层嵌套与标题抽象**：玩家进入秘法后，页面顶栏显示无交互的「秘法」二字，下方先切「装备强化 / 物品转化」，切入物品转化后再切「化灵 / 分解 / 转化」。玩家操作繁琐、层级深。
- **全物品平铺混乱**：化灵/分解/转化页面直接把背包内所有满足条件的物品渲染为一个庞大的网格，物品过多时大量占满屏幕且无法按品类/名称搜索，与全游戏统一的「槽位选择 -> 弹出选择网格」标准违背。
- **分解与转化缺乏批量次数**：化灵支持选数量，而分解装备与转化残卷被写死为 1 次，拥有大量同类装备或多张残卷时必须反复手动点击弹窗确认，体验割裂。

## 2. 改造方案

1. **状态与导航体系**：
   - 在 `uiStore` 增加 `enhancementSubTab: 'enhance' | 'liquefy' | 'disassemble' | 'convert'`（默认 `'enhance'`）。
   - 在 `App.tsx` 的 `crafting-page-header` 中，当 `craftingMode === 'enhancement'` 时，直接渲染 `[强化] [化灵] [分解] [转化]` 四个按钮。
   - `EnhancementPage` 统一接收或直接使用该状态，分流渲染「装备强化」与「物品转化（化灵/分解/转化）」。
2. **转化与分解窗口重构 (`SecretArtOperations.tsx`)**：
   - 彻底重构为类似 `EquipmentEnhancementPanel` 的双栏或规整工作台：
     - 左栏/主设置组：目标物品槽位（`ItemUseSlot`，点击触发 `ItemGridPicker`）、操作次数/数量选择器（`QuantitySelector`）、操作确认按钮。
     - 右栏/预览组：详细机制说明、单次/总计消耗与产出收益预览（化灵显示灵石预估、分解显示材料清单乘算预估、转化显示单次与总计期望说明）。
3. **服务端支持批量事务 (`EcsPlayerRuntimeAdapter.cs`)**：
   - 放开 `item.disassemble` 对 `secretQuantity != 1` 的拦截，按 `returns * quantity` 计算总返料。
   - 放开 `item.convert` 对 `secretQuantity != 1` 的拦截，循环执行 `quantity` 次随机掷骰，汇总获得的 `item.tome.*` 秘籍与未转化成功的保底灵石。
4. **门禁与测试**：
   - 更新服务端单测 `EnhancementContractTests.cs`，验证分解与转化的批量数量命令。
   - 更新前端单测 `secretArtOperations.test.mjs`。
   - 运行全量 `verify.sh` 门禁。
