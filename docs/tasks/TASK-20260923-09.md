# TASK-20260923-09 战斗团灭分流模型（原地复活 / 团灭即败）

## 需求来源

用户发现「怪物把玩家击杀后怪物也消失了」不符合设计意图。根因定位：`4e22179`
（TASK-20260914-09 审计整改，2026-09-15）为实现「死亡与复活规则」把战败路径从
`action.Status = Blocked`（战场冻结、敌人快照保留）改为 `CreateSearchState` +
`Respawning` 相位（拆场、敌人清空、波次重置回 1）。此前并不存在「怪物停手但时钟照走」
的行为——本次是落地一套新语义，不是回滚。

用户裁定：团灭处理要通用化，不能做成斗法特例——副本、闯关爬塔等后续模式都需要
「团灭即败」出口，因此抽象为战斗的两条正式分支：`onPartyWipe = respawn | defeat`。

## 已拍板语义（逐条确认）

| 决策点 | 结论 |
| :--- | :--- |
| 终局条件 | 一方全灭：敌方全灭=PlayerWon；玩家方全灭=团灭，按 `onPartyWipe` 分流 |
| `respawn`（野外 PvE 缺省） | 战斗不终结：玩家原地躺尸读条，怪物停手但回血/CD/Buff 到期照走；读条满起身续打同一波残局，波次不重置 |
| `defeat`（斗法/副本/爬塔） | `Outcome=EnemyWon` 终局信号；善后是模式级策略不进引擎（斗法=暂存物结算+冷却+拆场读条复活；野外 defeat=拆场读条满状态复活重搜第 1 波，即现行行为） |
| 起身结算 | 仅补满 HP；MP/技能 CD/自动消耗品 CD 一律「时钟照走」自然处理，不做额外重置 |
| 吟唱打断 | 阵亡瞬间双方吟唱全打断；未完成吟唱视为未释放——退还预扣灵力且不进入 CD（只有完整吟唱结算的技能才耗蓝进 CD） |
| 躺尸窗口敌方全灭 | 躺尸期间被 DoT/反伤跳死全灭 → 照常 PlayerWon 结算掉落与轮次，玩家起身后进下一波 |
| 阵亡计数 | 每次阵亡计 `totalDefeats`/`deaths`+1 并发 `combat.lost`；起身发 `combat.respawned` |
| 死循环兜底 | 不做：打不过就无限「死→复活」，玩家手动取消脱战（1 HP 重伤复苏） |
| 死亡资源回复 | 战内躺尸同 §9.3：气血锁 0，灵力回复按 5s 网格照常（对一切阵亡单位同构） |

## 实施方案（已完成）

1. **领域层**：
   - `CombatEncounterDefinition` 新增 `OnPartyWipe` 枚举（`Respawn`/`Defeat`），JSON 读
     `onPartyWipe`，缺省 `respawn`；`GameDataCatalog` 非法值拒绝；`DataTool` 增补词汇校验。
   - `CombatEncounterState` 携带 `PlayerRespawnSeconds`（>0 启用原地复活；斗法
     `DuelScriptEngine.Resolve` 固定不传按 defeat）与 `PlayerRespawnAtSeconds`
     （战斗时钟上的复活截止点，+∞ 表示无倒地窗口）。
   - `DeterministicCombatEngine.AdvanceTo`：玩家方全灭且原地复活启用 → Outcome 保持
     Running，`InterruptCasts` 打断全体吟唱并退还预扣灵力/撤销该槽预排冷却；边界集合
     改为 Buff/回复网格 + 复活截止点（怪物出手边界全部跳过）；到达复活点 → 起身仅补满
     HP → 双方重新 `DecideInitialActions`（已阵亡单位跳过）→ 续战；躺尸期间敌方全灭
     起身后统一 `UpdateOutcome` 落到 PlayerWon。
   - `ApplyBuffTick`：阵亡单位改为「HP 不回、MP 照回」（§9.3 战内同构口径）。
   - `UpdateOutcome`/`Restore` 的终局判定同步放宽：玩家死 + 复活点待触发 = Running。
   - `CombatAdvanceResult` 增 `PlayerDeathTimestamps`/`PlayerRespawnTimestamps`（战斗时钟）。
   - `CombatExpeditionState` 增 `PlayerRespawnAtSeconds` 持久化字段与 `IsValid` 不变量
     （Combat 相位允许玩家 HP=0 且复活待触发；非 Combat 相位不得携带）。
   - `SimulationEngine`：开战/恢复经 `InBattleRespawnSeconds` 分流（respawn→遭遇复活秒，
     defeat→0）；阵亡/起身事件按战斗时钟交错落 `combat.lost`/`combat.respawned` 并逐帧
     计败走与死亡；defeat 模式维持现行拆场 Respawning 读条善后（波次重置回 1）。
   - `SimulationSchedule`：倒地窗口只排复活截止点边界，回复静默推进不推送。
2. **协议/持久化**：`ProtocolSnapshotMapper` expedition DTO 增 `playerRespawnAtSeconds`
   （战斗时钟秒）与 `playerRespawnDurationSeconds`（读条总长，倒地窗口外为 null）；
   前端 `snapshot.ts` 映射 + `ExpeditionProgress` 类型同步。
3. **前端**：CombatArena combat 相位下玩家阵亡置灰（HP=0 自动落 is-dead）+ 行动条合成
   `kind:'respawn'` 复活读条（还魂中倒计时）；倒地窗口内敌方行动条不显示（停手语义）；
   `respawn` 相位保留给 defeat 分支善后读条。
4. **配表**：现有 encounter 不显式写字段（缺省 `respawn`）；config-editor 增
   `PARTY_WIPE_RULES` 枚举与遭遇编辑控件；DataTool 校验 `onPartyWipe` 词汇。
5. **测试**：新增 `CombatPartyWipeTests`（倒地窗口冻结怪物出手但回复/CD 照走、起身仅满血
   且 MP/CD 保留、团灭打断退还灵力撤销冷却、躺尸期 DoT 全灭起身后判 PlayerWon、defeat
   分支 EnemyWon 终局）；`CombatExpeditionSimulationTests` 原地复活不拆场/快照往返一致
   与 defeat 拆场重置回第 1 波两分支覆盖；`QueueLoopTests` 复活等待不轮换不计完成。
