## 1. 已锁定需求与设计边界

1. **记录范围**：仅记录当前进行中行动内发生的 **PVP 斗法（玩家对战）** 场次；单次行动最多滚动保留最近 **20 场**，单场最多记录 **1000 次行动**；行动出队归档时一并清空，不进入历史归档战报。
2. **全覆盖与计次粒度**：
   - 完整记录普通攻击、功法技能（伤害/治疗/支援/变招/多目标/连击/连锁）、战斗物品（丹药/符箓）、阵法（阵盘激活/天雷与血煞阵反击及维持消耗）、特质（开战/条件/火神覆写/蓄意爆发/燃魂叠层与每秒灼烧）及有实际数值变动的 1s/5s 周期回复。
   - 同次出手触发的全部衍生效果（吸血、吸蓝、反伤、蓄意爆发、阵盘反击、授 Buff、燃魂叠层、目标倒地）合并记入该次行动内，仅占 1 次行动配额；燃魂每秒火法灼烧与有数值变动的周期回复/阵盘维持各自独立记条。
   - 每次伤害精确记录伤害大类（物理 / 术法 / 真实）与五行属性（无 / 金 / 木 / 水 / 火 / 土）及命中状态标志（命中 / 闪避 / 暴击 / 破招 / 化解）。
3. **省流存储与按需拉取**：
   - 服务端不存储完整拼接文本，采用「参战单位表 `u` + 实体 ID 字典池 `defs` + 短键名 JSON 行动序列 `acts`」随 `duel` 分段 Brotli 压缩持久化落盘（`SectionCodec v47 -> v48` / `PostgresSchema v67 -> v68`）。
   - WebSocket `duel` 分段剥离 `duelRecords` 明细数组，仅下发 `duelRecordCount`；前端点开「战斗统计 → 斗法记录」时调用 `GET /api/v1/players/{playerId}/duel-records` 按需拉取，结合本地配表与富文本/图标组件动态拼装展示；进行中斗法按已播 `BattleElapsedSeconds` 实时截断防剧透。
