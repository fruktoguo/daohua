# TASK-20260924-07 斗法无对手静默 + 怪物掉落明细展示

## 需求

1. 斗法没有可匹配对手时，前端不再闪现「斗法感应中…」占位敌方卡（玩家视角的"奇怪机器人"），日志也不再提示 `duel.seeking`。
2. 怪物掉落物展示数量与概率：缩小版物品瓦片 `图标 ×数量 ~概率`；数量为区间时显示 `min-max`（配表 min 恒为 1，即 1-最大数量），固定数量直接显示实际值。
3. 实际掉落语义确认：先 roll 掉不掉（dropChance），再 roll 数量（min~max 整数均匀，含上限）。

## 分析

- 撮合链：`SimulationEngine` 搜寻完成→`chargesBefore>0` 进入 `DuelPending` 相位并写 `duel.seeking` 日志→同拍 `PlayerRuntime.TryMatchDuelAsync` 在已加载玩家中找 ±30% 实力候选，无候选 `AbortDuelSeek` 回退 Search+DuelSeekFailed。pending 快照会广播一帧，前端 `CombatArena` 对该相位渲染 `visual:null`+「斗法感应中…」的占位敌人卡——即用户看到的"机器人"。
- 掉落现状：`CombatDropDefinition(ItemId,DropChance,MinQuantity,MaxQuantity)` 领域模型齐备，结算已是「先判定后数量」两通道抽样；但 `Floor(min+(max-min)*roll)` 使 max 实际不可达（min=1,max=3 只会掉 1/2）。协议投影两处均只透传 itemId：`StaticGameCatalogMapper.ResolveMonster`（catalog encounters/maps）与 `ProtocolSnapshotMapper.ToNearbyMonster`（world section）。
- 前端消费：`CombatEcologyPanel`（节点生态详情卡）与 `WorldMapPanel`（地图怪物悬浮卡）以 `ItemTileReference` 平铺 `drops: string[]`；`NearbyPanel` 不渲染 drops。

## 实施

1. 领域 `SimulationEngine`：删除进入 DuelPending 时的 `duel.seeking` 日志；数量抽样改 `Floor(min+(max-min+1)*roll)` + Clamp(min,max)。
2. 服务端 `PlayerRuntime`：撮合双方 Attach 成功后各发一条系统日志 `斗法遭遇：{对手名} 与你狭路相逢。`（LogChannels.System，走 PlayerLogBuffer 保证重连回放）。
3. 协议投影：`drops` 由 `string[]` 升级为 `[{itemId,dropChance,minQuantity,maxQuantity}]`，两处投影同步。
4. 前端：`CombatantDefinition.drops`/`NearbyMonsterDefinition.drops` 类型与 `mapNearbyMonsters` 解析对齐新结构；`CombatArena` 移除 duel-pending 占位合成（isDuelPhase 收窄为 `duel`）；新增缩小版掉落瓦片组件（图标 + ×数量角标 + 概率小字）替换两处平铺。
5. 测试：`DuelSimulationTests` 去掉 `duel.seeking` 断言；新增区间数量掉落用例；`check-frontend-contracts.mjs` 补 drops 结构解析断言。
6. 设计文档：`07-战斗数值与内视规约.md` §7.10.1 补「无候选对手静默回退」一句；index.html 嵌入副本同步。
