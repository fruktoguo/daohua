## 1. 需求分析与目标

### 1.1 需求背景
游戏在 `TASK-20261102-02` 中实装了讨伐历练的「难度选择」系统（默认档 0，以及 T1 ~ T5 共 6 档）。在真实战斗中，选择不同难度时，怪物全属性按 $1.25^T$ 指数放大并向上取整（`Math.ceil`），击杀经验按 $1 + 0.60 \times T$ 线性提升，掉落率/保底掉落量按 $1 + 0.25 \times T$ 线性提升。
然而前端战斗模拟器（`CombatSimulatorModal`、`ExpeditionSimulator`）目前仅支持地图区域、地点节点和模拟时长选择，缺少了「T级难度（默认 / T1 ~ T5）」选择；模拟推演生成的怪物属性、掉落和经验依然固定在基础默认档（T0），无法评估玩家队伍在高难（T1~T5）下的胜率、战斗耗时、灵石收益及经验产出。

### 1.2 核心业务逻辑预期
1. **配置面板（SimulatorConfigPanel）**：
   - 增加难度选择控件（默认、T1、T2、T3、T4、T5 共 6 档），与讨伐历练弹窗和队伍设置保持一致。
   - 切换不同难度时，显示该难度下的怪物属性、经验、掉落加成提示说明。
2. **推演引擎（ExpeditionSimulator）**：
   - `SimulatorConfig` 增加 `difficulty?: number` 属性。
   - 波次生成（`generateWave`）中对 Boss、Elite、小怪和保底怪全面接入难度同构缩放：
     - 怪物全属性：`scaleMonsterAttributes(attributes, difficulty)`（$1.25^T$ 指数缩放并向上取整）。
     - 击杀经验：按 `getDifficultyExperienceMultiplier(difficulty)`（$1 + 0.60 \times T$）线性提升。
     - 掉落表：`scaleMonsterDrops(drops, difficulty)`（$1 + 0.25 \times T$ 线性提升掉率/保底掉落量）。
3. **推演报表与展示（SimulatorResultsView）**：
   - `SimulatorReport` 与 `SimulatorNodeComparisonItem` 携带所选的 `difficulty`。
   - 在结果概览头部、单节点报告头部及多节点对比列表中，清晰呈现推演难度标签（如 `[T1]` / `[默认难度]`），防止多难度结果混淆。
4. **自动化回归门禁**：
   - 补充 `simulator.test.mjs` 单测覆盖 T0~T5 各难度的推演确定性、属性放大、经验倍率与收益差异。
   - 通过 `scripts/verify.sh` 全量门禁校验。

## 2. 详细设计与实现方案

### 2.1 类型定义扩展（simulatorTypes.ts）
- `SimulatorConfig` 扩展 `difficulty?: number`。
- `SimulatorReport` 扩展 `difficulty: number`。
- `SimulatorNodeComparisonItem` 扩展 `difficulty: number`。

### 2.2 离线推演引擎同构（expeditionSimulator.ts）
- 引入 `frontend/src/game/combatDifficulty.ts` 中的 `scaleMonsterAttributes`、`scaleMonsterDrops`、`getDifficultyExperienceMultiplier`、`clampDifficultyTier`。
- `runSimulation` 解析配置中的 `difficulty`，钳位在 [0, 5]。
- `generateWave` 传导 `difficulty` 参数，生成敌人时应用属性、掉落、经验的同构缩放。

### 2.3 前端交互与视觉（SimulatorConfigPanel.tsx / CombatSimulatorModal.tsx / SimulatorResultsView.tsx）
- `SimulatorConfigPanel` 增加难度选项切换组（采用直观的胶囊按钮或单选网格，附带加成说明）。
- `CombatSimulatorModal` 管理 `difficulty` 状态并在发起推演时下发。
- `SimulatorResultsView` 在报告头部展示当前难度标识与对应数值倍率。
