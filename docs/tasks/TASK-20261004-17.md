# TASK-20261004-17 · 触发条件跟随技能维度迁移 + 框外条件入口 + 条件编辑器抗快照刷新修复

- **分类**：前端体验 / 交互通用化 / 数据模型调整 / Bug 修复
- **提出时间**：2026-10-04 21:39:20
- **状态**：✅ 已完成（verify.sh 全部门禁通过；待 UI 目检）

## 需求

### 第一轮（已完成）

1. **条件入口通用化**：当前战斗技能触发条件的入口是常驻在技能瓦片左下角的「条件」小按钮（`item-slot-inline-action--condition`），希望改为 **item hover 后从瓦片底部浮现「条件」按钮**，鼠标移动到按钮上点击即打开对应的条件设置界面；该 hover 浮现交互作为 item 通用模式，覆盖所有渲染条件按钮的槽位（功法神通面板装配槽、战斗面板装配槽、`ItemUseSlot` 物品槽）。
2. **条件编辑器抗刷新**：条件设置界面（`CombatTriggerEditor`）在战斗进行中/结束后会被服务端快照反复重置，导致无法正常编辑——根因是编辑器 `useEffect` 依赖 `initialTriggers` 引用，快照刷新 `combat` 对象后引用变化即触发 `setTriggers(cloneTriggers(...))` 覆盖未保存的编辑内容（`?? []` 兜底还会在每次渲染新建空数组放大该问题）。

### 第二轮

3. **条件跟随技能**：触发条件应挂接在功法 ID 维度而非装配槽位维度——卸下再装配、跨槽位移动同一功法时条件保留，已学功法目录瓦片也可直接配置条件。
4. **框外条件按钮**：条件按钮不再占用瓦片内部角落，改为浮现在瓦片画框之外（上方或下方）；具体方向需要根据瓦片 hover 悬浮卡的实际落位避让（`FloatingPopover` 落上方时按钮走下方，反之亦然），与悬浮卡方向联动调优。

## 方案

### 第一轮（已完成）

1. **编辑器重置修复**（`frontend/src/components/CombatTriggerEditor.tsx`）：`initialTriggers` 经 ref 中转，`useEffect` 依赖只保留 `open`——仅在弹窗打开瞬间同步一次外部初始值，打开期间外部快照刷新不再重置编辑状态。
2. **hover 浮现通用化**：
   - `frontend/src/styles/selection-grid.css`：`.item-slot-inline-action--condition` 默认 `opacity: 0; pointer-events: none`（保留可聚焦性，`:focus-within` 键盘可达）；卡片/shell 处于 `:hover / :focus-visible / :focus-within` 时经 keyframe 动画 `item-condition-rise-in`（opacity + translateY，合成器线程，遵循瓦片零重绘架构）从底部浮现。
   - hover 域选择器统一覆盖 `.abilities-slot-card` / `.combat-slot-card` / `.item-use-slot-tooltip` / `.combat-ability-slot-shell`，按钮无论挂在卡片层还是 shell 层都生效。
   - `frontend/src/components/AbilitiesPanel.tsx`：把 Lv 徽标 + 条件按钮（`combat-ability-slot-actions`）从 tooltip 触发域（shell 内）移到槽位卡片层（shell 外），与 App.tsx 战斗面板既有结构对齐——鼠标移到按钮上时 tooltip 不再弹出，点开编辑器也不会出现 tooltip 叠加在 modal 上的问题（FloatingPopover z-index 10000 > Modal 70）。

### 第二轮（已完成）

3. **触发条件按功法 ID 挂接**（服务端全链路）：
   - `src/Domain/Player/PlayerLoadout.cs`：`PlayerAbilitySlot` 移除 `Triggers` 字段；`PlayerLoadoutDocument`/`PlayerLoadoutState` 新增 `AbilityTriggers`（`abilityId → triggers[]` 映射，随装配导出修订号追踪）。
   - `src/Domain/Combat/CombatSkillState.cs`：`SkillSlot.FromAbilitySlots` 改从按功法 ID 索引的 `abilityTriggers` map 读自定义条件；`EcsWorldShard` 散件槽构造统一收拢到该入口。
   - `src/Server/Clean/LoadoutCommand.cs`：`loadout.replace` 载荷顶层新增 `abilityTriggers` map（槽位 `triggers` 字段删除）；key 校验为已习得功法 ID，值沿用 `ValidateTrigger` 逐条校验。
   - 存档版本 `SectionCodec.CurrentSchemaVersion` / `PostgresSchema.Version` v11→v12；新增 `migrations/0012_v11_to_v12.sql` 仅推进 schema_version 标签（新字段可缺省解码，旧存档槽位 triggers 字段反序列化时被忽略丢弃——内测口径允许）。
   - 物品消耗品触发条件本就在配表层（`consumable.Triggers`），不属于玩家 loadout，本次不动。
4. **框外条件按钮 + 悬浮卡避让**（前端）：
   - `frontend/src/components/FloatingPopover.tsx`：新增 `onPlacementChange` 回调（`computeSafeFloatingPosition` 已返回实际落位 `actualPlacement`）；`EffectTooltipTarget` 透传。
   - 新增 `frontend/src/components/ConditionedTile.tsx`：「瓦片 + 悬浮卡 + 框外条件按钮」三件套封装——按钮默认悬于瓦片上缘外侧（`bottom: 100%` 零间隙贴合保持 hover 连续），悬浮卡实际落在上方时按钮自动切到下缘外侧（`is-below`）。
   - `frontend/src/AbilitiesPanel.tsx` 与 `frontend/src/App.tsx` 战斗面板接入组件；已学功法目录瓦片同步获得条件入口（条件跟随功法的直接收益）。
   - 编辑器标题由槽位号改为功法名（`{name} · 触发条件`）。
   - `frontend/src/game/ids.ts` `assignAbilityToSlot` 删除槽位间 triggers 随迁逻辑（条件不再跟槽位）。
