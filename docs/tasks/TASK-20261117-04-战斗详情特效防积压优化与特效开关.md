## 1. 需求背景与根因分析

1. **切页回看瞬间爆播特效卡顿**：
   - 应用内切离「详情」页签（`CombatDetailsPage` `hidden={true}`）时，`CombatArena` 虽冻结了 React 订阅，但 `useCombatVfx` 未接入 `hidden`，仍在后台持续消费全量状态与原始日志并向 `CombatVfxRuntime` / `DaohuaVFX` 派发粒子与定时任务；切回可见解冻时，`ArenaActor` 与 `ArenaResource` 也会把旧快照到新快照间的 `recentEvents` 一次性集中重放。
   - 浏览器切后台标签页（`document.visibilityState === 'hidden'`）时，`requestAnimationFrame` 被浏览器挂起，但 WebSocket 快照仍在到达，`CombatVfxRuntime.schedule`（`delayMs <= 0` 走 `requestAnimationFrame`）及 `queueDomSync` 在 `scheduledRafs` 中不断堆积；切回标签页首帧瞬间同时触发所有积压帧，导致单帧爆出大量粒子与特效而严重卡顿。
2. **详情内部左上角添加特效开关**：
   - 在详情内部左上角操作区放置简短的「特效」+ 切换胶囊开关（持久化到本地存储）。
   - 关闭后不播放任何动画与特效（含 Canvas 双层特效、角色突进/施法/受击震颤闪白/闪避位移、血条断裂碎片、尸体消散及暴击/破招光效放大等），仅保留正常的伤害数字展示与基础血蓝/读条状态同步。

1. **持久化特效开关状态 (`frontend/src/game/combatVfxStore.ts`)**：

2. **共享文档可见性钩子与防积压内核保护**：

   - `frontend/src/vfx/index.ts`：`CombatVfxRuntime` 新增 `setPlaybackActive(active)` 与 `resize()`；停用时立即 `clearBattle()` 并拒绝后续 `schedule` / `play*` / `sync*`。
   - `frontend/src/vfx/useCombatVfx.ts`：接入 `{ hidden, enabled }` 与 `document` `visibilitychange` 监听；任一条件为不可见/关闭时立即停用并清场；恢复可见/开启时重置追踪状态并以 `isInitialBaseline = true` 静默对齐最新快照（不补播历史事件，仅即时同步当前仍在进行的吟唱环与阵盘）。
3. **详情组件联动与左上角开关 (`frontend/src/components/CombatArena.tsx` / `frontend/src/App.tsx` / CSS / i18n)**：

   - `ArenaActor` 与 `ArenaResource` 感知 `isEffectsActive = !hidden && documentVisible && vfxEnabled` 与 `isVisible = !hidden && documentVisible`：

     - 关闭特效时，跳过全部角色动作/受击/闪避动画与血条切片、禁用前摇等待，仅在 `.combat-arena-shell.is-vfx-disabled` 下展示简洁正常的伤害数字（与回血/闪避数字）。
