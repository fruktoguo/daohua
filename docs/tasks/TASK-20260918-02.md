## 需求分析

用户反馈两点：

1. 战斗中伤害跳字、技能释放动画、行动条三者时序不匹配。根因是推送节拍：领域事件已带精确时间戳，但统一在每秒一次 `AdvanceAllAsync` 中批量产生并推送——出手时刻 T 的事件要到 T+δ（0~1 秒）才到达，而行动条按绝对截止时间渲染是准的，于是伤害/结算永远晚半拍到一拍。
   - 用户期望：事件带时间戳、前端按时间渲染；行动条类"发送一次带完成时间、有变化才重复推送"。
   - 方案：边界驱动调度。战斗中下一次出手/相位边界完全可知，宿主服务在边界时刻醒来推进并推送，事件到达 ≈0 延迟，三者天然对齐；无边界时仍按 1 秒兜底。行动条已是截止时间驱动且快照为分段 diff（只推变更），满足"有变化才推"。
2. 敌方单位目前填满 1/2/3 号位（前排同列上中下），呈"上下排列"；改为纵深铺位"前后排列"（前排中 → 中排中 → 后排中）。

## 实现方案

### 领域层（纯函数，可测）

- `src/Domain/Simulation/SimulationSchedule.cs`：`NextVisibleBoundaryUtc(player, gameData)` 从聚合状态推导下一个用户可见事件的墙钟时刻：
  - 战斗相位：玩家/存活敌人最早 `nextAttackAt`、吟唱完成、技能冷却到点（战斗时钟 → `LastSimulatedAt` 墙钟映射）
  - 搜寻/复活相位：`LastSimulatedAt + phaseRemaining`
  - 斗法回放：下一剧本事件或终局
  - 斗法匹配等待（DuelPending）：无边界（撮合器每拍兜底）
  - 计时行动：`LastSimulatedAt + (duration - progress)`
  - 脱战技能冷却（AdvanceIdle 墙钟口径）、Buff 到期、自动使用冷却到点
  - 取全部候选的最小值；无候选返回 null

### 服务端运行时

- `PlayerActor`：每次 `ExecuteAsync` 成功后重算并缓存 `NextVisibleBoundaryUtc`（volatile ticks）。
- `PlayerRuntime`：`NextAdvanceBoundaryUtc` = 全部已加载 Actor 边界的最小值。
- `PlayerSimulationHostedService`：固定 1s `PeriodicTimer` 改为动态 `Task.Delay(clamp(min(boundary)-now, 50ms, 1s))`——边界时刻即醒即推；无边界 1 秒兜底，斗法撮合/暂存结算等每拍逻辑不受影响。

### 前端

- `CombatArena.tsx`：敌人占位按纵深序铺位 `[1, 4, 7, 2, 5, 8, 3, 6, 9]`（前中→中中→后中→前上→…），单敌仍 1 号前排中。
- 日志事件 `TimestampUnixMilliseconds` 已下发；边界推送后到达时刻≈发生时刻，跳字/动画/行动条自然同步，不新增协议字段。
