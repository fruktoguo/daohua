## 需求

用户裁定：境界成长乘区不应作为独立属性字段存在——行动速度本身就会缩减吟唱，不需要单独的「吟唱系数」；普攻增幅同理，不需要单独的「普攻倍率」。暴击伤害本身就是点数（默认自带 50 点 = 150% 暴伤）。要求把所有成长乘区折算为既有点数通道的「等级保送点数」，同步改动文档、代码实现与数据库（手动处理本地库）。

## 定稿方案（用户裁定）

**核心模型**：`CombatGrowthCurve` 不再产出独立乘区字段，改为按境界/等阶向既有点数通道注入「成长点数」，与装备/Buff 点数在同一池子相加、过同一条曲线。全部折算保持与旧因子曲线逐位等价，benchmark 期望表数值不变：

| 旧字段（删除） | 新口径 | 折算公式（x² = Progress 平方进度） |
| :--- | :--- | :--- |
| `CastTimeFactor` 吟唱系数 | 行动速度等级点 | `100·(1/(1−0.5x²)−1)`，满级 +100 点（读条 ×0.5） |
| `CooldownFactor` 冷却系数 | 冷却缩减等级点 | `100·(1/(1−0.75x²)−1)`，满级 +300 点（冷却 ×0.25） |
| `BasicAttackRatio` 普攻倍率 | 普攻增幅等级点 | `100·x²`，满级 +100 点（×2，Linear 精确等价） |
| `SkillIntensity` 技能强度 | 技能增幅等级点 | `30·(tier−1)`，满阶 +330 点（×4.3，精确等价） |
| `CriticalMultiplier` 暴击倍率 | 暴击伤害点数（新通道） | `50 + 350·x²`，基础 50 点 = 150%，满级 400 点 = ×5 |
| `SearchDelayFactor` 寻敌系数 | 复用行动速度点数 | 波间搜寻 ÷(1+行动速度/100)（装备点数同时生效） |

**普攻双除数保留**：普攻间隔 = 基准 1.0s ÷(1+攻击速度/100) ÷(1+行动速度/100)，等级向两个通道等量注入 → 等价旧 `(1−0.5x²)²`。

**乘位调整（语义变更，已确认）**：
- 普攻增幅点数移入原始伤害乘位：`rawDamage = AttackPower ×(1+普攻增幅/100)`（原后段增伤乘区删除，装备点数随成长同乘位、可穿甲）。
- 技能增幅点数并入技能威力基数：技能命中 `AttackPower = 攻基 ×(1+技能增幅/100) × 倍率 × 等级成长`；雷击符打击同源；治疗量同吃技能增幅（原仅吃技能强度）。
- 命中后段互斥分支（普攻/技能增幅取一）整体删除——普攻增幅在原始威力、技能增幅在威力基数，不再二次乘算。
- 暴击：`damage ×(1+暴击伤害点数/100)`。
- 寻敌时长改用行动速度总点数除数；组队规格 `SearchDelayFactor` → `SearchSpeedPoints`（全队取最大值=探路最快者带路）。
- 新增装备/怪物词缀键 `criticalDamageBonusPoints`（DataTool 词汇表同步）。

**面板**：删除「普攻倍率/技能强度/吟唱系数/冷却系数」整排；等级点数并入对应属性显示；暴击伤害按 `1+点数/100` 显示倍率。

**持久化与协议**：`CombatantStats` 仅经 `expedition.duel`（斗法回放镜像）落库——删 5 字段 + 增 `criticalDamagePoints`（缺省解码 50），走 v17→v18 标签迁移 + `PostgresSchema.Version` 同步 +1，手动对本地库执行迁移。
