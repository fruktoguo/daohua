### 3.2 发现的三类真实缺陷（非「仪式性」问题）

**① 门禁会「全绿但零执行」——最高优先级**

`dotnet test` 对以下两种情形均返回 0 且只打印空白：

- `--filter` 零匹配（实测：`--filter "FullyQualifiedName~ZZZNoSuchTest"` → rc=0，无任何输出行）；
- 测试宿主根本没启动。

实测触发条件：`obj/project.assets.json` 里的 `packageFolders` 指向 `/home/yuohira/.nuget/packages/`（WSL 路径）时，`dotnet test` 完全静默 rc=0；同一命令在 PowerShell 下 0 输出，`dotnet vstest` 直调则正常报 110 例。根因是 `NuGetPackageRoot` 在不同 shell 下解析不一致，`Microsoft.NET.Test.Sdk.props` 未被导入 → `IsTestProject` 为空。此时 `verify.sh` 的三套测试会「全部通过」而实际一个用例都没跑。

**② 45 个前端单测从未被任何门禁执行**

`frontend/src/**/*.test.mjs` 共 10 个文件 / 47 用例 / 1445 行，`frontend/package.json` 无 `test` script，`verify.sh` 无对应步骤，全仓无任何调用方。其中 2 个文件已漂移失败：

- `codexCalculations.test.mjs`：3 例失败——把材料总数钉死为 25 项、异材钉死 12 项，而配表现有 31 项材料 / 18 项异材。
- `realmCalculations.test.mjs`：整文件失败——直接 `import './combatConstants.ts'`，而该模块走 `import { getT } from '../i18n'` 目录导入，Node 原生 ESM 不支持（`ERR_UNSUPPORTED_DIR_IMPORT`）。

即：一套从未执行、且已静默腐烂的测试资产。

**③ 门禁守护已删除的故障面**

`OpsNetwork.IsPrivateOrLoopback`（`src/Server/Clean/Ops/OpsNetwork.cs`）零生产调用方——全仓仅命中定义处与 `OpsPanelTests` 的两条测试。`docs/backend/ops-panel.md:45` 明确记录「移除原仅限回环/私有网段 IP 的来源限制」。两条测试（含 12 行 `InlineData`）守护的是一个被有意移除的故障面。

## 4. 本轮实施（已执行）

1. **`scripts/verify.sh` 零测试硬闸**：新增 `run_suite()`，所有套件落 trx 并按 `<Counters executed>` 校验实际执行数，低于下限即 `exit 1`。下限只抓「近乎零」（Domain 300 / Ecs 80 / Server 300，`--fast` 180），不钉死具体用例数。该函数同时承担「`set -e` 下 grep 无匹配不中断」的 `|| true` 处理。
2. **`scripts/verify.sh` 构建拆分**：显式 `dotnet restore` + `dotnet build --no-restore`，消除隐式还原在解决方案级的逐项目重算抖动（实测同状态 9/15/33/47s → 稳定 restore 2s + build 5s）。

5. **修复 2 个腐烂前端测试**：
   - `codexCalculations.test.mjs`：把「总数/ID 清单硬钉」改为「分类规则不变量」——每项材料必须且只能落入一个子 Tab（互斥+完备）、子 Tab 归属与 `subCategory` 语义一致、`refinedMaterial` 的显式分流表必须覆盖全部精粹。

7. **删重复/错位门禁**：`bench-verify.sh` 删 `Ecs.Tests` 重跑（由 `verify.sh` 兜底）与 `15140` 端口守卫（该脚本不启服务，权威守卫在 `bench-service.sh` 的 `artifact_process_ids`）。
