## 2. 问题根因分析

1. **后端 `AdvanceAllAsync` 无条件切片与 `QuantizeElapsedSeconds` 整秒截断**：
   - `SimulationAdvanceHostedService` 虽然按所有玩家最早的 `NextAdvanceBoundary` 唤醒，但进入 `EcsPlayerRuntimeAdapter.AdvanceAllAsync(target)` 后，对所有已加载玩家无条件调用 `ecs.RunPlayerOnceAsync(playerId, target)`。
   - 只要宿主因 1s 保底节拍或其他玩家的战斗高频事件唤醒，所有正在读条的玩家都会被半途切片；`ActionExecutionRules.Pipeline.cs` 的 `CountTransition` 将进度推进一步视为状态变更（`e.Changed = true`），触发每秒/高频快照推送；且 `QuantizeElapsedSeconds` 将非整秒切片向下取整为整秒（余数存入 `SimulationCarrySeconds`），导致下发的 `progressSeconds` 比真实流逝时间滞后 `0~0.99s`。
2. **后端 `SimulationSchedule.NextVisibleBoundaryUtc` 边界计算缺口**：
   - 普通入队到空队列/暂停队列时新队首为 `Pending`，或刚入队的 `CombatEncounter`/`Travel` 尚未初始化 `Expedition`/`Travel`，未排 `0s` 立即唤醒边界。
   - 普通计时行动直接读取了静态 `definition.DurationSeconds`，未考虑强化耗时、技艺/建筑速度加成（`TimedActionDurationRules.Calculate`）与 `SimulationCarrySeconds`。
   - 战斗相位未纳入组队盟友出手/复活/技能边界；战外暂存区物品到期未纳入墙钟边界。
3. **后端 `ProtocolSnapshotMapper.ToActionQueueSection` 缺少 `completedRepeats`**：
   - 不切片模式下，无限循环（`remainingRepeats == -1`）或单项队列循环在单次边界推进内完成一轮并重置 `progressSeconds = 0` 时，若无 `completedRepeats` 字段，序列化后的 `action_queue` 分段与开局逐字节相同，会被 `BuildDelta` 过滤且前端无法识别换轮。
4. **前端非 `action_queue` 增量误重置 `lastQueueSyncPerformanceTime` 与动画频繁重建**：
   - `snapshot.ts` 在仅收到 `settings` 分段增量时也构造了 `patch.queue`，导致 `gameStore.ts` 将 `lastQueueSyncPerformanceTime` 重置为当前帧，而 `progressSeconds` 仍是旧值，进度条瞬间跳回。
   - `useSmoothProgress.ts` 和 `CombatArena.tsx` 在同一轮次内收到快照更新时频繁 `cancel()` 重建 Web Animations API 动画，且战场非战斗行动条在 `useMemo` 中混用 `Date.now()` 与无关依赖，造成视觉闪烁。

## 3. 实施方案

### 3.1 后端改造
1. **`src/Ecs/Engine/SimulationSchedule.cs`**：
   - 队首 `Status == ActionQueueStatus.Pending`（无论是否暂停）排 `0s` 立即唤醒激活为 `Running`。
   - 队首 `Expedition is null && Travel is null` 且 `ExecutionKind is CombatEncounter or Travel` 时排 `0s` 立即唤醒初始化。
   - 计时行动使用 `TimedActionDurationRules.Calculate(player, action, definition, gameData, assets: null)` 计算真实耗时，并结合 `SimulationCarrySeconds` 推导剩余秒数（首次未锁定强化等级返回 `0` 时排 `0s` 立即唤醒）。
   - 战斗相位纳入 `expedition.Allies` 存活盟友出手、倒地盟友复活与盟友技能边界。
   - 非斗法状态下纳入 `player.Duel.StagedItems` 最早到期时刻。
2. **`src/Server/EcsPlayerRuntimeAdapter.cs`**：
   - `RefreshNodeBuildingsAsync` 返回 `ValueTask<bool>` 标识建筑投影是否实质变更。
   - `AdvanceAllAsync` 中，对拥有活跃运行中队首行动（非 `DuelPending`）、无外部钱包/建筑投影变更、且 `target < NextAdvanceBoundary` 的玩家跳过半途切片，等其真正到达事件边界时一次性推进结算。
   - `ExecuteOwnedAsync` 的 `queue.configure` 分支在切换 `paused` 状态前，先推进结算当前已流逝时间，确保暂停/恢复边界精确无损。
3. **`src/Server/Clean/ProtocolSnapshotMapper.cs`**：
   - `ToActionQueueSection` 补充输出 `completedRepeats = action.CompletedRepeats`。

### 3.2 前端改造
1. **`frontend/src/game/types.ts`、`frontend/src/network/snapshot.ts`、`frontend/src/game/gameStore.ts`**：
   - `QueueEntry` 增加 `completedRepeats?: number` 并由 `mapQueue` 解析。
   - `PlayerPatch` 增加 `queueEntriesUpdated?: boolean`，仅当增量包含 `action_queue` 分段或 `queuePaused` 状态翻转时才更新 `lastQueueSyncPerformanceTime`。
2. **`frontend/src/game/useSmoothProgress.ts`**：
   - 纳入 `completedRepeats` 识别新轮次；同条目同轮次内若已在运行 WAAPI 动画且偏差在合理范围内，直接通过调整 `playbackRate` 或保持原动画平滑过渡，不再每次 `cancel()` 重建。
3. **`frontend/src/components/CombatArena.tsx`**：
   - `ArenaPhaseFill` 与 `ArenaPhaseState` 统一使用 `lastQueueSyncPerformanceTime` 动态计算搜寻/复活进度与剩余秒数。
   - 修复 `playerAction` 非战斗分支在 `useMemo` 中使用 `Date.now()` 及无关依赖导致的重置抖动。
