## 需求原文

「现在开始全部提交推送，然后把优化版本的ecs作为主要，然后业务逻辑换为ecs」「相当于整体就用优化版本的ecs作为核心架构了」

## 需求分析

- 优化版 YuoCore ECS 从"独立对照实验"晋升为**生产权威运行时**：`src/Server`（生产入口）直接装配优化内核宿主。
- OOP `PlayerRuntime`/`PlayerActor` 路径退役删除，业务命令全部迁移到 ECS 通道。
- `src/ServerEcs` 保留为 `ecs-current` 基线对照变体（差分/基准锚点），不再是生产路径。

## 实施总账

### 1. 生产宿主换血

- `src/Server/Server.csproj` 重写为 ECS-optimized 宿主壳：`YUOCORE_OPTIMIZED` 编译常量、`YuoCoreRoot=vendor/YuoCore-optimized`、链接 `src/ServerEcs/Program.cs` + `EcsPlayerRuntimeAdapter` + `src/Ecs` 项目引用。
- 删除 `src/Server/PlayerRuntime.cs`（OOP 宿主）、`src/Server/Program.cs`（OOP 装配）、`src/ServerEcsOptimized/`（临时壳项目退役）。
- `Game.slnx` 补登 `src/Ecs`、`src/ServerEcs`、`src/Server.Clean`、`tests/ServerEcs.Tests` 与 optimized 内核项目。

### 2. 业务命令全量迁移（OOP 18 命令 → ECS）

`EcsPlayerRuntimeAdapter` 补齐完整命令面：

| 类别 | 命令 |
| --- | --- |
| 行动 | `action.enqueue` / `action.remove` / `queue.configure` / `queue.move` / `queue.auto_use.configure` |
| 装配 | `loadout.replace`（经济事务 + 属性修订续写） |
| 功法 | `ability.learn`（分段事务 + 幂等键） |
| 成长 | `progression.breakthrough` |
| 世界 | `world.travel`（先推进后规划） |
| 建筑 | `building.build` / `building.upgrade` / `building.contribute` |
| 市场 | `market.place` / `market.cancel` / `market.claim`（走 `MarketRuntime`） |
| 物品 | `item.use` / `item.sell` 等钱包事务命令 |
| 玩家 | `player.rename` / `player.presence` |
| 模拟 | `simulation.advance`（内部推进） |

- 新增 `EcsWorldShard.MutatePlayer` 通用变更通道：组件状态 → `PlayerAggregate` 重建 → 领域操作 → `ApplyAggregateState` 回写 → 脏分段差集合并。
- 弃战路由 `RouteDuelForfeitAsync` 对齐 OOP `_pendingDuelForfeits` 语义；`accounts`/`marketRuntime` 依赖接入适配器构造。

### 3. 运行时语义对齐修复（本轮排查发现）

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 自然边界死循环（多人推进超 `MaxTransitionsPerAdvance`） | double 剩余预算残留亚 `DateTimeOffset` tick（~1e-7s）残差→`NextBoundaryAt` 量化回落同一时刻→零步长不动点 | `EcsActionPipeline`：`frameTarget>=NextBoundaryAt` 时按 `min(remaining,needed)` 直接消费（去掉量化差值二次限幅）；`CompleteClock` 对 `frameTarget>=windowEnd` 的 ≤1μs 残差归零 |
| 空闲玩家收到快照 delta | 推送条件未对齐 OOP `Simulation.Changed` | `AdvanceAllAsync` 仅 `simulation.Changed==true` 时推快照（日志仍按原语义） |
| `TouchedSections=null` | `HashSet` 差集漏记"已脏段再次触及" | `PlayerIdentityComponent.DirtyMarks` 按段流水号 + `TouchedSectionsSince` 差集（镜像 `PlayerAggregateState.DirtySectionMarks`，不回退） |
| `WireAttributesChanged` 恒 false | `MutatePlayer` 文档往返把 `VersionedList` 计数器重置为恢复基线 → `InputRevision` 恒定 | 修订号续写：`ApplyAggregateState` 直传聚合实例重载（跳过二次文档往返）+ `prev+(post−baseline)` 续写 `RestoreRevisionCounters`/`RestoreVersion`（`InternalsVisibleTo("DaoHua.Ecs")`）；适配器 `_attributeRevisions` 跟踪 |
