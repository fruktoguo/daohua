## 一、需求概述与已对齐口径

1. **彻底去除永久图床**：
   - 删除 `tools/cf-uploader/`（Cloudflare Worker + R2 永久图床）、`ChatImageUploadRegistry`、`CHAT_IMAGE_SECRET` 环境变量校验与 `/api/v1/chat/upload-ticket` / `/api/v1/chat/upload-confirm`（消除因旧内存哈希缓存与硬编码 `storage_id=2` 导致的重传死锁）；
   - 保留 `qqEmojis.ts` 内置 205 个经典动态表情既有逻辑；自定义表情包与聊天贴图统一走免登录开放 CORS 临时图床（`beeimg.cn/api/v2/upload`，动态探测 `api/v2/group` 可用游客 `storage_id` + 串行队列 + 超限/格式自适应 WebP 转码）。
2. **表情包上限 100 个与批量管理**：
   - 单角色最多收藏 `100` 个自定义表情包（前后端双端硬约束）；
   - 面板展示 `X/100` 容量计数并提供批量勾选删除（「管理 → 勾选/全选 → 删除所选」），达上限时显式提示不静默删旧；
   - `Ctrl+V` 粘贴图片保持自动加入表情包收藏（已满 100 时仍正常发图并提示未自动收藏）；面板点击表情包仅插入输入框草稿。
3. **本地强落盘与云端过期自动重传**：
   - 修复线上 Caddy CSP `connect-src` 拦截外部拉取与上传的问题；
   - IndexedDB 升级至 `v2`（新增 `blobs` store 按 `sha256` 主键去重保存原始二进制，保留 `images` store 按 URL 映射）；
   - 粘贴上传、选图上传、聊天右键「添加到表情包」、底部输入链接及多端同步入库，均强制将真实图片 `Blob` 写入本地 IndexedDB（浏览器 CORS 失败时降级经服务端无状态 SSRF 防护中继 `GET /api/v1/chat/sticker-fetch` 取回二进制，服务端不存图）；
   - 发送或点击已收藏表情包前精准探测云端 URL 存活性；若云端已过期且本地有 `Blob`，自动静默重新上传换取新直链、更新本地与云端同步状态并插入/发送新链；若云端过期且本机暂无缓存，标记 `needsReupload` 待持有原图缓存的其他端自动补传。
4. **多端同步（`social.player_stickers`，合流后顺延至 Schema v59 → v60）**：
   - 新增旁路表 `social.player_stickers`（含 `deleted_at` 墓碑列用于跨端离线删改 LWW 合并，30 天墓碑由 `PostgresRetentionWorker` 清理），不侵入 ECS 与玩家八分段；
   - 提供 `GET/POST/DELETE /api/v1/chat/stickers*` 鉴权接口，支持登录、重连、切回前台与打开表情面板自动同步，并按 `playerId` 隔离本地缓存。
   - 顺带修复 `LogFeed.tsx` 复读 `+1` 误把他人图片加入己方表情包的缺陷。
