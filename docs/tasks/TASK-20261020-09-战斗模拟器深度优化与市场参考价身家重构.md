## 1. 需求背景与核心目标

### 1.1 背景现状
1. **战斗模拟器交互与数据密集度低**：
   - 现存战斗模拟器配置面板数据密集度低，未合理利用 Tab，参战者编辑界面仅罗列了数十个零散属性输入框；技能、装备、消耗品槽位完全无法配置，无法模拟不同技能搭配、强化装备与自动吃药带来的真实战斗效果；
   - 地点选择为一个混合所有地图的长单选下拉，并带有冗余的「生态」选择器与「随机种子」输入框，既破坏了地图原生的怪物遭遇体系，又增加了认知负担；
   - 无法同时选择多个地图节点进行横向对比，玩家无法直观评估「去哪个地点挂机刷图收益最高、性价比最好」。
2. **市场参考价格与玩家身家口径缺失**：
   - 目前坊市缺乏统一的「市场参考价格」字段，玩家身家（`valuation`）此前简单采用卖一档（`BestAskPrice`），挂单被买空或无人挂单时价格剧烈失真或回落 0；
   - 模拟器掉落物收益无法折算为灵石价值，无法给出量化的每日收益期望。

### 1.2 核心业务需求
1. **市场单值滑动平均参考价与身家对齐**：
   - 数据库与市场模型增加「市场参考价格」（`reference_price`）；
   - 口径：按最近 10 次成交的平均价格，单笔成交购买多个视为一次（不按数量加权，以成交价格单价更新）；
   - 存储极致紧凑：只保留一个价格数值进行滑动平均更新（EMA 平滑，单浮点存储），严禁新建流水表或数组占用存储；
   - 无成交价时，回退到配表系统回收价格（`ItemDefinition.SellPrice`）；
   - 玩家身家（`PartyValuationService`）以及战斗模拟器收益折算统一按此参考价格计算。
2. **战斗模拟器参战人员多 Tab 详细配置**：
   - 参战者编辑拆分为多个独立 Tab：
     - 📊 **战斗属性 (Attributes)**：按基础生存、进攻输出、防御化解、五行伤害、特殊机制等模块化紧凑展示；
     - 📜 **功法技能 (Skills & Triggers)**：0 号内功心法 + 1~4 槽主动技能，支持选择技能、调节等级、配置触发器；
     - 🛡️ **穿戴装备 (Equipment)**：武器/头盔/胸甲/下装/鞋履/饰品 6 部位选择与 +0~+20 强化配置，属性实时叠加；
     - 🧪 **战斗消耗 (Consumables)**：3 药品 + 3 通用战斗消耗品槽位，支持配置绑定物品、数量与触发条件。
   - 支持一键导入自身完整装配（属性 + 技能 + 装备 + 消耗品）。
3. **地图选择与多节点多选对比**：
   - 地点选择重构为「区域 (Region)」与「节点 (Nodes)」二级联动；
   - 移除「生态」选择（采用地图节点本身的怪物生态体系）；
   - 移除「随机种子」输入（内部自动生成确定性种子）；
   - 支持**地图节点多选**，一次推演同时跑通多个选定地点。
4. **双组结果界面（简要对比 vs 详细剖析）**：
   - **简要信息对比**：直观横向对比多节点的刷图优劣，核心展示：
     - 每小时遇敌频次（Encounters/hr）、胜率（Win Rate %）；
     - 平均每天收益（Daily Revenue）：所有掉落物品按市场参考价计算的日产灵石总值；
     - 平均每天经验：修为经验（Daily Cultivation Exp）与六维经验（Daily Six-dimension Exp）；
   - **详细剖析**：支持单选节点深入查看：
     - 战况与妖兽击杀明细；
     - 伤害与承伤拆解；
     - 灵力缺口与 5 秒回复深度分析；
     - 战利品详细清单（包含每日掉落数量、市场参考单价、每日总值）；
     - 战斗实况流水日志。

## 2. 详细技术方案

### 2.1 数据库与后端身家模型
1. **Schema 升级（v38 -> v39）**：
   - `market.item_stats` 增加 `reference_price double precision NULL CHECK (reference_price IS NULL OR (reference_price > 0 AND reference_price = reference_price AND reference_price < 'Infinity'::double precision))`；
   - `PostgresSchema.Version = 39`，新增 `migrations/0039_v38_to_v39.sql`。
2. **成交维护参考价 (`PostgresMarketRepository.cs`)**：
   - 在挂单成交事务 `BumpItemStatsVolumeAsync` / `RefreshItemStatsBookAsync` 联动处，单笔成交以 `P` 更新：
     `reference_price = CASE WHEN market.item_stats.reference_price IS NULL THEN EXCLUDED.reference_price ELSE market.item_stats.reference_price * 0.9 + EXCLUDED.reference_price * 0.1 END`；
   - 一次购买多个算作一次，以成交单价更新，不加权数量；
   - `LoadItemStatsAsync` 读出 `reference_price`，映射至 `MarketItemStatsSnapshot` 与 `MarketItemStatsDto`。
3. **身家口径对齐 (`PartyValuationService.cs`)**：
   - `EquipmentUnitPrice` 与 `ItemUnitPrice` 改用 `TryGetReferencePrice` 优先，无成交价则回落配表回收价 `Math.Max(0, definition.SellPrice)`。

### 2.2 模拟器推演内核拓展 (`frontend/src/game/simulator/`)
1. **参战人员模型与属性解析**：
   - `SimulatorCombatantConfig` 新增 `equipment?: EquippedItem[]` 与 `consumables?: AutoUseSlot[]`；
   - 模拟开局按基础属性 + 装备基础属性 × (1 + 0.1 × 强化等级) 动态累加面板；
   - 消耗品在战斗循环中按血蓝阈值判定生效，补充生命/法力并记录恢复来源。
2. **修为与六维经验结算**：
   - 怪物阵亡时，基础经验结算为修为经验（受内功修为增幅加成）；
   - 按照 0 号槽内功的 `rootExpMultipliers` 乘率分配六维根基经验，无内功时六维各得全额；
   - 汇总每日（24小时）修为与六维经验产出。
3. **物品收益估值**：
   - 结合全局 `marketStats` 与 `catalog.items`，计算各掉落物品的市场参考价格 `getItemReferencePrice`；
   - 汇总每小时与每日灵石总产出。

### 2.3 前端界面与交互重构
1. `SimulatorPartyEditor.tsx`：参战者 4 大 Tab（战斗属性、功法技能、穿戴装备、战斗消耗品），支持高密度编辑与自身一键导入。
2. `SimulatorConfigPanel.tsx`：区域-节点二级联动，节点多选 Checkbox/Tag，移除生态与种子。
3. `SimulatorResultsView.tsx`：双组切换（简要对比表格 vs 节点详细剖析）。
4. `CombatSimulatorModal.tsx`：调度多节点批量推演与结果组织。
