# TASK-20261015-14 建筑建造状态右上角角标与加成展示体验优化

## 1. 任务背景与核心需求

用户在体验公共建筑系统时提出以下核心反馈与诉求：
1. **加成展示与状态困惑**：“我点击建造，显示还是待建造，但是，加成已经生效了”
   - **真实根因**：
     - 在 `frontend/src/game/buildingCalculations.ts` 中，`getBuildingSummaryBonusText` 在建筑未建成（`effectiveLevel <= 0`）时，硬编码生成前缀字符串 `待建: ${joined}`（例如 `待建: 吐纳修炼收益 +12%`）；
     - 在 `NearbyPanel.tsx` 建筑卡片中，该文案直接作为已生效加成放入了金色高亮样式容器 `<span className="building-card-bonus-tag">{bonusSummary}</span>`；
     - 玩家点击建造后，看到卡片上赫然写着“待建: ...”，误以为工程还未开工；同时看到高亮金色的“+12%”，又误以为加成已经生效。实际上后端规则中未建成建筑加成为 0（`EffectAtLevel(0) == Empty`），两者产生了严重的视觉和认知冲突。
2. **状态不明显**：“当前的建造者（建造中）和升级中，不是很明显，这两个状态显示在建筑item的右上角角标吧”
   - **真实根因**：
     - 当前建筑卡片左侧是 42x42px 的静态“建”字标记，右上角无任何角标；
     - 建造中仅在卡片名字旁以一个灰暗小 badge 显示；升级中（`level > 0 && targetLevel > 0`）时甚至完全不显示文字（只显示当前 `Lv.1`），仅底部有细进度条，极难辨识。
3. **潜在问题排查**：“然后检查一下建造是否有什么潜在问题”
   - **排查发现的潜在问题**：
     - **潜在问题 A（后端重大推送隐患）**：在 `EcsWorldShard.ApplyNodeBuildingProjection` 中，当公共节点建筑投影发生实质变更（`!same`，如有玩家提交材料、到期完工或等级跳变）时，仅调用了 `identity.MarkDirty(PlayerSectionKind.World)`，但未推进 `identity.StateVersion`。在主服定时推进循环 `AdvanceOnlinePlayersAsync` 中，若在线挂机玩家当前行动队列为空，因 `after.StateVersion == before.StateVersion && after.LastSimulatedAt == before.LastSimulatedAt`，该次投影更新直接被跳过，既不刷盘也不向客户端推送 WebSocket 快照，导致空闲玩家界面无法实时感知建筑完工与进度变更。
     - **潜在问题 B（前端材料引导缺失）**：建筑发起建造后仅生成地基，进度为 0%，卡片未明确提示“需提交材料”，新玩家往往误以为点击建造即会自动施工，不知道还需点入卡片提交材料。

## 2. 解决方案与技术设计

1. **消除加成误导与重构摘要展示**：
   - `getBuildingSummaryBonusText` 文案规范化：未建成时（`effectiveLevel <= 0`）明确标明为建成后预告，如 `建成生效: 吐纳修炼收益 +12%`，杜绝歧义的“待建”前缀；
   - 建筑卡片样式分层：当 `building.level > 0` 时维持金色生效加成标签；当 `building.level === 0` 时改用未生效样式 `.building-card-bonus-tag.is-pending`（柔和次级文字色，不再金色高亮），并提示材料提交状态。
2. **建筑卡片右上角角标（Corner Badge）**：
   - 在 `.nearby-card` 确保相对定位与层级；
   - 增加专用的右上角胶囊角标 `.building-corner-badge`：
     - 【建造中】（`level === 0 && targetLevel > 0`）：琥珀金色调微光胶囊，文字为「建造中」；
     - 【升级中】（`level > 0 && targetLevel > 0`）：灵气紫色调微光胶囊，文字为「升级中」；
     - 标题区域同步精简，避免重复冗余。
3. **修复后端建筑投影版本推进与推送**：
   - 在 `EcsWorldShard.ApplyNodeBuildingProjection` 发生实质变更时，同步递增 `identity.StateVersion`，确保空闲玩家亦能触发网络快照推送与持久化。
4. **测试与文档**：
   - 更新前端单测 `buildingCalculations.test.mjs`；
   - 更新前端公共组件文档 `docs/frontend/common-components.md`；
   - 运行完整门禁验证。
