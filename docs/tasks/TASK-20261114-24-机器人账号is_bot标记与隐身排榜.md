- **需求理解**：
  - 在 `identity.accounts` 新增 `is_bot boolean NOT NULL DEFAULT false` 显式标记，常规玩家注册/登录默认保持 `false` 无需人工干预。
  - 通过 `DaoHua-MarketBots` 创建及存量 `bot_%` 前缀账号统一标记为 `is_bot = true`。
  - 被标记为 `is_bot = true` 的账号在运行时仍可正常登录、连接 WebSocket、挂单撮合与推进行动，但**不出现在附近玩家列表中**（且不向同节点真实修士推送存在感刷新），也**不计入全服 12 张排行榜**（个人榜、名次库表 `leaderboard_ranks` 与宗门榜人数统计均排除 `is_bot = true`，全机器人宗门不入榜）。

## 技术方案

1. **数据库 Schema（v54 → v55，存档载荷标签保持 v43）**
   - `PostgresSchema.cs`：`Version` 升至 `55`，`identity.accounts` 表末尾新增 `is_bot boolean NOT NULL DEFAULT false`。
   - `migrations/0055_v54_to_v55.sql`：幂等 `ALTER TABLE identity.accounts ADD COLUMN IF NOT EXISTS is_bot boolean NOT NULL DEFAULT false;`，对既有 `login_normalized LIKE 'bot\_%' ESCAPE '\'` 的机器人账号批量打标 `is_bot = true`，并登记 `platform.schema_version = 55`。
   - `PostgresTestSchema.cs`：补充 `ADD COLUMN IF NOT EXISTS is_bot boolean NOT NULL DEFAULT false` 补丁，兼容既有测试库。
2. **认证、会话声明与附近玩家屏蔽**
   - `PostgresAccountRepository.cs`：`SessionIdentity` 增加 `bool IsBot = false`，`ValidateSessionAsync` 查询并返回 `a.is_bot`。
   - `SessionAuthentication.cs`：会话鉴权注入 `is_bot` Claim。
   - `WebSocketRuntime.cs`：握手登记存在感时将 `is_bot` 传入 `OnlinePresenceRegistry.RegisterAsync`。
   - `OnlinePresenceRegistry.cs`：`Entry` 增加 `bool IsBot`，`isBot == true` 不入节点倒排索引 `_nodeIndex` 且在 `SnapshotAtNode` 二次过滤；机器人进出与换节点只通知其自身 `OnlineChanged`/`NodeChanged`，不触发同节点真实修士 `PresenceChanged` 广播。保持 `IsOnline`/`GetNodeId`/`SnapshotOnlinePlayerIds`/`OnlineCount` 正常可用。
3. **排行榜屏蔽**
   - `LeaderboardRuntime.cs`：
     - `LoadBasePlayersAsync` 关联 `identity.accounts` 并追加过滤条件 `NOT a.is_bot`，使全部 11 张个人榜及 `game.leaderboard_ranks` 自动排除机器人。
     - `LoadZongmensAsync` 统计宗门成员时关联 `identity.players` 与 `identity.accounts` 并过滤 `i.status = 1 AND NOT a.is_bot`，确保机器人不虚增宗门人数、全机器人宗门因有效人数为 0 自动排除。
4. **市场机器人配套脚本**
   - 兄弟仓库 `../DaoHua-MarketBots` 中的 `tools/initNewServer30Bots.mjs` 与 `tools/provisionViaSsh.mjs` 在 `INSERT INTO identity.accounts` 中显式写入 `is_bot = true`，且冲突更新子句同步置 `is_bot = true`。
