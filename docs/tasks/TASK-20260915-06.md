即：行动收益 = 每个行动自行声明的收益列表，支持修为（Qi）、灵力（Mana）、生命（Hitpoints）、历练经验、物品、Buff，可按秒或按完成轮次结算。

## 方案

### 配表与协议形态（yields）

```json
"yields": [
  { "kind": "qi", "per": "second", "amount": 1 },
  { "kind": "experience", "per": "repeat", "amount": 10 },
  { "kind": "mana", "per": "second", "amount": 0.5 },
  { "kind": "hitpoints", "per": "repeat", "amount": 5 },
  { "kind": "item", "per": "repeat", "id": "item.x", "amount": 3 },
  { "kind": "buff", "per": "repeat", "id": "buff.x", "name": "凝神",
    "durationSeconds": 60, "modifiers": { "hpRegen": 2 } }
]
```

- `kind`：`qi | mana | hitpoints | experience | item | buff`
- `per`：`second`（持续速率）| `repeat`（单轮完成结算）
- `item`/`buff` 仅允许 `per: "repeat"`；`item` 需合法 `id`；`buff` 需 `id`+`name`+`durationSeconds>0`+可选 `modifiers`（hpRegen/mpRegen/attackSpeedRatio/damageAbsorptionRatio）
- 资源类收益禁止携带 `id`/`name`/`durationSeconds`/`modifiers`
- 旧字段 `qiPerSecond` / `experiencePerRepeat` / `outputs` 直接废弃，一次性迁移全部配表（本地开发清零原则）

### 领域改动

- `src/Domain/GameData/GameDataCatalog.cs`：新增 `ActionYieldKind`/`ActionYieldPeriod`/`ActionYield`/`BuffGrantSpec`；`ActionDefinition` 以 `Yields` 替代 `Outputs`/`QiPerSecond`/`ExperiencePerRepeat`；`ParseActions` 解析并校验；`ActionCatalog.Default` 同步。
- `src/Domain/Simulation/SimulationEngine.cs`：
  - `ApplyContinuousReward` 改为遍历 `per=second` 收益：Qi 逐秒累加进 `Progression.Qi/LifetimeQi`（保持浮点位级一致）；Mana/Hitpoints 逐秒累加并 clamp 到 `PlayerAttributeResolver` 解算上限（仅存在该类收益时才解算属性，避免热路径开销）；经验允许每秒形态。
  - `CompleteRepeat` 遍历 `per=repeat` 收益：物品→`AddDelta`；修为→Qi/LifetimeQi；灵力/生命→clamp 到上限；经验→Progression.Experience；Buff→`Buffs.Active` 授权（同 BuffId 刷新到期并叠加层数）。
  - `autoUseMultiplier` 作用于数值型收益（qi/mana/hitpoints/experience/item），Buff 授权不乘。
  - `action.completed` 事件 `ItemDeltas` 由 item 类收益聚合。
