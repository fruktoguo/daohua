## 2. 需求背景与核心目标

### 2.1 需求背景
原 i18n 体系中，中英文均以 `.ts` 脚本（`*.zh.ts` 与 `*.en.ts`）形式存放于 `frontend/src/i18n/domains/` 并全量静态打包入前端主 bundle 中。随着游戏内容拓展，存在以下痛点：
1. **多语言维护门槛**：非技术人员或社区翻译人员若需修改/扩展语言包，必须熟悉 TypeScript 语法并重新编译整个前端工程；
2. **打包体积增长**：新增更多语言（日文、韩文等）会导致首屏 JS Bundle 体积线性膨胀；
3. **开发者对照体验优化**：开发者需要中文直接在代码与 TS 对象中维护以享受 100% 静态类型安全、路径推导与自动补全，而其他语言包更适合作为静态资源（CSV）解耦并动态按需加载。

### 2.2 核心改造目标
1. **中文作为唯一类型基准与内置源**：保留 `frontend/src/i18n/domains/*.zh.ts` 与 `locales/zh-CN.ts`，作为 `Messages` 与 `TranslationKey` 编译期强类型推导基准，零延迟首屏内置；
2. **外语语言包全量转为 CSV 静态资源**：将现有英文词典导出并收拢为 `frontend/public/locales/en-US.csv`，移除冗余的 `*.en.ts` 脚本文件；
3. **运行时按需异步拉取与内存缓存**：在 `frontend/src/i18n/index.ts` 中实现零依赖轻量 RFC 4180 CSV 解析器，切换语言时异步 fetch 并缓存，未命中或加载中无缝回退至中文树状词典；
4. **提供一键导出与同步工具**：提供自动化脚本，支持从中文 TS 结构提取全量词条并导出为 CSV 模板或校验差异；
5. **规范与文档同步**：同步更新 `docs/frontend/common-components.md` 中的 i18n 规范。
