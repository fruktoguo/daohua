## 需求分析

用户反馈战斗「详情」页（combat 页签战场九宫格）中只能点击自己查看属性，队友（盟友阵列其他成员）点击无反应。排查发现 `UnitInspectDto.Side` 协议契约早已预留 `ally` 观察侧（「预留队友」），但服务端 `ProtocolSnapshotMapper` 只对 `enemy` 下标投影属性面板、前端非本机盟友 `ArenaActor` 未接 `onInspect`——协议预留能力未落地。

## 设计边界

1. 复用既有 UnitInspect 按需一次性交付链路：登记武装 → 下一帧快照投影一次 → 自动解除，丢帧保留武装重投。
2. 盟友属性数据源为 `ActionParticipantSnapshot.Stats`（开打冻结面板，共享剧本唯一公共输入），走 `ToAttributesDto(CombatantStats)` 统一投影重载，与敌怪/斗法镜像同一 wire 形状。
3. 本机位成员仍走 `'player'` 本地详情（combat.attributes 常驻下发），不经 ally 观察通道。
4. 前端 `inspectedActor` 扩展 `ally:{memberIndex}` 形态，身份缓存键为 `ally:{playerId}`。
5. 不新增协议类型、不改快照分段结构、不留兼容分支。
