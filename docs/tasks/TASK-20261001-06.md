# TASK-20261001-06 命令回执浮动提示差异化与气泡丝滑化

## 需求

- 提出时间：2026-10-01 17:37:51
- 用户反馈：右下角总是弹「命令已提交」，不明所以且干扰；希望改成更流畅丝滑的指令反馈，不同指令应有各自合适的提示文本。

## 现状问题（代码分析）

- 右下角气泡是全局 `Notice` 组件（`App.tsx`，`.notice` 定位 `right:24px bottom:24px`）。
- 内容来源：服务端 `EcsPlayerRuntimeAdapter.ExecuteOwnedAsync` 对**每一条成功命令**统一回 `PlayerCommandResult(true, "OK", "命令已提交。")`；前端 `gameClient.ts` 对 `CommandResult` 回执 `if (result.message) setNotice(...)` 无条件弹泡。
- 后果：队列开关、行动排序、装备穿戴、行动入队等高频自证操作每点必弹；且服务端通用回执会覆盖前端发送时已弹的市场方向专属提示（`market.notice.buySubmitted` 等）。
- 附带小毛病：同文案连续提示时 zustand 状态值不变，`Notice` 计时不重置，第二条可能提前消失、无重播动画。

## 方案

- 服务端：成功回执文案按命令差异化（`SuccessNotice` 静态映射）；高频或界面已自证的操作（行动入队/移除/排序、队列与自动使用配置、装备替换、`market.place`/`market.cancel` 前端已即时提示、`simulation.advance`/`player.presence` 内部指令）返回空串静默——前端空串天然不弹泡。失败路径不变，仍走具体错误文案。
- 前端：
  - `.notice` 加入场动效（淡入 + 上移，`transform/opacity` 走合成器，符合零重绘约定）；
  - `gameStore` 增加 `noticeSeq` 计数，`setNotice(非空)` 递增；`Notice` 订阅序号并把 `key` 绑到气泡节点——同文案重复提示重新计时并重播动画。
