## 需求分析

1. **现状与矛盾**：
   - 当前「甘露」（`ability.ganlu`）被视作支援类 Buff 技能（走 `hpRegenPerSecond: 1.0` 通道），未配置直接治疗效果。
   - 原层数计算公式仅由法攻百分比与技能增幅放大：
     $$\text{extraStacks} = \text{SpellAttack} \times 8\% \times \text{levelGrowth} \times \left(1 + \frac{\text{SkillBonusPoints}}{100}\right)$$
     $$\text{Stacks} = 1 + \left\lfloor \text{extraStacks} + 10^{-9} \right\rfloor$$
   - 导致即使装备了提供治疗提升/治疗增幅的副手（如「甘露瓶」`equipment.ganlu-flask` +5 点、「回春铃」`equipment.huichun-bell` +6 点）或木灵根，甘露层数与跳血数值完全无法获得任何增益，严重违背认知直觉。

2. **新口径规则**：
   - 甘露施加的「甘露」Buff（`buff.ganlu`）层数派生引入施法者实时「治疗增幅」（`HealingBonusPoints`）作为独立乘区放大。
   - 放大对象为甘露总基础层数（基础 1 层 + 术法攻击派生层数）：
     $$\text{healingMultiplier} = \text{PercentValue.Multiplier}(\text{caster.EffectiveStats.Effects.HealingBonusPoints}, \text{PercentCurveMode.Linear})$$
     $$\text{baseStacks} = 1 + \max(0, \text{SpellAttack}) \times 8\% \times \text{levelGrowth} \times \left(1 + \frac{\text{SkillBonusPoints}}{100}\right)$$
     $$\text{totalStacks} = \text{baseStacks} \times \text{healingMultiplier}$$
   - **取整规则**：严格遵循技能设计本身的**向下取整（`Math.Floor`）**，保底 1 层：
     $$\text{finalStacks} = \max\left(1, \left\lfloor \text{totalStacks} + 10^{-9} \right\rfloor\right)$$
   - **数值示例**：
     - 100 AP、1 级（成长 1.0）、0 技能增幅、50 治疗增幅（+50%）：
       $(1 + 100 \times 8\%) \times 150\% = (1 + 8) \times 1.5 = 13.5$，向下取整为 **13 层**。
     - 0 治疗增幅时：$(1 + \text{extraStacks}) \times 1.0 = 1 + \text{extraStacks}$，向下取整与原逻辑严格向后等价。
