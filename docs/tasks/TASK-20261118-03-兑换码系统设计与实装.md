## 核心需求与设计决策对齐

经与用户交互确认，敲定四项核心设计边界：
1. **兑换码双模式支持**：
   - **通用口令码（`universal`）**：自定义固定口令（如 `DAOHUA666`），支持过期时间/永不过期、全服限量/不限量，每名玩家限兑 1 次；
   - **批次单次码（`single_use`）**：批量生成（`1~5000` 个，可选前缀，32 字符无歧义字母表剔除 `0/O/1/I`），一码一用，同批次每名玩家限兑 1 次。
2. **奖励发放路径**：直接入账 `economy.player_asset_balances`（记入第 ⑤ 类白名单流水 `ops.redeem` 保留 30 天，玩家批次防重表 `economy.player_redeem_claims` 永久保留），在线实时 `ReloadWalletAndNotifyAsync` 热刷新背包，并在界面用 `<ItemTile>` 图标化展示所获奖励（支持货币、绑定功德、材料消耗品及指定强化等级 `+0..+20` 装备）。
3. **玩家前端入口**：内嵌在 `SettingsPage` 的「设置 → 账号」分组卡片内（不新增设置子页签）。
4. **运营管理闭环**：接入 `/ops` 运维网页（新增「系统 → 兑换码」视图）+ `/ops/api` 接口 + `scripts/dev-tui.mjs` `:redeem` 快捷指令，支持建码、批量导出、查看核销进度与停用/恢复。
