## 一、需求概述与根因诊断

### 用户原始诉求
1. 现有邮件界面视觉粗糙且格式严重错乱（截图可见 `仙 / 门 / 传 / 书` 纵向单字叠排、头部异常拉高、空状态左右嵌套双虚线框及大量无效留白）；
2. 将邮件中心由「替换 `.main-content` 主视区」改为「基于公共 `Modal` 的独立弹窗」；
3. 兼顾横屏（桌面 / 手机横屏）与竖屏（窄屏手机）可用性；
4. 显著提升空间利用率与信息密度。

### 根因剖析
1. **格式炸裂**：旧 `MailPage.tsx` 头部 `<Icon name="mail" />` 未传显式 `size`，且 `.mail-title` 未限定 `svg` 尺寸，导致 SVG 在 Flex 行内纵向拉伸并将标题文字挤压为 1 字宽竖排。
2. **布局浪费与空态套娃**：原页头占用三行垂直高度（「返回修行」+ 标题 + 冗长副标题 + 独立筛选栏）；0 封邮件时仍强制渲染左右两栏，左侧虚线框 + 右侧外实框套内虚线框；附件卡片采用纵排大卡片占高过高。
3. **未拉取详情自动选中瑕疵**：`mailStore.ts` 在刷新/筛选/删信后回退选中 `visible[0]?.mailKey`，但未（也不应在未点选前）请求详情把未读标记为已读，导致右侧出现裸「加载正文详情」按钮。

## 二、技术方案与边界

1. **文档先导对齐**：
   - 更新 [`docs/design/总纲/27-邮件系统与双轨存储规约.md`](../design/总纲/27-邮件系统与双轨存储规约.md) §5、[`docs/design/总纲/19-名词术语对照表.md`](../design/总纲/19-名词术语对照表.md) §19.11 与 [`docs/frontend/common-components.md`](../frontend/common-components.md) §42，将 `MailPage` 整页替换方案修正为 `MailModal` 独立响应式弹窗方案（后端零改动）。
2. **`mailStore` 选中语义收敛**：
   - 取消 `setFilter` / `refreshList` / `deleteOneMail` / `deleteAllReadMails` 自动回退选中 `visible[0]` 的逻辑：仅保留仍在可见集中的已选 `mailKey`，否则置 `null`，杜绝未经点选静默标已读及未拉正文态。
3. **`MailModal` 独立弹窗（复用 `Modal` + `ConfirmDialog`）**：
   - 挂载于 `App.tsx` 顶层弹窗层（紧邻 `HelpModal`），保留底层 `.main-content`、桌面 `Sidebar` 与移动端 `BottomNav` 原有页签与高亮状态不中断；
   - **紧凑顶栏**：去冗余返回键与副标题，将标题徽标、总封数、分段筛选（全部 / 未读徽标 / 可领附件徽标）与批量操作（一键领取 / 删除已读 / 刷新图标钮）收敛至紧凑单行（竖屏双行），并预留右上 `.modal-close` 避让；
   - **全屏统一空态**：加载中或可见列表为 0 封时，渲染整幅居中 `.mail-unified-empty`（筛选为空时附带一键「查看全部传书」），彻底消灭双虚线框套娃；
   - **双端布局**：
     - 桌面/横屏（及矮横屏 `@media (orientation: landscape) and (max-height: 540px)`）：`min(920px, calc(100vw - 28px)) × min(620px, calc(100dvh - 28px))` 锁死外框，左栏紧凑 2 行列表卡片（`292px`，矮横屏 `248px`）+ 右栏正文与紧凑横向 `40×40px` 附件卡独立滚动；
     - 竖屏窄屏：占满可用视口 `calc(100vw - 14px) × min(780px, calc(100dvh - 18px))`，单栏满高列表 ↔ 详情钻取（详情顶部展示 `← 返回列表` 与有效期胶囊，底栏等分触控操作钮）；
   - **图标与暗亮双主题硬防护**：全部 `<Icon>` 显式传入 `size` 且 CSS 锁定 `svg` 尺寸与 `flex-shrink: 0`；完整支持暗墨玄石与 `[data-theme="light"]` 宣纸朱印主题。
