## 需求分析

用户对顶部主行动栏（`QueueCenter` → 当前行动卡）提出两点优化：

1. **进度文本与进度条对比度不足**：`.progress-text` 直接叠在填充渐变上，填充后段为亮金（`#c9b46d → #e8d69a`）加亮色端头，浅色文字（`--text: #e9e3d2`）压在亮金填充上时对比度明显下降。
2. **战斗状态敌我血条布局**：当前 `.queue-combat-vital` 为「16px 标签列 + 中间细条 + 右侧文字」三段网格；用户希望改为**两条完整进度条、文字内嵌条内居中**，与主行动栏其他进度文本（`.progress-text` 条内居中）保持一致，**并保留原血条的斜切倾斜轮廓**。

## 方案取舍：描边 vs 背景光晕

**结论：选暗色描边（多层 text-shadow），不加光晕。**

- 填充渐变后段为亮金，若加亮色光晕会进一步降低对比度；若加暗色柔晕，在 14px 高的条内会糊成一团，10px 小字号下发虚。
- 暗色描边在「暗轨底」与「亮金填充」两种背景上都保证文字边缘分离度，是游戏 UI 进度条文字的标准做法；纯 text-shadow 实现，零 DOM 增量、零布局改动。
- 实现为 8 方向 1px 暗色描边 + 保留原柔影加深，`.progress-text` 与新的战斗血条内嵌文字共用同一描边参数。

## 战斗血条改造方案

- JSX（`App.tsx` `CombatActionProgress`）：删除独立标签 `<span>` 列，`己`/`敌` 标签与数值分别包一层 span 成为条内文字的两个 flex 项（`己 1.2万/2.3万（52%）`），`<strong>` 绝对定位条内居中；`<i><b/></i>` 填充结构保留（CSS transition 平滑，无 WAAPI 依赖）。
- CSS（`styles.css`）：`.queue-combat-vital` 改为 14px 高完整条（与 `.progress` 同高），暗底 + 内阴影托底；**保留原斜切平行四边形轮廓**（`clip-path` 8px 斜切 ≈ 原 10px 高 6px 斜切的同角度放大），斜切轮廓下不加深色边框（边框会被 clip 裁出断线），与原血条的无边框斜切观感一致；保留敌我绿/红填充梯度。
- 条内文字容器用 **flex 而非 grid**：血条文字内含多个子节点（标签/数值/百分比），grid 会把每个子节点竖着堆成独立网格项、条内只露出第一个字（首版实测踩坑）；flex 沿主轴横排居中才符合条内单行语义。
- 移动端（≤520px 竖屏）：血条上下两行改为两条 12px 高条（12+2+12=26px 恰好填满 `.queue-combat-state`），文字 9px，删除原 7px 缩字规则。
