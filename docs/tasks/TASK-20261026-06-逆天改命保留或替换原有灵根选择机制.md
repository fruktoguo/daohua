# TASK-20261026-06 逆天改命保留或替换原有灵根选择机制与实时完整加成展示

## 任务背景与目标

1. **用户核心需求**：
   - **痛点一（机制层面）**：当前逻辑下，玩家已叩入天门后再次开天门（逆天改命），服务端直接将抽取的随机新灵根覆盖了玩家当前生效的灵根（`ConfirmedValues` 直接被改写），导致无法反悔，洗出更差的灵根会直接劣化角色属性与破境乘区。
   - **痛点二（展示层面）**：阵盘调配时只显示纯灵根点数数值，玩家无法直观感知当前五行点数调配所带来的全部具体战斗/百艺收益。
   - **用户决策与需求定案**：
     1. **采纳方案 B（调配后替换）**：改命抽出新灵根后，依然允许玩家在阵盘中拖拽微调（散功 2 返 1、灌注 1:1），调整满意后再点击【替换】，或者不满意点击【保留原灵根】放弃本次改命。
     2. **加成实时联动全显**：根据当前的灵根调配，界面能够**直接显示完整的全部加成**（元素攻防增免伤、战斗专精特化、修仙百艺速度增幅、破境修为乘区与境界资质评价），而非仅显示灵根点数数字，拖拽即时响应。

2. **核心业务逻辑预期**：
   - **消耗与计数**：改命抽取（Reroll）时即时扣除对应底蕴或逆命丹，并永久累加改命次数 `HeavenGateRerollCount + 1`（推动后续抽取的期望总值继续提升至 500）。
   - **已生效灵根不立即改变**：改命生成新灵根后，原已生效的灵根（`ConfirmedValues`）保持生效，角色的属性加成、百艺速度加成与本层破镜乘区在裁决前完全不受影响。
   - **双灵根待决议状态**：
     - 原有灵根：当前生效灵根；
     - 候选灵根：本次逆天改命新生成的五行灵根分布（支持在阵盘中散功 2 返 1、灌注 1:1 进行重分配）。
   - **玩家裁决操作**：
     - **【替换灵根】**：确认采纳本次微调后的灵根分布，将其正式确立为当前生效灵根，覆盖原灵根；
     - **【保留原灵根】**：放弃本次改命产物，继续保留原灵根不变，清除本次候选灵根（消耗的底蕴与改命次数正常沉淀）。
   - **离线与断线稳态**：若玩家抽取后未做选择即断线或刷新，服务端快照保留候选状态，重连后依然显示待裁决对比，绝不丢失状态或意外生效。

## 方案设计与技术路径

   - 实施完成时间：2026-10-26 13:42:00
   - 当前状态：✅ 已完成
   - 负责机制：单主 Agent 独立闭环完成
    - `RolledValues`（抽取原生分布）
    - `ConfirmedValues`（当前生效分布）
    - `Entered`（是否已入天门）
    - `RerollCount`（累计改命次数）
  - 语义扩展：
    - 在已入天门状态下（`Entered == true`）：
      - 当 `RolledValues == null` 或 `RolledValues == ConfirmedValues` 时，表示当前无待决议的新灵根；
      - 当 `RolledValues != null` 且 `RolledValues != ConfirmedValues` 时，表示当前存在已改命但待裁决的候选灵根！
- 指令协议扩展（`progression.heaven_gate`）：
  - `reroll`：执行改命，扣除底蕴/逆命丹，`RerollCount + 1`，将抽取结果写入候选池（`RolledValues`），此时**不改写 `ConfirmedValues`**。
  - `accept`：玩家确认采纳候选灵根（支持携带客户端调配后的五行点数，经合法性校验），将其覆写至 `ConfirmedValues`，清除候选池。
  - `discard`：玩家放弃候选灵根，将 `RolledValues` 重置为 `ConfirmedValues`，保持 `ConfirmedValues` 不变。

### 2. 服务端适配与不变量保障 (`src/Server/EcsPlayerRuntimeAdapter.cs`)
- 改命分支（`case "reroll"`）：
  - 若 `alreadyEntered` 为 true：
    - 扣减底蕴 / 扣减逆命丹；
    - `nextRerollCount` 自增；
    - 抽取 `rerolledValues`；
    - 执行 `gate.Apply(rolled: rerolledValues, confirmed: gate.ConfirmedValues, entered: true, nextRerollCount)`；
    - 原生效灵根 `ConfirmedValues` 保持不变，面板属性不发生突变。
- 新增裁决分支：
  - `case "accept"`：若当前已入天门且存在待裁决候选灵根，读取载荷中调配后的灵根点数（若未传则直接用抽取原生点数），经 `IsValidAllocation` 校验合法后写入 `ConfirmedValues`，并将 `RolledValues` 对齐，触碰 `Progression` 脏标记。
  - `case "discard"`：若当前已入天门且存在待裁决候选灵根，将 `RolledValues` 重置为 `ConfirmedValues`，触碰 `Progression` 脏标记。
