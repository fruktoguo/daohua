# TASK-20260930-07 行动队列循环悬浮说明 + 「自动移动」开关

## 需求

- 提出时间：2026-09-30 18:18:56
- 用户反馈：行动列表右侧的「循环」开关 hover 无提示；新增「自动移动」开关——行动开始时若入队记录地点与当前地点不一致，自动移动到目标地点再开始行动，而非走地点不符直接跳过的逻辑。

## 方案

- **循环提示**：`QueueCenter` 循环 checkbox 用 `FloatingTooltip`（`displayContents`，不破坏布局）包裹，文案说明「所有行动执行完会重新加入行动列表，持续循环执行」。
- **入队锚点**：`ActionIntent` 新增 `AnchorNodeId`——`PlayerAggregate.Enqueue` 入队时记录驻留节点（`World.EdgeId is null ? World.NodeId : null`，旅途中不登记），恢复/导出/ECS 往返全链保留。
- **设置开关**：`PlayerSettingsState.AutoTravelEnabled`（默认 false），`PlayerSettingsStateDocument`/`SettingsDocument`/wire settings/`queue.configure` 全链扩展；分段编解码 schema v4→v5。
- **自动移动准入**：`SimulationEngine.TryStartActionCore` 地点不符分支新增 `TryEnqueueAutoTravel`——开启开关、锚点仍在 `AllowedNodeIds`、`world.travel` 存在且世界图可达时，按 `PlanFromPosition` 插队一条 `world.travel` 至队首并挂起原行动（复用 `EnqueuePriority` 同语义），产出 `action.auto-travel` 事件；任一前置不满足回落原 `action.blocked` 语义。
- **插队通道**：`IPlayerActionContext.EnqueuePriority` 接口化（`PlayerAggregate` 显式委托、`EcsPlayerActionContext` 组件直写实现），`incrementVersion: false` 供模拟内部使用保持「一次推进一次版本提交」。
