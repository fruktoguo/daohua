## 3. 关键发现

### 3.1 现状已暴露的真实缺陷（方案方向正确，修复点不同）

- **陈旧会话误杀重连**：玩家刷新页面时，旧 socket 拆除与新连接到达存在竞态。当前「拒绝新连接」语义下，新连接会吃到 `1008` → 前端按 authFailure 永久停连显示「会话过期」，只能手动刷新。改为「踢旧纳新」语义可一并根治。
- **踢旧语义引入 actor 误删竞态**：`HandleAsync` 的 `finally` 无条件 `runtime.RemoveAsync(playerId, true)`。一旦允许新连接顶替旧连接，旧会话拆除时会把新会话刚 `LoadAsync` 的 actor 一起移除刷盘。落地时必须让 `Remove`/`RemoveAsync` 以「被拆除的 session 仍是注册会话」为前提（当前 `SessionRegistry.Remove` 已按实例比较移除，天然可复用该判定）。
- **前端阻断不等于资源阻断**：BroadcastChannel 守卫运行在 SPA bundle 加载之后，无法做到「未下载资源前阻断」；要达成需把极小的探测脚本内联进 `index.html`。
- **方案示例代码缺陷**：
  - `localStorage` 降级逻辑**方向颠倒**：`storage` 事件只在其他标签页触发，新标签页写 key 会杀死旧运行页而非自身。正确做法是写入 `{tabId, ts}` 后比较，或先读再写配合心跳续期处理崩溃残留。
  - BroadcastChannel 存在双页近同时打开互判对方的竞态（双方都收到 `I_AM_RUNNING` 双双自杀），需 tabId 时间戳决胜。
  - `window.stop()` 不终止 rAF/定时器/WebSocket；本项目应走 `gameClient.dispose()` + 由 `useGameStore` 驱动正规 Modal 遮罩（遵循 `docs/frontend/common-components.md`），而非 `document.body.innerHTML` 覆写。
- **阶段二心跳缺口**：ZSET 方案依赖周期 `zadd` 续期但示例只写了准入；进程内实现可直接以 socket 生命周期为真值，连心跳都不需要。
- **指纹现实约束**：iOS/Safari 会掩蔽 `UNMASKED_RENDERER_WEBGL`；指纹可被插件伪造，定位为「提高成本」而非「身份证明」；`crypto.subtle` 需安全上下文。建议指纹 + IP 组合判定，配额 N 走 `ServerOptions` 配置。

### 3.2 落地形态建议（去 Redis 化）

- **互踢**：`SessionRegistry` 增加 `TryAddOrKick` 原子语义（`ConcurrentDictionary` 上锁/AddOrUpdate），为 `WebSocketSession` 增加可取消句柄（如 `CancellationTokenSource`），老会话收到 `WireMessageType` 下线通知 + 独立关闭码（如 `4005`，区别于会话过期 `1008/4001–4004`），前端对 `4005` 显示「账号在其他端登录」且不自动重连。
- **设备限额**：新增进程内 `DeviceRegistry`（`ConcurrentDictionary<fpHash, HashSet<PlayerId>>`），在 Hello 鉴权后、actor 加载前校验配额；socket 关闭即移除，无需 TTL/心跳。指纹经 `HelloRequest` 扩展字段上报 → 同步前端 `protocol.ts` 枚举与编解码 + 端到端信封往返单测（协议强对齐门禁）。
- **合规红线**：配额拒绝路径要在握手早期返回明确 `ErrorDto`，不得静默；所有新错误码同步 i18n 词条。
