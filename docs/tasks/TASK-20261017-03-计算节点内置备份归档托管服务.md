# TASK-20261017-03 计算节点内置备份归档托管服务

## 任务背景与核心需求

在 `TASK-20261017-01` 中，我们通过外部脚本和定时任务（cron / systemd timer）打通了从主服到本地计算节点的备份拉取通路。
但用户提出进一步诉求：**后续如果有其他计算节点接入，不希望每次都通过手动布置脚本或配置定时任务**。
为了实现**真正的一劳永逸、开箱即用、零运维手动布置**，本任务将异地灾备备份归档能力原生内置到 `src/ComputeNode` 进程自身中，形成可选的后台托管服务 `BackupArchiveWorker`。

## 架构与核心设计

1. **跨平台原生实现（零外部 Shell/Cron 依赖）**：
   - 基于 .NET `IHostedService` / `BackgroundService`；
   - 纯 C# 原生流式 HTTP 下载与断点校验，摆脱对 Linux 外部 `rsync`、`cron`、`systemd` 或 Bash 环境的强依赖；
   - 无论计算节点运行在 Linux、Windows、macOS 还是 Android PRoot 掌机上，体验与行为 100% 保持一致。

2. **自适应激活与按需存储**：
   - 通过配置 `ComputeNode:BackupStorage:Directory`（或环境变量 `DAOHUA_BACKUP_STORAGE_DIR`）驱动：
     - 若节点未配置存储目录（如轻量无状态计算节点），Worker 不加载，不产生任何开销；
     - 若节点配置了本地目录（如本地大硬盘服务器、odin 掌机），Worker 自动激活，定期自动拉取与对账。

3. **网络与安全链路复用**：
   - 自动复用计算节点既有的 `UpstreamUrls` 推导主服基础 URL（如 `https://daohua.yuohira.com`）；
   - 走标准 443 HTTPS 端口传输，携带专用内部 `X-Backup-Token`，不受代理与内网防火墙干扰。

4. **可观测性支持**：
   - 在 `/healthz` 端点自动暴露 `backupArchive` 状态（启用状态、最新同步时刻、成功对账文件数、错误信息）。
