## 需求分析

用户要求新增一个 Skill：全局注释检查、分析与生成。三条核心诉求：

1. **全局**：覆盖整个仓库的代码注释（支持指定范围收窄）。
2. **中等详细度的中文 XML 注释**：所有注释维持统一口径——说清「做什么 + 为什么 + 关键约束」，不写废话也不写论文；C# 用 `///` XML 注释，前端 TS 无 XML 惯例，用 JSDoc `/** */` 执行同一标准。
3. **行间注释**：对无法一眼看出作用的方法内实现（魔法数、顺序依赖、确定性约束、绕行方案等）补充 `// 中文` 行间注释，解释「为什么」而非「做什么」。

## 实施方案

- 新增 `.agents/skills/comment-audit/SKILL.md`，核心设计：
  - **范围与优先级**：用户指定范围优先；未指定时按 `src/Domain` → `src/Ecs` → `src/Server` → `src/Protocol` → `src/ComputeNode` → `frontend/src` → `tools/` 推进；`tests/` 不要求 XML 注释（测试名即文档），只补复杂段行间注释；`vendor/` submodule 永不修改；生成代码跳过。
  - **中等详细度标准**：按类型/方法/属性/`<remarks>` 分级给出量化要求，附好/坏注释示例（废话注释明确禁止）。
  - **扫描手段**：利用 `dotnet build -p:GenerateDocumentationFile=true` 触发 CS1591 警告盘点缺失 XML 注释的公共 API，配合直接读文件检查 `///` 覆盖与低质量注释（英文/废话/过期）。
  - **安全边界**：只改注释行，diff 不得出现代码逻辑变更；注释与行为矛盾时以代码为准改注释，疑似 bug 停下报告；不删有效注释，英文注释中文化而非重写。
  - **术语对齐**：修仙词汇中文原词 + 拼音标识符（`Qi`/`Linggen`/`Gongfa`），以总纲 19 名词术语对照表为准。
