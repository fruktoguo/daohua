## 需求背景

用户提出当前没有批量使用——以技能书为例，`ability.learn` 一次只能研读一本。
经确认的设计边界（要求写入设计文档）：

- **槽位消耗品**（丹药、后续符阵等）：不提供手动使用入口，只能装配到自动使用槽位按既有机制生效。
- **手动即时消耗品**（技能书、装备、后续宝箱类等）：手动消耗；除装备外原则上都支持批量消耗，具体按使用场景决定。
- 交互方式：背包「使用」弹出数量选择弹窗（复用丢弃/回收的 `QuantitySelector` + 二次确认模式）。

## 现状盘点

- `ability.learn` 协议 payload 仅有 `itemId`，服务端固定 `-1` 扣减、单本结算（秘籍已习得 +10000/未习得领悟；残卷已习得 +500）。
- 前端 `InventoryItemCell` 的「参悟」与右键快用均一次一本。
- `item.discard`/`item.sell` 已有 `quantity` 参数 + `ItemQuantityDialog`/`QuantitySelector` 数量弹窗模式可复用。

## 实施方案

1. **设计文档（先行）**：
   - `05-技能神通与秘籍残卷体系.md` §5.2 补批量研读语义（秘籍 N 本：首本领悟、其余每本 +10000；已习得全量 +10000/本；残卷 N×500，须已习得）。
   - `06-持续消耗品机制与生活制造体系.md` §6.2.1 明确手动即时消耗品与槽位消耗品边界、批量消耗原则。
2. **服务端**：`ability.learn` 读 `quantity`（缺省 1；校验有限、≥1、整数），逐本循环 `GrantAbilityExperience`（保持单本语义等价与升级账本粒度），`AssetDelta` 按 `-quantity` 扣减；余额不足仍由经济事务拒绝回滚。
3. **前端**：秘籍/残卷「使用」（菜单与右键）打开数量弹窗，`ability.learn` 携带 `quantity`；装备维持即点即穿。
4. **文档同步**：`logic-development-guide.md` 命令表、`common-components.md` 组件描述、总纲查看器内嵌快照、i18n 模板 CSV。
5. **测试**：`EcsAdapterBoundaryTests` 增加批量研读用例（多本扣减 + 经验累计 + 未习得首本领悟）。
