## 3. 根因分析

### 3.1 需求 A：水灵不爆技能

**现象**：水灵在战斗模拟器中全程不释放甘露。

**排查过程**：

1. 先排除领域层嫌疑：`DeterministicCombatEngine.Start` + `spirit.Skills` 直跑，水灵在 40 秒内正常施放甘露 3 次并挂上 `buff.ganlu`——**领域层无 Bug**。
2. 沿 ECS 生产路径复核：`CreateEncounterCore` → `EncounterWaveSelector.Select` → `CombatantTemplate(m.Stats, m.Skills)`，槽位触发器沿用领域层解析结果，**服务端路径正确**。
3. 转向前端离线推演：`frontend/src/game/simulator/expeditionSimulator.ts` 装配怪物技能时触发器取的是 `def?.defaultTriggers`，**完全丢弃了怪物技能槽上的 `triggerHpRatio`**。
4. 实证对照（`SimSkillTriggerEvaluator` 直接求值）：

   | 口径 | 触发器 | 怪物视角求值 |
   | :--- | :--- | :--- |
   | 服务端（`triggerHpRatio: 1.0` 折叠） | `self current-hp-percentage ≤ 100` | **true** |
   | 前端（`ability.ganlu.defaultTriggers`） | `ally-lowest-hp` + `missing-hp ≥ 1` | **false** |

**根因**：服务端 `GameDataCatalog.ParseMonsterDefinitions` 按「槽位 `triggers` → `triggerHpRatio` 折叠 → 功法 `defaultTriggers` → 恒可用」解析出最终触发条件，但 `StaticGameCatalogMapper.ResolveMonster` 投影怪物技能槽时只下发 `abilityId` + `level`，**丢弃了解析后的触发条件**。前端模拟器因此退回功法默认条件——甘露的默认条件 `ally-lowest-hp` + `missing-hp ≥ 1` 在怪物视角下（友方 = 敌方阵营、且需已残血）恒为假，水灵永不施放。

> 附带影响面：任何带条件默认触发器的功法被怪物携带时都会出现同类问题（当前配表中仅甘露命中 `ally-lowest-hp` 语义）。

### 3.2 需求 B：技能书掉落

`item.tome.ganlu` / `item.fragment.ganlu` 在 `manuals.json` 中**完全不存在**，水灵掉落表只有 `item.broken-spirit-core`。

掌心雷秘籍/残卷**已由木灵投放**（`item.tome.palm-lightning` 0.001 / `item.fragment.palm-lightning` 0.02），符合总纲 §5.2 规范（完整技能书 0.1%、残卷 2.0%），无需重复投放。

### 3.3 需求 C：甘露 buff 描述与独立悬浮窗

- `frontend/src/game/format.ts` 的 `buffClause()` 只覆盖 `damageBonusPoints` / `damageAbsorptionPoints` / `threatPoints` / `threatPerSecondMaxHpPoints`，**未处理 `hpRegen` / `mpRegen`**——甘露唯一的 buff 效果量（`hpRegen: 5.0`）因此在描述中完全丢失。
- `frontend/src/components/EffectTooltip.tsx` 的 `resolveAbilityAsideCards()` 只产出「升级进度」+（internal 时）「内功增益」+「六维倾向说明」，**没有任何 Buff 效果副卡**。
- `frontend/src/game/types.ts` 的 `CombatAbilityDefinition.buff` 类型缺 `buffId` / `stackPolicy` / `spellAttackStackInterval` / `maxStacks` / `hpRegenPostRatio` / `mpRegenPostRatio`。

## 4. 实现方案

### 4.1 需求 A：触发条件下发口径对齐

**服务端**（`src/Server/Clean/StaticGameCatalogMapper.cs`）：`ResolveMonster` 的技能槽投影增加 `triggers`，直接下发领域层已解析的最终条件。

**前端**：
- `frontend/src/game/types.ts`：`CombatAbilitySlot` 增加可选 `triggers` 字段。
- `frontend/src/game/simulator/expeditionSimulator.ts`：新增导出函数 `resolveMonsterSkillTriggers(slot, ability)`，装配怪物技能时优先采用服务端下发的槽位条件；**未下发时**才回退功法 `defaultTriggers`。注意不能用 `||` 兜底——服务端下发的空数组表示「恒可用」，必须原样保留。

### 4.2 需求 B：秘籍/残卷落地

- `config/game-data/items/manuals.json`：新增 `item.tome.ganlu`（售价 100）与 `item.fragment.ganlu`（售价 10），文案取自甘露配表描述。
- `config/game-data/monsters/tier1_minions.json`：水灵掉落表新增甘露秘籍（0.001）与残卷（0.02）。
- `frontend/src/game/ids.ts`：登记两个物品的图标/色调/品阶。
- `frontend/src/i18n/domains/game.zh.ts`：登记物品 label 与 description 词条（i18n 门禁要求配表枚举全覆盖）。
- **图标资产补齐**：其余 20 组秘籍/残卷（40 件）均有专属 WebP 图标，新增的甘露两件原本只能回退为文字瓦片。按既有「MOSS-Image 图腾 → 线装书/残卷合成」管线补齐：
  - `.agents/skills/moss-art/scripts/moss_generator.py`：新增 `logos_ganlu` 批次（2×2 象限出 4 版候选，提示词要求「纯黑底纯白实心」）；**修正图腾批次取图逻辑**——原先取的是工作流 node 18 的 RMBG 抠图产物，黑底被当背景抠掉导致白形退化为描边，改为取 node 30 的未抠图原图 `moss-image_*.png`；**修正图腾切图的外扩策略**——纯黑底各象限图形互不相连，原先 12% 外扩会带入邻格候选，改为按 bbox 严格矩形裁切。
  - `.agents/skills/moss-art/scripts/composite_manuals.py`：`INTERNAL_CONFIGS` 增加甘露条目（封皮青蓝 `(40,108,138)`、微倾 `-8°`），复用既有线装书/残卷母版合成。
  - 产物：`art/emblems/emblem.ganlu.webp`（128px 图腾母版，象牙色 RGB 237，与其余 10 个 emblem 同规格）、`frontend/src/assets/items/item.tome.ganlu.webp`、`item.fragment.ganlu.webp`（64px 运行时图标）。合成前后既有 40 件图标逐字节比对无差异。

### 4.3 需求 C：Buff 描述与独立悬浮窗

- `frontend/src/game/types.ts`：扩展 `CombatAbilityDefinition.buff` 类型，补齐 `buffId` / `stackPolicy` / `spellAttackStackInterval` / `maxStacks` / `hpRegenPostRatio` / `mpRegenPostRatio`。
- `frontend/src/game/format.ts`：`buffClause()` 补 `hpRegen` / `mpRegen` 描述（按服务端 5 秒结算点口径表述），并追加叠层规则说明（`maxKeep` 与法攻动态层数）。
- `frontend/src/components/EffectTooltip.tsx`：新增 `extractAbilityBuffBonusItems()` 与 `createAbilityBuffAsideCard()`，**复用既有 `extractBuffBonusItems` + `createBonusAsideCard`**（与装备属性、药品效果、实时 Buff 共用同一套「通用属性数值加成独立悬浮窗」规范），接入 `resolveAbilityAsideCards()`。
