## 需求分析

用户提出：当前 ECS 仅是调度调用层（System→Pipeline→Domain 静态函数三段转调），要设计**彻底的 ECS 方案**——运行时状态与业务规则本体都落在组件与系统上，Domain 退化为纯库（配表/类型/公式/编解码）。

设计岔路已与用户对齐：

1. **组件粒度（用户自定）**：按反应性拆分——需要响应事件的挂独立组件（如受击触发类 buff 一型一组件）；纯属性修饰 buff 合并容器；角色战斗属性整体一组件；行动队列一组件；HP/MP 入"持久化资源组件"（战斗内外均持久化）；非战斗行动属性一组件。
2. **战斗内核**：采用"内核保留 + 段内触发器化"——`AdvanceTo` 批量窗口调度不动（性能命脉），段内规则经 `RunSystem<T>(entity)` 在边界固定点同步派发，可战中即时反应。
3. **持久化**：分段落库格式不动，组件↔分段映射层扩展（reactive buff 序列化进 Buffs 分段扩展字段）。
4. **迁移**：一次性重构（长分支，门禁全绿才合并）。
5. **ComputeNode**：统一换装 `EcsWorldShard`，执行路径与生产服构造级一致（一致性由构造保证而非双跑验证）。
