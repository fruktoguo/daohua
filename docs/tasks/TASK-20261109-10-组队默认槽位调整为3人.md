## 1. 需求背景与核心目标

### 1.1 业务背景
在修仙大世界与数值量化模型中，多人讨伐与三人组队模式（3-Player Team，总纲 §11.2.6）是核心玩法的标准协同规格。此前队伍开启槽位（`openSlots`，可配置范围 2~5）在系统新建与缺省时默认为满编 5 人。为使组队匹配与副本讨伐更贴近主流队伍规模、降低开战门槛，需将组队默认开启槽位统一调整为 3 人。

### 1.2 预期实现边界
1. **范围保持不变**：槽位下限保持 `MinOpenSlots = 2`，上限保持 `MaxPartyMembers = 5`，队长仍可在 2~5 范围内任意手动调整。
2. **默认值调整为 3**：
   - 数据库 Schema：`social.parties.open_slots` 的 `DEFAULT` 值由 5 改为 3。
   - 服务端持久化：`CreatePartyAsync` 创建队伍显式写入 `open_slots = 3`（`SocialRuntime.DefaultOpenSlots`）。
   - 服务端契约与模型：`PartyRecord` 构造记录默认参数设为 3。
   - 前端社交状态：`socialStore.ts` 导出 `PARTY_OPEN_SLOTS_DEFAULT = 3`；`SocialPage.tsx` 在缺少 `openSlots` 时缺省回退为 3。
   - 协议与文档：前后端协议注释与设计总纲第 21 篇同步对齐。
