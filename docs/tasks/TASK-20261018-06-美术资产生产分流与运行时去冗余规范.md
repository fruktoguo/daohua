# TASK-20261018-06: 美术资产生产分流与运行时去冗余规范（art/源稿留存与public/极简单一格式）

## 1. 任务背景与核心需求

当前游戏视觉资产（尤其主角道貌立绘）在生成交付时，将 AI 产出的无损大 PNG、WebP 与矢量 SVG 同时拷入了 `frontend/public/avatars/`。虽然前端组件具备顺序懒回退机制不会在单次渲染中重复下载，但多格式混放导致了严重问题：
1. **生产镜像与构建冗余（死重）**：`frontend/public/` 下的全量文件均会原样打包打入生产 Docker 镜像与前端 `dist/`，白白增加构建拷贝时间与容器体积。
2. **多端版本一致性风险**：同一个角色存在多份文件，一旦后续修改维护未能同步更新各格式，不同回退路径的终端将展示不一致的画面。
3. **资产分工未对齐项目边界**：`.dockerignore` 已明确忽略根目录 `art/`（美术源资产库），但此前缺乏自动化规范，导致原始生成源稿越界进入了生产前端静态目录。

为此，彻底重塑美术资产分流规范与加载架构：
- **明确项目边界**：`art/` 专职存放 AI 原图、分层稿与无损源素材（不进镜像）；`frontend/public/` 仅存放生产运行时单一最优定型文件（折面立绘仅保留 `.svg`，怪物立绘仅保留 `.webp`）。
- **清理既有冗余**：将所有素材完整同步留存在 `art/avatars/`，随后安全清理 `frontend/public/avatars/` 中的多余位图与过程稿。
- **优化前端加载逻辑**：`avatarStore.ts` 与 `CharacterAvatar.tsx` 消除对冗余位图的无序 404 探测，角色直接解析 SVG，怪物直接解析 WebP。
- **生图技能（Skill）与项目规范闭环**：同步更新 `planar-art` 与 `moss-art` 的工程交付章节，以及 `AGENTS.md` 美术边界说明。
