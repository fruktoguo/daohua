# TASK-20261004-03 历练页分组重组与行动地点黑名单（excludedNodeIds）

- **提出时间**：2026-10-04 02:20:00（上一轮会话）
- **状态**：✅ 已完成
- **分类**：前端体验重组 / 行动地点约束 / 全栈

## 需求

用户裁定：

1. 历练页行动分组按**技艺归属**区分——采集类行动组名直接叫「采集」，组名后跟随玩家当前该技艺等级；不再叫「特殊行动」。
2. 讨伐分组直接叫「讨伐」，不叫「妖兽历练行动」。
3. 「修炼」页签撤销，修炼类行动并入历练页作为**常驻行动**。
4. 引气入体是特殊行动：其他行动配置了才出现在某地点，引气入体默认全图都有——需要不支持引气入体的地点时才特殊配置。

## 方案与落点

1. **领域** `src/Domain/GameData/GameDataCatalog.cs`：`ActionDefinition` 增 `ExcludedNodeIds`（`IReadOnlySet<string>?`），配表 `excludedNodeIds` 解析、拷贝构造补齐；`AllowedNodeIds` 与 `ExcludedNodeIds` 同配即装配拒绝（互斥）。
2. **执行层** `src/Ecs/Systems/ActionExecutionRules.Timed.cs`：开轮 `availableHere` 改为「白名单须在列（若配置）且黑名单不含（仅驻足判定，行进中不触发）」；自动移动锚点准入同构——黑名单行动锚点在排除集内时回落 Blocked。
3. **服务端** `src/Server/EcsPlayerRuntimeAdapter.cs`：入队 `WRONG_LOCATION` 校验补黑名单分支；`Program.cs` 行动目录 wire 增 `excludedNodeIds` 透传。
4. **Bench** `src/Bench/Program.cs`：播种落点同时满足 allowed 且不在 excluded。
5. **DataTool** `src/DataTool/Program.cs`：`excludedNodeIds` 节点引用校验 + 与 `availableNodeIds` 互斥校验。
6. **前端**：
   - `types.ts`/`actionCalculations.ts`：`excludedNodeIds` 字段与 `isActionAvailableAtNode` 同口径预览；
   - `App.tsx` `ExplorationPage` 重写为四段分组：**常驻**（`type=cultivation`）→ **技艺组**（`{name} Lv.{level}`，按 `TECHNIQUE_IDS` 序）→ **历练**（无技艺归属探索）→ **讨伐**（`type=combat`）；删 `SkillPage` 与修炼导航；
   - `uiStore.ts` `TabId` 删 `'cultivation'`；`app.zh.ts` 删 `nav.cultivation`/`cultivationHint`，新增 `residentActions`/`techniqueGroup`/`otherActions`/`huntActions` 键。
7. **测试**：`AutoTravelTests.cs` 新增 `ExcludedNodeIds` 用例（仅列名节点受阻、锚点未排除仍可自动移动回场、白名单黑名单同配拒绝）。

## 边界

- 常驻语义 = 无白名单 + 无黑名单（或黑名单不含当前节点）。`cultivation.draw-qi` 不配约束即默认全图可行，无需逐节点登记；未来禁某点只需该行动配 `excludedNodeIds`。
- 节点 `availableActionIds` 仅作地图详情展示元数据（资源列表），不再承担执行门禁。
- 当前无任何行动配置 `excludedNodeIds`（机制预留，全部修炼类行动默认全图）。
