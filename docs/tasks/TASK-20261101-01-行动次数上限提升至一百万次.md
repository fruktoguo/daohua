## 1. 需求背景与核心目标

### 1.1 背景
服务端与协议契约（`src/Protocol/Contracts.cs`、`src/Domain/Player/PlayerActionQueueMutation.cs`、`PlayerStateDocument.cs`）对非无限行动计划执行次数（`RepeatCount`）所允许的有效区间一直是 `[1, 1_000_000]`（一百万次），或特殊值 `-1`（无限循环）。
此前前端 UI 的数量选择器组件（`QuantitySelector`）在行动面板（`App.tsx`）与装备强化页面（`EnhancementPage.tsx`）中硬编码了 `max={1000}`，导致玩家在有限次数模式下最高只能输入 1,000 次，与后端契约不一致。

### 1.2 核心目标
1. 将前端有限行动重复次数的输入上限由 `1,000` 提升至与服务端契约一致的 `1,000,000`（一百万次）。
2. 在 `frontend/src/network/protocol.ts` 导出统一常量 `MAX_ACTION_REPEATS = 1_000_000`，杜绝多处硬编码幻数。
3. 同步收拢 `frontend/src/App.tsx` 及 `frontend/src/components/EnhancementPage.tsx` 的调用点。
4. 保持 `QuantitySelector` 默认行为及其他业务场景（如商店购买、道具使用）各自既有上限不变。

---

## 2. 影响范围与实现边界

- **受影响文件**：
  - `frontend/src/network/protocol.ts`：增加并导出 `MAX_ACTION_REPEATS = 1_000_000` 常量。
  - `frontend/src/App.tsx`：两处 `QuantitySelector`（行动详情与立即开始面板）接入 `MAX_ACTION_REPEATS`。
  - `frontend/src/components/EnhancementPage.tsx`：强化重复次数 `QuantitySelector` 接入 `MAX_ACTION_REPEATS`。
- **边界说明**：
  - 纯前端 UI 上限约束调整；服务端与协议层已原生支持 1..1,000,000 整数，无需变动后端逻辑与 schema。
  - 商店/背包物品使用场景等维持原有各自的上限或库存限制，不受本次变动影响。
