## 1. 用户需求原文

当前的经验获取有没有通用计算方式?因为我之前给所有的技艺的经验获取增加了个计算公式,但是实际经验是写在配置文件的
就是经验主要是按照基准来的
如,一级 10秒的一个行动增加10点经验,而18级的10秒行动增加133经验,也就是10秒等同 对应等级的普通怪物的击杀经验

把经验获取的配置,改为百分比吧,如,普通的挖矿,配置就是50%体魄,50%力道,总百分比之和支持超过100%
引气入体这种修炼行动,也可以这么实现,100%的修为,50%的经脉,50%的根骨

## 2. 现状分析

- 此前 TASK-20261013-08 确定了非战斗行动六维经验的理论公式：
  `基准经验 = 对应等级普通怪物击杀经验 × (基础时长秒 / 10s)`
  但该公式此前仅用于线下计算，实际数值作为固定数字（如 5, 8, 107, 267, 334 等）硬编码在 `config/game-data/actions/*.json` 的 `amount` 字段中。
- 修炼行动（引气入体）的修为收益（`experience` 10）也是固定填在 JSON 中。
- 配表一旦调整时长或等级，必须逐个文件手工重新推算并手动改写各个 JSON，维护成本高且容易出错。

## 3. 架构设计与技术方案

1. **配置语义升级**：
   - 在 `ActionYield` 配置中，针对 `experience` 与 `rootexp` 类型，支持显式配置 `"percentage": N`（如 `100` 代表 100%、`50` 代表 50%）或 `"ratio": R`（如 `1.0` 或 `0.5`）。
   - 总百分比之和支持任意数值（可超过 100%，如引气入体为 100% 修为 + 50% 经脉 + 50% 根骨 = 200%）。
   - 固定数值产出（如物品件数 `amount: 1`、固定灵力 `amount: 10` 等）保持 `amount` 原样，形成兼容并蓄的优雅模型。

2. **基准经验通用推导**：
   - 行动等级裁决：若行动显式配置 `"level"` 则优先采用；缺省按 `CraftingRecipeRules.ResolveRequiredRealmLevel(action, catalog)` 从产物/材料 Tier 自动推导（T1→1级，T2→18级）。
   - 单轮 100% 基准经验：
     `BaseActionExp = RealmProgression.MonsterKillExperience(actionLevel, Minion) × (action.DurationSeconds / 10.0)`
   - 按秒持续行动（如赶路）：
     `BaseActionExpPerSecond = RealmProgression.MonsterKillExperience(actionLevel, Minion) × (1.0 / 10.0)`
   - 各项经验产出：
     `Amount = Math.Round(BaseActionExp × ratio)`

3. **装配与运行时模型**：
   - `ActionYield` 记录 `Ratio` 与推导后的 `Amount`。
   - `GameDataCatalog` 在装配期统一解析计算出各行动的实际 `Amount`，保证 ECS 运行时执行规则零反射、零重复计算、100% 确定性。
   - 服务端下发 `/api/v1/catalog/actions` 时同时携带推导的 `amount` 与配置的 `percentage`/`ratio`，前端无缝兼容并可直观显示百分比。

4. **配表与文档对齐**：
   - 批量更新 `config/game-data/actions/*.json`（cultivation, gathering, crafting, alchemy, forging, talismans, formations）中的经验与六维经验配置为 `percentage`。
   - 同步修订 `docs/design/总纲/20-技艺体系与符箓阵法强化规约.md` 等相关总纲。
