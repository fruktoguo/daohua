# TASK-20261112-13 组队消耗品冻结修复与调度压测对照模块

## 需求分析与核心理解

- **业务目标**：为「组队挂机无限吃消耗品 / 消耗品判定 5 秒 tick 延迟」的优化方案提供**实测数据**，替代静态推断；用真实战斗代码路径对比「现状 5 秒 tick 调度」与「事件驱动即时调度」在 500 单人 + 100 个五人队规模下的 CPU/分配/时间成本。
- **核心逻辑预期**：
  1. 组队会话 `ActionParticipantSnapshot` 缺失 `ConsumableTriggers` 冻结字段——玩家按物品配置的消耗品触发条件不进会话，`ConsumableTriggerResolver` 回退配表空触发器，导致 CD 一好就吃（本任务修复该冻结缺陷，A/B 两组统一生效，保证对比变量只有调度策略）。
  2. 新增调度模式开关 `ConsumableScheduleMode { PeriodicTick, EventDriven }`：EventDriven 下消耗品判定挂在每个战斗自然边界结算后（`ICombatPhaseDispatcher` 装饰钩子），冷却/持续到期作为唤醒边界，激活后级联收敛至无新触发，战外相位不判定；默认 `PeriodicTick` 保持现状生产行为。
  3. `src/Bench` 新增 `sim` 子命令：纯内存、真实配表（`GameDataCatalog.LoadEmbedded`）、真实引擎（`SimulationEngine` / `ActionParticipationSessionEngine`）、确定性种子玩家画像（3 消耗品槽 + 玩家触发器 + 技能 + 装备）；500 单人 + 100 个五人队，同一输入下双模式各跑 1 小时模拟时长，输出墙钟/CPU/分配/GC/边界数/判定数/消费数对比 JSON。
- **影响范围与实现边界**：`src/Domain/Player`（快照字段）、`src/Ecs`（会话引擎与单人引擎模式分支）、`src/Bench`（新子命令）；不连数据库、不改生产默认行为（模式缺省 PeriodicTick）、不提交 git。

## 技术方案

1. `ActionParticipantSnapshot` 增加 `ConsumableTriggers`（`IReadOnlyDictionary<string, JsonElement[]>?`，可缺省解码）+ `IsValid` 校验；`CaptureActionParticipantSnapshot`（在线聚合）与 `FromState`（持久化投影）两条定格路径采集；会话引擎构造容器成员时灌入 `member.Loadout.ConsumableTriggers`。
2. `ConsumableScheduleMode` 枚举（Ecs 层）：会话引擎 `Create`/`Restore` 可选参数；EventDriven 下——`EvaluateConsumables` 返回激活数并在 `_battle is null` 时零判定，`_nextConsumableEvaluation` 语义切换为「最早槽位冷却/持续到期」唤醒边界，`AdvanceBattle` 注入 `ICombatPhaseDispatcher` 装饰器在 `ICombatOutcomePhase` 后级联判定。
3. 单人 `SimulationEngine.AdvanceTo` 可选 mode 参数：EventDriven 下 `PrepareResourceBoundaryCore` 仅战斗相位激活即时品，战斗推进用同款装饰器逐边界判定。
4. `src/Bench` `sim` 命令：确定性玩家生成（种子化 Guid）、队伍 spec 构造、MeterListener 观测 `domain.combat.event` 边界耗时、引擎计数器（判定/激活/边界数）、GC/CPU/墙钟采集，JSON 报告落 `artifacts/bench/`。

## 压测实测（2026-11-12 全量）

- 规模：500 单人 + 100 五人队（1000 实体）× 60 分钟挂机模拟，全真配表/战斗/消耗品/触发器；`dotnet run --project src/Bench -c Release -- sim --solo 500 --teams 100 --minutes 60`
- 画像：境界 20 + 清风剑 + 重斩/掌心雷；药品槽止血散 + 通用槽顺气丸/雷击符/聚灵阵盘；玩家级触发条件（hp<60% / mp<50% / 敌方存活≥1）
- 结果：

| 指标 | tick(5s) | event(逐边界) | 倍率 |
| --- | --- | --- | --- |
| 墙钟 | 35.3s | 45.9s | 1.30× |
| CPU | 34.1s | 39.3s | 1.15× |
| 分配 | 21.6GB | 29.3GB | 1.36× |
| 战斗边界 | 1,806,362 | 1,929,019 | ≈1 |
| 判定调用 | 469,292 | 2,662,079 | 5.67× |
| 激活 | 96,022 | 89,744 | 0.93× |

- 结论：判定调用 5.7× 但单次 ~4µs，边际墙钟 +10.6s/1000玩家·小时；1000 玩家·小时全真模拟单线程 46s 跑完，生产实时负载下远不构成卡顿。
- 行为分叉说明：solo repeats 102000→90000、激活 96022→89744——判定时机变化引起合理语义分叉（战外不吃药、边界即时响应），输入完全同源。
- 回归：`PartyConsumableTriggerFreezeGatesSessionAutoUse` 验证 ConsumableTriggers 冻结进会话（修复前必失败）；Domain.Tests 307/307 全绿。
- 产物：`artifacts/bench/consumable-sim-60m.json`；命令 `sim --solo --teams --minutes --seed --modes tick,event --report`。
