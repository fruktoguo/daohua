## 改动

### 1. 清理

```bash
rm -rf art/master_256      # 64 张 256 母版，4.3MB
rm -rf art/_build          # 空目录（切图中间产物，已在 .gitignore）
rm -rf /tmp/items_web_32_backup /tmp/items_web_64_backup \
       /tmp/icon_view /tmp/icon_compare /tmp/icon_filter
```

`art/` 清理后只剩：`source/`（原图，8.6MB）、`legacy_128/`（26 张唯一高清，208KB）、
`sheets.json`（切图规格）、`icon_ids.json`（名称→ID 映射）。

`/tmp` 里的 32px 备份、64px 备份与三张对比页（32/64/128 三档对照、最近邻 A/B、四象限 DPR 图）
一并清除 —— 32px 档已被判定不再需要，留着反而是「项目里还有第二档尺寸」的隐患。

> 注：`/tmp/items_web_32_backup` 删除后，**回退到 32px 的路径消失**。这是刻意的：
> 32px 已被否决，且 90 张里那 64 张随时可由 `art/sheets.json` 重出。

### 2. 切图工具：默认只出 64

`icon-sheet-grid-slice` 技能的 `slice_grid_sheet.py` 原默认产出两级资产（256 母版 + 64 网页版）。
本次把 **`--master-size` 默认值改为 `0`（不出母版）**：

| 参数 | 改前 | 改后 |
| :--- | :--- | :--- |
| `--master-size` | `256` | **`0` = 不出母版** |
| `--web-size` | `64` | `64`（不变） |

- 需要工程母版时显式传 `--master-size 256`（能力保留，只是不再默认）。
- 新增入参校验：`--master-size 0` 与 `--web-size 0` 同时成立 → 直接报错退出，避免跑完一轮什么都没有。
- 预览总览改为跟随实际产出的那一级取图（原先硬编码取母版路径）。

### 3. 不做的事

- **不改任何 CSS / JS**：`image-rendering: pixelated` 三处保持不动（TASK-20260913-04 / -05 的结论继续有效）。
- **不改运行时尺寸**：90 张仍是 64×64 WebP q90。
- **不引入第二档尺寸的任何代码路径**：不写「多尺寸并行产出」的开关或回退分支。
