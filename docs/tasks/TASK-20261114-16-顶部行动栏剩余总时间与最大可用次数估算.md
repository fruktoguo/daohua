## 核心需求与边界

1. **展示位置**：仅作用于顶部当前行动栏（`CurrentActionCard` `.qc-repeats`），不改服务端协议与领域模拟逻辑；队列列表与下一行动预览保持原次数展示。
2. **总剩余时间口径（实时扣减）**：
   - 基于服务端已包含全部加速的单轮真实耗时 `entry.durationSeconds` 与当前轮实时已过时间 `elapsedSeconds`：
     - `baseRemainingSeconds = Math.max(0, durationSeconds - progressSeconds) + Math.max(0, effectiveCount - 1) * durationSeconds`
     - `remaining = Math.max(0, baseRemainingSeconds - elapsedSinceSync)`
   - 当队列暂停（`queuePaused`）、行动受阻（`entry.status === 'blocked'`）或退场动画期间冻结计时；正常推进时由 `CurrentActionRepeatsLabel` 独立切片订阅并通过 `useLayoutEffect` + 250ms DOM 直写实时倒计时，不触发无关父组件重渲染。
3. **分行动类型策略**：
   - **战斗（`combat` / `combat-encounter`）与赶路（`travel`）**：不显示次数耗时与材料次数估算，保持原样。
   - **可一直进行且无硬性材料阻断的行动（采集 `exploration`、修炼 `cultivation`）**：
     - 有限次 `N`：显示 `{n}次 ({duration})`。
     - 无限次 `∞`：仅保留 `∞`，不显示预期耗时，且不订阅背包/底蕴状态。
   - **材料/资源消耗型行动（制造/炼丹/炼器/符箓/阵法/宗门炼制、`foundationCostRatio` 逆命丹、以及化灵/分解/转化秘法）**：
     - 按服务端 `EnhancementRules.CountOccupied` 同源口径扣除已穿戴与 `enhance.equipment` 队列占用的装备件数（不将秘法自身计为自锁），计算当前资源可支持的真实最大次数 `maxSupported`。
     - 无限次 `∞`：显示 `∞ (x{maxSupported} {duration})`；`maxSupported <= 0` 时显示 `∞ (x0)`。
     - 有限次 `N`：取 `effectiveCount = min(N, maxSupported)`；若被材料截断（`effectiveCount < N`），显示 `{n}次 (x{effectiveCount} {duration})`（`0` 次显示 `{n}次 (x0)`），材料充足时显示 `{n}次 ({duration})`。
   - **装备强化（`enhance.equipment`）**：
     - 不预测概率成败与等级波动，直接按当前目标等级单轮材料消耗（灵石 `(currentLevel + 1) * 10`；若配置 `auxItemId` 且 `currentLevel >= protectLevel`，同时计入保护材料可用库存）计算最大可执行次数与总时间；无限/有限截断格式同上。
4. **紧凑时间格式**：
   - `< 60s`：`{s}秒`；`< 1h`：`{m}分` / `{m}分{s}秒`；`< 24h`：`{v}小时`（1 位小数、去尾 `.0`，如 `5.8小时`）；`>= 24h`：`{v}天`（1 位小数、去尾 `.0`）。
