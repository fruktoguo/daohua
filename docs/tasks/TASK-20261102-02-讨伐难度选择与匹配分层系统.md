## 1. 需求分析与目标

### 1.1 需求背景
当前野外讨伐历练仅有单一默认难度，难以满足高境界、高战力玩家的挑战诉求与进阶收益预期；同时，斗法（PVP）当前仅按同节点盲配，不同实力追求与风险偏好的队伍混杂。为此引入讨伐「难度选择」功能（默认、T1~T5 共六档），同步配套斗法三区间隔离匹配、怪物全属性指数强化、击杀经验与掉落率线性加成、全怪属性向上取整优化，以及讨伐任务弹窗与队伍界面的交互重构。

### 1.2 核心业务逻辑预期
1. **难度等级与分档**：
   - 难度共分为 6 档：默认（Tier 0）、T1（Tier 1）、T2（Tier 2）、T3（Tier 3）、T4（Tier 4）、T5（Tier 5）。
2. **斗法匹配三区间隔离**：
   - 区间划分：
     - 区间 0：默认难度（仅与默认难度匹配）
     - 区间 1：T1 ~ T3（T1、T2、T3 互相匹配）
     - 区间 2：T4 ~ T5（T4、T5 互相匹配）
   - 双匹配条件：必须在**同一地图节点（NodeId）**且处于**同一难度匹配区间**。
   - 节点队伍数量感知：当前区域显示的斗法队伍数量需根据自身当前选定的难度区间动态过滤显示。
3. **难度数值与收益加成**：
   - **怪物全属性（指数增长）**：每提升 1 个难度提升 25%，倍率为 $1.25^T$（T5 为 $1.25^5 \approx 3.0518$，即全属性提升约 305%）。
   - **经验收益（线性增长）**：每提升 1 个难度提升 60%，倍率为 $1 + 0.60 \times T$（T5 提升 300%，即 4.0 倍）。
   - **掉落率与掉落量（线性增长）**：
     - 掉落率提升 25%，倍率为 $1 + 0.25 \times T$（T5 提升 125%）。
     - 对于基础概率已达 100%（保底必掉）的条目，转为提升掉落量：数量区间按 $(1 + 0.25 \times T)$ 向上取整。
4. **怪物属性向上取整（底层计算）**：
   - 所有怪物的战斗属性（气血、法力、攻击、护甲、法抗、命中、闪避、暴击、抗暴、破招、化解等），在基础解算以及难度放大后，底层数值计算统一执行 `Math.Ceiling` 向上取整，彻底杜绝小数并保持前后端数值完全一致。
5. **讨伐独立弹窗优化**：
   - 隐藏原弹窗中的「消耗」、「产出」、「耗时」三项。
   - 隐藏顶部的副标题说明文本。
   - 难度选择下拉框放置在「斗法」复选框旁边并列排布。
   - 切换难度后，弹窗内怪物的数值 Hover 预览、击杀经验与掉落预览、当前节点参战队伍数量实时联动变更。
6. **队伍系统集成**：
   - 队伍档案（PartyProfile）支持设置难度（下拉框），队长可改、队员只读。
   - 组队讨伐会话开战时冻结队伍难度，生成对应强度的怪群与收益。

## 2. 详细设计与实现方案

### 2.1 协议与领域模型
- `ActionIntent` 与 `ActionIntentRequest`：新增 `Difficulty`（0~5，默认 0）。
- `PartyProfileRecord` 与 `PartyProfileDto`：新增 `Difficulty`（0~5，默认 0）。
- 组队会话 `ActionParticipationSpec`：新增 `Difficulty`。
- `social.parties` 表结构与迁移：增加 `difficulty` 列并提供 schema 升级。

### 2.2 怪物属性与掉落解算
- 在怪物属性生成与难度放大处接入向上取整算法与指数属性缩放。
- 在 `ApplyCombatRewards` 掉落结算处接入线性经验倍率与掉落率/掉落量提升逻辑。

### 2.3 斗法撮合与队伍感知
- `CountNodeDuelCombatTeams` 扩展支持难度区间过滤。
- 心跳 PongResponse 或队伍数量查询下发各区间队伍计数。
- `MatchDuelsOwned` 撮合算法增加难度区间一致性约束。

### 2.4 前端交互与视觉
- `App.tsx` 讨伐弹窗：精简信息行，增加难度下拉框，与斗法开关并列。
- `CombatEcologyPanel.tsx` 与 `MonsterDisplay.tsx`：支持传入选定难度，动态计算展示取整属性与加成掉落。
- `SocialPage.tsx`：队伍信息面板与创建表单增设难度下拉框。
