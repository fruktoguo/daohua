# TASK-20261004-12 药品回复走 Buff 5 秒口径与聚灵阵盘转普通持续消耗品

- **提出时间**：2026-10-04 17:00:00
- **状态**：✅ 已完成
- **分类**：数值模型调整 / 消耗品机制 / 全栈

## 需求

用户裁定：

1. 药品的每秒回复灵力值或者生命值，应该走 Buff，系统的是每 5 秒回复——药品回复数值语义为「每 5 秒结算点回复量」，结算走既有 Buff 通道与 5 秒资源/战斗边界，前端「每秒回复」文案是错误标注。
2. 阵盘是持续性消耗品，持续 300s，冷却 300s——聚灵阵盘从 `durable` 永驻部署改为普通持续消耗品：入场自动消耗 1 件充入 300 秒（战斗时钟扣减），耗竭后进入 300 秒冷却才允许再次补能。

## 现状判定

- 药品回复**已实现** Buff 通道：`consumable.buffs` 的 `hpRegen`/`mpRegen` 注入 `ActiveBuff`/`CombatBuffState`，与系统自然回复同口径在每 5 秒边界结算（战外 `CompleteResourceRegeneration`、战内 `CombatBuffTickSystem`）。唯一错误是前端词条「每秒气血/灵力回复」。
- 聚灵阵盘当前为 `durable:true` 永驻：不消耗、不耗竭、战外注入 +∞ `ActiveBuff`，与本次需求冲突，须改普通持续消耗品生命周期。
- 持续消耗品的 `cooldownSeconds` 此前无消费点；`CooldownUntilUnixSeconds` 槽位字段已存在（即时消耗品在用），本次复用同一字段承载持续消耗品冷却。

## 方案与落点

1. **配置** `config/game-data/items/materials.json`：`item.juling-formation-disk` 删除 `durable`，新增 `durationSeconds:300`、`cooldownSeconds:300`；保留 `isContinuous:true` 与 `buffs`（`mpRegen:5`、`mpRegenPostRatio:0.3`）。
2. **领域** `src/Domain/GameData/GameDataCatalog.cs`：`ConsumableDefinition` 增 `CooldownSeconds` 字段（默认 0），解析 `cooldownSeconds` 并校验有限非负；即时消耗品激活路径改用该字段（合并解析点，不再重复 raw 读）。
3. **ECS** `src/Ecs/Systems/CombatActionRules.cs`：
   - `RechargeCombatSustainedSlots`：`slot.CooldownUntilUnixSeconds > 入场时刻` 时跳过补能。
   - `DrainCombatSustainedSlots`：剩余归零（耗竭）时写 `CooldownUntilUnixSeconds = 耗竭墙钟时刻 + CooldownSeconds`；冷却起算点取耗竭时刻而非激活时刻——持续时长只在战斗内存活时钟扣减，若按激活起算，冷却恒不早于耗竭结束、永不生效。
   - `ActionExecutionRules.Timed.cs` 战外路径同口径补齐：`PrepareSustainedAutoUse` 行动起点补能加冷却门槛，`CompleteSustainedAutoUse` 耗竭时写冷却——`cooldownSeconds` 字段在非战斗域持续消耗品上语义一致，避免配置后静默失效。
4. **前端**：`market.zh.ts` 词条 `hpRegenPerSecond`/`mpRegenPerSecond` 重命名 `hpRegenPerFiveSeconds`/`mpRegenPerFiveSeconds`，文案改「每5秒气血/灵力回复」；`knownZhixue`/`knownShunqi` 同步；`ItemDisplay.tsx` 引用与 `template.csv` 同步。
5. **测试**：改写 `DurableFormationDiskInjectsInfiniteBuffWithoutConsuming` 为持续/冷却生命周期断言；`CombatConsumableTests` 增耗竭→冷却→再充能链路用例；增药品 Buff 回复（无即时回血、回复折叠进 5 秒公式）用例。
6. **文档**：总纲 §6.2.3/§6.8 与 §20.3 同步阵盘新生命周期与冷却语义。

## 边界

- 冷却语义：耗竭后 300 秒（墙钟）内不入战补能；搜寻/脱战阶段时长冻结，复活读条清空全部槽位冷却沿用既有口径。
- 阵盘效果只在遭遇战内存活时钟生效（`CombatBuffState` 注入，过期时刻=战斗时钟+槽位剩余）；搜寻间隙与战外自然回复不再受阵盘加成——与「持续消耗品」语义一致，区别于原 durable 全域驻留。
- `durable` 机制（`SyncDurableConsumableBuffs`/`ActiveBuff` 注入、`CreateEncounterCore` 复制、前端常驻展示）保留为通用能力，当前无物品使用。
- `CreateEncounter` 调试入口不做自动使用结算（无钱包/差量上下文），阵盘 buff 在该入口不生效，与既有自动使用口径一致。
