## 需求分析

用户询问项目是否存在「受伤时 / 攻击时」事件触发器或回调。现状确认：只有技能施放的轮询式条件触发（`defaultTriggers` / `DuelTriggerEvaluator` / 怪物 `TriggerHpRatio`），没有任何 OnHit / OnDamaged 回调；`hpDrainRatio`/`lifeStealRatio`/`armorDamageRatio`/`damageTakenRatio` 为只透传展示、结算不生效的死字段。

用户明确要求：

1. **不走 event 回调**，走「接口 + 传参」的钩子管线，可用特性（Attribute）排序。
2. 完整落地，可先写完再接入；吸血、吸蓝、反伤都要实现。
3. 效果数据来源用类型打包（行动 id、攻击者、被攻击者、技能信息合在一起），后续加效果不动签名。

## 实现方案

### 管线基础设施（`src/Domain/Combat/CombatHooks.cs`）

- `CombatEffectProfile`：效果强度参数包（HpDrainRatio / MpDrainRatio / DamageReflectRatio），挂在 `CombatantStats.Effects`；后续新增效果只加字段，不改签名。
- `CombatHitContext`：单次攻击结算上下文（Encounter/Attacker/Target/AttackStats/AbilityId/Side/Count/AtSeconds + Hit/Critical/Broken/Parried/Damage + DerivedEvents + NextRoll 确定性随机）。
- `CombatHookOrderAttribute`：类级排序特性；同值按类型全名字典序兜底，保证跨进程确定性。
- 三阶段接口：`ICombatResolveMutator`（判定前，可改 AttackStats）、`ICombatDamageMutator`（伤害已算未落账）、`ICombatAftermathHook`（落账后）。
- `CombatHookPipeline`：静态构造时反射扫描 Domain 程序集 → 无状态单例冻结有序数组，运行期零反射。
- `ResolveAttack` 为唯一插桩点（普攻/玩家技能/怪物技能/斗法镜像全部汇流此处）；衍生伤害直接落账不再走管线，防递归。

### 首批钩子

- `HpDrainHook`（Order 100）：命中且伤害>0 时攻击方按 `HpDrainRatio × 实伤` 回血，产出 Healing 衍生事件。
- `ManaDrainHook`（Order 110）：命中后按 `MpDrainRatio × 实伤` 从目标灵力池偷取（目标减、自身加至上限）。
- `DamageReflectHook`（Order 200）：受击方按 `DamageReflectRatio × 实伤` 反弹给攻击方（衍生伤害，计入受击方威胁值）。

### 数据通路

- 玩家：装备 `specialMechanics.hpDrainRatio` / `mpDrainRatio` / `damageReflectRatio` 经 `PlayerAttributeResolver` 汇入 `PlayerAttributes.Effects` → `ToCombatant()`。
- 怪物：配表 `hpDrainRatio` / `mpDrainRatio` / `damageReflectRatio` 经 `GameDataCatalog` 怪物构建汇入 `CombatantStats.Effects`。
- `ProtocolSnapshotMapper`：玩家 `hpDrainRatio` 展示字段从硬编码 0 改为真实结算值。
