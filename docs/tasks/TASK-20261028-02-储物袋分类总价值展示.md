# TASK-20261028-02 储物袋分类总价值展示

## 任务背景与核心需求

### 业务目标
在修仙行囊（储物袋 / 背包）界面中，各品类（重要、消耗品、装备法宝、功法、材料）已按大类分段展示。当前分类标题仅展示分类名称（如「材料」）及种类格数（如「12」），玩家无法直观感知该品类所持物品的总资产价值。
本任务旨在为各品类标题文本后追加呈现该品类的可支配总价值（以灵石计），使玩家对各分类资产规模一目了然。

### 核心逻辑预期
1. **单价解析口径**：
   - 装备类：根据装备定义或静态基础售价表 `resolveEquipmentBaseSellPrice`，结合当前强化等级变体通过 `calculateEquipmentSellPrice(eqBasePrice, enhancementLevel)` 折算强化增值后的单价；
   - 普通物品 / 材料 / 丹药 / 典籍：读取配表 `sellPrice`（或静态兜底 `resolveDefaultItemDefinition`）；
   - 灵石通宝自身单价为 1，功德等不可出售通宝单价为 0。
2. **扣除占用件数**：
   - 背包持存中可能包含当前已穿戴或正在强化锁定的件数（`getOccupiedEquipmentCounts`）；
   - 总价值只计算储物袋中实际可支配件数 `Math.max(0, item.amount - occupiedCount)` 的价值总和。
3. **展示形式与交互**：
   - 在各分组标题 `.inventory-group-title` 内分类名称后追加展示总价值标签（如 `（总价值 1.23万 灵石）`）；
   - 支持数字自动缩写与格式化（`formatNumber`），原生 `title` 属性提示精确到个位的灵石总数；
   - 保证移动端与桌面端自适应排版，在窄屏下不溢出不折乱。
4. **i18n 词条闭环**：
   - 新增 `app.inventoryPanel.groupTotalValue` 词条，同步更新 `zh-CN`、`template.csv`。

### 影响范围与实现边界
- **影响范围**：
  - `frontend/src/game/ids.ts`：导出 `resolveInventoryItemUnitPrice` 与 `calculateInventoryGroupTotalValue` 纯计算函数；
  - `frontend/src/components/RightSidebar.tsx`：计算并渲染各分组总价值；
  - `frontend/src/styles.css`：优化分组标题排版与样式；
  - `frontend/src/i18n/`：新增相关词条；
  - `frontend/src/game/inventoryGroup.test.mjs`：增加单元测试覆盖总价值计算。
- **实现边界**：纯前端展示与纯计算逻辑，不涉及服务端数据协议或持久化改动。
