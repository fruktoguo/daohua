## 需求背景

用户提出特质系统三分流设计（纯属性增益 / 常驻修饰 / 条件触发，「设计上分开，实现上有点差别」），首批落地两个特质：

- **看不到我**：开战起持续 10 秒，威胁始终为 0。用户裁定实现路径「开战添加一个 buff 就行了」。
- **力微饭否**：常规威胁规则为「1 点伤害→1 威胁、1 点治疗→3 威胁」；该特质使玩家**受到伤害时按伤害减免前的原始伤害等额增加自身威胁**（另类嘲讽）。

审计发现的机制缺口（实现前必须处理）：`EffectiveThreat` 全部消费点都在「玩家选敌方目标」侧，**敌方出手目标固定传 `encounter.Player`，玩家 Threat 无敌方侧消费端**。接通方式：敌方 `ResolvePending`/`DecideNextAction` 的 target 改为 `SelectTarget(PlayerAllies)` 威胁轮盘——单盟友时 `aliveCount==1` 提前返回不掷点，单盟友行为逐位等价；多盟友（召唤物/组队）自动生效。用户已裁定完整实现。

## 实现方案

### 特质三分流落法

| 类别 | 本期实例 | 路径 |
| --- | --- | --- |
| 常驻修饰（反应参数） | 力微饭否 | 特质 ID → `CombatTraitRules` 折算 `Effects.ThreatOnTakenPoints = 100` → 现有 OnHit 触发器管线消费 |
| 条件触发（授予型） | 看不到我 | 特质 ID → `CombatantStats.Traits` → `CombatEncounterState.Create` 开战授予 `buff.yinshen`（10s，`ThreatPoints = -100`） |

### 数据流

```text
PlayerProgression.TraitIds（VersionedList<string>，存档 v9）
  → PlayerAttributeResolver.Resolve（特质 → Effects 点数折算 + ID 集合透传）
  → PlayerAttributes.Traits → ToCombatant → CombatantStats.Traits/Effects
  → 看不到我：Create 授予 buff.yinshen（ThreatPoints:-100 → EffectiveThreat=0）
  → 力微饭否：OnHit handler 判宿主=受击方 → Target.Threat += raw×points/100
```

### 关键语义裁定

- `ThreatOnTakenPoints` 走 `CombatEffectProfile` 同族反应参数通道（点数/100）：受击时 `Threat += RawDamage × Points/100`，力微饭否授予 100（1:1）。装备/怪物配表同通道可复用。
- 「减免前原始伤害」锚定 `CombatHitContext.RawDamage`：`ResolveHit` 内把 `rawDamage`（第一层守方抗性穿甲前的面板威力）写入上下文，handler 不重算公式——第一层穿甲即守方减免起点，该字段是唯一无歧义口径。
- 受击判定 `context.Hit`：未命中不算「受到伤害」。
- 看不到我授予点只在 `CombatEncounterState.Create`（首次开战）；快照 Restore 由 Buffs 还原不重授；玩家复活（Respawn→DecideInitialActions）不重授。
- 全零威胁退化均匀是威胁系统固有规则：看不到我在全员零威胁时非绝对隐身（权重仍为最低）。
- 敌方轮盘随机通道：出手 18、决策 19（目标抽取族 3/16/17 顺延）。
