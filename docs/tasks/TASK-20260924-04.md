# TASK-20260924-04 讨伐弹窗节点生态化重构

## 需求
- 讨伐行动弹窗（`ActionModal`）不再平铺全部怪物简要数值：主体改为当前地点生态怪物**图标网格**；悬停图标出**简要信息**，单击图标弹出**详细信息**。
- 行动显示名按当前驻留地点本地化：人在「漱玉溪」时历练页与弹窗显示「讨伐 漱玉溪」，不再固定显示「讨伐 青云仙山」；弹窗内怪物也必须按当前节点生态解析，而不是行动钉死的 `combatEncounterId`。
- 文档与实际代码同步修复。

## 分析
- **遭遇错配根因**：`ActionModal` 按 `action.combatEncounterId`（固定 `encounter.twilight-pass`）渲染 `CombatEncounterPanel`；服务端 `SimulationEngine.ResolveCombatEncounter` 实际按玩家当前节点 `encounterIds` 确定性抽取遭遇，前后端口径不一致。
- **生态数据源**：静态目录 `maps[].nodes[].monsters/eliteEnemies/bossEnemies`（`StaticGameCatalogMapper.ToNode` 已按节点 `encounterIds` 预解析为 `CombatantDefinition` 全字段），与实战遭遇同根同源，前端直接取用，无需自行解析遭遇池。
- **名称本地化**：行动名内嵌地图名（「讨伐 青云仙山」「讨伐 星陨异境」）；显示层把当前地图名替换为当前节点名（行进中 `nodeId=null` 不替换），覆盖行动卡、行动弹窗、队列名与战斗区显示名。
- **交互模板**：复用 `FloatingPopover` 双层嵌套（内层 hover 简卡 `interactive={false}` + 外层 click 详卡）与 `FloatingInfoCard`，对齐 `InventoryItemCell`/`MapMonsterPill` 既有模式。
