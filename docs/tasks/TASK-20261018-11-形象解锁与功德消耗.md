# TASK-20261018-11 形象解锁与功德消耗系统

## 1. 任务背景与核心诉求

原先玩家主角形象（道貌外观）直接全部开放自选，现重构为修仙境界成长与功德积累的解锁体系：
1. **默认解锁基线**：默认仅开放「女剑修」（`default` / `player`）与「男剑修」（`male` / `player-male`）两款经典剑修形象。
2. **功德消耗解锁**：
   - 剩余所有道貌形象（魔修、丹师、火修、武尊、玉修、灵尊、幽仙、星君、天师、哥特萝莉、机动JK、重装萌妹、卫衣JK等），均需消耗 **5,000 功德**解锁。
   - 货币抵扣规则：**同时支持使用绑定功德（`item.gongde-bound`）与流通功德（`item.gongde`），且严格优先扣除绑定功德**。
   - 若（绑定功德 + 流通功德）< 5,000，则提示功德不足。
3. **二次确认防误触**：
   - 消耗功德时必须弹出二次确认弹窗（复用 `ConfirmDialog` 通用组件）。
   - 弹窗内明确展示即将扣除的功德总量及明细（如优先扣除绑定功德数量、流通功德数量），得到用户确认后方才上行解锁。
4. **服务端权威持久化与防作弊**：
   - 解锁状态作为角色设置分段（`PlayerSettingsState`）的权威字段 `unlockedAvatars` 落盘持久化。
   - 新增 `player.unlock_avatar` 命令，在同一资产事务内扣除功德并标记解锁；
   - 服务端 `player.set_avatar` 强校验：禁止佩戴任何尚未解锁的形象，杜绝客户端绕过伪造。

## 2. 架构设计与实现方案

### 2.1 领域与服务端设计 (`Domain` & `Server`)
1. **领域设置实体 `PlayerSettingsState`**：
   - 新增 `HashSet<string> UnlockedAvatars`，默认初始化包含 `["player", "player-male"]`。
   - 提供 `bool IsAvatarUnlocked(string? avatar)`：女剑修与男剑修恒为 true；其余检查是否存在于已解锁集合中。
   - 提供 `bool UnlockAvatar(string? avatar)`：规整化并加入已解锁集合，自动标脏 `PlayerSectionKind.Settings`。
   - `PlayerAggregate.SetAvatar`：增加前置校验，未解锁形象拒绝设置并抛出领域异常。
2. **存档编解码与快照 (`SectionCodec` & `PlayerStateDocument`)**：
   - `SettingsDocument` 与 `PlayerSettingsStateDocument` 扩充 `IReadOnlyList<string>? UnlockedAvatars = null`。
   - 缺省解码为 `["player", "player-male"]`，无缝兼容老存档。
   - 升级 `SectionCodec.CurrentSchemaVersion`（33 -> 34）与 `PostgresSchema.Version`（33 -> 34）。
   - 新增 `migrations/0034_v33_to_v34.sql`。
3. **命令调度与资产结算 (`EcsPlayerRuntimeAdapter`)**：
   - `player.unlock_avatar` 命令：
     - 规整化目标形象 ID 并校验是否有效；
     - 检查是否已解锁（已解锁直接幂等返回）；
     - 读取玩家资产钱包，计算 `boundMerit`（`item.gongde-bound`）与 `normalMerit`（`item.gongde`）；
     - 若总功德不足 5,000，失败返回 `INSUFFICIENT_MERIT`；
     - 优先扣除绑定功德：`deductBound = Math.Min(boundMerit, 5000)`，`deductNormal = 5000 - deductBound`；
     - 组装扣除资产流水 `AssetDelta` 并调用 `aggregate.UnlockAvatar` + `aggregate.SetAvatar`，通过 `CommitPlayerAssetsAsync` 提交；
   - `player.set_avatar` 命令：
     - 校验 `before.State.Settings.IsAvatarUnlocked(normalized)`，未解锁返回 `AVATAR_LOCKED` 错误。

### 2.2 前端状态与交互实现 (`frontend`)
1. **形象状态管理器 `avatarStore.ts`**：
   - 状态中扩充 `unlockedAvatars: readonly string[]`（默认 `['default', 'male']`）；
   - 提供 `isUnlocked(avatarId: PlayerAvatarId): boolean` 查询；
   - 提供 `setUnlockedAvatars(avatars: readonly string[]): void` 批量更新。
2. **快照解析链路 `snapshot.ts`**：
   - 在全量快照与增量快照的 `settings` 映射处理中，提取 `settings.unlockedAvatars` 并同步至 `avatarStore`。
3. **设置页形象分类 `SettingsPage.tsx`**：
   - 瓦片呈现：已解锁正常可选；未解锁暗调蒙层并带有锁头徽章与「5000」功德标识；
   - 二次确认交互：点击未解锁瓦片，计算背包中绑定与流通功德总和；弹出 `ConfirmDialog` 展示消耗明细并优先扣除绑定功德；功德充足确认后上行 `player.unlock_avatar`。
