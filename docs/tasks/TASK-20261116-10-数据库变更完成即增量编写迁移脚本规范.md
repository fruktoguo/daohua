## 1. 需求背景与核心边界

此前 `TASK-20261115-01` 取消日常手写单次 `migrations/NNNN_vX_to_vY.sql` 后，本地开发/测试库在版本推进后缺少增量脚本，导致本地测试频繁面临只能 `RESET` 清库的困境。

经与用户对齐，确立以下核心规则调整：

1. **开发完成时必须增量编写迁移/修复脚本**：凡涉及数据库 DDL/权限、`SectionCodec` 存档载荷或影响旧存档加载的配表删改，在任务完成时**必须**同步推进版本号、登记 [`docs/backend/db-version-changes.md`](../backend/db-version-changes.md)，并**立即增量编写当前最新版本的迁移/修复脚本 `migrations/NNNN_v{from}_to_v{to}.sql`**（同步更新 `migrations/README.md`），确保本地测试库可平滑就地升级。
2. **`prod-release` 时交叉查漏与兜底**：正式服发布前，阶段 0 依然通读 `db-version-changes.md` 并与 `git diff`、`migrations/` 链条交叉对账，**检查是否有遗漏或断链**；无遗漏则直接走常规链式迁移，有遗漏则先补齐（或按停写手迁路线确认后执行）。
3. **保留既有隔离边界**：`migrations/` 仍保持可整体删除、不参与编译与镜像构建、代码中禁止 migration runner；`docs/backend/db-version-changes.md` 继续作为变更台账保留。
