## 2. 问题根因分析

1. **伤害浮字包含生硬中文文字标签**：
   - 当前战斗伤害数字前端渲染时，暴击、破招、化解（拆招）、破招·暴击在数字前方渲染了文本形式的胶囊标签（如 `[暴击]`、`[破招]`、`[化解]`、`[破招·暴击]`）；
   - 在二值属性极简小图标（`StatGlyph`，包括 `glyph.crit.webp`、`glyph.parry-break.webp`、`glyph.parry-resolve.webp`）已经全量实装入库的前提下，文本标签占用过多横向排版宽度且视觉上显得杂乱臃肿；
   - 伤害数字本身只需要高对比的战斗数字与对应机制的极简小图标徽记，无需文字赘述。
2. **暴击伤害数字附加感叹号冗余**：
   - 原暴击伤害格式化逻辑中，单暴击追加了 `!`、破招暴击复合追加了 `!!`（如 `-2500!`、`-3800!!`）；
   - 用户明确要求移除暴击数字末尾的感叹号，仅保留纯净规范的格式化负数伤害，由金色/烈橙色阶大字体、电芒与小图标徽章承担暴击视觉层级。
3. **闪避（Dodge）纯文本语义保留**：
   - 闪避事件并非伤害数字（未命中且无伤害数值），必须清晰保留纯文本「闪避」（若附带化解则附带化解图标），身法飘逸滑行不可隐匿。

---

## 3. 实施方案

1. **组件修改（CombatArena.tsx）**：
   - 引入 `StatGlyph` 极简二值属性小图标组件；
   - 声明 `renderFloatBadgeIcon` 辅助函数，将 `badge`（`'crit'` / `'break'` / `'parry'` / `'break-crit'`）映射为对应的二值小图标：
     - `crit`：`<StatGlyph glyph="crit" size={13.5} />`（道金）
     - `break`：`<StatGlyph glyph="parry-break" size={13.5} />`（纯白/琥珀橙）
     - `parry`：`<StatGlyph glyph="parry-resolve" size={13.5} />`（银白/冰蓝）
     - `break-crit`：并排展示破招与暴击双图标 `<StatGlyph glyph="parry-break" size={13.5} /><StatGlyph glyph="crit" size={13.5} />`
   - 保留 `badgeLabel` 作为徽标容器的 `aria-label` 与 `title` 属性，保障无障碍辅助功能与悬停语义说明；
   - 移除命中伤害字符串中对 `isCrit` 与 `isBreakCrit` 追加的 `!` 和 `!!`，直接使用纯净的 `formattedDamage`；
   - 闪避（`!event.hit`）依旧完整保留 `t('combat.arena.dodge')`（「闪避」）纯文本展示。
2. **样式调优（expedition.css）**：
   - 优化 `.arena-float-badge` 样式为 `display: inline-flex; align-items: center; justify-content: center; gap: 2px;`；
   - 调整 padding（`1.5px 3.5px`）与 margin，使小图标在微光胶囊中居中对齐、轮廓饱满，配合既有的流派微光阴影（box-shadow）形成高品质冲击反馈。
