## 1. 需求理解与目标边界

- **核心需求**：当服务器处于版本更新/迁移停机窗口，或发生意外宕机/重启恢复（“服务器爆炸”）时，不再向玩家直接暴露裸 `502`/`503` 网关错误或无法访问页面，而是展示与《道化太初》当前视觉风格完全一致的临时状态页面，明确告知玩家当前发生了什么，并在服务恢复后自动刷新恢复。
- **实现边界**：
  1. **宿主机 Caddy 网关层与静态维护页（主防线）**：由于生产前端 `wwwroot` 托管在 `daohua-app` 容器内，容器停止或不可达时必须由宿主机 Caddy 直接兜底（`/opt/daohua/static/status/`）；支持通过 `/opt/daohua/maintenance.flag` 区分「计划更新维护中」与「意外异常/重启恢复中」两种场景，并兼顾 `/api/*`、`/ws` 的标准 JSON `503` 错误响应与严苛 CSP（`script-src 'self'`，无内联脚本）。
  2. **视觉风格一致性**：对齐 [ConnectingPage.tsx](file:///d:/Project/Vibe/DaoHua/frontend/src/components/ConnectingPage.tsx)、[styles.css](file:///d:/Project/Vibe/DaoHua/frontend/src/styles.css) 与 [theme.css](file:///d:/Project/Vibe/DaoHua/frontend/src/styles/theme.css)，支持浅色（宣纸朱印）与深色（玄墨金纹）双主题（读取 `localStorage.getItem('daohua.theme')`），沿用 `.panel` 四角云纹雕花、灵气微粒与太极聚灵/警示动效，且不进入 `frontend/dist` 与 Android `asset-manifest.json`。
  3. **部署与自动更新脚本联动**：[deploy-prod.sh](file:///d:/Project/Vibe/DaoHua/scripts/deploy-prod.sh) 与 [ccr-auto-update.sh](file:///d:/Project/Vibe/DaoHua/deploy/ccr-auto-update.sh) 在更新窗口自动管理 `maintenance.flag`，并在停写前先就位静态维护页与 Caddy 配置。
  4. **已在线客户端平滑衔接**：[gameClient.ts](file:///d:/Project/Vibe/DaoHua/frontend/src/network/gameClient.ts) 在重连探测 `/api/v1/auth/session` 识别 `SERVER_UPDATING` / `SERVER_UNAVAILABLE`（`502`/`503`/`504`），在断连重试提示与熔断页精准告知玩家真实原因。
