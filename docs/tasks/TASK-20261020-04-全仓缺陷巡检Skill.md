## 需求

用户要求共同设计一个 **goal 指令**，用于自动分析、发现并修复前后端潜在问题。

## 关键决策

1. **载体选 SKILL.md 而非命令文件**：goal 模式每轮以隐藏 `goal-continuation` 消息续跑，命令文件是一次性展开，续跑后会丢失规程；Skill 每轮可被重新 `read`，且能被 `/skill:defect-sweep` 手动单轮调用。
2. **一条目标句 + 磁盘台账**：goal 目标句只引用「按 skill 规程执行直到退出判据满足」，全部细则留在 `SKILL.md`，避免目标句膨胀到不可维护；每轮结果落盘 `docs/tasks/` 的表格，跨轮不依赖上下文记忆。
3. **九切片轮转**：每轮只做一个切片，防止跨领域发散与上下文污染；切片边界与仓库真实目录一一对应。
4. **三级分诊**：自主级（机械可判定、不改变设计语义）直接修；报审级（玩法/数值/协议/存档/测试删除/生产操作）只汇总；记录级转 `comment-audit` / `doc-optimize`。
5. **硬停机判据**：三选一，且明确「停机 ≠ 无问题」，必须报未覆盖切片与残留风险，阻断「已全面检查」式空结论。

## 退出判据

1. 九切片各至少一轮且最近一整轮零新增自主级缺陷；
2. 连续两轮无新证据、无新工具活动；
3. 达轮数上限（默认 8）。
