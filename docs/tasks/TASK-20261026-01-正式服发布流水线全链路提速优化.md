## 1. 需求复述与设计理解

### 1.1 背景与现状
当前项目正式服发布流水线（`scripts/release-prod.sh` 及 `prod-release` Skill）单次执行耗时普遍在 **10 ~ 15 分钟**（如 TASK-20261025-05 门禁 324s、全流程 10 分钟；TASK-20261024-07 耗时 30 分钟），严重制约高频迭代效率。
经深度剖析，主要瓶颈在于：
1. **阶段 0 门禁 (`verify.sh --full`) 串行化**：5 套 C# 测试与前端检查/测试/构建依次串行推进，耗时 5.5 分钟；
2. **odin 掌机传输网络风暴**：`ComputeNode` 自包含产物含 344 个小文件（80MB），采用 `scp -r` 逐文件交互传输，SSH 握手 RTT 在掌机网络下放大至 1~2 分钟；
3. **前端被重复全量构建 3 次**：门禁一次（宿主机）、Docker 构建一次（容器内 `npm ci` + `npm run build`）、APK 打包一次（宿主机）；
4. **Docker 容器健康检查盲等**：`start-period=20s` 导致容器启动后必等至少 20 秒才判定 healthy；
5. **远端备份 `-Z 9` 极限压缩**：2c4g 主服务器跑 gzip:9 压缩导出，长时间占满 CPU，拖慢后续镜像拉取；
6. **Docker 构建依赖海外 npm 源**：容器内默认访问 `registry.npmjs.org` 极易偶发严重延迟。

### 1.2 预期目标
- 将日常发布总耗时从 **10~15 分钟** 压缩至 **3~4 分钟以内**；
- 保持全部生产安全红线与多阶段构建、备份校验、指纹对齐完全不变。
