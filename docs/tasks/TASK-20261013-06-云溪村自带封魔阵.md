## 需求原文

> 给初始地点弄一个 30 级的自带的封魔阵。

## 需求分析

- 「初始地点」= 出生节点 `node.yunxi-village`（云溪村，`snapshot.ts` 缺省节点与遭遇 `encounter.qi-beast` 所在地）。
- 「自带的封魔阵」= 节点初始即存在的竣工建筑，不走玩家建造流程；
  依赖 TASK-20261013-05 的 `building.demon-seal-array`。
- 「30 级」= 竣工 `Level=30`，封魔阵削弱比 = 0.01×30 = −30% 怪物气血上限与双攻双防。
- 后续仍走通用规则：玩家可正常贡献升级（L30→31），播种不覆盖既有行。

## 实现方案

1. 文档先行：`09-节点公共建筑系统.md` §9.4 节点配置清单增补 `prebuiltBuildings` 字段语义
   （节点自带竣工建筑，播种幂等、不覆盖既有行），重建 `总纲/index.html`。
2. 领域：`NodeBuildingRules.ResolvePrebuiltBuildings(JsonElement node)` 解析节点
   `prebuiltBuildings`（`[{buildingId, level}]`，level≥1，非法项跳过，严格校验由 DataTool 承担）。
3. 注册表：`NodeBuildingRegistry.EnsureLoadedAsync` 全量装载后遍历 `gameData.Maps[].nodes[]`，
   对每条种子行执行 `InsertIfAbsentAsync`（Level=N、TargetLevel=0、StartedAt=0、空材料——
   竣工态不参与惰性完工推算）；已存在行经 `TryLoadAsync` 采纳活行，跨实例由唯一约束收敛。
4. 配表：`qingyun_mountain.json` 云溪村节点增 `prebuiltBuildings`（封魔阵 L30）。
   不加 scenery 陈设条目：`world.buildings` 与 `nodeBuildings` 同列渲染共用 entityId 键，
   同名双卡会造成 React 键冲突与展示重复，功能建筑卡本身已含名称/等级/效果与详情入口。
5. DataTool：`prebuiltBuildings[].buildingId` 建筑引用存在性 + `level` 正整数校验。
6. 测试：`NodeBuildingRulesTests` 补 `ResolvePrebuiltBuildings` 解析用例；
   `NodeBuildingRegistryTests` 补播种用例（装载即竣工 L30、效果聚合生效、二次装载不重复建行）。
