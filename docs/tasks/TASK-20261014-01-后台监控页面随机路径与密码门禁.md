## 1. 用户需求与设计确认

> 调整ops,当前的本地是ops,正式服务器没法用,增加一个独立的后台监控页面,链接使用随机网址,并且需要输入密码

经与用户对齐确认：
1. **复用现有 Ops 全功能面板**：正式服与本地共用 `OpsApp` 全部监控与运维能力；本地开发保留 `/ops` 兼容 `dev.sh` 与 `dev-tui.mjs`，同时支持动态随机路径。
2. **启动时动态随机生成路径**：未显式配置 `Ops:Path` 时，服务端每次启动自动生成高熵随机路径 `/ops-<16位hex>` 并输出到启动日志；生产环境也可在 `/opt/daohua/daohua.env` 中通过 `OPS_PATH` 固定。
3. **读写全量密码验证**：进入后台页面前先展示独立密码登录门禁页；服务端所有 Ops 只读与写操作接口均强制校验 `X-Ops-Token` 密码头（移除原仅限内网/回环 IP 的来源限制，使正式服经 Caddy 反代可正常访问）；服务端对任何未匹配当前激活 Ops 路径的 `/ops` 及 `/ops-*` 请求直接返回 HTTP 404，防止 SPA fallback 暴露后台入口。
