## 一、背景与根因

在线上核查「星金丹 vs 王总」斗法（`v0.3.23`）时，发现原战斗模型将 `CombatantState.IsPlayer` 硬绑定为 `Id.StartsWith("player")`，导致 PVP 中应战方（`enemy:0`）`IsPlayer == false`，发起方所有依赖 `target-enemy/is-player` 或 `enemies/has-player` 的消耗品与技能全面哑火。进一步全链路审计暴露出 6 处底层结构性不对称：

1. **身份与阵营耦合**：缺少正交的 `CombatSide`（`SideA` / `SideB`）与 `CombatantKind`（`Player` / `Monster` / `Summon`），多处靠 ID 前缀或 `PlayerAllies.Contains` 反查；
2. **同刻消耗品偏向发起方且单向不收敛**：`DuelScriptEngine` 固定先跑完发起方全部消耗品再跑应战方，同刻雷击符永远发起方抢先斩杀，且后手打残先手不触发当刻收敛吃药；
3. **同刻出手顺序偏向甲方**：`CombatEventAdvanceSystem.Boundaries` 固定先 `PlayerAllies` 后 `Enemies`，同攻速互杀甲方 100% 胜出；
4. **开局决策与周期 Tick 顺序不对称**：`DecideInitialActions` 先敌后友导致灵力视野不等；`CombatBuffTickSystem` 先甲后乙导致同刻燃魂致死中途改变「单挑王 / 我要打十个」状态；
5. **随机侧位与目标通道不对称**：友方 `channel 3` vs 敌方 `channel 18/19`，且固定绑定发起方=0、应战方=1，交换 `(initiator, defender)` 会改变随机流与胜负；
6. **前端模拟器阵盘反击单侧硬编码**：`combatEngine.ts` 的 `triggerFormationReactiveStrike` 直接对 `playerAllies` 提前返回，阻断右侧玩家触发天雷/血煞阵盘反击。

## 二、核心设计方案（已与用户确认）

1. **正交一等模型**：引入 `CombatSide`（`SideA`/`SideB`）与 `CombatantKind`（`Player`/`Monster`/`Summon`），`IsPlayer`/`IsMonster`/`IsSummon` 统一由 `Kind` 派生；`CombatEncounterState` 新增 `IsSymmetric`、`SideA`/`SideB`、`UnitsOf`/`AlliesOf`/`OpponentsOf`/`FindUnit` 及 `CreateSymmetric(...)`（两侧对称命名 `sideA:{i}` / `sideB:{i}`，默认均为 `Player`）；PVE 路径保留既有序列与确定性位级一致。
2. **同刻同时生效（Simultaneous Barrier）**：
   - 开局/波末动作决策：先基于同一冻结快照并行求值触发器与技能选择，再统一提交预扣灵力与读条时刻；
   - 同刻周期 Tick：双侧全员回复/燃魂/掉层结算完后统一剔除到期 Buff 并刷新存活人数特质；
   - 同刻出手（普攻/技能）：收集本刻双侧所有到期存活单位，同刻 ≥2 名单位同时出手时在波初快照下完成攻防/反应/Buff 求值，波末统一按「先落伤 → 存活者吃治疗/吸血 → 落灵力与 Buff → 刷新存活人数特质 → 回填尾帧资源」提交，允许同刻互杀判平，彻底消除先手偏向与满血吸血顺序偏差；
   - 同刻消耗品（多方对称波次收敛）：持续阵盘按总纲 §7.9.5 全队生效，即时/续期消耗品按波次快照双侧同步判定与落账，循环收敛直至整波无人触发。
3. **严格交换不变性与无偏随机流**：对称模式双侧共用目标通道（`18`/`19`），`DuelScriptEngine.Resolve` 按双方规范 `PlayerId` 序列归序并按 `seed & 1` 对称分配随机流侧标签，确保 `Resolve(A, B, seed)` 与 `Resolve(B, A, seed)` 100% 镜像等价，且跨种子对任意 UUID 严格 50/50 无偏。
4. **1~5 vs 1~5 多方斗法协议升级（Schema `v70 -> v71`，存档标签 `v49 -> v50`，additive 零破档）**：
   - `DuelScriptEvent` 新增 `AttackerUnitIndex = 0`、`TargetUnitIndex = 0`；
   - 新增 `DuelPlaybackUnit` 单位回放镜像，`DuelPlaybackState` 新增 `SelfUnitIndex = 0`、`SelfUnits`、`OpponentUnits` 及 `ForTeamViewer(...)`；
   - `DuelScriptEngine.Resolve` 主实现扩展为两侧 1~5 名 `IReadOnlyList<DuelCombatant>`，单人重载薄委托；`DuelActionRecorder`、`AdvanceDuelPlayback`、`ProtocolSnapshotMapper` 与前端 `CombatArena` / `useCombatVfx` / `CombatStatsPanel` 全链同步支持多方视角与 1v1 向下兼容。
   - 增量迁移脚本 `migrations/0071_v70_to_v71.sql`（推进三张存档表标签 `v49 -> v50`，登记 `schema_version = 71`）。
