# TASK-20261105-01 标准版本号规范与流水线自动化变动规则设计

## 1. 任务背景与核心目标

当前道化太初全系统统一采用 Git Commit SHA（形如 `sha-6a962404` 或 `v0.1.0-sha-041398c2`）作为不可变镜像标签、服务端运行时展示版本、前端构建版本以及发布标签。

### 现状痛点
1. **不可比性与无序**：Git SHA 属于散列校验码，不具备数学单调性，开发者、运维系统以及前端更新感知机制无法直观对比版本的新旧或计算迭代跨度。
2. **外部生态与玩家体感不友好**：向玩家发布更新公告、移动端安装包上架应用商店（TapTap、Google Play 等）、GitHub Releases 归档时，`sha-xxxx` 无法传递产品里程碑（内测演进、公测、大版本、新境界等），显得杂乱且业余。
3. **缺乏语义化指导**：缺少统一的标准变动规则矩阵，开发团队无法明确何时该升大版本、何时该升功能版本、何时属于日常热更或数值配平。

### 核心目标
设计符合国际通行 **语义化版本 2.0.0 (Semantic Versioning, SemVer)** 标准的版本号规则与变动判定矩阵，定义全仓单一权威版本源（SSOT），清晰界定多端多模块（Web SPA、Android APK、Server、ComputeNode、OCI 镜像、数据库 Schema、协议契约）的映射关系与解耦边界，并提供平滑替代现有 SHA 流水线的工程改造实施路径。

---

## 2. 详细设计方案

### 2.1 版本号标准格式（SemVer 2.0.0）

遵循 `v<MAJOR>.<MINOR>.<PATCH>[-<PRE_RELEASE>][+<BUILD_METADATA>]`：

- **基础正式版本格式**：`vX.Y.Z`（例如：`v0.2.0`、`v1.0.0`）
  - `MAJOR`（主版本号）：重大破坏性架构重构、正式公测商业化里程碑、底层不可逆断代更新。
  - `MINOR`（次版本号）：新增大型玩法系统、新境界开放、配表大版本、向下兼容的功能迭代。
  - `PATCH`（修订版本号）：Bug 修复、数值配平、文案热更、日常小修补。
- **预发布标识（Pre-release）**：
  - `vX.Y.Z-alpha.N`：内部技术验证版本。
  - `vX.Y.Z-beta.N`：玩家小范围封测版本。
  - `vX.Y.Z-rc.N`：发布候选版本（Release Candidate）。
- **构建元数据（Build Metadata）**：
  - `+build.<commit_sha>` 或 `+<git_rev>`，仅用于内部构建追溯，不参与 SemVer 优先级对比。

### 2.2 变动判定矩阵（何时变动哪一位？）

| 版本位 | 变动场景定义 | 业务与系统示例 | 关联动作 / 联动规则 |
| :--- | :--- | :--- | :--- |
| **MAJOR (X)** | 1. 游戏运营阶段里程碑跨越<br>2. 核心网络通信协议不可逆断代<br>3. 存档格式发生彻底断代（打破兼容且清空重置） | - 从内测阶段（`0.y.z`）迈入正式不删档公测（`1.0.0`）<br>- 全新赛季重置或年度资料片 | - `MINOR` 归零，`PATCH` 归零<br>- 数据库 Schema 与 Protocol 版本同步升级<br>- 前端强制断线重连并拉取最新全量资源 |
| **MINOR (Y)** | 1. 玩法系统或大型功能新增<br>2. 境界等级上限扩展<br>3. 向下兼容的领域模型演进与 API 扩展 | - 开放全新大境界（如筑基期、结丹期）及专属配表<br>- 新增宗门领地、跨服坊市、难度分层等完整系统 | - `PATCH` 归零<br>- 配表指纹更新<br>- 触发客户端自动平滑重载感知（`versionManager`） |
| **PATCH (Z)** | 1. Bug 修复与稳定性补丁<br>2. 游戏数值配平与经济学调整<br>3. 界面交互优化、i18n 补充、文案修正 | - 修复怪物掉落数量计算漏洞<br>- 调整装备强化概率或副手属性加成<br>- 修复 CSS 样式错位或补全缺失 i18n 词条 | - 仅递增 `PATCH`<br>- 如不涉及底层协议与二进制结构，老客户端可平滑热更新或自动静默重载 |

### 2.3 单源权威（SSOT - Single Source of Truth）

为避免前端、后端、C# 工程文件、Docker 镜像构建脚本各自定义版本导致的分叉，建立仓库级单一版本真源：

- **真源位置**：`version.json`（位于仓库根目录）
  ```json
  {
    "version": "0.2.0",
    "stage": "alpha",
    "protocolVersion": 2,
    "releaseNotes": "讨伐难度分层与全新物品反查系统"
  }
  ```
- **消费与分发**：
  - **前端**：`frontend/package.json` 的 `version` 自动与根 `version.json` 同步；Vite 构建时注入 `VITE_APP_VERSION="v0.2.0"`。
  - **服务端 / ComputeNode**：构建时通过 `-p:InformationalVersion="v0.2.0"` 或统一读取 `Directory.Build.props` 注入 C# 程序集。
  - **运维与状态端点**：`/healthz`、`/readyz`、`/api/v1/system/version` 及 WebSocket HelloAck 均回显统一的标准版本号。

### 2.4 各端与多模块映射矩阵

| 目标端 / 产物 | 映射字段 / 规范 | 示例值 | 说明 |
| :--- | :--- | :--- | :--- |
| **主服 / 计算节点镜像** | `IMAGE_TAG` | `daohua:v0.2.0`<br>`daohua:prod` | 不可变标签使用 `v0.2.0`（取代 `sha-xxxx`），配合不可变 Digest 与 `prod` 浮动标签 |
| **前端 SPA** | `VITE_APP_VERSION` | `v0.2.0` | 前端界面右上角/设置面板显示；供 `versionManager` 探针判定 |
| **Android APK** | `versionName` | `0.2.0` | 玩家视觉可见版本，展示于应用详情与商店更新公告 |
| **Android APK** | `versionCode` | `20000` | 纯整型单调自增码，公式：`MAJOR*100000 + MINOR*1000 + PATCH*10 + BUILD` |
| **GitHub Releases** | `Tag` & `Title` | `v0.2.0`<br>`道化太初 v0.2.0` | 取代之前的 `v0.1.0-sha-041398c2` |
| **TapTap 开发者中心** | 版本号与更新说明 | `0.2.0` | 由 `scripts/taptap-publish.sh` 读取统一版本并上传包体 |

### 2.5 体系解耦：与其他内部版本号的关系边界

产品发布版本号（Release Version）必须与系统内部的技术指标严格解耦，职责互不干扰：

1. **发布版本号（Release Version，`vX.Y.Z`）**：面向玩家、运维部署、应用商店和整体产品迭代；
2. **协议契约版本（`ProtocolConstants.CurrentVersion`）**：仅用于标记 WebSocket 帧格式与信封序列化契约兼容性；
3. **数据库架构版本（`PostgresSchema.Version`）**：仅用于标记 PostgreSQL 表结构与系统列演进（对应 `migrations/`）；
4. **存档分段编解码版本（`SectionCodec.CurrentSchemaVersion`）**：仅用于标记玩家二进制/JSON 存档载荷的向下兼容能力；
5. **配表内容指纹（`GameDataCatalog.Fingerprint`）**：仅用于校验配表内容增量一致性（SHA-256 哈希）。

---

### 2.6 流水线脚本改造方案（平滑淘汰 SHA）

1. **`scripts/docker-build-prod.sh`**：
   - 默认优先从 `version.json` 读取 `vX.Y.Z` 作为 `RELEASE_TAG`，允许命令行显式 `--release-tag` 覆盖；
   - Git Commit SHA 仅作为构建元数据写入 OCI Label `org.opencontainers.image.revision` 与 C# 编译元数据中，不再作为镜像的主 Tag 名字。
2. **`scripts/release-prod.sh`**：
   - 支持参数 `--bump patch|minor|major` 自动升级版本号，或交互式确认当前发布的版本号；
   - 自动生成对应版本的不可变镜像标签 `daohua:vX.Y.Z`、APK 包 `daohua-vX.Y.Z.apk` 与 Git Tag `vX.Y.Z`。
3. **`scripts/build-apk.sh`**：
   - 读取统一版本的 `MAJOR.MINOR.PATCH` 自动注入 Android `versionName` 与 `versionCode`。
