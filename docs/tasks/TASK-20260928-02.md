# TASK-20260928-02：观测埋点编译期零成本化 + YuoCore 内核正式定名

- 登记时间：2026-09-28 13:00
- 类别：性能 / 架构收敛
- 用户原话：「去掉影响性能的埋点，或者说弄成那种，关闭就完全不影响性能的；然后所有都改为正式的，YuoCore不要加后面的优化后缀，就是相当于正式采用了」

## 背景

三版本对照设施退役后（TASK-20260928-01），仓库仍保留两套命名残留：内核目录 `vendor/YuoCore-optimized`、基准变体 `ecs-optimized`；观测埋点（`RuntimeInstrumentation`/`YuoCoreTrace`/`ecs.system.run.*`）虽有无监听器早退，但仍在生产二进制中携带委托检查与结构体开销。

## 实施

### 埋点编译期零成本化

- `Directory.Build.props`：新增 `DaoHuaObservability` 属性，`-p:DaoHuaObservability=false` 时注入 `DAOHUA_OBSERVE_OFF;YUOCORE_TRACE_OFF` 编译常量；同时删除已死的 `BenchVariant` obj 隔离块（同名程序集双变体机制已随基线退役）。
- `src/Domain/Common/RuntimeInstrumentation.cs`：`#if !DAOHUA_OBSERVE_OFF` 保留真实实现（Meter/Stopwatch/AsyncLocal），`#else` 全部入口 `=> default`/空操作；`Measurement`/`ScenarioScope` 的 `Dispose` 在 OFF 下为空。OFF 构建中所有 `using var m = Measure(...)` 调用点经内联+死代码消除后零指令。
- `vendor/YuoCore/src/YuoCore.Ecs/YuoCoreTrace.cs`：同款 `#if !YUOCORE_TRACE_OFF` 双实现；内核独立构建默认启用（内核观测测试不受影响），宿主生产构建关闭。
- `Dockerfile`：两个 `dotnet publish` 均加 `-p:DaoHuaObservability=false`；补 `COPY Directory.Build.props`（否则容器内 props 不生效）。
- 验证：OFF 构建的 `Domain.dll` 内不存在 `daohua.runtime.duration` 字符串（UTF-16 元数据检查），ON 构建存在；双模式构建均 0 警告 0 错误。
- 注意：`SystemBase` 热循环内的 5 个局部计数器（scanned/nullSkipped 等）在 OFF 下仍保留 `++` 累加——单实体约 3 次 ALU 操作，JIT 死存消除依赖后 Count 空桩内联；为不碎片化内核热循环未加 `#if`，属于可忽略残差。

### 正式定名

- `vendor/YuoCore-optimized` → `vendor/YuoCore`：`git mv` + `.git/modules/vendor/` 迁移 + `worktree`/`gitdir` 指针修正 + `.gitmodules` 更新；上游分支仍为 `ecs-optimized`（远端正名不动）。
- 全仓引用替换：`Game.slnx`、`Dockerfile`、`verify.sh`、`dev.sh`、`dev-hot.mjs`、`bench-*.sh`、`src/Ecs/Ecs.csproj`、`src/Domain/Domain.csproj`、`.dockerignore`（移除 frontend-sim 条目）。
- 基准变体 `ecs-optimized` → `ecs`：`BenchVariant.Parse`、库名 `daohua_bench_ecs`、产物 `artifacts/runtime/ecs`、`BenchmarkHost` 白名单、三脚本用法文本。
- SHA 钉更新：内核新提交 `7b36f80`（`bench-service.sh` `CORE_SHA` + `Bench/Program.cs` `ExpectedYuoCoreSha`）。
