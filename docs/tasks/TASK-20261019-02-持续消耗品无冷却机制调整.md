# TASK-20261019-02 持续消耗品无冷却机制调整

## 1. 任务背景与核心需求

- **提出时间**：2026-10-19 02:40:00
- **需求来源**：用户明确提出指令——「调整，持续性消耗物品，不要有cd」。
- **问题分析**：
  - 在既有机制中，持续性消耗物品（`isContinuous = true`）如阵法制品聚灵阵盘（`item.juling-formation-disk`）配有 `cooldownSeconds = 300`，在 300 秒持续时间耗尽后会进入 300 秒冷却时间，期间即使背包/托管中有存量也无法继续补能，导致阵法或增益存在强制空窗期；
  - 持续性消耗物品的本质是维持特定持续增益或产出倍率，只要玩家持有足量制品，应当能够随时间自然耗尽并无缝自动扣件续充；而冷却时间（CD）属于即时性消耗物品（如止血散、顺气丸、雷击符等即时触发效果）的频次限制机制；
  - 因此需要将所有持续性消耗物品的 CD 彻底移除，保持持续性消耗品为纯粹的「时长-库存」续航模型，耗竭后只要有剩余库存或托管配额，下一周期（或行动起点/战内续补）即可无缝自动使用续补，不再受任何冷却阻断。

## 2. 详细技术方案与改动范围

### 2.1 文档先行（总纲真源修订）
- `docs/design/总纲/06-持续消耗品机制与生活制造体系.md`：
  - 修订 §6.1.4 持续消耗品机制：持续消耗品无冷却（`cooldownSeconds` 恒为 0 或缺省），耗竭后只要满足使用条件且背包有库存，在下一个行动起点或战斗波次/战内即可无缝自动使用续补；
- `docs/design/总纲/20-技艺体系与符箓阵法强化规约.md`：
  - 修订 §20.3 阵法制品聚灵阵盘描述：原「持续 300 秒、冷却 300 秒」修订为「持续 300 秒、无冷却（0s CD），入场自动消耗 1 件充入 300 秒，耗竭后只要背包有存量即可直接续充」；
- `docs/design/总纲/index.html`：
  - 镜像修订 HTML 视图中的相应章节。

### 2.2 配表与契约校验门禁
- `config/game-data/items/materials.json`：
  - 聚灵阵盘（`item.juling-formation-disk`）移除 `"cooldownSeconds": 300` 声明；
- `src/Domain/GameData/GameDataCatalog.cs`：
  - 持续性消耗品（`consumable.IsContinuous`）不允许配置正冷却（`consumable.CooldownSeconds > 0` 判定为非法配置并报错）；
- `src/DataTool/Program.cs`：
  - items 校验中增加断言：若 `consumable` 声明了 `"isContinuous": true`，其 `cooldownSeconds` 必须缺省或为 0，严禁配置大于 0 的数值。

### 2.3 ECS 运行时规则与组队会话引擎
- `src/Ecs/Systems/ActionExecutionRules.Timed.cs`：
  - `PrepareSustainedAutoUse`：非战斗持续消耗品补能准入不再检查 `slot.CooldownUntilUnixSeconds`；
  - `CompleteSustainedAutoUse`：持续消耗品耗尽时不再向 `AutoUseSlotState` 写入冷却时间戳；
- `src/Ecs/Systems/CombatActionRules.cs`：
  - `DrainCombatSustainedSlots`：战斗存活时钟持续扣减耗尽时，持续消耗品不再向槽位写入冷却时间戳；
  - `RechargeCombatSustainedSlots`：战斗入场与战内续补时，持续消耗品不再受 `CooldownUntilUnixSeconds` 限制，耗竭后只要满足触发条件与背包库存，立即扣件并充能注入 Buff；
- `src/Ecs/ActionParticipationSessionEngine.cs`：
  - `EvaluateSustained`：持续消耗品到期时 `CooldownUntilUnixSeconds` 保持为 0，若托管中有配额且单位存活满足条件，立即在当前推进中无缝再充能下一个周期。

### 2.4 测试用例更新与门禁验证
- `tests/Domain.Tests/CombatConsumableTests.cs`：
  - 测试阵盘测试数据移除 `cooldownSeconds: 40`；
  - `SustainedSlotCooldownsAfterDepletionBeforeNextRecharge` 重构为 `SustainedSlotRechargesWithoutCooldownAfterDepletion`，验证持续消耗品耗竭后无 CD 即可直接重新扣件充能；
- `tests/Domain.Tests/ActionParticipationSessionTests.cs`：
  - 组队会话聚灵阵盘测试：验证 300 秒持续时间到期耗尽后直接无缝充能第 2 件，无需经过 300 秒冷却窗口；
- `tests/Domain.Tests/TechniqueAndEnhancementTests.cs`：
  - 断言聚灵阵盘配表属性 `consumable.CooldownSeconds == 0`，耗竭前后冷却恒为 0。
