# TASK-20261113-08 全服排行榜整点快照投影

## 需求复述（2026-11-13 16:38 确认）

用户要求「超高性能的全服排行榜，每小时更新数据」。经问答裁定：

- **榜单清单（12 榜）**：境界榜（等级+经验）/ 技艺榜×7（炼丹/炼器/制符/强化/阵法/采集/挖掘，每艺一榜）/ 身家榜（估值口径同 `PartyValuationService`）/ 灵石榜 / 宗门榜（按人数）/ 斗法榜（按生平击破同道）。
- **名次深度**：榜页 Top 50 + 全服个人精确名次。
- **节奏**：整点快照（小时边界物化，榜页标注结算时刻）。

## 关键既有基座（勘察结论）

- `game.player_projection`：分段落库同事务顺带维护的读模型（`PostgresSectionRepository.UpsertProjectionAsync` 解析 section 载荷提取字段），当前仅 `realm_rank/node/presence/offline_since/last_active_at` ——排行榜投影的天然扩展点。
- `PartyValuationService`：身家估值权威口径（装备+功法+工具按坊市参考价/回收价），已支持「在线快照 + 离线 loadout 分段批量解码（含刷盘队列叠加）」。
- 技艺经验在 `loadout` 分段 `TechniqueExperiences`；等级经 `TechniqueCatalog.LevelFor`（境界曲线前 30 级线性削减）派生。
- 灵石在 `economy.player_asset_balances`（`currency.spirit-stone`），宗门成员/大殿在 `social.zongmen*`/`game.node_buildings`，均纯 SQL。
- **斗法生涯胜负计数缺失**：`DuelWins/DuelLosses` 仅存于行动/离线/每日三账本，需向 `progression` 新增生涯持久字段（记账点：duel.won/duel.lost/ApplyDuelForfeit 三处，模式同 `Progression.TotalDefeats`）。
- 文档红线：`commercial-persistence-architecture.md` §117——排行榜只能是派生数据；`initial-design.md`——完全离线账号只进排行榜聚合。
- `PlayerCardModal`/`PlayerCardDto` 全域可查（TASK-20261109-11 已为排行榜放开名片权限）。

## 设计要点（详见总纲第 26 篇）

- 领域：`progression` 载荷新增 `duelWins`/`duelLosses` 生涯计数（可缺省解码 → 存档标签 +1）。
- 投影：`player_projection` 扩 `experience/lifetime_experience/duel_wins/duel_losses/avatar` 五列；loadout 不投影（整点批量解码）。
- 物化：`LeaderboardSnapshotWorker`（BackgroundService）整点对齐 + 启动补齐；`game.leaderboard_snapshots`（JSONB payload）+ `game.leaderboard_ranks`（score>0 全服名次）。
- 读路：`GET /api/v1/leaderboards`、`GET /api/v1/leaderboards/{boardId}`，预序列化字节 + ETag + `Cache-Control: private,max-age=60`，零 DB 命中。
- 前端：新顶级页签 LeaderboardPage，二级榜 Tab，行点击弹 PlayerCardModal。
- Schema v53 + migrations/0053_v52_to_v53.sql。
