## 维护规约

1. **触发时机**：每次用户发起任何**非 Bug 修复**性质的任务（包括但不限于新功能设计、数值模型调整、架构重构、世界观扩充、前端界面与体验开发等），必须在启动开发前先分析用户需求与提示词，登记入本文档。
2. **时刻记录时间**：任务提出时间、需求分析完成时间、各阶段开发进度节点时间以及最终完成时间均需精确记录（格式：`YYYY-MM-DD HH:mm:ss`）。
3. **持续同步**：在开发周期中（如完成子模块、通过测试、遇到阻塞或变更设计），必须同步更新本文档的任务进度条与进度日志。
4. **状态流转**：
   - `📋 规划中`：已记录需求与方向，等待排期或细化方案。
   - `🚀 进行中`：正在编写代码、配置、文档或测试。
   - `🧪 联调/验证中`：功能已初成，正在进行领域测试、前端构建或容器同构验收。
   - `✅ 已完成`：已通过全部验证并提交 Git，移至已完成区域。
   - `⏸️ 挂起/废弃`：需求调整或优先级变更。
