本文档用于追踪《道化太初》的计划开发方向、功能规划、正在执行的任务与历史完成进度。

---

## 维护规约

1. **触发时机**：每次用户发起任何**非 Bug 修复**性质的任务（包括但不限于新功能设计、数值模型调整、架构重构、世界观扩充、前端界面与体验开发等），必须在启动开发前先分析用户需求与提示词，在本文档及独立详情文档中登记。
2. **详情独立建档**：**任务实现方案、技术设计、子任务分解、时间节点与过程日志一律存放在 `docs/tasks/TASK-YYYYMMDD-XX-任务简称.md` 独立文件中**——命名格式为「`TASK-` + 年月日 + `-` + 当日两位序号 + `-` + 任务简要中文名」（示例：`TASK-20261011-07-任务面板归档与命名规约.md`；任务编号沿用 `TASK-YYYYMMDD-XX`，文件名简称为检索辅助、可在实施前微调但须与看板链接同步），严禁在本文档中堆砌冗长实现详情，保持主看板清晰轻量。
3. **时刻记录时间**：任务提出时间、需求分析完成时间、各阶段开发进度节点时间以及最终完成时间均需精确记录（格式：`YYYY-MM-DD HH:mm:ss`）。
4. **持续同步**：在开发周期中（如完成子模块、通过测试、遇到阻塞或变更设计），必须同步更新对应独立任务文档及本文档的状态与进度。
5. **状态流转**：
   - `📋 规划中`：已记录需求与方向，等待排期或细化方案。
   - `🚀 进行中`：正在编写代码、配置、文档或测试。
   - `🧪 联调/验证中`：功能已初成，正在进行领域测试、前端构建或容器同构验收。
   - `✅ 已完成`：已通过全部验证并提交 Git，移至已完成区域。
   - `⏸️ 挂起/废弃`：需求调整或优先级变更。
6. **本地开发任务硬约束**：当前任务默认不承担历史兼容；不得新增旧数据迁移、双读双写、legacy fallback 或过渡适配。测试只覆盖关键不变量和独立高风险故障面，禁止覆盖率驱动的重复测试与过度防御式实现。
7. **历史归档**：任务详情文档按月度深度合并归档至 `docs/tasks/archive/archive-YYYY-MM.md`——已完成任务详情提炼入档后删除原文件、可从 Git 历史找回；进行中/验证中任务保留详情文档与看板行不入档（2026-11-13 起按此口径，首批 2026-10-11 归档含当时在途任务属历史快照）。当前月度档：2026-08 档 73 项、2026-09 档 117 项、2026-10 档 310 项、2026-11 档 86 项。归档条目含编号/名称/分类/时间/状态/摘要；同日编号冲突的任务在归档条目中标注。
