## 维护规约

1. **触发时机**：每次用户发起任何**非 Bug 修复**性质的任务（包括但不限于新功能设计、数值模型调整、架构重构、世界观扩充、前端界面与体验开发等），必须在启动开发前先分析用户需求与提示词，在本文档及独立详情文档中登记。
2. **详情独立建档**：**任务实现方案、技术设计、子任务分解、时间节点与过程日志一律存放在 `docs/tasks/TASK-YYYYMMDD-XX.md` 独立文件中**，严禁在本文档中堆砌冗长实现详情，保持主看板清晰轻量。
3. **时刻记录时间**：任务提出时间、需求分析完成时间、各阶段开发进度节点时间以及最终完成时间均需精确记录（格式：`YYYY-MM-DD HH:mm:ss`）。
4. **持续同步**：在开发周期中（如完成子模块、通过测试、遇到阻塞或变更设计），必须同步更新对应独立任务文档及本文档的状态与进度。
5. **状态流转**：
   - `📋 规划中`：已记录需求与方向，等待排期或细化方案。
   - `🚀 进行中`：正在编写代码、配置、文档或测试。
   - `🧪 联调/验证中`：功能已初成，正在进行领域测试、前端构建或容器同构验收。
   - `✅ 已完成`：已通过全部验证并提交 Git，移至已完成区域。
   - `⏸️ 挂起/废弃`：需求调整或优先级变更。
6. **本地开发任务硬约束**：当前任务默认不承担历史兼容；不得新增旧数据迁移、双读双写、legacy fallback 或过渡适配。测试只覆盖关键不变量和独立高风险故障面，禁止覆盖率驱动的重复测试与过度防御式实现。

## 开发方向路线图 (Roadmap)

### 近期核心方向

1. **基础世界与战斗核心闭环**
   - 战斗引擎与技能体系深化
   - 数值期望模型与关卡基准校准
2. **挂机与结算确定性**
   - 在线/离线快进补算与一致性验证
   - 冷挂机计算节点联调与性能基线压测
3. **前端界面与交互体验规范化**
   - 公共组件与统一模板收拢
   - 移动端/桌面端自适应与悬浮卡片规范落地
4. **协作规范与自动化流程**
   - 任务看板与需求追踪机制建立
   - 多 Agent 并行协作开发机制落地
